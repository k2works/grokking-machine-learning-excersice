    第 11 章 サポートベクターマシンとカーネル法（Python 版）¶

    原著第 11 章「Finding boundaries with style」を Python で実装します。第 5 章のパーセプトロンは「分けられればどこでもよい」でした。SVM は できるだけ広い余白を空ける 境界線を選びます。

    サンプル実装は apps/grokking-ml-python/src/grokking_ml/ch11_svm.py です。

    Jupyter Notebook で試す: この章の実験は ch11.ipynb にまとめてあります。実装本体を読み込んで動かすので、値を変えてその場で試せます。

    この章で作るもの¶

    • ヒンジ損失とマージン
    • 正則化つきの SVM 学習
    • 線形・多項式・RBF カーネル
    • カーネル版パーセプトロン

    パーセプトロンの何が不満なのか¶

    第 5 章のパーセプトロンは、8 点すべてを正しく分類できた時点で更新を止めます。その境界線がぎりぎりでも構いません。

    実際に測ってみると、驚く結果になります。

    def test_svm_leaves_a_wider_margin_than_the_perceptron():
    perceptron, _ = perceptron_algorithm(POINTS, PERCEPTRON_LABELS)
    as_svm = SupportVectorMachine(tuple(perceptron.weights), perceptron.bias)
    svm, _ = train_svm(POINTS, LABELS, epochs=20000, regularization=0.01)

    # どちらも完全に分離できている
    assert accuracy(as_svm, POINTS, LABELS) == pytest.approx(1.0)
    assert accuracy(svm, POINTS, LABELS) == pytest.approx(1.0)
    # しかしパーセプトロンは分離できた時点で止まるため、余白がない
    assert as_svm.margin(POINTS, LABELS) == pytest.approx(0.0)
    assert svm.margin(POINTS, LABELS) > 0.5
    モデル 正解率 マージン幅
    パーセプトロン（第 5 章） 1.0 0.0
    SVM（正則化 0.01） 1.0 0.648

    パーセプトロンのマージンは 0 でした。 境界線の上にちょうど乗っている点があるのです。第 5 章で score >= 0 を正のクラスとする約束にしたおかげで正解率は 1.0 ですが、その点が少しでも動けば誤分類になります。

    正解率という指標は、この危うさを一切見せません。第 7 章で「正解率だけでは足りない」と学びましたが、ここでも別の形で同じことが起きています。

    マージンとヒンジ損失¶

    SVM は「境界線から距離 1 以内に点があってはいけない」と要求します。

    def hinge_loss(model: SupportVectorMachine, point: Point, label: int) -> float:
    """ヒンジ損失。マージンの内側に入った分だけ罰する。"""
    return max(0.0, 1.0 - label * model.score(point))

    label * score は「正しい側にどれだけ離れているか」です。ラベルを +1 / -1 で表すのはこのためです（第 5・6 章の 0/1 では、この積が意味を持ちません）。

    状況 label × score ヒンジ損失
    正解かつ余裕がある 2.0 0.0
    正解だがぎりぎり 0.5 0.5
    境界線上 0.0 1.0
    誤分類 -1.0 2.0

    「正解しているのに損失が残る」 のが第 5 章との決定的な違いです。パーセプトロンは正解した点を無視しましたが、SVM は「正解したがマージンの内側にいる点」も押し返します。

    第 6 章のロジスティック回帰も正解した点を動かしましたが、動機が違います。ロジスティックは「確率を 1 に近づけたい」、SVM は「境界から遠ざけたい」です。

    正則化とマージンのトレードオフ¶

    def svm_error(
    model: SupportVectorMachine,
    points: Sequence[Point],
    labels: Sequence[int],
    regularization: float = 0.1,
) -> float:
    """SVM の目的関数。ヒンジ損失の平均 + 重みの大きさへの罰。"""
    losses = sum(
        hinge_loss(model, point, label) for point, label in zip(points, labels)
    ) / len(points)
    penalty = regularization * sum(w * w for w in model.weights)
    return losses + penalty

    第 4 章の L2 正則化とまったく同じ形の罰則項です。ただし 目的が違います。

    章 正則化の目的 効果
    第 4 章 過学習を防ぐ 重みを縮めてモデルを単純化
    第 11 章 マージンを広げる 重みを縮めると境界線の余白が広がる

    マージン幅は 2 / ||w|| に比例します。重みを小さくすることが、そのまま余白を広げることになります。 第 4 章では「複雑さを抑える」ための道具だったものが、ここでは「余白を稼ぐ」ための道具になりました。同じ式が別の意味を持つ例です。

    def test_weaker_regularization_widens_the_margin():
    loose, _ = train_svm(POINTS, LABELS, epochs=20000, regularization=0.01)
    tight, _ = train_svm(POINTS, LABELS, epochs=20000, regularization=0.1)
    assert loose.margin(POINTS, LABELS) > tight.margin(POINTS, LABELS)

    このテストは直感に反します。 「正則化を強くすれば重みが小さくなり、マージンが広がるのでは」と考えたくなります。

    実際には逆でした。正則化が強すぎると重みが 0 方向へ潰れ、||w|| が小さくなる以上に 境界線からの距離そのものが縮みます。マージンは「もっとも近い点までの距離」なので、重みを縮めすぎると点との位置関係が崩れます。

    正則化 重み マージン
    0.01 (1.697, 1.668) 0.648
    0.05 (0.968, 0.936) 0.401
    0.10 (0.873, 0.856) 0.385

    更新則¶

    def svm_step(
    model: SupportVectorMachine,
    point: Point,
    label: int,
    learning_rate: float = 0.01,
    regularization: float = 0.1,
) -> SupportVectorMachine:
    """1 点分の更新。マージンの内側なら押し返し、常に重みを縮める。"""
    inside_margin = label * model.score(point) < 1.0
    weights = []
    for w, x in zip(model.weights, point):
        gradient = 2.0 * regularization * w
        if inside_margin:
            gradient -= label * x
        weights.append(w - learning_rate * gradient)
    bias = model.bias + (learning_rate * label if inside_margin else 0.0)
    return SupportVectorMachine(tuple(weights), bias)

    2 つの力が働きます。

    1. 常に働く力: 重みを 0 方向へ縮める（2 × 正則化 × w）
    2. マージンの内側でだけ働く力: 点を押し返す（label × x）

    マージンの外にいる点では 2 番目が消えるので、重みが少し縮むだけ です。これをテストで固定しました。

    def test_svm_step_leaves_confident_points_almost_alone():
    model = SupportVectorMachine(weights=(1.0, 1.0), bias=-3.0)
    moved = svm_step(model, (3.0, 2.0), 1, learning_rate=0.01, regularization=0.1)
    # マージンの外なので、重みを縮める力しか働かない
    assert moved.bias == pytest.approx(model.bias)
    assert moved.weights[0] < model.weights[0]

    バイアスがまったく動かない ことが「押し返す力が働いていない」ことの証拠になります。

    カーネル法¶

    XOR は直線で分けられません（第 10 章）。ニューラルネットは隠れ層で解きましたが、SVM は別のアプローチを取ります。

    点を高次元へ写してから直線を引く。 ただし、写した先の座標を計算せず、内積だけを求めます。これがカーネルトリックです。

    Kernel = Callable[[Point, Point], float]


def linear_kernel(a: Point, b: Point) -> float:
    """線形カーネル。ただの内積。"""
    return dot(a, b)


def polynomial_kernel(degree: int = 2, constant: float = 1.0) -> Kernel:
    """多項式カーネル。特徴量の積を暗黙のうちに作る。"""

    def kernel(a: Point, b: Point) -> float:
        return (dot(a, b) + constant) ** degree

    return kernel


def rbf_kernel(gamma: float = 1.0) -> Kernel:
    """RBF（ガウシアン）カーネル。距離が近いほど 1 に近づく。"""

    def kernel(a: Point, b: Point) -> float:
        squared_distance = sum((x - y) ** 2 for x, y in zip(a, b))
        return math.exp(-gamma * squared_distance)

    return kernel

    polynomial_kernel と rbf_kernel は 関数を返す関数 です。ハイパーパラメータ（次数、gamma）を固定した「カーネル」を作ります。第 4 章以降 F# 版でずっと使ってきた部分適用を、Python ではクロージャで実現しています。

    linear_kernel だけは引数を取らないので、直接カーネルとして渡せます。「設定が要るものは工場関数、要らないものは関数そのもの」 という使い分けです。

    カーネルの意味¶

    polynomial_kernel(degree=2) は (x·y + 1)² を計算します。展開すると x₁²y₁² + 2x₁y₁x₂y₂ + ... という項が現れます。これは「x₁², x₁x₂, x₂², x₁, x₂, 1」という 6 次元空間での内積と同じです。

    つまり、6 次元へ写す計算を 一度もせずに、その空間での内積が手に入ります。これが「トリック」と呼ばれる所以です。

    RBF カーネルはさらに極端で、無限次元空間の内積 に相当します。

    def test_rbf_kernel_decays_with_distance():
    kernel = rbf_kernel(gamma=1.0)
    near = kernel((0.0, 0.0), (0.5, 0.0))
    far = kernel((0.0, 0.0), (3.0, 0.0))
    assert 0.0 < far < near < 1.0

    RBF は「同じ点なら 1、遠いほど 0 に近い」という 類似度 です。距離の測り方をそのままモデルに持ち込めます。

    カーネル分類器¶

    @dataclass(frozen=True)
class KernelClassifier:
    """カーネル分類器。訓練点そのものを重み付きで覚えておく。"""

    points: tuple[tuple[float, ...], ...]
    labels: tuple[int, ...]
    weights: tuple[float, ...]
    bias: float
    kernel: Kernel

    def score(self, point: Point) -> float:
        return self.bias + sum(
            weight * label * self.kernel(support, point)
            for weight, label, support in zip(self.weights, self.labels, self.points)
        )

    モデルが訓練データそのものを保持します。 これまでのモデルは重みベクトル（第 3〜6・10 章）や確率表（第 8 章）、木（第 9 章）でしたが、カーネル法は 訓練点を捨てられません。

    写した先の空間の座標が計算できない以上、「その空間での重みベクトル」も持てません。代わりに「どの訓練点とどれだけ似ているか」の重み付き和で予測します。

    これは実用上の弱点でもあります。訓練データが 100 万点あれば、予測のたびに 100 万回のカーネル計算が要ります。重みが 0 の点は無視できる ので、実際には「重みが正の点」だけが効きます。それが サポートベクター です。

    def test_only_misclassified_points_gain_weight():
    model = train_kernel_classifier(XOR_POINTS, XOR_LABELS, kernel=rbf_kernel(), epochs=200)
    # 重みが増えた点だけがサポートベクターとして効く
    assert any(weight > 0.0 for weight in model.weights)
    assert all(weight >= 0.0 for weight in model.weights)

    実行結果¶

    XOR を 3 種類のカーネルで解きます。

    カーネル 正解率
    線形 0.50
    多項式（2 次） 1.00
    RBF 1.00

    線形カーネルは 0.5、つまり当てずっぽうと同じです。 内積しか使わないので、実質的に第 5 章のパーセプトロンと変わりません。

    多項式カーネルと RBF カーネルは 1.0 に達しました。アルゴリズムは一切変えず、カーネル関数を差し替えただけです。

    def test_kernel_classifier_with_a_linear_kernel_cannot_solve_xor():
    model = train_kernel_classifier(XOR_POINTS, XOR_LABELS, kernel=linear_kernel)
    assert kernel_accuracy(model, XOR_POINTS, XOR_LABELS) < 1.0


def test_polynomial_kernel_solves_xor():
    model = train_kernel_classifier(XOR_POINTS, XOR_LABELS, kernel=polynomial_kernel(degree=2))
    assert kernel_accuracy(model, XOR_POINTS, XOR_LABELS) == pytest.approx(1.0)

    第 10 章のニューラルネットワークと同じ問題を、まったく違う方法で 解いたことになります。

    手法 XOR の解き方
    ニューラルネット（第 10 章） 隠れ層で特徴を 学習する
    カーネル法（第 11 章） カーネルで特徴を 設計する

    ニューラルネットは「どう変換すべきか」をデータから学びます。カーネル法は「こう変換せよ」を人間が指定します。前者は柔軟だが不透明、後者は明快だが選択が難しい というトレードオフです。

    まとめ¶

    • パーセプトロンは分離できた時点で止まるため、マージンが 0 になることがあります。正解率は 1.0 でも危ういモデルです。
    • ヒンジ損失は「正解しているのにまだ損失が残る」形をしています。これがマージンを稼ぐ力になります。
    • SVM の正則化は第 4 章と同じ式ですが、目的が「過学習防止」から「マージン拡大」に変わります。
    • カーネルは「高次元へ写した先での内積」を、写さずに計算します。
    • カーネル法はモデルが訓練点を保持します。重みが正の点がサポートベクターです。
    • XOR は隠れ層（第 10 章）でもカーネル（本章）でも解けます。学習するか設計するかの違いです。
