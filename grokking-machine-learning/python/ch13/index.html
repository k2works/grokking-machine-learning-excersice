    第 13 章 エンドツーエンドの実例（Python 版）¶

    原著第 13 章「Putting it all in practice」を Python で実装します。これまでの章で作った部品を組み合わせて、生データから評価までを 1 本のパイプラインに通します。

    新しいアルゴリズムは登場しません。本章の主題は 「実務のほとんどは前処理と評価である」 ということです。

    サンプル実装は apps/grokking-ml-python/src/grokking_ml/ch13_end_to_end.py です。

    Jupyter Notebook で試す: この章の実験は ch13.ipynb にまとめてあります。実装本体を読み込んで動かすので、値を変えてその場で試せます。

    この章で作るもの¶

    • 欠損値の補完・正規化・One-Hot エンコーディング
    • 生データから特徴量ベクトルへの変換
    • 3 つのモデル（第 6・9・12 章）の学習と比較
    • 第 7 章の指標による評価

    部品を組み合わせるだけ¶

    インポートを見れば、本章の性格が分かります。

    from grokking_ml.ch04_regularization import train_test_split
from grokking_ml.ch06_logistic_regression import LogisticClassifier, logistic_regression
from grokking_ml.ch07_metrics import (
    ConfusionMatrix, auc, confusion_matrix, f1_score, precision, recall,
)
from grokking_ml.ch07_metrics import accuracy as matrix_accuracy
from grokking_ml.ch09_decision_trees import Tree, build_tree
from grokking_ml.ch12_ensembles import AdaBoost, train_adaboost

    5 つの章から部品を集めています。 どれも書き換えていません。第 4 章の分割、第 6 章のロジスティック回帰、第 7 章の指標、第 9 章の決定木、第 12 章の AdaBoost。

    10 章分の積み重ねが、ここで一気に繋がります。

    第 4 章の分割がそのまま使えた¶

        train_x, train_y, test_x, test_y = train_test_split(
        dataset.points, dataset.labels, test_ratio=0.3, seed=0
    )

    第 4 章の train_test_split は Sequence[float] の特徴量を想定して書きました。本章の特徴量は list[float]（多次元の点）です。型ヒントは合っていませんが、実装はインデックスの並べ替えしかしていないので、そのまま動きます。

    これは Python の動的型付けの利点であり、同時に危うさでもあります。Kotlin 版と F# 版では型が合わず、本章で分割関数を書き直すことになりました。

    前処理¶

    実務のデータは、そのままではモデルに渡せません。

    欠損値¶

    def parse_number(text: str, default: float = 0.0) -> float:
    """数値に見えない値は既定値に落とす。欠損への最初の砦。"""
    try:
        return float(text)
    except ValueError:
        return default


def impute_missing(column: Sequence[float | None]) -> list[float]:
    """欠損を中央値で埋める。平均より外れ値に強い。"""
    known = [value for value in column if value is not None]
    filler = median(known)
    return [filler if value is None else value for value in column]

    平均ではなく中央値を使います。 外れ値に引きずられないためです。

    def test_impute_missing_is_robust_to_outliers():
    # 平均なら 1000 に引きずられるが、中央値なら影響を受けない
    filled = impute_missing([1.0, 2.0, 3.0, 1000.0, None])
    assert filled[-1] == pytest.approx(2.5)

    [1, 2, 3, 1000] の平均は 251.5 ですが、中央値は 2.5 です。1 件の入力ミスが全欠損値を汚染するのを防げます。

    型を Sequence[float | None] としているのが要点です。「値がない」ことを None で表し、0.0 と区別します。 第 8 章で見た「Python の Counter は 0 と不在を区別できない」という問題を、ここでは意識的に避けました。

    正規化¶

    def normalize(column: Sequence[float]) -> list[float]:
    """最小 0・最大 1 に揃える。値の幅が違う特徴量を対等に扱うため。"""
    low = min(column)
    high = max(column)
    if high == low:
        return [0.0 for _ in column]
    return [(value - low) / (high - low) for value in column]

    年齢は 18〜70、収入は 200〜900。このまま第 6 章のロジスティック回帰に渡すと、収入だけが効いてしまいます。 重みの更新量は特徴量に比例する（第 3 章の二乗トリック以来ずっとそうです）ので、値の大きい特徴量が支配的になります。

    第 9 章の決定木は各特徴量を独立に見るため正規化が不要ですが、同じ前処理を通したほうがモデルの比較が公平になります。

    high == low のときに 0 除算しないことも仕様として固定しました。

    def test_normalize_handles_a_constant_column():
    # 幅が 0 の列で 0 除算しない
    assert normalize([5.0, 5.0, 5.0]) == [0.0, 0.0, 0.0]

    カテゴリ変数¶

    def one_hot(column: Sequence[str]) -> tuple[list[list[float]], list[str]]:
    """カテゴリ列を 0/1 の列に展開する。"""
    categories = sorted(set(column))
    rows = [[1.0 if value == category else 0.0 for category in categories] for value in column]
    return rows, list(categories)

    「東京・大阪・京都」を 0・1・2 と番号で表すと、「京都は東京の 2 倍」という存在しない大小関係が生まれます。 モデルはその数値をそのまま重みに掛けるので、意味のない順序を学習してしまいます。

    代わりに 3 本の 0/1 列へ展開します。sorted でカテゴリを辞書順に固定しているのは、列の順番が実行のたびに変わらないようにするため です（set は順序を保証しません）。

    生データから特徴量へ¶

    def build_dataset(rows: Sequence[Row], label_column: str) -> Dataset:
    """生の行データを、数値の特徴量ベクトルとラベルに変換する。"""
    labels = [1 if row[label_column] == "yes" else 0 for row in rows]
    numeric_columns = ["age", "income"]
    categorical_columns = ["city"]

    columns: list[list[float]] = []
    names: list[str] = []
    for name in numeric_columns:
        raw = [None if row[name] == "" else parse_number(row[name]) for row in rows]
        columns.append(normalize(impute_missing(raw)))
        names.append(name)
    for name in categorical_columns:
        expanded, categories = one_hot([row[name] for row in rows])
        for index, category in enumerate(categories):
            columns.append([row[index] for row in expanded])
            names.append(f"{name}={category}")

    points = [[column[i] for column in columns] for i in range(len(rows))]
    return Dataset(points=points, labels=labels, feature_names=names)

    列ごとに処理してから、最後に行へ転置します。 正規化も欠損補完も「列全体」を見る操作なので、この順序が自然です。

    feature_names を持たせているのは、モデルを解釈するときに必要になる からです。第 9 章の決定木は Split(feature=1, threshold=0.4) と答えますが、「特徴量 1」が何なのかは名前がないと分かりません。

    3 つのモデルを同じ土俵で比較する¶

    def evaluate(
    name: str,
    predict: Callable[[Point], int],
    probability: Callable[[Point], float],
    points: Sequence[Point],
    labels: Sequence[int],
) -> Evaluation:
    """予測関数と確率関数から、第 7 章の指標をまとめて算出する。"""
    matrix: ConfusionMatrix = confusion_matrix(labels, [predict(point) for point in points])
    return Evaluation(
        name=name,
        accuracy=matrix_accuracy(matrix),
        precision=precision(matrix),
        recall=recall(matrix),
        f1=f1_score(matrix),
        auc=auc(labels, [probability(point) for point in points]),
    )

    モデルの型ではなく「予測関数」と「確率関数」を受け取ります。 これにより、共通のインターフェースを後付けせずに 3 つのモデルを同じ関数で評価できます。

    3 つのモデルは出力の形がばらばらです。

    モデル 予測 「確率」に相当するもの
    ロジスティック回帰（第 6 章） 0 / 1 予測確率（0〜1）
    決定木（第 9 章） 0 / 1 なし（0/1 をそのまま使う）
    AdaBoost（第 12 章） +1 / -1 重み付き投票のスコア（範囲は不定） 
    def evaluate_adaboost(
    model: AdaBoost,
    points: Sequence[Point],
    labels: Sequence[int],
) -> Evaluation:
    """第 12 章の AdaBoost を評価する。ラベルは +1 / -1 なので 0 / 1 に戻す。"""
    return evaluate(
        "adaboost",
        lambda point: 1 if model.predict(point) == 1 else 0,
        model.score,
        points,
        labels,
    )

    AdaBoost だけラベルの表現が違う ため、変換が必要でした。第 11 章で +1/-1 を導入した判断が、ここで統合コストとして表れています。

    AUC は「順位さえ合っていればよい」指標なので、確率でなくスコアでも計算できます（第 7 章で「AUC は閾値に依存しない」と確かめたとおりです）。決定木の 0/1 はほぼ順位情報を持たないため AUC が低めに出ますが、それも含めて比較の材料になります。

    実行結果¶

    「40 歳未満かつ収入 400 超なら購入」という規則に従う擬似データ 40 件（うち 9 件に 1 件は年齢が欠損）で試します。

    cd apps/grokking-ml-python
uv run pytest tests/test_ch13_end_to_end.py -q
    モデル 正解率 適合率 再現率 F1 AUC
    ロジスティック回帰 0.667 0.333 0.333 0.333 0.741
    決定木 0.750 0.500 1.000 0.667 0.833
    AdaBoost 0.750 0.500 0.333 0.400 0.778

    決定木が勝ちました。 真の規則が「40 歳未満 かつ 収入 400 超」という 2 つの閾値の組み合わせなので、軸に平行な分割を積む決定木と相性が良いのです。ロジスティック回帰は 1 本の直線しか引けないため、この「かつ」を表現しきれません。

    アルゴリズムの優劣ではなく、データの性質との相性です。 第 12 章で「バギングと AdaBoost のどちらが良いかは問題による」と書いたのと同じ構図が、ここでも現れました。

    そして指標ごとに順位が変わることも確認できます。

    • 正解率 で見ると決定木と AdaBoost が同点
    • 再現率 で見ると決定木が圧勝（買う人を全員拾えている）
    • 適合率 はどちらも 0.5（半分は空振り）

    第 7 章で「正解率だけでは足りない」と学んだことが、実データで再現しました。

    再現性¶

    def test_the_pipeline_is_reproducible():
    assert run_pipeline(ROWS) == run_pipeline(ROWS)

    パイプライン全体が決定的である ことをテストで固定しました。@dataclass(frozen=True) の __eq__ により、評価結果のリストごと比較できます。

    すべての乱数にシード（分割・ロジスティック回帰）を渡してあるので、何度実行しても同じ結果になります。「昨日と数字が違う」という事態は、機械学習のデバッグをもっとも難しくします。

uv run pytest

    まとめ¶

    • 本章に新しいアルゴリズムはありません。10 章分の部品を組み合わせただけです。
    • 欠損の補完は平均ではなく中央値。1 件の外れ値が全体を汚染しません。
    • 正規化しないと、値の大きい特徴量だけが効きます。
    • カテゴリを番号で表すと、存在しない大小関係が生まれます。One-Hot で展開します。
    • モデルの型ではなく「予測関数」を受け取れば、共通インターフェースなしに比較できます。
    • どのモデルが勝つかはデータの性質次第です。本章のデータでは決定木が最良でした。
