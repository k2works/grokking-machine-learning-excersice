    第 5 章 パーセプトロン（F# 版）¶

    原著第 5 章「Using lines to split our points」を F# で実装します。第 3・4 章の回帰は 数値を予測 するものでしたが、本章からは 分類 に入ります。点を直線で 2 つのクラスに分けるパーセプトロンを実装します。

    サンプル実装は apps/grokking-ml-fsharp/src/GrokkingMl/Ch05Perceptron.fs です。

    Polyglot Notebook で試す: この章の実験は ch05.ipynb にまとめてあります。実装本体を読み込んで動かすので、値を変えてその場で試せます。

    この章で作るもの¶

    • 線形分類器 score = w・x + bias、score >= 0 なら 1
    • 誤分類した点だけを使ってモデルを動かすパーセプトロントリック
    • パーセプトロン誤差関数と正解率
    • トリックを繰り返すパーセプトロンアルゴリズム

    回帰と分類の違い¶

    回帰（第 3・4 章） 分類（本章）
    出力 連続値（価格など） ラベル（0 か 1）
    モデルが表すもの データに沿う直線 データを 分ける 直線
    誤差 予測値と正解値の差 誤分類した点の境界からの距離
    更新するタイミング すべての点で 誤分類した点だけ

    分類では 正しく分類できている点は 1 ミリも動かしません。

    データセット¶

    原著と同じ「悲しい／楽しい」文の分類データを使います。特徴量は 2 つの単語 aack と beep の出現回数、ラベルは 1 が「楽しい」です。

    aack beep ラベル
    1 0 0
    0 2 0
    1 1 0
    1 2 0
    1 3 1
    2 2 1
    2 3 1
    3 2 1

    この 2 群は直線で完全に分離できます（線形分離可能）。

    モデル¶

    /// 特徴量ベクトル。
type Point = float list

/// 線形分類器 score = w・x + bias。score >= 0 なら 1、そうでなければ 0。
type Perceptron =
    { Weights: float list
      Bias: float }

/// 重み付き和。
let score (model: Perceptron) (point: Point) =
    List.map2 (*) model.Weights point
    |> List.sum
    |> (+) model.Bias

/// スコアの符号による分類。境界線上は正のクラスとして扱う。
let predict (model: Perceptron) (point: Point) = if score model point >= 0.0 then 1 else 0

    type Point = float list は F# では 型略称 であり、Kotlin の typealias と同じく新しい型を作りません。それでもシグネチャに Point と書けることの価値は大きく、float list が何を表すのかが読み手に伝わります。

    List.map2 (*) model.Weights point に注目してください。演算子をそのまま関数として渡せます。 fun a b -> a * b と書く必要はありません。内積の定義がほぼ数式のまま 1 行になります。

    score と predict を分けているのが要点です。score は境界線からどれだけ離れているかを表す連続値、predict はそれを 0 か 1 に潰した結果です。誤差関数はスコアのほうを使います。

    >= 0.0 としているのは、境界線上の点を正のクラスへ倒す約束です。この決めごとは明示的にテストしています。

    [<Fact>]
let ``predict は境界線上を正のクラスとして扱う`` () =
    let onLine = { Weights = [ 1.0; 1.0 ]; Bias = -2.0 }
    Assert.Equal(0.0, score onLine [ 1.0; 1.0 ], 6)
    Assert.Equal(1, predict onLine [ 1.0; 1.0 ])

    パーセプトロントリック¶

    /// パーセプトロントリック。誤分類した点だけモデルを動かす。
let perceptronTrick (learningRate: float) (model: Perceptron) (point: Point) (label: int) =
    let error = float (label - predict model point)

    if error = 0.0 then
        model
    else
        { Weights = List.map2 (fun w x -> w + learningRate * error * x) model.Weights point
          Bias = model.Bias + learningRate * error }

    error = label - predict は 3 通りの値しか取りません。

    ラベル 予測 error 動き
    1 1 0 動かない
    0 0 0 動かない
    1 0 +1 境界線を点のほうへ寄せる
    0 1 -1 境界線を点から遠ざける

    if が式なので、「動かない場合はモデルそのもの、動く場合は新しいレコード」という 2 つの結果を分岐の両腕として並べられます。早期リターンという概念すら要りません。

    F# は暗黙の数値変換を行わないため、float (label - predict model point) と明示的に変換しています。整数のまま learningRate * error を書くとコンパイルエラーです。手数は増えますが、型の混在が事故にならないことは第 4 章と同じ利点です。

    同じモデルをそのまま返すため、テストは等価比較で確認できます。

    [<Fact>]
let ``perceptronTrick は正しく分類できた点では動かない`` () =
    Assert.Equal(model, perceptronTrick 0.01 model [ 1.0; 2.0 ] 1)

    レコードは既定で構造的等価性を持つので、この 1 行で「値として等しい」ことを検証できます。

    第 4 章の二乗トリックと式を並べると、違いは掛ける値だけだと分かります。

    章 更新式（重み）
    第 3・4 章（二乗トリック） w + 学習率 × 特徴量 × 誤差の大きさ
    第 5 章（パーセプトロン） w + 学習率 × 特徴量 × 誤差の符号（+1 / -1 / 0）

    誤差関数¶

    分類の誤差を「何個間違えたか」で測ると学習に使えません。間違えた個数は境界線を少し動かしても変わらない ため、改善の方向が分からないからです。

    そこでパーセプトロン誤差は、誤分類した点について 境界線からの距離（スコアの絶対値） を使います。

    /// 1 点分の誤差。正しく分類していれば 0、誤っていればスコアの絶対値。
let perceptronError (model: Perceptron) (point: Point) (label: int) =
    if predict model point = label then
        0.0
    else
        abs (score model point)

/// 全点の平均誤差。
let meanPerceptronError (model: Perceptron) (points: Point list) (labels: int list) =
    List.map2 (perceptronError model) points labels
    |> List.average

/// 正解率。
let accuracy (model: Perceptron) (points: Point list) (labels: int list) =
    List.map2 (fun point label -> if predict model point = label then 1.0 else 0.0) points labels
    |> List.average

    List.map2 (perceptronError model) points labels は部分適用の好例です。モデルを固定した Point -> int -> float の関数ができ、それを 2 本のリストに同時適用します。ラムダを書く必要がありません。

    List.average があるおかげで「合計して個数で割る」を自分で書かずに済みます。Python 版・Kotlin 版では sum / len と書いていた箇所です。

    正解率も同じ形に揃えました。真偽値を 1.0 / 0.0 に写して平均を取れば、それがそのまま正解率です。「正解率 = 正解フラグの平均」という定義がコードに現れます。

    パーセプトロンアルゴリズム¶

    /// パーセプトロンアルゴリズム。モデルとエポックごとの平均誤差を返す。
let perceptronAlgorithm
    (learningRate: float)
    (epochs: int)
    (seed: int)
    (points: Point list)
    (labels: int list)
    =
    let rng = Random(seed)
    let dimensions = List.length (List.head points)
    let initial = { Weights = List.replicate dimensions 0.0; Bias = 0.0 }

    let step (model, errors) _ =
        let errors = meanPerceptronError model points labels :: errors
        let i = rng.Next(List.length points)
        let model = perceptronTrick learningRate model points[i] labels[i]
        (model, errors)

    let model, errors = List.fold step (initial, []) [ 1..epochs ]
    (model, List.rev errors)

    構造は第 3 章の線形回帰とまったく同じです。List.fold で状態（モデルと誤差の履歴）を畳み込み、誤差は :: で積んで最後に List.rev します。違うのは適用するトリックだけです。

    次元数を List.head points から取っているので、2 次元に限定されません。

    実行結果¶

    学習率 0.01、1000 エポックで次の結果になりました。

    項目 値
    aack の重み 0.04
    beep の重み 0.02
    バイアス -0.08
    正解率 1.0
    学習中の最大平均誤差 0.03
    最終の平均誤差 0.0

    境界線は 0.04 × aack + 0.02 × beep - 0.08 = 0、つまり 2 × aack + beep = 4 です。8 点すべてを正しく分類できています。

    重みが 0.04 や 0.02 と小さいことに驚くかもしれません。分類では 重みの絶対値ではなく比率と符号だけが意味を持つ ためです。すべての重みとバイアスを 100 倍しても境界線は同じ位置にあり、予測も変わりません。回帰では重みの大きさそのものが予測値を決めていたのと対照的です。

    Kotlin 版は aack + beep = 3 という別の境界線に到達しました。線形分離可能なデータには 正しい境界線が無数にある ためです。乱数列の違いで到達する解が変わりますが、どれも正解率 1.0 です。第 3・4 章では「同じくらいの誤差に収束する」ことを確認しましたが、本章では 正解率が 1.0 になること が言語をまたいだ共通の検証になります。

    誤差の推移が示すもの¶

    テストでは誤差の推移について、一見奇妙な事実を固定しています。

    [<Fact>]
let ``perceptronAlgorithm はデータを分離する`` () =
    let trained, errors = perceptronAlgorithm 0.01 1000 0 points labels
    Assert.Equal(1.0, accuracy trained points labels, 6)
    Assert.Equal(1000, List.length errors)
    // 初期モデル（重みもバイアスもすべて 0）はすべての点が境界線上にあるため誤差 0
    Assert.Equal(0.0, List.head errors, 6)
    // 学習の途中では誤差が生じ、最終的に 0 へ戻る
    Assert.True(List.max errors > 0.0)
    Assert.Equal(0.0, List.last errors, 6)

    初期状態の誤差が 0 になります。 重みもバイアスもすべて 0 なので、どの点のスコアも 0 です。誤分類した点の誤差は |スコア| = 0 になり、合計しても 0 なのです。

    これはパーセプトロン誤差の性質を突いた例です。この誤差関数は「境界線からどれだけ食い込んでいるか」しか見ていないので、全点が境界線上にある退化した状態を最良と誤認します。正解率は 0.5 しかないのに、です。

    第 3 章では「誤差が減った」ことを検証しましたが、本章で同じ検証を書くと 0.0 < 0.0 で失敗します。誤差が単調に減るという思い込みをテストが壊してくれました。 学習が進むかどうかを見るなら、誤差ではなく正解率を見るべきです。

    まとめ¶

    • 分類は誤分類した点だけを使って学習します。正しい点は動かしません。
    • 演算子を関数として渡せるため、内積は List.map2 (*) の 1 行で書けます。
    • 部分適用により、List.map2 (perceptronError model) のようにラムダなしで写像できます。
    • List.average があるので、「正解率 = 正解フラグの平均」を定義どおりに書けます。
    • パーセプトロン誤差は全点が境界線上にある退化状態を 0 と評価します。学習の進み具合は正解率で見ます。
