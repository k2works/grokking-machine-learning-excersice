    第 11 章 サポートベクターマシンとカーネル法（F# 版）¶

    原著第 11 章「Finding boundaries with style」を F# で実装します。第 5 章のパーセプトロンは「分けられればどこでもよい」でした。SVM は できるだけ広い余白を空ける 境界線を選びます。

    サンプル実装は apps/grokking-ml-fsharp/src/GrokkingMl/Ch11Svm.fs です。

    Polyglot Notebook で試す: この章の実験は ch11.ipynb にまとめてあります。実装本体を読み込んで動かすので、値を変えてその場で試せます。

    この章で作るもの¶

    • ヒンジ損失とマージン

    パーセプトロンの何が不満なのか¶

    第 5 章のパーセプトロンは、8 点すべてを正しく分類できた時点で更新を止めます。その境界線がぎりぎりでも構いません。

    [<Fact>]
let ``SVM はパーセプトロンより広いマージンを残す`` () =
    let perceptron, _ = GrokkingMl.Ch05Perceptron.perceptronAlgorithm 0.01 1000 0 points perceptronLabels

    let asSvm =
        { Weights = perceptron.Weights
          Bias = perceptron.Bias }

    let svm, _ = trainSvmWith 0.01 20000 0.01 0 points labels

    // どちらも完全に分離できている
    Assert.Equal(1.0, accuracy asSvm points labels, 6)
    Assert.Equal(1.0, accuracy svm points labels, 6)
    // しかしパーセプトロンは分離できた時点で止まるため、余白がない
    Assert.Equal(0.0, margin asSvm points, 6)
    Assert.True(margin svm points > 0.5)

    第 5 章の Perceptron レコードから本章の SupportVectorMachine レコードへ、フィールドを移し替えています。F# のレコードは構造が同じでも別の型 なので明示的な変換が要りますが、そのぶん「これは SVM として測っている」という意図が読めます。

    モデル 正解率 マージン幅
    パーセプトロン（第 5 章） 1.0 0.0
    SVM（正則化 0.01） 1.0 0.577

    パーセプトロンのマージンは 0 でした。 境界線の上にちょうど乗っている点があるのです。正解率という指標は、この危うさを一切見せません。

    マージンとヒンジ損失¶

    /// ヒンジ損失。マージンの内側に入った分だけ罰する。
let hingeLoss (model: SupportVectorMachine) (point: Point) (label: int) =
    max 0.0 (1.0 - float label * score model point)

/// マージン幅。境界線からもっとも近い点までの距離の 2 倍。
let margin (model: SupportVectorMachine) (points: Point list) =
    let norm = sqrt (model.Weights |> List.sumBy (fun w -> w * w))

    if norm = 0.0 then
        0.0
    else
        2.0 * (points |> List.map (score model >> abs) |> List.min) / norm

    List.map (score model >> abs) の >> に注目してください。「スコアを計算して絶対値を取る」という 2 段の処理が、関数合成 1 つになります。 第 8 章の fst >> tokenize >> Set.ofList と同じ書き方です。

    float label * score model point と明示的に変換しているのは、F# が暗黙の数値昇格を行わないためです。第 5・6 章から一貫しています。

    状況 label × score ヒンジ損失
    正解かつ余裕がある 2.0 0.0
    正解だがぎりぎり 0.5 0.5
    境界線上 0.0 1.0
    誤分類 -1.0 2.0

    「正解しているのに損失が残る」 のが第 5 章との決定的な違いです。

    正則化とマージンのトレードオフ¶

    let svmError
    (regularization: float)
    (model: SupportVectorMachine)
    (points: Point list)
    (labels: int list)
    =
    let losses = List.map2 (hingeLoss model) points labels |> List.average
    losses + regularization * (model.Weights |> List.sumBy (fun w -> w * w))

    List.map2 (hingeLoss model) は部分適用です。モデルを固定した関数を 2 本のリストに同時適用します。第 5 章の perceptronError、第 8 章の logLoss と同じ形で、章をまたいで同じパターンが繰り返し使えます。

    第 4 章の L2 正則化とまったく同じ形の罰則項ですが、目的が違います。

    章 正則化の目的
    第 4 章 過学習を防ぐ（重みを縮めてモデルを単純化）
    第 11 章 マージンを広げる（重みが小さいほど余白が広い）

    マージン幅は 2 / ||w|| に比例します。同じ式が別の意味を持つ例です。

    [<Fact>]
let ``正則化が弱いほどマージンは広がる`` () =
    let loose, _ = trainSvmWith 0.01 20000 0.01 0 points labels
    let tight, _ = trainSvmWith 0.01 20000 0.1 0 points labels
    Assert.True(margin loose points > margin tight points)

    このテストは直感に反します。 正則化が強すぎると重みが 0 方向へ潰れ、||w|| が小さくなる以上に 境界線からの距離そのものが縮みます。

    正則化 重み マージン
    0.01 (1.689, 1.695) 0.577
    0.10 (0.827, 0.849) 0.278

    更新則¶

    let svmStep
    (learningRate: float)
    (regularization: float)
    (model: SupportVectorMachine)
    (point: Point)
    (label: int)
    =
    let insideMargin = float label * score model point < 1.0

    let weights =
        List.map2
            (fun w x ->
                let gradient =
                    2.0 * regularization * w - (if insideMargin then float label * x else 0.0)

                w - learningRate * gradient)
            model.Weights
            point

    { Weights = weights
      Bias = model.Bias + (if insideMargin then learningRate * float label else 0.0) }

    2 つの力が働きます。

    1. 常に働く力: 重みを 0 方向へ縮める（2 × 正則化 × w）
    2. マージンの内側でだけ働く力: 点を押し返す（label × x）

    if が式なので、条件付きの項をそのまま減算の中に書けます。マージンの外にいる点では 2 番目が消えるので、重みが少し縮むだけ です。バイアスが動かないことが「押し返す力が働いていない」証拠になります。

    カーネル法¶

    XOR は直線で分けられません（第 10 章）。SVM は 点を高次元へ写してから直線を引く ことで解きます。ただし、写した先の座標を計算せず、内積だけを求めます。これがカーネルトリックです。

    /// 2 点の類似度を測る関数。
type Kernel = Point -> Point -> float

/// 内積。
let dot (a: Point) (b: Point) = List.map2 (*) a b |> List.sum

/// 線形カーネル。ただの内積。
let linearKernel: Kernel = dot

/// 多項式カーネル。特徴量の積を暗黙のうちに作る。
let polynomialKernel (degree: int) (constant: float) : Kernel =
    fun a b -> (dot a b + constant) ** float degree

/// RBF（ガウシアン）カーネル。距離が近いほど 1 に近づく。
let rbfKernel (gamma: float) : Kernel =
    fun a b ->
        let squaredDistance = List.map2 (fun x y -> (x - y) ** 2.0) a b |> List.sum
        exp (-gamma * squaredDistance)

    let linearKernel: Kernel = dot の 1 行が F# らしい点です。 既存の dot 関数がそのままカーネルの型に適合するため、ラッパーを書く必要がありません。Python では def linear_kernel(a, b): return dot(a, b) と包み直し、Kotlin では { a, b -> dot(a, b) } とラムダにしました。カリー化された関数型（Point -> Point -> float）だからこそ、そのまま代入できます。

    polynomialKernel と rbfKernel は「カーネルを返す関数」です。第 9 章の Impurity、第 4 章の Regularization と同じく、設定を部分適用で固定する という一貫した解き方です。

    カーネルの意味¶

    polynomialKernel 2 1.0 は (x·y + 1)² を計算します。展開すると x₁²y₁² + 2x₁y₁x₂y₂ + ... という項が現れます。これは 6 次元空間での内積と同じです。

    つまり、6 次元へ写す計算を 一度もせずに、その空間での内積が手に入ります。RBF カーネルはさらに極端で、無限次元空間の内積 に相当します。

    カーネル分類器¶

    /// カーネル分類器。訓練点そのものを重み付きで覚えておく。
type KernelClassifier =
    { Points: Point list
      Labels: int list
      Weights: float list
      Bias: float
      Kernel: Kernel }

/// カーネルによる判別スコア。
let kernelScore (model: KernelClassifier) (point: Point) =
    List.zip3 model.Weights model.Labels model.Points
    |> List.sumBy (fun (weight, label, support) -> weight * float label * model.Kernel support point)
    |> (+) model.Bias

    モデルが訓練データそのものを保持します。 これまでのモデルは重みベクトル（第 3〜6・10 章）や確率表（第 8 章）、木（第 9 章）でしたが、カーネル法は 訓練点を捨てられません。

    List.zip3 で 3 本のリストを同時に走査します。ラムダの引数で 3 要素タプルを分解できるため、weight・label・support に一度で名前が付きます。インデックスを使わずに済むのは、3 本のリストが同じ長さである前提がコードに現れているから でもあります。

    学習ループは fold とレコード更新構文で書きました。

        let step (model: KernelClassifier) _ =
        let i = rng.Next(List.length points)

        if float labels[i] * kernelScore model points[i] <= 0.0 then
            { model with
                Weights = model.Weights |> List.mapi (fun j w -> if j = i then w + learningRate else w)
                Bias = model.Bias + learningRate * float labels[i] }
        else
            model

    { model with ... } は レコードの一部だけを差し替えた新しいレコード を作ります。Points・Labels・Kernel は変わらないので書く必要がありません。Kotlin の copy() に相当しますが、F# では構文として組み込まれています。

    第 5 章のパーセプトロンと同じく、誤分類した点だけ（<= 0.0 のとき）重みを増やします。正しく分類できていればモデルをそのまま返します。

    実行結果¶

    XOR を 3 種類のカーネルで解きます。

    カーネル 正解率
    線形 0.50
    多項式（2 次） 1.00
    RBF 1.00

    線形カーネルは 0.5、つまり当てずっぽうと同じです。 内積しか使わないので、実質的に第 5 章のパーセプトロンと変わりません。

    多項式カーネルと RBF カーネルは 1.0 に達しました。アルゴリズムは一切変えず、カーネル関数を差し替えただけです。

    第 10 章のニューラルネットワークと同じ問題を、まったく違う方法で解いたことになります。

    手法 XOR の解き方
    ニューラルネット（第 10 章） 隠れ層で特徴を 学習する
    カーネル法（第 11 章） カーネルで特徴を 設計する

    まとめ¶

    • レコードは構造が同じでも別の型なので、第 5 章のモデルを SVM として測るには明示的な変換が要ります。
    • List.map (score model >> abs) のように、関数合成で 2 段の処理を 1 つにまとめられます。
    • let linearKernel: Kernel = dot と、既存関数をそのまま関数型の値に代入できます。カリー化の恩恵です。
    • List.zip3 で 3 本のリストを同時に走査でき、タプルの分解で名前が付きます。
    • { model with ... } により、レコードの一部だけを差し替えた新しい値を作れます。
