    #09 アプリ推薦の決定木（Kotlin）¶

    原著ノートブック: Chapter_09_Decision_Trees/App_recommendations.ipynb

    6 人のユーザーの「端末」と「年齢」から、おすすめアプリを決定木で当てます。

    Smile の DecisionTree を使いますが、scikit-learn とは 3 つ違いがありました。 多出力分類に対応していない、木の上限を明示しないと落ちる、 そして 分割が決定的 です。

    サンプル実装¶

    項目 内容
    実装 apps/grokking-ml-kotlin-lib/src/main/kotlin/lib/Nb09AppRecommendations.kt
    テスト apps/grokking-ml-kotlin-lib/src/test/kotlin/lib/Nb09AppRecommendationsTest.kt
    実行 ./gradlew test --tests Nb09AppRecommendationsTest

    目的変数は名義尺度だと型で示す¶

    Smile のデータフレームは、列に 尺度（measure） を持たせられます。 これを付けないと、整数のラベルが 回帰の目的変数 として扱われます。

    private fun buildFrame(
    columns: Map<String, IntArray>,
    labels: IntArray,
    classCount: Int,
): DataFrame {
    // Smile は目的変数が「名義尺度」であることを型で示す必要がある。
    // ただの IntVector にすると回帰木として扱われてしまう
    val labelField = StructField(
        "App",
        DataTypes.IntegerType,
        smile.data.measure.NominalScale(*Array(classCount) { APP_CLASSES[it] }),
    )
    ...
}

    scikit-learn は y の中身を見て自動で判断します（文字列なら分類、実数なら回帰）。 Smile は 明示させる 設計です。冗長ですが、 「0, 1, 2 というラベルを回帰してしまう」事故は起きません。

    多出力分類がない¶

    原著のカテゴリ版は、3 列の目的変数を同時に予測する多出力分類でした。 Smile にはこれがありません。

    /**
 * 年齢をカテゴリに潰した版を学習する。
 *
 * 原著は 3 列の目的変数を同時に予測する **多出力分類** にしているが、
 * Smile は対応していない。3 つのアプリを 1 列の名義尺度に直して学習する。
 * 結果として木の形は原著と変わりうるが、全問正解する点は同じである。
 */
fun fitCategorical(): DecisionTree

    3 つの one-hot 列を 1 列のクラス番号に畳み直しました。 この問題では どちらでも同じ木になる ので実害はありませんが、 原著が示していた value = [[3, 3] [5, 1] [4, 2]] のような 「列ごとの内訳」は見られなくなります。

    葉の数の上限で一度落ちた¶

    DecisionTree.fit(formula, frame) を呼ぶと、実行時に落ちました。

    java.lang.IllegalArgumentException: Invalid maximum leaves: 1

    引数 2 つの版は、葉の数の上限をデータ件数から自動で決めます。 6 件しかないと上限が 1 になり、木が作れません。

    /**
 * 決定木を学習する。
 *
 * 引数 2 つの `DecisionTree.fit` は、葉の数の上限をデータ件数から自動で決める。
 * 6 件しかないと上限が 1 になり `Invalid maximum leaves: 1` で落ちるので、
 * ここでは上限を明示的に渡す。scikit-learn は既定で制限なしに育てる。
 */
private fun fitTree(frame: DataFrame): DecisionTree =
    DecisionTree.fit(Formula.lhs("App"), frame, SplitRule.GINI, 20, 100, 1)

    (SplitRule, maxDepth, maxNodes, nodeSize) を明示します。 scikit-learn は 既定で制限なし に育てるので、この問題は起きません。

    教材のような小さいデータでいきなり落ちる のは、 実務向けに既定値を決めているライブラリの副作用です。

    木の構造は DOT 文字列で取り出す¶

    scikit-learn は tree.plot_tree(dt) で図を描きます。 Smile は Graphviz の DOT 形式を文字列で返す だけです。

    /**
 * 木の構造を DOT 形式の文字列で得る。
 *
 * scikit-learn は `tree.plot_tree` で図を描くが、Smile は
 * **Graphviz の DOT 形式を文字列で返す** だけである。図にするには
 * 別途 Graphviz に通す必要がある。テキストなので差分は取りやすい。
 */
fun toDot(model: DecisionTree): String = model.dot()

    実際の出力はこうなります。

    digraph CART {
 node [shape=box, style="filled, rounded", color="black", fontname=helvetica];
 edge [fontname=helvetica];
 1 [label=<Age &le; 20.0<br/>size = 6<br/>impurity reduction = 0.3889>, ...];
 1 -> 2 [labeldistance=2.5, labelangle=45, headlabel="True"];
 1 -> 3 [labeldistance=2.5, labelangle=-45, headlabel="False"];
 2 [label=<App = Atom Count<br/>size = 3<br/>deviance = 2.4328>, ..., shape=ellipse];
 3 [label=<Platform_Android &le; 0.5<br/>size = 3<br/>impurity reduction = 0.4444>, ...];
 ...
}

    図を描けないのは不便ですが、テキストなのでテストしやすい という利点があります。 正規表現で分割条件を取り出しました。

    /**
 * DOT 文字列から、分割に使われた特徴量としきい値を根から順に取り出す。
 *
 * Smile のラベルは `<Age &le; 20.0<br/>size = 6<br/>...>` という HTML 風の
 * 書式になっている。`&le;` は `<=` の実体参照である。
 */
fun splits(model: DecisionTree): List<Split> =
    SPLIT_LABEL.findAll(model.dot())
        .map { Split(it.groupValues[1], it.groupValues[2].toDouble()) }
        .toList()

/** DOT のノードラベルから特徴量名としきい値を取り出す正規表現 */
private val SPLIT_LABEL = Regex("""label=<([A-Za-z_]+) &le; ([0-9.]+)<br/>""")

    &le; は HTML の実体参照で <= を表します。 DOT のラベルが HTML 風の書式（<...>）なので、< をそのまま書けないためです。

    表示する値も違う¶

    scikit-learn Smile
    内部節に出す値 その節の ジニ不純度（gini = 0.611） その分割で得られた 不純度の減少量（impurity reduction = 0.3889）
    葉に出す値 クラスごとの件数（value = [3, 0, 0]） 予測クラスと逸脱度（App = Atom Count / deviance = 2.4328） 
    @Test
fun `Smile は不純度ではなく不純度の減少量を表示する`() {
    // scikit-learn の plot_tree は各節の gini を出すが、
    // Smile の DOT はその節で得られた impurity reduction を出す
    val dot = toDot(fitNumeric())

    assertTrue(dot.contains("impurity reduction"))
    assertTrue(!dot.contains("gini"))
}

    原著の gini = 0.611 に対応する値が、Smile の出力には存在しません。 impurity reduction = 0.3889 は「この分割で不純度がどれだけ下がったか」で、別の量です。

    根の分割は原著と一致する¶

    @Test
fun `数値版の根は年齢20歳で分割する`() {
    // 原著の出力: X[0] <= 20.0（X[0] は Age）
    val rootSplit = splits(fitNumeric()).first()

    assertEquals("Age", rootSplit.feature)
    assertEquals(20.0, rootSplit.threshold, 1e-12)
}

    Age <= 20.0 まで一致しました。 しきい値の決め方（隣り合う値の中点）も同じです。

    2 段目は原著が Platform_iPhone、Smile は Platform_Android を選びます。 2 つの列は互いに裏返しなので、木としては等価 です。

    @Test
fun `2段目は端末で分割する`() {
    // 原著は Platform_iPhone、Smile は Platform_Android。
    // 2 つの列は互いに裏返しなので、木としては等価
    for (model in listOf(fitNumeric(), fitCategorical())) {
        val second = splits(model)[1]

        assertTrue(second.feature in setOf("Platform_iPhone", "Platform_Android"))
        assertEquals(0.5, second.threshold, 1e-12)
    }
}

    Smile は決定的¶

    Python 版 では、木の形が実行のたびに変わりました。 scikit-learn が同点の候補から無作為に選ぶためです。

    Smile はそれをしません。

    @Test
fun `Smile は同じ入力に対して同じ木を作る`() {
    // scikit-learn は同点の分割候補から無作為に選ぶため木の形が変わるが、
    // Smile は決定的なので毎回同じ木になる
    assertEquals(toDot(fitNumeric()), toDot(fitNumeric()))
    assertEquals(splits(fitNumeric()), splits(fitNumeric()))
}

    DecisionTree に random_state にあたる引数はありません。 何度実行しても同じ木が返ります。

    教材としてはこちらのほうが扱いやすい 性質です。 一方でランダムフォレスト（#20 で扱う予定）のように 「木ごとに違う分割を選ぶ」ことに意味がある場面では、別の仕組みが要ります。

    この章で Kotlin が効いた場面・効かなかった場面¶

    場面 評価
    木の再現性 効いた — 決定的なので毎回同じ木になる
    DOT 出力 効いた — テキストなので差分もテストも取りやすい
    分割の抽出 効いた — Regex.findAll と分解で 3 行
    名義尺度の明示 引き分け — 冗長だが回帰と取り違えない
    多出力分類 効かなかった — Smile に無く 1 列に畳む
    葉の数の上限 効かなかった — 小さいデータで落ちる
    図の描画 効かなかった — DOT を Graphviz に通す手間が要る
    表示される値 効かなかった — gini が出ず原著と突き合わせられない
