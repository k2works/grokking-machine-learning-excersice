    #19 カーネルとハイパーパラメータを比べる（Kotlin）¶

    原著ノートブック: Chapter_11_Support_Vector_Machines/SVM_graphical_example.ipynb

    #17 で作った 3 つのデータセットに、いろいろな SVM を当てる回です。 原著は 9 つの正解率を印刷します。

    Python 版 は 9 つすべてが 16 桁一致 しました。 Kotlin（Smile）で一致したのは 4 つ です。 そして途中で、それ以前に片付けるべき問題が見つかりました。

    サンプル実装¶

    項目 内容
    実装 apps/grokking-ml-kotlin-lib/src/main/kotlin/lib/Nb19SvmKernels.kt
    テスト apps/grokking-ml-kotlin-lib/src/test/kotlin/lib/Nb19SvmKernelsTest.kt
    実行 ./gradlew test --tests "lib.Nb19*"

    まず、Smile の SVM は毎回違う答えを出す¶

    同じデータ・同じ引数で 4 回学習させた結果です。

    poly2 = 0.7727272727272727
poly2 = 0.9
poly2 = 0.8272727272727273
poly2 = 0.9181818181818182

    0.77 から 0.92 まで、実行のたびに変わります。

    原因は Smile の SVM が LASVM というオンライン近似解法で、 内部で乱数を使う ためです。scikit-learn の SVC は libsvm の SMO で 厳密解に収束するので決定的です。

        /**
     * 既定の乱数の種。
     *
     * **Smile の SVM は種を固定しないと実行のたびに結果が変わる。**
     * 同じデータ・同じ引数で `one_circle` に 2 次の多項式カーネルを当てたところ、
     * 0.773 / 0.900 / 0.827 / 0.918 と毎回違う正解率が出た。
     * scikit-learn の `SVC` は決定的なので、この違いは移植で必ず踏む。
     */
    const val SEED = 0L

    学習のたびに種を設定するようにしました。

        fun fitLinear(data: Dataset, c: Double = 1.0, tolerance: Double = 1e-3): Classifier<DoubleArray> {
        smile.math.MathEx.setSeed(SEED)
        return SVM.fit(data.x, data.signedY, c, tolerance)
    }

    「SVM は決定的」という前提が、ライブラリを替えると崩れます。 #13 以降のニューラルネットワークでは乱数を覚悟していましたが、 SVM で踏むとは思いませんでした。

    このシリーズで「値が毎回変わる」に気付けたのは、 同じ検算を何度も走らせていた からです。1 回しか実行していなければ、 たまたま出た 0.9 を「まあ近い」と書いていたはずです。

    一致したもの、しなかったもの¶

    種を 0 に固定した結果です。

    データ 設定 原著 Smile
    linear 線形 C=1 0.9333333 0.9333333（完全一致）
    linear 線形 C=0.01 0.8666667 0.5
    linear 線形 C=100 0.9166667 0.6666667
    one_circle 多項式 2 次 0.8909091 0.9
    one_circle 多項式 4 次 0.9 0.8181818
    two_circles RBF γ=0.1 0.8772727 0.8636364
    two_circles RBF γ=1 0.9045455 0.9045455（完全一致）
    two_circles RBF γ=10 0.9636364 0.9636364（完全一致）
    two_circles RBF γ=100 0.9909091 0.9909091（完全一致）

    RBF は 4 つ中 3 つが完全一致 しました。 一方 極端な C では大きく外れます。

        @Test
    fun `極端なCでは原著から大きく外れる`() {
        // 原著は C=0.01 で 0.867、C=100 で 0.917。Smile はどちらも大きく下回る。
        // Smile の SVM は LASVM（オンライン近似解法）で、C が極端だと
        // 収束しきらない。scikit-learn は libsvm の SMO で厳密解に到達する
        assertEquals(0.5, accuracy(fitLinear(linear, c = 0.01), linear), 1e-15)
        assertEquals(0.6666666666666666, accuracy(fitLinear(linear, c = 100.0), linear), 1e-15)
    }

    C = 0.01 で 0.5。60 件のうちラベル 1 が 30 件なので、 これは「全部同じ答え」を意味します。まったく学習できていません。

    近似解法は「ほどほどの設定なら十分な答えを速く出す」ものです。 C を極端に振るとその前提から外れます。 原著がこの章で見せたいのは まさにその極端な設定の効果 なので、 Smile では章の主旨が伝わりません。

    「正解率が近い/遠い」ではなく、その設定でそのライブラリが使えるかどうか の 問題として記録しました。

    カーネルを文字列ではなくオブジェクトで渡す¶

        fun fitKernel(
        data: Dataset,
        kernel: MercerKernel<DoubleArray>,
        c: Double = 1.0,
        tolerance: Double = 1e-3,
    ): Classifier<DoubleArray> {
        smile.math.MathEx.setSeed(SEED)
        return SVM.fit(data.x, data.signedY, kernel, c, tolerance)
    }

    scikit-learn は kernel='poly' と文字列で指定しますが、 Smile は MercerKernel のインスタンスを渡します。

    そのぶん、どの式を使っているかが明示的になります。 そして「明示的にしないと書けない」ので、 scikit-learn の既定値を調べ直すことになりました。

        /**
     * scikit-learn の `gamma='scale'` を計算する。
     *
     * `1 / (n_features * X.var())`。**分散は列ごとではなく行列全体** で取る。
     */
    fun scaleOf(data: Dataset): Double {
        val values = data.x.flatMap { it.asIterable() }
        val mean = values.average()
        val variance = values.sumOf { (it - mean) * (it - mean) } / values.size
        return 1.0 / (2 * variance)
    }

    gamma='scale'（scikit-learn 0.22 からの既定）は 1 / (特徴量数 × 分散) です。分散は列ごとではなく行列全体 で取ります。 文字列で 'scale' と書いているぶんには意識しませんが、 移植すると調べざるをえません。

    RBF も同じで、Smile の GaussianKernel は σ を取るので 1/√(2γ) に換算します。

        /** scikit-learn の `kernel='rbf', gamma=g` に対応する。σ は `1/√(2γ)` */
    fun rbfKernel(gamma: Double): GaussianKernel = GaussianKernel(Math.sqrt(1.0 / (2 * gamma)))

    この換算が正しかったことは、RBF の 3 つが完全一致した ことで確かめられました。 換算を間違えていれば、4 つとも外れていたはずです。

    傾向は再現できる¶

        @Test
    fun `gammaを上げるほど正解率が単調に上がる`() {
        // 原著と同じ傾向。値がずれても、章が示したい性質は再現できている
        val scores = listOf(0.1, 1.0, 10.0, 100.0).map { gamma ->
            accuracy(fitKernel(twoCircles, rbfKernel(gamma)), twoCircles)
        }

        assertEquals(scores.sorted(), scores)
    }

    値が 1 つずれても、単調増加という性質は保たれます。 数字が合わないときに何を代わりに検証するか、という問いへの 1 つの答えです。

    まとめ¶

    項目 原著と一致するか
    線形 C=1 完全一致
    線形 C=0.01 / C=100 大きく外れる（近似解法が極端な C で収束しない）
    多項式 2 次 / 4 次 近いが一致しない
    RBF γ=1 / 10 / 100 完全一致
    RBF γ=0.1 近いが一致しない
    gamma と正解率の単調性 一致
    決定性 種を固定しないと毎回変わる（原著は決定的）
