    #01 線形回帰を 3 つのトリックで学習する（Kotlin）¶

    原著ノートブック: Chapter_03_Linear_Regression/Coding_linear_regression.ipynb

    部屋数から住宅価格を予測する直線を引きます。3 つのトリックを手で書いて反復学習し、 最後に同じ問題を Smile の OLS に解かせて答え合わせをします。

    Python 版との違いは 2 つあります。乱数列が違うのでトリックの学習結果は原著と一致しないこと、 そして 閉じた式の解は完全に一致する ことです。この非対称が、そのまま検証方針になります。

    サンプル実装¶

    項目 内容
    実装 apps/grokking-ml-kotlin-lib/src/main/kotlin/lib/Nb01LinearRegression.kt
    テスト apps/grokking-ml-kotlin-lib/src/test/kotlin/lib/Nb01LinearRegressionTest.kt
    実行 ./gradlew test --tests Nb01LinearRegressionTest

    データセット¶

    val FEATURES = intArrayOf(1, 2, 3, 5, 6, 7)
val LABELS = intArrayOf(155, 197, 244, 356, 407, 448)

    直線を表す型¶

    Python 版は dataclass、Kotlin では data class です。ここでの効きどころは 構造的等価性が自動で付いてくる ことでした。

    /** 学習された直線。原著の `price_per_room` と `base_price` に対応する */
data class Line(val pricePerRoom: Double, val basePrice: Double) {
    fun predict(numRooms: Double): Double = basePrice + pricePerRoom * numRooms
}

    原著はトリックの戻り値をタプル (price_per_room, base_price) にしていましたが、 Kotlin には可変長のタプルがありません。Pair で書くこともできますが、 first / second では意味が読めなくなります。Line を返す形にしました。

    その結果、絶対トリックのテストが 1 行で書けます。

    @Test
fun `絶対トリックは誤差の大きさに依存しない`() {
    val small = absoluteTrick(0.0, 1.0, 2.0, 10.0, learningRate = 0.01)
    val large = absoluteTrick(0.0, 1.0, 2.0, 802.0, learningRate = 0.01)

    // data class なので構造的等価性でそのまま比べられる
    assertEquals(small, large)
}

    3 つのトリック¶

    シンプルトリックと var¶

    Kotlin では引数が val なので、原著のように引数そのものを書き換えられません。 ローカルの var に写してから更新します。

    fun simpleTrick(
    basePrice: Double,
    pricePerRoom: Double,
    numRooms: Double,
    price: Double,
    random: Random,
): Line {
    val smallRandom1 = random.nextDouble() * 0.1
    val smallRandom2 = random.nextDouble() * 0.1
    val predictedPrice = basePrice + pricePerRoom * numRooms
    var slope = pricePerRoom
    var intercept = basePrice
    if (price > predictedPrice && numRooms > 0) {
        slope += smallRandom1
        intercept += smallRandom2
    }
    // ...残り 3 つの分岐も原著のまま
    return Line(slope, intercept)
}

    4 つの分岐のうち 3 番目だけ intercept を減らす非対称な書き方も、原著のままです。 忠実な再現が目的なので、気づいた不整合も勝手に直しません。

    原著は random をグローバルに使っていましたが、Kotlin では Random を引数で渡します。 テストから種を固定できるようにするためです。

    二乗トリック¶

    分岐が消え、更新式そのものになります。

    fun squareTrick(
    basePrice: Double,
    pricePerRoom: Double,
    numRooms: Double,
    price: Double,
    learningRate: Double,
): Line {
    val predictedPrice = basePrice + pricePerRoom * numRooms
    val error = price - predictedPrice
    return Line(
        pricePerRoom + learningRate * numRooms * error,
        basePrice + learningRate * error,
    )
}

    分岐が無いので var も要らず、Line を 1 つ組み立てて返すだけになりました。 3 つのトリックのなかで、Kotlin にいちばん素直に収まるのがこれです。

    トリックの切り替えは enum で¶

    原著は使うトリックを コメントアウトで切り替えて いました。

    #price_per_room, base_price = simple_trick(base_price,
#price_per_room, base_price = absolute_trick(base_price,
price_per_room, base_price = square_trick(base_price,

    これを enum class にすると、when が網羅性を検査してくれます。

    /** どのトリックで学習するか。原著はコメントアウトで切り替えていた */
enum class Trick { SIMPLE, ABSOLUTE, SQUARE }

    line = when (trick) {
    Trick.SQUARE ->
        squareTrick(line.basePrice, line.pricePerRoom, numRooms, price, learningRate)
    Trick.ABSOLUTE ->
        absoluteTrick(line.basePrice, line.pricePerRoom, numRooms, price, learningRate)
    Trick.SIMPLE ->
        simpleTrick(line.basePrice, line.pricePerRoom, numRooms, price, random)
}

    when を式として使っているので else を書く必要がなく、トリックを 1 つ足したら コンパイルエラーで教えてくれます。Python 版では文字列で受けて ValueError を投げており、 同じ間違いが実行時まで見つかりません。

    学習ループ¶

    原著は学習ループの中で描画していました。ここでは途中経過を返します。

    /** 学習の途中経過。原著が学習ループの中で描いていたものを記録する */
data class TrainingLog(
    val line: Line,
    /** 各エポック開始時点の直線 */
    val history: List<Line>,
    /** 各エポック開始時点の RMSE */
    val errors: List<Double>,
)

    repeat(epochs) {
    history.add(line)
    // 原著は features[0] だけを使って誤差を測っている
    errors.add(rmse(labels, features[0] * line.pricePerRoom + line.basePrice))

    val i = random.nextInt(features.size)
    val numRooms = features[i].toDouble()
    val price = labels[i].toDouble()
    // ...トリックを適用
}

    誤差の計算に features[0] しか使っていないのは原著のコードがそうなっているためで、 ここも直さずに写しています。

    rmse は原著が NumPy の内積で書いていた式を、sumOf に置き換えました。

    fun rmse(labels: IntArray, prediction: Double): Double {
    val squaredSum = labels.sumOf { label ->
        val difference = label - prediction
        difference * difference
    }
    return sqrt(squaredSum / labels.size)
}

    labels が IntArray で prediction が Double なので、label - prediction は Double になります。sumOf はラムダの戻り値型で多重定義が解決されるため、 Double を返している限り整数の桁あふれは起きません。

    原著の数値と一致するもの・しないもの¶

    乱数の消費順序（初期化 2 回 → 毎エポック 1 回）は原著と揃えてあります。 それでも kotlin.random.Random は Python の Mersenne Twister と別のアルゴリズム なので、 同じ種を渡しても同じ数列にはなりません。

    だからトリックの学習結果は原著の 51.044 / 91.594 には一致しません。 一致しないものを一致したことにはせず、収束先で検証 します。

    @Test
fun `二乗トリックは最小二乗解へ収束する`() {
    // 乱数列が Python と違うので原著の 51.044 / 91.594 には一致しない。
    // 閉じた式の解に十分近づくことで検証する
    val exact = fitWithSmile()
    val result = linearRegression(learningRate = 0.01, epochs = 10000, trick = Trick.SQUARE)

    assertEquals(exact.pricePerRoom, result.line.pricePerRoom, 1.0)
    assertEquals(exact.basePrice, result.line.basePrice, 1.0)
}

    Smile に解かせる¶

    scikit-learn の LinearRegression にあたるのが Smile の OLS です。

    fun fitWithSmile(
    features: IntArray = FEATURES,
    labels: IntArray = LABELS,
): Line {
    val df = DataFrame.of(
        DoubleVector.of("rooms", DoubleArray(features.size) { features[it].toDouble() }),
        DoubleVector.of("price", DoubleArray(labels.size) { labels[it].toDouble() }),
    )
    val model = OLS.fit(Formula.lhs("price"), df)
    // Smile は切片を coefficients() に含めず intercept() で返す
    return Line(model.coefficients()[0], model.intercept())
}

    scikit-learn との作法の違い¶

    scikit-learn Smile
    入力の形 ndarray を reshape(-1, 1) 列に名前のある DataFrame
    目的変数の指定 fit(X, y) の第 2 引数 Formula.lhs("price") で列名を指す
    切片の取得 model.intercept_ model.intercept()
    傾きの取得 model.coef_[0] model.coefficients()[0]

    coefficients() に切片が入っていない のが引っかかりどころでした。 scikit-learn の感覚で coefficients()[1] を読むと ArrayIndexOutOfBoundsException になります。 実際、環境構築時のスモークテストでこれを踏みました。

    数値は原著と完全に一致します。

    @Test
fun `Smile の解は原著と同じ数値になる`() {
    // 原著 scikit-learn の出力
    //   Coefficient: [50.39285714]
    //   Intercept: 99.59523809523819
    val line = fitWithSmile()

    assertEquals(50.39285714, line.pricePerRoom, 1e-8)
    assertEquals(99.59523809523819, line.basePrice, 1e-8)
}

    @Test
fun `Smile の4部屋の予測は原著と同じ数値になる`() {
    // 原著の出力: Predicted label for feature 4: [301.16666667]
    assertEquals(301.16666667, fitWithSmile().predict(4.0), 1e-7)
}

    異なるライブラリ・異なる言語・異なる数値計算バックエンドでも、 最小二乗の解は一意に決まる ので小数点以下 8 桁まで揃います。 反復学習の結果が言語ごとにばらつくのとは対照的です。

    この章で Kotlin が効いた場面¶

    場面 効いた言語機能
    トリックの戻り値 data class — Pair.first より意味が読める
    絶対トリックのテスト 構造的等価性 — 2 つの結果を 1 行で比較
    トリックの切り替え enum class + when — 網羅性をコンパイル時に検査
    二乗トリック 分岐が消え var も不要になった

    逆に窮屈だったのは、引数が val でシンプルトリックにローカル var が要る点です。 原著が引数を直接書き換えるスタイルなので、そこだけ写経ができませんでした。
