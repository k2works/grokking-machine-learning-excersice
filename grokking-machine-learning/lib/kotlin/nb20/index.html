    #20 ランダムフォレストと AdaBoost（Kotlin）¶

    原著ノートブック: Chapter_12_Ensemble_Methods/Random_forests_and_AdaBoost.ipynb

    18 通のメールを 2 特徴量で振り分ける小さなデータに、アンサンブル学習を当てる回です。 Smile は RandomForest・AdaBoost・GradientTreeBoost をすべて持っているので、 scikit-learn と 1 対 1 に対応が付きます。

    結果は 決定木まわりは完全一致、ランダムフォレストは固定できない でした。

    サンプル実装¶

    項目 内容
    実装 apps/grokking-ml-kotlin-lib/src/main/kotlin/lib/Nb20EnsembleSpam.kt
    テスト apps/grokking-ml-kotlin-lib/src/test/kotlin/lib/Nb20EnsembleSpamTest.kt
    実行 ./gradlew test --tests "lib.Nb20*"

    弱学習器の分割がしきい値まで一致する¶

    この回でいちばん気持ちの良い結果です。

        @Test
    fun `弱学習器が選ぶ分割はscikit-learnと完全に一致する`() {
        // 特徴量もしきい値も同じところを選んだ。CART の分割規則が同じなら、
        // 6 点しかないデータでは解が一意に決まる
        assertEquals(listOf("Lottery" to 4.5, "Sale" to 8.0, "Sale" to 5.5), (0..2).map { splitOf(fitWeakLearner(it)) })
    }

    Lottery ≤ 4.5・Sale ≤ 8.0・Sale ≤ 5.5。 Python 版・F# 版とまったく同じ です。

    6 点しかないデータでジニ不純度を最小化する分割は一意に決まるので、 CART の規則さえ合っていれば言語もライブラリも関係ありません。 #11 で F# の自前 CART を scikit-learn に合わせ込んだときに 洗い出した 4 つの規則が、ここでも効いています。

    深さの数え方が 1 つずれる¶

        /**
     * 1 組ぶんのデータに深さ 1 の決定木（切り株）を当てる。
     *
     * [#10][Nb10DecisionTreeBoundary] で見たように **Smile の深さは
     * scikit-learn より 1 大きく数える**。scikit-learn の `max_depth=1`
     * （分割 1 つ）に対応するのは Smile の `maxDepth = 2` である。
     */
    fun fitWeakLearner(index: Int): DecisionTree = fitDecisionTree(batch(index), maxDepth = 2)

    #10 で見つけた対応が、そのまま使えました。 過去の回の知見が効く のは、同じシリーズを通しで移植している利点です。

    もし maxDepth = 1 のまま渡していたら、木が育たず葉 1 つになり、 「Smile の AdaBoost は弱すぎる」と誤った結論を書いていたはずです。

    ランダムフォレストの結果が固定できない¶

        @Test
    fun `ランダムフォレストの正解率は固定できない`() {
        // 原著の出力は 0.8333333333333334。Smile は木をスレッド並列で育てるので、
        // MathEx.setSeed を呼んでも実行ごとに変わる。40 回の実測では
        // 0.500〜0.889 に散らばり、最頻値は 0.778 だった。
        // 原著の値もこの範囲に入るが、1 点として突き合わせることはできない
        val scores = (1..10).map { accuracy(fitRandomForest(), all) }

        assertTrue(scores.all { it in 0.4..1.0 }, "実測範囲を外れた: $scores")
    }

    #19 で SVM の非決定性に気付いたので、今回は最初から疑いました。 MathEx.setSeed(0) を呼んでも 固定できません。

    40 回走らせた分布です。

    正解率 回数
    0.500 3
    0.556 1
    0.611 3
    0.667 5
    0.722 8
    0.778 12
    0.833 5
    0.889 3

    0.500 から 0.889 まで散らばります。 幅が 0.39 もあります。

    理由は Smile の RandomForest が 木をスレッド並列で育てる ためです。 どのスレッドがどの部分標本を取るかは実行順に依存し、 グローバルな種を設定しても各スレッドの取り分は変わります。

    smile.threads システムプロパティを 1 にしても変わりませんでした （クラス初期化時に読まれるためと思われます）。

    「原著の 0.833 も分布の中に入っている」 とは書けます。 しかしそれは「一致した」ではありません。 1 回だけ実行して 0.833 が出たら、そう書いてしまっていたところでした。

    このシリーズで身についた習慣は、「一致した」と書く前に何度か回す ことです。

    ブースティング 2 種は決定的¶

        @Test
    fun `ブースティング2種は種を固定すれば再現する`() {
        // AdaBoost と勾配ブースティングは木を順番に育てるので決定的になる。
        // 並列に育てるランダムフォレストだけが固定できない
        assertEquals(accuracy(fitAdaBoost(), all), accuracy(fitAdaBoost(), all), 0.0)
        assertEquals(accuracy(fitGradientBoosting(), all), accuracy(fitGradientBoosting(), all), 0.0)
    }

    アルゴリズムの性質がそのまま再現性に出ます。 ブースティングは前の木の結果を見て次を作るので、並列化できません。 そのぶん決定的です。

    「速い」と「再現する」が両立しないことがある、という具体例になりました。

    AdaBoost は 3 者 3 様¶

        @Test
    fun `AdaBoostは原著と一致しない`() {
        // 原著は 0.8888888888888888。Smile は 0.8333333333333334。
        // なお **現在の scikit-learn も原著と一致しない**（0.7777777777777778）。
        // 原著の既定 algorithm='SAMME.R' が 1.6 で削除されたため。
        // 3 つとも違う値になる、めずらしい回である
        assertEquals(0.8333333333333334, accuracy(fitAdaBoost(), all), 1e-15)
    }
    正解率
    原著（scikit-learn 0.2x、SAMME.R） 0.8889
    現在の scikit-learn（SAMME） 0.7778
    Smile 0.8333

    3 つとも違います。 原著とも、現在の Python 版とも一致しません。

    同じ「AdaBoost」という名前で、3 通りの答えが出ました。 アルゴリズム名だけでは何も決まらない、という話です。

    まとめ¶

    項目 原著と一致するか
    決定木（制限なし）1.0 完全一致
    弱学習器 3 本の正解率 完全一致
    弱学習器の分割（特徴量・しきい値） 完全一致（3 言語すべて）
    ランダムフォレスト 固定できない（0.500〜0.889 に散らばる）
    AdaBoost 一致しない（0.8333）
    勾配ブースティング 一致しない（0.7778）
