    #13 ニューラルネットワークの境界（Python）¶

    原著ノートブック: Chapter_10_Neural_Networks/Graphical_example.ipynb

    ニューラルネットワークの章に入ります。円形に分布した 110 点を、 2 層の隠れ層を持つネットワーク で分類し、決定境界を見ます。

    #10 の決定木は境界が軸に平行な長方形でした。 ニューラルネットワークは 曲線 を引けます。そこが原著の見せ場です。

    サンプル実装¶

    項目 内容
    実装 apps/grokking-ml-python-lib/src/grokking_ml_lib/nb13_neural_network_boundary.py
    テスト apps/grokking-ml-python-lib/tests/test_nb13_neural_network_boundary.py
    実行 uv run pytest tests/test_nb13_neural_network_boundary.py

    ネットワークの形¶

    def build_model():
    """原著と同じ形のネットワークを組む。

    原著は `Dense(128, input_shape=(2,))` と書いているが、いまの Keras は
    `Input` 層を使うよう警告を出す。層の構成は変えずに `Input` へ寄せた。

    `Dropout` は学習中だけ働き、指定した割合のユニットを無効にする。
    過学習を抑える仕組みで、**推論時は何もしない**。
    """
    from tensorflow import keras

    return keras.Sequential(
        [
            keras.layers.Input((2,)),
            keras.layers.Dense(HIDDEN_UNITS[0], activation="relu"),
            keras.layers.Dropout(DROPOUT_RATE),
            keras.layers.Dense(HIDDEN_UNITS[1], activation="relu"),
            keras.layers.Dropout(DROPOUT_RATE),
            keras.layers.Dense(2, activation="softmax"),
        ]
    )

    原著の input_shape=(2,) は、いまの Keras では警告が出ます。

    UserWarning: Do not pass an `input_shape`/`input_dim` argument to a layer.
When using Sequential models, prefer using an `Input(shape)` object
as the first layer in the model instead.

    層の構成は変えずに Input へ寄せました。警告を残したまま写経すると、 読者が同じ警告を見て不安になります。

    パラメータ数は完全に一致する¶

    原著の model.summary() は Total params: 8,770 を出します。

    def test_パラメータ数は原著と同じ8770() -> None:
    # 原著の model.summary() が出す Total params: 8,770
    # (2*128 + 128) + (128*64 + 64) + (64*2 + 2) = 384 + 8256 + 130
    assert build_model().count_params() == 8770
    assert (2 * 128 + 128) + (128 * 64 + 64) + (64 * 2 + 2) == 8770

    内訳まで手で確かめられます。 各層は「重み（入力数 × ユニット数）+ バイアス（ユニット数）」です。

    層 重み バイアス 小計
    Dense(128) 2 × 128 = 256 128 384
    Dense(64) 128 × 64 = 8192 64 8256
    Dense(2) 64 × 2 = 128 2 130
    合計 8770

    8770 個のパラメータを 110 点で学習します。 パラメータのほうが 80 倍多い。 過学習して当然の設定で、だから Dropout が入っています。

    def test_Dropoutは学習可能なパラメータを持たない() -> None:
    # Dropout はユニットを無効にするだけで、重みを持たない
    model = build_model()
    dropout_layers = [
        layer for layer in model.layers if layer.__class__.__name__ == "Dropout"
    ]

    assert len(dropout_layers) == 2
    assert all(len(layer.weights) == 0 for layer in dropout_layers)

    学習結果は再現できない¶

    原著は種を 2 つ固定しています。

    np.random.seed(0)
tf.random.set_seed(1)

    それでも 再現できません。理由は 2 つあります。

    1. Dropout が学習のたびに違うユニットを無効にする（種で制御はされるが、 Keras の版が変わると乱数の消費順序が変わる）
    2. 重みの初期化方法や最適化の実装が版によって変わる

    原著の学習ログには最初のエポックで accuracy: 0.5251 とあります。 実測では 0.6364 でした。最初の 1 エポックから違います。

    なので、テストは 収束と境界の形 で書きました。

    def test_学習後は多数派より良い予測をする(data, trained) -> None:
    # 常に 0 と答えるだけで 84/110 = 0.764 になる。それを上回る必要がある
    predictions = predicted_classes(trained, features(data))
    accuracy = float(np.mean(predictions == labels(data)))

    assert accuracy > 84 / 110

    「多数派を答えるだけ」を基準にする のがこのデータでは重要です。 110 点のうち 84 点がクラス 0 なので、何も学習しなくても 0.764 になります。 「正解率 0.76 が出た」だけでは、学習できているか分かりません。

    境界が曲線になる¶

    #10 では、決定木の境界が軸に平行であることを 「予測が切り替わる x 座標が 1 か所しかない」ことで示しました。

    ニューラルネットワークでは 行ごとに切り替わる位置が変わります。

    def boundary_changes_per_row(grid: NDArray[np.int_]) -> list[int]:
    """各行で予測が切り替わった回数を返す。

    決定木なら軸に平行な境界なので、切り替わる位置は行によらず同じだった。
    ニューラルネットワークは曲線を引けるので、行ごとに変わる。
    """
    return [int(np.sum(row[1:] != row[:-1])) for row in grid]

    def test_境界は行ごとに変わる(data, trained) -> None:
    # 決定木（#10）の境界は軸に平行で、切り替わる位置が行によらなかった。
    # ニューラルネットワークは曲線を引けるので、行ごとに変わる
    grid = decision_grid(trained, data)
    changes = boundary_changes_per_row(grid)

    assert len(set(changes)) > 1

    さらに、円形のデータなので 境界が閉じます。

    def test_境界は閉じた形になる(data, trained) -> None:
    # 円形のデータなので、内側を囲む境界ができる。
    # 少なくとも 1 行は「外・内・外」と 2 回切り替わる
    grid = decision_grid(trained, data)
    changes = boundary_changes_per_row(grid)

    assert max(changes) >= 2

    「2 回切り替わる行がある」= 内側の領域を横切っている ということです。 決定木でも長方形なら 2 回切り替われますが、 このデータで決定木を使うと階段状の粗い近似になります。

    原著が図で見せている「円を囲む滑らかな境界」を、 図を見ずに 2 つのテストで言い当てられました。

    まとめ¶

    項目 原著と一致するか
    データの規模（110 点・84 対 26） 完全一致
    ネットワークの形 完全一致
    パラメータ数（8770） 完全一致
    学習ログの数値 再現できない（Dropout と Keras の版差）
    境界の性質（曲線・閉じている） 一致

    Kotlin の Smile も F# の Accord も Dropout がありません。 そこがどう効くかは各言語の記事で扱います。
