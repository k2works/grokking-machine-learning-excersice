    #01 線形回帰を 3 つのトリックで学習する（Python）¶

    原著ノートブック: Chapter_03_Linear_Regression/Coding_linear_regression.ipynb

    部屋数から住宅価格を予測する直線を引きます。まず 3 つのトリックを手で書いて反復学習し、 最後に同じ問題を scikit-learn の LinearRegression に解かせて答え合わせをします。

    このノートブックの読みどころは、手で書いた反復学習の到達点と、閉じた式の解が どれだけ近いか です。原著もそこを狙って、最後に scikit-learn を並べています。

    サンプル実装¶

    項目 内容
    実装 apps/grokking-ml-python-lib/src/grokking_ml_lib/nb01_linear_regression.py
    テスト apps/grokking-ml-python-lib/tests/test_nb01_linear_regression.py
    実行 uv run pytest tests/test_nb01_linear_regression.py

    データセット¶

    原著は 6 点だけの小さなデータを直接書いています。

    FEATURES = np.array([1, 2, 3, 5, 6, 7])
LABELS = np.array([155, 197, 244, 356, 407, 448])

    部屋数が 1 増えるとおよそ 50 だけ価格が上がる、ほぼ直線に乗ったデータです。 このあと学習する price_per_room（傾き）が 50 前後になれば、うまくいっています。

    直線を表す型¶

    原著は傾きと切片を 2 つの変数として持ち回り、タプルで返していました。 2 つで 1 つの意味を持つので、dataclass にまとめます。

    @dataclass
class Line:
    """学習された直線。原著の `price_per_room` と `base_price` に対応する。"""

    price_per_room: float
    base_price: float

    def predict(self, num_rooms: float) -> float:
        return self.base_price + self.price_per_room * num_rooms

    トリックの関数自体は、原著と一字一句同じ形を保つためタプルを返すままにしています。 呼び出し側でまとめるほうが、原著のコードとの対応が追いやすいからです。

    3 つのトリック¶

    シンプルトリック¶

    予測が外れた向きに、小さな乱数のぶんだけ直線を動かします。

    def simple_trick(base_price, price_per_room, num_rooms, price):
    small_random_1 = random.random() * 0.1
    small_random_2 = random.random() * 0.1
    predicted_price = base_price + price_per_room * num_rooms
    if price > predicted_price and num_rooms > 0:
        price_per_room += small_random_1
        base_price += small_random_2
    if price > predicted_price and num_rooms < 0:
        price_per_room -= small_random_1
        base_price += small_random_2
    if price < predicted_price and num_rooms > 0:
        price_per_room -= small_random_1
        base_price -= small_random_2
    if price < predicted_price and num_rooms < 0:
        price_per_room -= small_random_1
        base_price += small_random_2
    return price_per_room, base_price

    4 つの分岐のうち 3 番目だけ base_price を減らし、他は増やしています。 対称に書くなら 2 番目と 4 番目も揃うはずですが、原著がこう書いているのでそのまま写しました。 忠実な再現が目的なので、気づいた不整合も勝手に直しません。

    絶対トリック¶

    乱数をやめ、学習率と部屋数に比例した幅で動かします。

    def absolute_trick(base_price, price_per_room, num_rooms, price, learning_rate):
    predicted_price = base_price + price_per_room * num_rooms
    if price > predicted_price:
        price_per_room += learning_rate * num_rooms
        base_price += learning_rate
    else:
        price_per_room -= learning_rate * num_rooms
        base_price -= learning_rate
    return price_per_room, base_price

    このトリックは どれだけ外れたかを見ていません。誤差が 8 でも 800 でも、動く幅は同じです。 テストではそこを直接確かめています。

    def test_絶対トリックは誤差の大きさに依存しない() -> None:
    # 誤差が 8 でも 800 でも、動く幅は学習率と部屋数だけで決まる
    small = absolute_trick(0.0, 1.0, 2.0, 10.0, learning_rate=0.01)
    large = absolute_trick(0.0, 1.0, 2.0, 802.0, learning_rate=0.01)

    assert small == large

    二乗トリック¶

    誤差の大きさにも比例させると、分岐そのものが要らなくなります。

    def square_trick(base_price, price_per_room, num_rooms, price, learning_rate):
    predicted_price = base_price + price_per_room * num_rooms
    price_per_room += learning_rate * num_rooms * (price - predicted_price)
    base_price += learning_rate * (price - predicted_price)
    return price_per_room, base_price

    price - predicted_price が符号を持つので、上に外れたか下に外れたかを if で 場合分けする必要がなくなりました。3 つのなかでこれがいちばん短く、いちばん速く収束します。

    学習ループ¶

    原著は学習ループの中で matplotlib を呼び、エポックごとに直線を描いていました。 描画と学習が混ざっていると、テストから呼べません。ここでは 途中経過を戻り値として返す ように分けます。

    @dataclass
class TrainingLog:
    """学習の途中経過。原著が学習ループの中で描いていたものを記録する。"""

    line: Line
    #: 各エポック開始時点の直線。原著の `draw_line` に渡していた値
    history: list[Line] = field(default_factory=list)
    #: 各エポック開始時点の RMSE
    errors: list[float] = field(default_factory=list)

    ループ本体は原著のままです。

        for _ in range(epochs):
        history.append(Line(price_per_room, base_price))
        # 原著は features[0] だけを使って誤差を測っている（スカラーの予測値と
        # ラベル全体の差を取る）。ここも原著の式のまま写している
        predictions = features[0] * price_per_room + base_price
        errors.append(rmse(labels, predictions))

        i = random.randint(0, len(features) - 1)
        num_rooms = features[i]
        price = labels[i]

    誤差の計算に features[0] しか使っていないのは、原著のコードがそうなっているからです。 本来は全点の予測値を使うべきところですが、ここも直さずに写しています。

    乱数の消費順序を守る¶

    原著と同じ数値を再現するうえで いちばん壊れやすいのがここ です。

    原著は random.seed(0) のあと、random.random() を 2 回（傾きと切片の初期化）、 そのあと毎エポックで random.randint() を 1 回呼びます。 この順序が 1 つでもずれると、以降の乱数列が全部ずれて数値が一致しなくなります。

    たとえば履歴の記録を randint のあとに移動しただけでは壊れませんが、 初期化を 1 行にまとめて random.random(), random.random() の評価順に頼るような書き方をすると、 将来の読み手が順序を入れ替えたときに黙って壊れます。順序に意味があることをコメントで明示しています。

    原著と同じ数値が出る¶

    1000 エポックの二乗トリックは、原著の出力と 完全に一致 します。

    def test_二乗トリック1000エポックは原著と同じ数値になる() -> None:
    # 原著 `Coding_linear_regression.ipynb` の出力
    #   Price per room: 51.04430678220095
    #   Base price: 91.59448307644864
    result = linear_regression(FEATURES, LABELS, learning_rate=0.01, epochs=1000, seed=0)

    assert result.line.price_per_room == pytest.approx(51.04430678220095)
    assert result.line.base_price == pytest.approx(91.59448307644864)

    10000 エポック版が一致しない理由¶

    原著のノートブックには、誤差を記録する 10000 エポック版のセルもあり、 50.674635969827705 / 99.8711944536109 を出力しています。この数値は再現できません。

    原著は random.seed(0) をノートブックのセルで一度だけ呼んでいるため、 10000 エポック版は 1000 エポック版が消費し終わった 続きの乱数列 から始まります。 つまりこの出力は「セルの実行順」に依存した値で、単独では意味を持ちません。

    再現できないものを、できたことにはしません。ここでは代わりに 閉じた式の解に近づくこと を検証しています。

    def test_エポックを増やすと最小二乗解に近づく() -> None:
    # 原著のノートブックは 10000 エポック版で 50.67 / 99.87 を出しているが、
    # あれは 1000 エポック版と乱数列を共有した状態の値で、単独では再現しない。
    # ここでは「閉じた式の解に近づく」ことを確認する
    exact = fit_with_scikit_learn()
    result = linear_regression(FEATURES, LABELS, learning_rate=0.01, epochs=10000, seed=0)

    assert result.line.price_per_room == pytest.approx(exact.coef_[0], abs=1.0)
    assert result.line.base_price == pytest.approx(float(exact.intercept_), abs=1.0)

    scikit-learn に解かせる¶

    ここからが原著の締めくくりです。同じ問題を、反復ではなく閉じた式で解きます。

    def fit_with_scikit_learn(features=FEATURES, labels=LABELS) -> LinearRegression:
    """同じ問題を scikit-learn に解かせる。

    scikit-learn は特徴量を 2 次元配列で受け取るので `reshape(-1, 1)` が要る。
    こちらは反復ではなく閉じた式で解くため、乱数にも学習率にも依存しない。
    """
    return LinearRegression().fit(np.asarray(features).reshape(-1, 1), labels)

    reshape(-1, 1) は scikit-learn の作法です。特徴量が 1 つでも「サンプル数 × 特徴量数」の 2 次元配列を要求するので、[1, 2, 3, 5, 6, 7] を [[1], [2], [3], [5], [6], [7]] に変えます。

    結果は原著と完全に一致します。

    def test_scikit_learnの解は原著と同じ数値になる() -> None:
    # 原著の出力
    #   Coefficient: [50.39285714]
    #   Intercept: 99.59523809523819
    model = fit_with_scikit_learn()

    assert model.coef_[0] == pytest.approx(50.39285714, abs=1e-8)
    assert float(model.intercept_) == pytest.approx(99.59523809523819)

    4 部屋の予測も同じです。

    def test_scikit_learnの4部屋の予測は原著と同じ数値になる() -> None:
    # 原著の出力
    #   Predicted label for feature 4: [301.16666667]
    model = fit_with_scikit_learn()

    assert model.predict(np.array([[4]]))[0] == pytest.approx(301.16666667, abs=1e-7)

    手で書いた学習と、ライブラリの解を並べる¶

    求め方 傾き 切片
    二乗トリック 1000 エポック 51.044 91.594
    二乗トリック 10000 エポック 51.053 99.097
    scikit-learn（閉じた式） 50.393 99.595

    1000 エポックの時点で 傾きはほぼ合っている のに、切片は 8 ほどずれています。 エポックを 10 倍にすると切片が追いつきました。傾きのほうが先に決まり、切片が遅れて追従するのは、 二乗トリックの更新式で傾きの更新幅に num_rooms（1〜7）が掛かっているためです。 切片の更新幅にはそれが掛からないぶん、動きが遅くなります。

    ライブラリの fit() は、この反復の到達点を 1 回の計算で 出しています。 自前実装版の第 3 章 で書いた反復のコードと、この節を見比べると、 fit() が肩代わりしている範囲がはっきりします。
