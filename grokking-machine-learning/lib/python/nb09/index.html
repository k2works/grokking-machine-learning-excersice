    #09 アプリ推薦の決定木（Python）¶

    原著ノートブック: Chapter_09_Decision_Trees/App_recommendations.ipynb

    #08 で不純度の物差しを作ったので、今度は実際に木を育てます。 6 人のユーザーの「端末」と「年齢」から、おすすめアプリを当てる小さな例です。

    原著は同じデータを 2 通りの形 で学習させます。 年齢をカテゴリ（若者 / 大人）に潰した版と、数値のまま渡した版です。

    この回の発見は、木の形が実行のたびに変わること。 DecisionTreeClassifier は同点の分割候補から無作為に 1 つ選びます。

    サンプル実装¶

    項目 内容
    実装 apps/grokking-ml-python-lib/src/grokking_ml_lib/nb09_app_recommendations.py
    テスト apps/grokking-ml-python-lib/tests/test_nb09_app_recommendations.py
    実行 uv run pytest tests/test_nb09_app_recommendations.py

    データセット¶

    #: 原著の元データ。この 6 人ぶんの情報しかない
APP_DATASET = pd.DataFrame(
    {
        "Platform": ["iPhone", "iPhone", "Android", "iPhone", "Android", "Android"],
        "Age": [15, 25, 32, 35, 12, 14],
        "App": [
            "Atom Count", "Check Mate Mate", "Beehive Finder",
            "Check Mate Mate", "Atom Count", "Atom Count",
        ],
    }
)

    6 行 3 列。決定木の説明のために、答えが目で追える大きさ にしてあります。

    カテゴリ版は多出力分類になる¶

    原著は one-hot 符号化した表を 手で書き下して います。 #02 では pd.get_dummies を使っていたのに、ここでは使いません。

    APP_DATASET_ONE_HOT = pd.DataFrame(
    {
        "Platform_iPhone": [1, 1, 0, 1, 0, 0],
        "Platform_Android": [0, 0, 1, 0, 1, 1],
        "Age_Young": [1, 0, 0, 0, 1, 1],
        "Age_Adult": [0, 1, 1, 1, 0, 0],
        "App_Atom_Count": [1, 0, 0, 0, 1, 1],
        "App_Beehive_Finder": [0, 0, 1, 0, 0, 0],
        "App_Check_Mate_Mate": [0, 1, 0, 1, 0, 0],
    }
)

    注目すべきは 目的変数も 3 列に展開している ことです。

    X = app_dataset_one_hot[['Platform_iPhone','Platform_Android','Age_Adult','Age_Young']]
y = app_dataset_one_hot[['App_Atom_Count','App_Beehive_Finder','App_Check_Mate_Mate']]

    y が 3 列あるので、これは 多出力分類 です。 scikit-learn の決定木は複数の目的変数を同時に予測でき、 各節のジニ不純度は 列ごとの平均 になります。

    def test_多出力分類では目的変数が3列になる() -> None:
    model = fit_categorical(random_state=0)

    assert model.n_outputs_ == 3
    assert isinstance(model.classes_, list)
    assert len(model.classes_) == 3

    classes_ が 配列ではなくリスト になるのが多出力の目印です。 単一出力なら ndarray が返ります。

    原著の木のラベルにもそれが出ています。

    gini = 0.407
value = [[3, 3]
[5, 1]
[4, 2]]

    value が 3 行あります。3 つの目的変数それぞれの内訳です。

    しきい値は隣り合う値の中点¶

    数値版の根は X[0] <= 20.0 です。

    def test_しきい値は隣り合う年齢の中点になる() -> None:
    # 20 歳の人はいない。15（Atom Count）と 25（Check Mate Mate）の中点である
    ages = sorted(APP_DATASET["Age"])
    summary = summarize(fit_numeric(random_state=0), NUMERIC_FEATURES)

    assert 20.0 not in ages
    assert summary.root_threshold == pytest.approx((15 + 25) / 2)

    データに 20 歳の人はいません。 15 歳（Atom Count）と 25 歳（Check Mate Mate）の 中点が選ばれています。決定木は、値が変わる境目の中点を候補にします。

    これは「20 歳が意味のある境界だ」ということではありません。 16 歳から 24 歳のどこで切っても訓練データの結果は同じ で、 中点はその範囲の代表として選ばれただけです。

    2 つのジニ不純度の違い¶

    版 根のジニ不純度
    カテゴリ版（多出力） 0.407
    数値版（単一出力） 0.611

    同じデータなのに値が違います。測っている対象が違う からです。

    数値版は 3 クラスの分布（3, 1, 2）に対する不純度で、$1 - (9+1+4)/36 = 0.611$。 カテゴリ版は 3 つの 2 値列それぞれの不純度の平均です。

    def test_カテゴリ版のジニは数値版より小さい() -> None:
    # 原著の 0.407 と 0.611。多出力分類のジニは 3 列の平均なので値が下がる
    categorical = summarize(fit_categorical(random_state=0), CATEGORICAL_FEATURES)
    numeric = summarize(fit_numeric(random_state=0), NUMERIC_FEATURES)

    assert categorical.root_gini < numeric.root_gini

    同じ「gini」というラベルでも、比較できるとは限りません。 原著は 2 つの木を並べて見せていますが、この値を直接比べる意味はありません。

    木の形は実行のたびに変わる¶

    ここがこの回のいちばんの発見です。

    Platform_iPhone と Platform_Android は 互いに裏返し の列です。 どちらで分割しても結果は同じなので、分割の良さが完全に同点 になります。

    DecisionTreeClassifier は同点の候補から 無作為に 1 つ選びます。 種を変えて 100 回学習させ、木の形を数えました。

    def test_数値版の木の形は2通りに割れる() -> None:
    # Platform_iPhone と Platform_Android は互いに裏返しなので、
    # 2 段目の分割はどちらを選んでも同じ結果になる。scikit-learn は
    # 同点の候補から無作為に選ぶため、種を変えると木の形が変わる
    structures = Counter(
        tuple(split_features(fit_numeric(random_state=seed), NUMERIC_FEATURES))
        for seed in range(100)
    )

    assert set(structures) == {
        ("Age", "Platform_iPhone"),
        ("Age", "Platform_Android"),
    }
    # どちらもおおむね半々に現れる
    for count in structures.values():
        assert 30 < count < 70

    2 通りがほぼ半々 に現れます（実測で 98 対 102）。

    カテゴリ版はもっと分かれます。年齢も端末も裏返しの列を持つので、組み合わせで 4 通りです。

    def test_カテゴリ版の木の形は4通りに割れる() -> None:
    # 年齢も端末も裏返しの列を持つので、組み合わせで 4 通りになる
    structures = Counter(
        tuple(split_features(fit_categorical(random_state=seed), CATEGORICAL_FEATURES))
        for seed in range(100)
    )

    assert len(structures) == 4
    for count in structures.values():
        assert 10 < count < 40

    実測で 49 / 49 / 47 / 55（200 回中）と、ほぼ 4 等分でした。

    何が安定していて、何が変わるのか¶

    def test_木の形が変わっても正解率と節の数は変わらない() -> None:
    # 再現できないのは形だけで、性能は変わらない
    summaries = [
        summarize(fit_numeric(random_state=seed), NUMERIC_FEATURES) for seed in range(20)
    ]

    assert {summary.score for summary in summaries} == {1.0}
    assert {summary.node_count for summary in summaries} == {5}
    assert {round(summary.root_gini, 3) for summary in summaries} == {0.611}
    項目 安定するか
    正解率（1.0） 安定
    節の数（5） 安定
    根のジニ不純度（0.611） 安定
    根の分割（Age <= 20.0） 安定
    2 段目の分割 変わる（iPhone / Android のどちらか）

    根は安定します。 年齢での分割のほうが端末での分割より明確に良いので、 同点になりません。同点になるのは 2 段目だけです。

    原著は種を渡していない¶

    原著は random.seed(0) を最初のセルで呼んでいますが、 #04 と同じく これは scikit-learn に効きません。 DecisionTreeClassifier(random_state=...) を渡さない限り、 毎回違う木ができます。

    def test_種を固定すれば同じ木になる() -> None:
    # 再現性が要るなら random_state を渡す。原著は渡していない
    first = split_features(fit_numeric(random_state=7), NUMERIC_FEATURES)
    second = split_features(fit_numeric(random_state=7), NUMERIC_FEATURES)

    assert first == second

    「木を見せる」教材でこれは効きます。 読者が同じノートブックを実行しても、 本に載っている図と違う木が出ることがあります。

    まとめ¶

    項目 原著と一致するか
    正解率（両版とも 1.0） 完全一致
    根の分割（Age <= 20.0 / 年齢の列） 完全一致
    根のジニ不純度（0.611 / 0.407） 完全一致
    節の数（5） 完全一致
    2 段目の分割 実行のたびに変わる（等価な 2 通り）

    Kotlin 版・F# 版では、そもそもライブラリの選択から変わります。 Kotlin 版 の Smile は 決定的 に分割し、 F# 版 の ML.NET は 木の構造を外に出しません。
