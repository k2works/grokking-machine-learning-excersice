    #05 ロジスティック回帰の学習（Python）¶

    原著ノートブック: Chapter_06_Logistic_Regression/Coding_logistic_regression.ipynb

    #04 と同じ形の 8 点を、今度はロジスティック回帰で分けます。 ステップ関数がシグモイドに、パーセプトロン誤差が対数損失に置き換わるだけで、 アルゴリズムの骨格は同じです。

    この章の見どころは、原著が示す「対数損失の別の書き方」が 実際には対数損失と一致しないこと です。式を追って、正しい形も並べます。

    テスト apps/grokking-ml-python-lib/tests/test_nb05_logistic_regression.py

    データセット¶

    #: 原著が使う 8 点。#04 と似ているが最後の 2 点が入れ替わっている
FEATURES = np.array([[1, 0], [0, 2], [1, 1], [1, 2], [1, 3], [2, 2], [3, 2], [2, 3]])
LABELS = np.array([0, 0, 0, 0, 1, 1, 1, 1])

    #04 は [2, 3], [3, 2] の順でしたが、こちらは [3, 2], [2, 3] です。 集合としては同じで、並び順だけが違います。原著の入力ミスと思われますが、 線形分離の結果は変わらないので、そのまま写しました。

    シグモイド¶

    def sigmoid(x: float) -> float:
    """シグモイド関数。

    原著のコメントどおり `exp(x) / (1 + exp(x))` で書く。教科書によくある
    `1 / (1 + exp(-x))` と数学的には同じだが、x が大きな負の数のときに
    `exp(-x)` が溢れない形になっている。
    """
    return float(np.exp(x) / (1 + np.exp(x)))

    原著はここに珍しくコメントを残しています。 「本では 1/(1+np.exp(-x)) と書いたが、この書き方のほうが小さい浮動小数点数で安定する」。

    2 つの式が同じ値を返すことをテストで確かめました。

    def test_シグモイドの2つの書き方は一致する() -> None:
    # 原著が使う exp(x)/(1+exp(x)) と、教科書の 1/(1+exp(-x))
    for x in [-3.0, -0.5, 0.0, 1.7, 4.2]:
        assert sigmoid(x) == pytest.approx(1 / (1 + np.exp(-x)))

    対数損失¶

    パーセプトロン誤差は「当たれば 0」でしたが、対数損失は当たっていても 0 になりません。

    def log_loss(
    weights: list[float], bias: float, features: NDArray[np.int_], label: int
) -> float:
    """対数損失。当たっていても 0 にはならず、確信の度合いで連続的に変わる。"""
    pred = prediction(weights, bias, features)
    return float(-label * np.log(pred) - (1 - label) * np.log(1 - pred))

    def test_対数損失は当たっていても0にはならない() -> None:
    # パーセプトロン誤差は当たれば 0 だったが、対数損失は確信の度合いで変わる
    weights, bias = [1.0, 1.0], 0.0
    # FEATURES[4] = [1, 3] はラベル 1。スコア 4 なのでよく当たっている
    confident = log_loss(weights, bias, FEATURES[4], 1)
    # FEATURES[0] = [1, 0] はラベル 0。スコア 1 なので外している
    wrong = log_loss(weights, bias, FEATURES[0], 0)

    assert 0 < confident < 0.1
    assert wrong > 1.0

    この性質が、あとで収束の速さに効いてきます。 「もう十分に当たっている点」も損失を持ち続けるので、 学習が止まらず、直線はどんどん急になっていきます。

    原著の「別の書き方」は対数損失と一致しない¶

    原著はセルを 1 つ使って、対数損失の別表現を紹介します。

    def soft_relu(x):
    return np.log(1+np.exp(x))

def alternate_log_loss(weights, bias, features, label):
    pred = prediction(weights, bias, features)
    return soft_relu((pred-label)*score(weights, bias, features))

    pred は シグモイドを通した 0〜1 の確率 です。 (pred - label) は -1 や +1 ではなく、その中間の値になります。

    実際に計算すると一致しません。

    スコア ラベル 対数損失 原著の別表現
    -2.0 0 0.12692801 0.58103216
    -2.0 1 2.12692801 1.92011028
    0.0 0 0.69314718 0.69314718
    0.0 1 0.69314718 0.69314718
    3.0 1 0.04858735 0.62453660

    スコアが 0 のときだけ一致します。 どちらも soft_relu(0) = log 2 になるからです。

    def test_スコアが0のときだけ両者は一致する() -> None:
    # (pred - label) * 0 も (1 - 2 * label) * 0 も 0 になるため
    weights, bias = [1.0, 1.0], -1.0
    features = np.array([1, 0])  # スコア = 1 - 1 = 0

    assert score(weights, bias, features) == pytest.approx(0.0)
    assert alternate_log_loss_original(weights, bias, features, 1) == pytest.approx(
        log_loss(weights, bias, features, 1)
    )

    正しい形¶

    (pred - label) ではなく (1 - 2 * label) を掛けると厳密に一致します。 ラベルが 0 なら +1、1 なら -1 です。

    def alternate_log_loss(
    weights: list[float], bias: float, features: NDArray[np.int_], label: int
) -> float:
    """対数損失と厳密に等しい「別の書き方」。

    ラベルが 0 なら +1、1 なら -1 を掛ける。つまり `(1 - 2 * label)`。
    こうすると `soft_relu` の中身が `log_loss` の定義そのものになる。
    """
    return soft_relu((1 - 2 * label) * score(weights, bias, features))

    導出は 2 行です。スコアを $s$、シグモイドを $\sigma$ とします。

    • $y = 1$ のとき: $-\log \sigma(s) = -\log \frac{e^s}{1+e^s} = \log(1 + e^{-s}) = \text{softRelu}(-s)$
    • $y = 0$ のとき: $-\log(1 - \sigma(s)) = -\log \frac{1}{1+e^s} = \log(1 + e^{s}) = \text{softRelu}(s)$

    符号が $y$ で反転するので、$(1 - 2y)$ を掛ければ 1 本の式にまとまります。

    両方を実装して、片方は一致し、もう片方は一致しないことをテストで固定しました。

    def test_正しい別の書き方は対数損失と厳密に一致する() -> None:
    # ラベルが 0 なら +1、1 なら -1 を掛ける。つまり (1 - 2 * label)
    weights, bias = [1.0, 1.0], 0.0
    for i in range(len(FEATURES)):
        for label in [0, 1]:
            assert alternate_log_loss(weights, bias, FEATURES[i], label) == pytest.approx(
                log_loss(weights, bias, FEATURES[i], label)
            )

    原著がこれに気づかなかった理由

    原著は total_alternate_log_loss も定義していますが、その中身は alternate_log_loss ではなく log_loss を呼んでいます。 合計を取る関数が別表現を使っていないので、 ノートブックを実行しても両者の食い違いが表に出ません。 バグが 2 つ重なって、互いを隠している形です。

    ロジスティックトリック¶

    def logistic_trick(...) -> tuple[list[float], float]:
    """ロジスティックトリック。パーセプトロンのトリックと同じ形をしている。

    違いは `pred` が 0 / 1 ではなく 0〜1 の連続値であること。おかげで
    「少しだけ間違えた」点は少しだけ動かす、という調整が入る。

    #04 の「短く書いた版」と違い、**バイアスの更新はループの外側にある**。
    原著もここでは正しく書いている。
    """
    updated = list(weights)
    pred = prediction(weights, bias, features)
    for i in range(len(updated)):
        updated[i] += (label - pred) * features[i] * learning_rate
    bias += (label - pred) * learning_rate
    return updated, bias

    #04 で見たバイアスの二重更新は、ここでは起きていません。 bias += ... が for の外側にあります。原著もこの章では正しく書いています。

    pred が連続値になったので、「どれだけ外したか」が更新幅に反映されます。

    def test_確信を持って間違えた点ほど大きく動く() -> None:
    # パーセプトロンのトリックは当たり外れの 2 値でしか動かなかったが、
    # ロジスティックトリックは pred が連続値なので度合いが効く
    close = logistic_trick([1.0, 1.0], -3.0, np.array([1, 2]), 1)
    far = logistic_trick([1.0, 1.0], -10.0, np.array([1, 2]), 1)

    assert far[0][0] > close[0][0]

    収束はパーセプトロンより遅い¶

    原著は 500 エポックで学習し、([1.2019, 0.7009], -2.7884) を出しています。 #04 と同じ理由（random に種が無い）で再現できません。

    種を固定して走らせると、500 エポックでは 1 点を取り違えます。

    エポック 重み バイアス 予測 対数損失の合計
    500 [0.749, 0.216] -1.037 1 点誤り 3.754
    2,000 [1.184, 0.627] -2.358 1 点誤り 2.619
    5,000 [1.722, 1.075] -3.999 全点正解 1.754
    20,000 [2.810, 2.098] -7.627 全点正解 0.867

    パーセプトロンは 500 エポックで揃っていました。ロジスティック回帰が遅いのは、 対数損失が当たっていても 0 にならない からです。 すべての点が「もっと確信を持て」と押し続けるので、 分離できたあとも重みが伸び続け、境界の位置が定まるまで時間がかかります。

    20,000 エポックの重みが 5,000 エポックの約 2 倍になっているのがその現れです。 比 $w_0 : w_1$ はほぼ変わらず、大きさだけが増えています。 直線の向きは決まっていて、確信の強さだけが上がり続けているのです。

    def test_学習後は全点を正しく分類できる() -> None:
    # 500 エポックでは 1 点（[1, 2]）を取り違える。対数損失は当たっていても
    # 0 にならないので、パーセプトロンより収束に時間がかかる
    result = logistic_regression_algorithm(epochs=5000, seed=0)

    scikit-learn に解かせる¶

    def fit_with_scikit_learn(features=FEATURES, labels=LABELS) -> LogisticRegression:
    """同じ問題を scikit-learn の `LogisticRegression` に解かせる。"""
    return LogisticRegression().fit(features, labels)

    予測は完全に一致し、係数は 4 桁まで 一致します。

    項目 原著 実測
    係数 0 1.00458154 1.00465774
    係数 1 0.93718206 0.93711261
    切片 -3.1600974622 -3.1598379956 
    def test_scikit_learnの係数は原著と4桁一致する() -> None:
    # 原著の出力
    #   Coefficients: [1.00458154 0.93718206]
    #   Intercept: -3.1600974622062727
    # lbfgs ソルバの収束判定が変わっているため、5 桁目から分かれる
    model = fit_with_scikit_learn()

    assert model.coef_[0][0] == pytest.approx(1.00458154, rel=1e-4)
    assert model.coef_[0][1] == pytest.approx(0.93718206, rel=1e-4)
    assert float(model.intercept_[0]) == pytest.approx(-3.1600974622062727, rel=1e-4)

    #01 の線形回帰は 15 桁一致しました。あちらは閉じた式で解が一意に決まるのに対し、 こちらは lbfgs による反復 です。収束判定の閾値が版によって変わるので、 最後の数桁がそろいません。

    係数の重みが小さいこと にも注目です。手書きの学習は 20,000 エポックで [2.81, 2.10] まで伸びましたが、scikit-learn は [1.00, 0.94] で止まっています。 LogisticRegression が 既定で L2 正則化を掛けている（C=1.0）ためです。 #03 で見た正則化が、ここでは「重みの伸びすぎ」を止める役に回っています。
