    #11 大学院入学審査の決定木（F#）¶

    原著ノートブック: Chapter_09_Decision_Trees/University_Admissions.ipynb

    入学審査データ 400 件から合否を決定木で当て、木の大きさを変えて過学習を見ます。

    #09・#10 で書いた自前の CART を一般化しました。 その結果、原著の出力をすべて再現 できています。 節の数（15）、正解率（0.885）、2 人の出願者の合否、 2 特徴量の木の正解率（0.8525 / 0.8625 / 0.93）まで一致しました。

    サンプル実装¶

    項目 内容
    実装 apps/grokking-ml-fsharp-lib/src/GrokkingMlLib/Nb11UniversityAdmissions.fs
    テスト apps/grokking-ml-fsharp-lib/tests/GrokkingMlLib.Tests/Nb11UniversityAdmissionsTests.fs
    実行 dotnet test

    制限をレコードにまとめる¶

    原著は 3 つの制限を引数で渡します。F# ではレコードにしました。

    /// 木を育てるときの制限。原著の 3 つの引数にそのまま対応する
type Limits =
    { /// `max_depth`。根を深さ 0 と数える
      MaxDepth: int
      /// `min_samples_leaf`。葉に残る件数の下限
      MinSamplesLeaf: int
      /// `min_samples_split`。分割してよい節の件数の下限
      MinSamplesSplit: int }

/// 制限なし
let unlimited =
    { MaxDepth = 100
      MinSamplesLeaf = 1
      MinSamplesSplit = 2 }

    unlimited を基準に with で書き換えられる のが効きます。

    /// GRE と TOEFL の 2 特徴量だけで学習する
let fitExams (data: Admissions) (maxDepth: int) =
    fit data examFeatures { unlimited with MaxDepth = maxDepth }

    「深さだけ制限して、他は既定のまま」が 1 行で表せます。 Python のキーワード引数と同じ読みやすさを、値の側で実現しています。

    3 つの制限は木を育てる 1 か所で見ます。

    let isPure = (labels |> Array.distinct |> Array.length) <= 1

if isPure || depth >= limits.MaxDepth || labels.Length < limits.MinSamplesSplit then
    Leaf(majority labels)

    MinSamplesLeaf だけは分割候補の選別に使うので、別の場所です。

    if leftIndices.Length < minSamplesLeaf || rightIndices.Length < minSamplesLeaf then
    None

    None を返して「この分割は候補にしない」と表します。 Option があるおかげで、「使えない分割」を例外や番兵値なしに扱えます。

    同数の葉で原著と食い違った¶

    最初の実装は、原著の 2 人目の出願者を True と予測しました。原著は False です。

    原著のコメントに答えが書いてありました。

    # A node in the white (neutral) leaf gets a false prediction

    その葉は合否が同数 です。原著の図では色が付かず白いままになります。 scikit-learn は同数のとき クラス順で先頭のもの（False）を選びます。

    こちらは Array.maxBy を使っており、出現順で先に来たほう を選んでいました。

    /// 葉の予測クラス。もっとも多いクラスを返す。
///
/// **同数のときはクラス名の小さいほうを選ぶ。** scikit-learn は `np.argmax` を
/// クラス順に並べた件数配列へ適用するので、同数なら先頭のクラス（ここでは
/// `"false"`）が選ばれる。原著が「白い（中立な）葉は False になる」と
/// コメントしているのはこの挙動である。出現順で選ぶと結果が変わる。
let private majority (labels: string[]) =
    labels
    |> Array.countBy id
    |> Array.sortBy (fun (label, count) -> -count, label)
    |> Array.head
    |> fst

    Array.sortBy の複合キー (-count, label) で 「件数の降順、同数ならラベルの昇順」を表します。 #06 では Seq.sortBy のタプルで昇順・降順を混ぜられず比較関数を書きましたが、 ここは 符号を反転させれば済む数値 なので 1 行で書けました。

    [<Fact>]
let ``CGPAだけ下げると不合格に変わる`` () =
    // 原著の出力: 8.9 を 8.0 にすると False。
    // 原著は「白い（中立な）葉は False になる」とコメントしている。
    // 同数の葉でクラス名の小さいほうを選ぶ規則にしないと、ここが True になる
    Assert.False(predictApplicant (fitSmaller data) [ 320.0; 110.0; 3.0; 4.0; 3.5; 8.0; 0.0 ])

    原著のコメント 1 行が、実装の細部を決めました。 再現を目的にすると、こういう脇の記述が重要な手がかりになります。

    節の数まで完全に一致した¶

    [<Fact>]
let ``2特徴量の木の節の数も scikit-learn と一致する`` () =
    // 深さ 1 は 3 節、深さ 2 は 7 節、制限なしは 197 節
    Assert.Equal(3, nodeCount (fitExams data 1))
    Assert.Equal(7, nodeCount (fitExams data 2))
    Assert.Equal(197, nodeCount (fitExams data 20))

    197 節まで一致します。 400 件のデータで、木を育てる過程が 最後の分割まで scikit-learn と同じ判断をしているということです。

    一致に必要だったのは 4 つの規則でした。

    1. しきい値は隣り合う値の中点（#09）
    2. 同点の分割は列の順に最初のもの（#09）
    3. 同数の葉はクラス名の小さいほう（この章）
    4. 深さは根を 0 と数える（#10）

    どれか 1 つでも違えば、197 節のどこかでずれます。

    過学習が数字で見える¶

    [<Fact>]
let ``節が28倍になっても正解率は7ポイントしか上がらない`` () =
    // 深さ 2 の 7 節（0.8625）から制限なしの 197 節（0.93）へ。過学習の割に合わない
    let shallow = fitExams data 2
    let unbounded = fitExams data 20

    Assert.Equal(7, nodeCount shallow)
    Assert.Equal(197, nodeCount unbounded)
    Assert.True(accuracy unbounded data examFeatures - accuracy shallow data examFeatures < 0.08)

    原著は図でしか見せていませんが、節の数と正解率を並べると過学習が数字で読めます。 「木が複雑になった割に当たるようになっていない」ことが、 図を見なくても分かる形になりました。

    この章で F# が効いた場面・効かなかった場面¶

    場面 評価
    制限の表現 効いた — レコードと with で「1 つだけ変える」が 1 行
    使えない分割 効いた — Option で番兵値なしに表せる
    同数の扱い 効いた — sortBy (-count, label) の複合キー 1 行
    木の再利用 効いた — #09・#10 の CART をそのまま一般化できた
    原著との一致 効いた — 197 節まで完全一致
    ライブラリの恩恵 効かなかった — 決定木は 3 回連続で自前実装

    決定木の 3 本（#09・#10・#11）で、 F# は一度もライブラリを使いませんでした。 ライブラリが無いぶん、規則を 1 つずつ明示することになり、 結果として原著にいちばん近づきました。 皮肉ですが、この連載らしい結末です。
