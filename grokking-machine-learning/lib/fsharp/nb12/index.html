    #12 回帰木（F#）¶

    原著ノートブック: Chapter_09_Decision_Trees/Regression_decision_tree.ipynb

    決定木を 回帰 に使う回です。年齢からアプリの利用日数を予測します。

    #09 からの CART を回帰用に書き換えます。 判別共用体の型を 1 つ差し替えるだけ で済んだのが、この章の見どころです。

    サンプル実装¶

    項目 内容
    実装 apps/grokking-ml-fsharp-lib/src/GrokkingMlLib/Nb12RegressionTree.fs
    テスト apps/grokking-ml-fsharp-lib/tests/GrokkingMlLib.Tests/Nb12RegressionTreeTests.fs
    実行 dotnet test

    葉の型を差し替えるだけ¶

    分類木の定義はこうでした（#09）。

    type Tree =
    | Leaf of prediction: string
    | Node of feature: string * threshold: float * left: Tree * right: Tree

    回帰木はこうなります。

    /// 回帰木。葉が **平均値** を返すのが分類木との違い
type Tree =
    | Leaf of prediction: float
    | Node of threshold: float * left: Tree * right: Tree

    Leaf の型が string から float に変わっただけ です （特徴量が 1 つしかないので feature も落としました）。

    分類木が「葉は多数決」、回帰木が「葉は平均」という違いは、 この 1 語に集約されています。

    Smile は smile.classification.DecisionTree と smile.regression.RegressionTree という 別のクラス を用意していました。 scikit-learn も DecisionTreeClassifier / DecisionTreeRegressor と別クラスです。 型の側を変えるだけで済むのは、判別共用体で書いたからこその身軽さです。

    [<Fact>]
let ``判別共用体は回帰木でも木の形をそのまま表す`` () =
    // 分類木の Leaf は string、回帰木の Leaf は float。型だけ差し替えれば済む
    match fit 2 with
    | Node(35.0, Node(15.0, Leaf 7.0, Leaf 6.0), Node(65.0, left, Leaf 4.5)) ->
        Assert.Equal(Leaf(4.0 / 3.0), left)
    | other -> failwith $"想定と違う木になった: {other}"

    木の形を 1 つのパターンで書き下せる のも #09 と同じです。 Leaf 7.0 のように 浮動小数点数をパターンに直接書ける ので、 分類木のときと同じ読み味になります。

    分割の基準が変わる¶

    分類木はジニ不純度を最小にしました。回帰木は二乗誤差の合計を最小にします。

    /// 二乗誤差の合計。回帰木ではこれを最小にする分割を選ぶ
let private squaredError (values: float[]) =
    if Array.isEmpty values then
        0.0
    else
        let mean = Array.average values
        values |> Array.sumBy (fun v -> (v - mean) ** 2.0)

    空の配列で 0 を返す ようにしています。 #08 のジニ不純度は空で 1 を返し、エントロピーは 0 を返しました。 ここは「誤差の合計」なので 0 が自然です。

    分割の探索は分類木とまったく同じ形です。

    let best =
    candidateThresholds xs
    |> Array.choose (fun threshold -> ... )
    |> Array.sortBy (fun (total, _, _, _) -> total)
    |> Array.tryHead

    candidateThresholds（隣り合う値の中点）も #09 から変えていません。 変わったのは「何を最小にするか」だけ です。

    手計算の 9 通りが完全に一致¶

    [<Fact>]
let ``各分割の重み付きMSEは原著と同じ`` () =
    // 原著のセル出力をそのまま期待値にしている
    let expected =
        [ 5.25; 3.9642857142857144; 3.916666666666667; 1.9833333333333334
          4.25; 4.983333333333333; 5.166666666666667; 5.25; 5.25 ]

    let splits = splitMses days

    expected
    |> List.iteri (fun index value -> Assert.Equal(value, splits.[index].WeightedMse, 14))

    小数点以下 14 桁まで一致しました。

    NaN の扱いも原著どおりです。

    /// 空の配列の平均は NaN。原著も NumPy の警告つきで NaN を出している
let private meanOrNaN (values: float[]) =
    if Array.isEmpty values then nan else Array.average values

    F# には nan というリテラルがあります。 Double.NaN と書かずに済むのは 数値計算コードで地味に効きます。判定は System.Double.IsNaN です。

    木も予測も完全に一致¶

    [<Fact>]
let ``予測は scikit-learn と完全に一致する`` () =
    // 10 歳 -> 7、20〜30 歳 -> 6、40〜60 歳 -> 1.333、70〜80 歳 -> 4.5
    let expected = [ 7.0; 6.0; 6.0; 4.0 / 3.0; 4.0 / 3.0; 4.0 / 3.0; 4.5; 4.5 ]
    let tree = fit 2

    expected
    |> List.iteri (fun index value -> Assert.Equal(value, predict tree ages.[index], 12))

    葉の値も一致します。

    [<Fact>]
let ``葉は平均値を返す`` () =
    // 分類木は多数決だったが、回帰木は葉に落ちた点の平均を返す
    Assert.Equal<float list>([ 7.0; 6.0; 4.0 / 3.0; 4.5 ], leafValues (fit 2))

    leafValues が返すリストをそのまま比較できます。 Assert.Equal<float list> で、4 つの葉の値を 1 行で確かめられます。

    深さ 0 の木は平均を返す¶

    [<Fact>]
let ``深さ0の木は全体の平均を返す`` () =
    // 分割が 1 つも入らないので、どの年齢でも 4.0
    Assert.Equal(4.0, predict (fit 0) 10.0, 12)
    Assert.Equal(4.0, predict (fit 0) 80.0, 12)

    分割が 1 つも無い回帰木は、常に全体の平均を返します。 原著が最初に確かめた np.array([7,5,7,1,2,1,5,4]).mean() -> 4.0 が、 そのまま「木を育てる前の予測」にあたります。

    分類木なら「常に多数派のクラスを返す」に対応します。 どちらも「特徴量を一切見ないモデル」 で、 そこからどれだけ良くなったかが木を育てる意味です。

    3 言語の比較¶

    項目 Python Kotlin F#
    回帰木 DecisionTreeRegressor smile.regression.RegressionTree 自前の CART
    分類木との関係 対になるクラス名 別パッケージ・別名 Leaf の型を差し替えるだけ
    9 通りの MSE 一致 一致（15 桁） 一致（14 桁）
    木の分割 一致 一致 一致
    予測値 一致 一致 一致

    3 言語すべてが完全一致しました。 分類木の 3 本（#09〜#11）では 毎回どこかが食い違ったのと対照的です。 回帰木は分割基準が最小二乗しかなく、連続値のラベルでは同点も起きにくいためです。

    この章で F# が効いた場面・効かなかった場面¶

    場面 評価
    分類木からの移行 効いた — Leaf の型を差し替えるだけ
    木の検証 効いた — 浮動小数点数もパターンに直接書ける
    葉の値の比較 効いた — リストを 1 行で比較
    NaN 効いた — nan リテラルがある
    ライブラリの恩恵 効かなかった — 決定木は 4 回連続で自前実装
