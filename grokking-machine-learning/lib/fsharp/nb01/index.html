    #01 線形回帰を 3 つのトリックで学習する（F#）¶

    原著ノートブック: Chapter_03_Linear_Regression/Coding_linear_regression.ipynb

    部屋数から住宅価格を予測する直線を引きます。3 つのトリックを手で書いて反復学習し、 最後に同じ問題を Math.NET の Fit.Line に解かせて答え合わせをします。

    F# で目立つのは 原著の「引数を書き換える」スタイルが、そのままでは書けない ことです。 束縛が既定で不変なので、シンプルトリックの 4 つの if をどう表現するかが最初の分かれ道になります。

    サンプル実装¶

    項目 内容
    実装 apps/grokking-ml-fsharp-lib/src/GrokkingMlLib/Nb01LinearRegression.fs
    テスト apps/grokking-ml-fsharp-lib/tests/GrokkingMlLib.Tests/Nb01LinearRegressionTests.fs
    実行 dotnet test

    データセット¶

    let features = [| 1; 2; 3; 5; 6; 7 |]
let labels = [| 155; 197; 244; 356; 407; 448 |]

    直線を表す型¶

    レコード型にメンバーを 1 つ持たせます。

    /// 学習された直線。原著の `price_per_room` と `base_price` に対応する
type Line =
    { PricePerRoom: float
      BasePrice: float }

    member this.Predict(numRooms: float) = this.BasePrice + this.PricePerRoom * numRooms

    タプル (float * float) でも書けますが、それだと傾きと切片を取り違えても型が通ります。 レコードならフィールド名が必須になるので、取り違えがコンパイルエラーになります。

    3 つのトリック¶

    シンプルトリックと「不変で書き換える」¶

    原著は引数 price_per_room と base_price を直接書き換えていました。 F# では let 束縛が不変なので、同じ名前で 束縛し直しながら 段を進めます。

    let simpleTrick (random: Random) (line: Line) (numRooms: float) (price: float) =
    let smallRandom1 = random.NextDouble() * 0.1
    let smallRandom2 = random.NextDouble() * 0.1
    let predictedPrice = line.BasePrice + line.PricePerRoom * numRooms

    let slope, intercept = line.PricePerRoom, line.BasePrice

    let slope, intercept =
        if price > predictedPrice && numRooms > 0.0 then
            slope + smallRandom1, intercept + smallRandom2
        else
            slope, intercept

    let slope, intercept =
        if price > predictedPrice && numRooms < 0.0 then
            slope - smallRandom1, intercept + smallRandom2
        else
            slope, intercept

    // ...残り 2 つの分岐も同じ形
    { PricePerRoom = slope; BasePrice = intercept }

    シャドーイングで「前の段の値を受けて次の段を作る」形になり、 原著の 4 つの if が 4 段のパイプライン として並びました。 if が式なので else が必須になり、「何もしない」場合も明示的に書くことになります。 原著の if は暗黙に「何もしない」を持っていたので、そこが顕在化します。

    4 つの分岐のうち 3 番目だけ intercept を減らす非対称も原著のままです。 else が並ぶことで、その非対称がかえって見やすくなりました。

    二乗トリック¶

    分岐が無いので、F# ではもっとも短くなります。

    let squareTrick (learningRate: float) (line: Line) (numRooms: float) (price: float) =
    let predictedPrice = line.BasePrice + line.PricePerRoom * numRooms
    let error = price - predictedPrice

    { PricePerRoom = line.PricePerRoom + learningRate * numRooms * error
      BasePrice = line.BasePrice + learningRate * error }

    引数の順序を learningRate から始めているのは、部分適用を効かせるため です。 squareTrick 0.01 と書けば「学習率 0.01 で固定したトリック」が値として得られます。

    トリックの切り替えは判別共用体で¶

    原著はコメントアウトで切り替えていました。F# では判別共用体にします。

    /// どのトリックで学習するか。原著はコメントアウトで切り替えていた
type Trick =
    | Simple
    | Absolute
    | Square

    line <-
    match trick with
    | Square -> squareTrick learningRate line numRooms price
    | Absolute -> absoluteTrick learningRate line numRooms price
    | Simple -> simpleTrick random line numRooms price

    match の網羅性はコンパイラが検査するので、ケースを足し忘れると警告で止まります。 Kotlin の enum class + when と同じ効き方ですが、F# は 既定で網羅性を要求する ぶん強めです。

    学習ループ¶

    type TrainingLog =
    { Line: Line
      /// 各エポック開始時点の直線
      History: Line list
      /// 各エポック開始時点の RMSE
      Errors: float list }

    履歴の積み方が Python・Kotlin と違います。F# の list は不変の連結リストなので、 末尾追加は毎回リスト全体を作り直すことになります。先頭追加で積んで、最後に 1 度だけ反転 します。

        // 履歴は先頭追加で積み、最後に 1 度だけ反転する。末尾追加を繰り返すより安い
    let mutable line = initial
    let mutable history = []
    let mutable errors = []

    for _ in 1..epochs do
        history <- line :: history
        // 原著は features[0] だけを使って誤差を測っている
        errors <- rmse labels (float features.[0] * line.PricePerRoom + line.BasePrice) :: errors

        let i = random.Next(features.Length)
        let numRooms = float features.[i]
        let price = float labels.[i]
        // ...トリックを適用

    { Line = line
      History = List.rev history
      Errors = List.rev errors }

    mutable を 3 つ使っています。List.fold で畳み込む書き方もできますが、 「累積器に直線・履歴・誤差の 3 つを持つタプル」になって、原著のループとの対応が読めなくなります。 原著のコードとの照合しやすさを優先 して、明示的なループにしました。

    rmse は Array.sumBy で書きます。

    let rmse (labels: int[]) (prediction: float) =
    let squaredSum =
        labels |> Array.sumBy (fun label -> (float label - prediction) ** 2.0)

    sqrt (squaredSum / float labels.Length)

    float label の変換が必須です。F# は整数と浮動小数点を暗黙に混ぜないので、 Python や Kotlin では気づかずに済んでいた変換が、ここで型エラーとして表面化します。

    原著の数値と一致するもの・しないもの¶

    乱数の消費順序は原著と揃えてありますが、System.Random は Python の Mersenne Twister と別のアルゴリズムです。同じ種でも同じ数列にはなりません。

    トリックの学習結果は原著の 51.044 / 91.594 には一致しないので、収束先で検証します。

    [<Fact>]
let ``二乗トリックは最小二乗解へ収束する`` () =
    // 乱数列が Python と違うので原著の 51.044 / 91.594 には一致しない。
    // 閉じた式の解に十分近づくことで検証する
    let exact = fitWithMathNet features labels
    let result = linearRegression features labels 0.01 10000 Square 0

    Assert.Equal(exact.PricePerRoom, result.Line.PricePerRoom, 1.0)
    Assert.Equal(exact.BasePrice, result.Line.BasePrice, 1.0)

    xUnit の Assert.Equal は多重定義に注意

    第 3 引数に 0 を渡すと int の precision（小数点以下の桁数） と解釈され、 整数に丸めて厳密比較されます。許容誤差として使いたいときは 1.0 のように float を明示します。ここで一度ハマりました。

    Math.NET に解かせる¶

    scikit-learn の LinearRegression にあたるものを、F# では ML.NET ではなく Math.NET から取ります。

    let fitWithMathNet (features: int[]) (labels: int[]) =
    let xs = features |> Array.map float
    let ys = labels |> Array.map float
    let struct (intercept, slope) = MathNet.Numerics.Fit.Line(xs, ys)

    { PricePerRoom = slope; BasePrice = intercept }

    なぜ ML.NET を使わないのか¶

    ML.NET にも回帰トレーナーはありますが、厳密な最小二乗を解く Ols は MKL ネイティブライブラリ（libMklImports）を要求 し、macOS x64 では 実行時に NotSupportedException になります。

    反復解法の Sdca なら動きますが、こちらは近似解で、ラベルの正規化を怠ると non-finite weights で発散します。原著の LinearRegression は閉じた式で解いているので、 同じ性質を持つ Math.NET の Fit.Line を選びました。

    struct パターンが要る¶

    Fit.Line は 構造体タプル struct (float * float) を返します。 通常のタプルとして受けようとすると型エラーになるので、let struct (a, b) = ... と書きます。

    error FS0193: 型の制約が一致しません。
  'struct (float * float)' は ''a * 'b' と互換性がありません

    返る順序が (切片, 傾き) で、scikit-learn の coef_ / intercept_ とは逆です。 ここもレコードのフィールド名が効く場面でした。タプルのまま持ち回っていたら、 取り違えても型が通ってしまいます。

    数値は原著と完全に一致します。

    [<Fact>]
let ``MathNet の解は原著と同じ数値になる`` () =
    // 原著 scikit-learn の出力
    //   Coefficient: [50.39285714]
    //   Intercept: 99.59523809523819
    let line = fitWithMathNet features labels

    Assert.Equal(50.39285714, line.PricePerRoom, 8)
    Assert.Equal(99.59523809523819, line.BasePrice, 8)

    [<Fact>]
let ``MathNet の4部屋の予測は原著と同じ数値になる`` () =
    // 原著の出力: Predicted label for feature 4: [301.16666667]
    let line = fitWithMathNet features labels

    Assert.Equal(301.16666667, line.Predict 4.0, 7)

    Python の scikit-learn、Kotlin の Smile、F# の Math.NET — 3 つの別実装が小数点以下 8 桁まで揃います。最小二乗の解が一意に決まるからです。

    この章で F# が効いた場面¶

    場面 効いた言語機能
    傾きと切片の取り違え防止 レコードのフィールド名が必須
    シンプルトリックの 4 分岐 シャドーイングで段を積む。else が必須になり非対称が見える
    トリックの切り替え 判別共用体 + match の網羅性検査
    学習率の固定 引数順を工夫した部分適用
    整数と浮動小数点の混在 暗黙変換が無く、float 変換が型で強制される

    逆に窮屈だったのは、学習ループで mutable を 3 つ使った点です。 関数型らしく fold で書くこともできますが、原著のループとの対応が読めなくなるため見送りました。
