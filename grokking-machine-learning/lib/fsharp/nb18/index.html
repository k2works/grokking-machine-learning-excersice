    ノートブック #18 類似度行列で RBF カーネルを分解する（F# 版）¶

    原著ノートブック: Chapter_11_Support_Vector_Machines/Calculating_similarities.ipynb

    RBF カーネルの正体を 手で計算して見せる 回です。 7 点のデータに対して全対の類似度を計算し、7 列の特徴量を足してから 線形 SVM を当てます。

    計算部分は 原著の出力と 16 桁まで一致 しました。 SVM 側は ML.NET の LinearSvm を使いましたが、 そこで 既定値のままだと 1 点を誤分類する という発見がありました。

    サンプル実装¶

    項目 内容
    実装 apps/grokking-ml-fsharp-lib/src/GrokkingMlLib/Nb18CalculatingSimilarities.fs
    テスト apps/grokking-ml-fsharp-lib/tests/GrokkingMlLib.Tests/Nb18CalculatingSimilaritiesTests.fs
    実行 dotnet test --filter "FullyQualifiedName~Nb18"

    類似度と行列¶

    let similarity (a: float[]) (b: float[]) =
    let dx = a.[0] - b.[0]
    let dy = a.[1] - b.[1]
    exp (-dx * dx - dy * dy)

/// 全対の類似度を並べた 7 × 7 の行列
let similarityMatrix () =
    Array.init Size (fun i -> Array.init Size (fun j -> similarity points.[i] points.[j]))

    Array.init の入れ子が、原著の二重ループにそのまま対応します。 可変の rows を用意して append する必要がありません。

    [<Fact>]
let ``類似度行列は原著の表と一致する`` () =
    let matrix = similarityMatrix ()

    // 原著の表の 1 行目: 1.000000 0.367879 0.367879 0.367879 0.367879 0.135335 ...
    Assert.Equal(0.36787944117144233, matrix.[0].[1], 15)
    Assert.Equal(0.1353352832366127, matrix.[0].[5], 15)
    // 2 行目の Sim4: 0.018316（距離の 2 乗が 4）
    Assert.Equal(0.01831563888873418, matrix.[1].[4], 15)
    // 3 行目の Sim5: 0.006738（距離の 2 乗が 5）
    Assert.Equal(0.006737946999085467, matrix.[2].[5], 15)

    Assert.Equal の桁指定は 15 が上限¶

    原著のセルに残っている 1.522997974471263e-08 を検証しようとして躓きました。

    System.ArgumentOutOfRangeException :
  Rounding digits must be between 0 and 15, inclusive. (Parameter 'digits')

    xUnit の Assert.Equal(expected, actual, digits) は 小数点以下の桁数 を指定するもので、Math.Round に渡されます。 16 以上は受け付けません。

    1.52e-08 を 16 桁の精度で比べたければ、小数点以下 23 桁が要ります。指定できません。

        // 桁が小さいので相対誤差で比べる（Assert.Equal の桁指定は 15 が上限）
    Assert.True(abs (similarity origin [| 3.0; 3.0 |] / 1.522997974471263e-08 - 1.0) < 1e-15)

    小さい値を高い精度で比べるときは、相対誤差に切り替える 必要があります。 pytest の approx(rel=...) や Kotlin の絶対誤差指定（1e-23 と書ける）と違い、 xUnit のこの API は絶対誤差しか表現できません。

    このシリーズでは #05・#07 でも Assert.Equal(..., 15) を使ってきましたが、 値が 0.1〜1 の範囲だったので気付きませんでした。

    手書きの予測式は 16 桁一致する¶

    let svmRbfPrediction (newPoint: float[]) =
    Array.init Size (fun i -> similarity newPoint points.[i] * predictionSigns.[i])
    |> Array.sum

        let expected =
        [| -0.7293294335267746
           -0.9749464141121803
           -0.9749464141121804
           0.9884223081103513
           0.9884223081103514
           0.8650001793912898
           0.8650001793912898 |]

    Assert.Equal<float[]>(expected, trainingPredictions ())

    配列まるごとの完全一致 です。許容誤差を渡していません。 原著の np.dot と F# の Array.sum が、7 要素では同じ順序で足しています。

    LinearSvm は既定値だと原点を外す¶

    ここが F# 側の発見です。

    /// **`numberOfIterations` を明示しないと原点を誤分類する。** 既定のままだと
/// 7 点のうち原点（ラベル 0）だけを 1 と答えた。原点は 6 点のちょうど真ん中で
/// 最も判定が難しい。1000 回に増やすと 7 点すべて正しくなる。

        let model = ctx.BinaryClassification.Trainers.LinearSvm(numberOfIterations = 1000).Fit data

    原点 (0, 0) はラベル 0 で、6 点のちょうど中心にあります。 Python 版 で見たとおり、手書きの予測式でも -0.729 と、他の点（-0.975）より 0 に近い値になります。 7 点のうち最も判定が微妙な点 です。

    ML.NET の LinearSvm は確率的勾配法で解くので、反復が足りないと そこに届きません。scikit-learn の SVC は libsvm の SMO で厳密解に収束させるので、 反復回数を気にする必要がありません。

    「同じ線形 SVM」でも解き方が違えば、既定値の意味も変わります。 係数が一致しないのも同じ理由です。

    [<Fact>]
let ``SVMは7点すべてを正しく分類する`` () =
    // ML.NET の LinearSvm は確率的勾配法で解くので、libsvm の SMO を使う
    // scikit-learn とは **係数が一致しない**。原著の svm.coef_ とは
    // 突き合わせられないので、代わりに分類結果で確かめる
    let predict = fit ()
    let predicted = features () |> Array.map predict

    Assert.Equal<int[]>(y, predicted)

    Kotlin 版（Smile）は係数を公開しないので比べられず、 F# 版（ML.NET）は公開していても値が違うので比べられません。 係数まで一致したのは Python 版だけ でした。

    single への変換¶

    [<CLIMutable>]
type Sample =
    { [<VectorType(9)>]
      Features: single[]
      Label: bool }

    ML.NET は特徴量を single（32 ビット）で扱います。 float（64 ビット）で計算した類似度を渡すときに精度が落ちます。

    類似度の値は 0.006〜1 の範囲なので、single の有効桁 7 桁でも 分類には十分でした。ただ 原著と係数を突き合わせる用途には最初から向きません。 ML.NET は「大きなデータを速く回す」ための設計です。

    まとめ¶

    項目 原著と一致するか
    7 点のデータ 完全一致
    類似度行列 16 桁まで一致
    手書きの予測式の 7 つの値 完全一致（許容誤差なし）
    SVM の係数 9 個 一致しない（解き方が違う。single 精度でもある）
    7 点の分類結果 一致（ただし numberOfIterations を上げる必要がある）
