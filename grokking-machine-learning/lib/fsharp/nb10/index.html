    #10 決定木の境界を図示する（F#）¶

    原著ノートブック: Chapter_09_Decision_Trees/Graphical_example.ipynb

    2 次元の 12 点を決定木で分け、決定境界を見る回です。 原著はジニ・エントロピー・深さ 1 の 3 つのモデルを並べます。

    #09 で書いた自前の CART を拡張して使います。 不純度の指標を差し替えられるようにする のがこの回の設計上の主題で、 判別共用体と高階関数が素直に効きました。

    サンプル実装¶

    項目 内容
    実装 apps/grokking-ml-fsharp-lib/src/GrokkingMlLib/Nb10DecisionTreeBoundary.fs
    テスト apps/grokking-ml-fsharp-lib/tests/GrokkingMlLib.Tests/Nb10DecisionTreeBoundaryTests.fs
    実行 dotnet test

    指標を判別共用体で差し替える¶

    原著の criterion='gini' / 'entropy' を判別共用体にします。

    /// 分割の基準。原著の `criterion='gini'` / `'entropy'` に対応する
type Criterion =
    | Gini
    | Entropy

/// 指標に応じた不純度。[Nb08GiniEntropy] の関数をそのまま使う
let impurityOf criterion (labels: string list) =
    match criterion with
    | Gini -> gini labels
    | Entropy -> entropy labels

    #08 で書いた gini と entropy をそのまま呼べます。 あの回は「決定木の下準備」でしたが、ここで実際に部品として組み込まれました。

    match は網羅性を検査するので、指標を 1 つ足せばコンパイラが impurityOf の修正漏れを教えてくれます。 Python の文字列比較（if criterion == 'gini'）にはこの保護がありません。

    深さの数え方を明示する¶

    Kotlin 版 では Smile が根を深さ 1 と数えており、 scikit-learn とずれていました。自前実装なので こちらで決められます。

/// `maxDepth` は **scikit-learn と同じ数え方** で、根を深さ 0 とする。
/// `maxDepth = 1` なら分割が 1 つ入る。

    scikit-learn に合わせました。深さ 0 も試せます。

    [<Fact>]
let ``深さ0の木は根だけになる`` () =
    // 分割が 1 つも入らない。12 点の半分しか当たらない
    Assert.Empty(splitConditions (fit Gini 0))
    Assert.Equal(0.5, accuracy (fit Gini 0), 12)

    Smile が maxDepth = 1 で返したのと同じ木 です。 Kotlin では意図せずここに落ちましたが、F# では「深さ 0」と書いた結果です。

    深さ 1 は原著と同じ 0.8333 になります。

    [<Fact>]
let ``深さ1の木は12点中10点しか当てられない`` () =
    // 原著と同じ 0.8333。直線 1 本では 2 点を取り違える
    Assert.Equal(10.0 / 12.0, accuracy (fit Gini 1), 12)

    木の同一性を 1 行で確かめる¶

    判別共用体は構造的等価性を持つので、木そのものを比較できます。

    [<Fact>]
let ``ジニとエントロピーは同じ木になる`` () =
    // 分割の候補に同点が無いので、どちらの指標でも同じ順序で選ばれる。
    // #09 では同点があって木の形が変わったのと対照的
    Assert.Equal(fit Gini unlimited, fit Entropy unlimited)

    Assert.Equal(tree, tree) で木全体を比較しています。

    Python では split_conditions() に変換してから比較しました。 Kotlin では DOT 文字列を正規表現で解析してから比較しました。 F# は 木そのものが値 なので、変換を挟まずに済みます。

    分割条件も原著と一致します。

    [<Fact>]
let ``木は scikit-learn と同じ3つの条件で分割する`` () =
    // scikit-learn も x_0 <= 5.0 / x_1 <= 8.0 / x_1 <= 2.5 を選ぶ
    Assert.Equal<(string * float) list>(
        [ "x_0", 5.0; "x_1", 8.0; "x_1", 2.5 ],
        splitConditions (fit Gini unlimited)
    )

    Array.pairwise で境界を探す¶

    決定木の境界は軸に平行なので、格子の横方向で予測が変わる位置は限られます。

    /// 左右で予測が変わる x 座標を集める。
///
/// 決定木の境界は軸に平行なので、変わる位置は分割しきい値の近くに限られる。
let boundaryColumns (grid: DecisionGrid) =
    grid.Predictions
    |> Array.collect (fun row ->
        row
        |> Array.pairwise
        |> Array.indexed
        |> Array.choose (fun (i, (previous, current)) ->
            if previous <> current then Some grid.XValues.[i + 1] else None))
    |> Array.distinct
    |> Array.sort

    Array.pairwise が「隣り合う組」を作り、Array.choose が 「条件を満たすものだけ変換して集める」 を 1 度に行います。

    Python では添字で row[column] != row[column - 1] と比べ、 set に add していました。F# は パイプラインが処理の流れをそのまま表します。

    Array.indexed を挟むのは、pairwise が添字を落とすためです。 i + 1 と書いているのは、pairwise の i 番目の組が 元の配列の i 番目と i+1 番目だからです。

    #09 では Array.pairwise をしきい値の候補作りに使いました。 同じ関数が違う目的で効く のが、細かい標準ライブラリの厚みです。

    [<Fact>]
let ``境界は軸に平行になる`` () =
    // 決定木の境界は長方形の集まりなので、予測が変わる x 座標は
    // 分割しきい値の直後だけに限られる
    let changes = boundaryColumns (decisionGrid (fit Gini unlimited) PlotStep)

    Assert.Equal(1, changes.Length)
    Assert.Equal(5.2, changes.[0], 9)

    3 言語の比較¶

    項目 Python Kotlin F#
    決定木 DecisionTreeClassifier Smile DecisionTree 自前の CART
    指標の指定 文字列 'gini' 列挙型 SplitRule 判別共用体 Criterion
    深さの数え方 根が 0 根が 1 根が 0（自分で決めた）
    木の比較 条件のリストに変換 DOT を正規表現で解析 木そのものを比較
    3 つの分割 一致 一致 一致
    境界（x = 5.2） 一致 一致 一致

    3 言語とも同じ木・同じ境界に到達しました。 #09 が同点のせいでばらついたのとは対照的です。 データに同点が無ければ、決定木の学習は本来決定的なアルゴリズムです。

    この章で F# が効いた場面・効かなかった場面¶

    場面 評価
    指標の差し替え 効いた — 判別共用体 + match の網羅性検査
    #08 の部品の再利用 効いた — gini / entropy をそのまま呼べる
    木の比較 効いた — 構造的等価性で変換なしに比較できる
    境界の探索 効いた — pairwise → indexed → choose のパイプライン
    深さの定義 効いた — 自前実装なので scikit-learn に合わせられる
    ライブラリの恩恵 効かなかった — #09 に続き ML.NET を使えていない
