    第 4 章 過学習・未学習と正則化（Kotlin 版）¶

    原著第 4 章「Optimizing the training process」を Kotlin で実装します。モデルが 単純すぎる（未学習） ときと 複雑すぎる（過学習） ときの見分け方を学び、複雑さを抑える手段として L1 / L2 正則化を実装します。

    サンプル実装は apps/grokking-ml-kotlin/src/main/kotlin/ch04/Regularization.kt です。

    Kotlin Notebook で試す: この章の実験は ch04.ipynb にまとめてあります。実装本体を読み込んで動かすので、値を変えてその場で試せます。

    この章で作るもの¶

    • 多項式モデル y = bias + w1*x + w2*x² + ... + wn*xⁿ
    • データを訓練用とテスト用に分ける trainTestSplit
    • 正則化項を加えた二乗トリック
    • 次数を変えたときの訓練誤差とテスト誤差の比較

    未学習と過学習¶

    状態 訓練誤差 テスト誤差 原因
    未学習（underfitting） 大きい 大きい モデルが単純すぎてデータの傾向を表せない
    ちょうどよい 小さい 小さい —
    過学習（overfitting） とても小さい 大きい モデルが複雑すぎて訓練データを丸暗記した

    訓練誤差だけを見ていては過学習を検出できません。 学習に使わないデータを取り分けておく必要があります。

    モデル¶

    第 3 章の Model（傾きと切片）を任意次数へ拡張します。

    /** 多項式モデル y = bias + w1*x + w2*x^2 + ... + wn*x^n。 */
data class PolynomialModel(val weights: List<Double>, val bias: Double) {
    val degree: Int get() = weights.size

    fun predict(x: Double): Double =
        bias + weights.withIndex().sumOf { (index, w) -> w * x.pow(index + 1) }
}

/** x から [x, x^2, ..., x^degree] を作る。 */
fun polynomialFeatures(x: Double, degree: Int): List<Double> =
    (1..degree).map { power -> x.pow(power) }

    degree を val degree: Int get() = weights.size としているのがポイントです。フィールドではなく 派生プロパティ にすることで、重みの個数と次数が食い違う状態を作れなくしています。

    withIndex() と分解宣言により、重み weights[i] が x^(i+1) に対応することがコード上に現れます。

    訓練データとテストデータの分割¶

    戻り値が 4 つのリストになるため、data class で名前を付けます。

    /** 訓練用とテスト用に分割したデータセット。 */
data class Split(
    val trainFeatures: List<Double>,
    val trainLabels: List<Double>,
    val testFeatures: List<Double>,
    val testLabels: List<Double>,
)

/** データを訓練用とテスト用に分割する。 */
fun trainTestSplit(
    features: List<Double>,
    labels: List<Double>,
    testRatio: Double = 0.3,
    seed: Int = 0,
): Split {
    val indices = features.indices.shuffled(Random(seed))
    val testSize = (features.size * testRatio).toInt()
    val testIndices = indices.take(testSize)
    val trainIndices = indices.drop(testSize)
    return Split(
        trainFeatures = trainIndices.map { features[it] },
        trainLabels = trainIndices.map { labels[it] },
        testFeatures = testIndices.map { features[it] },
        testLabels = testIndices.map { labels[it] },
    )
}

    第 3 章では戻り値に Pair を使いましたが、4 要素になると Quadruple のような型は標準にありませんし、あったとしても first / third では何のことか分かりません。要素が 3 つ以上になったら名前付きの型を作る のが Kotlin の定石です。

    features.indices.shuffled(Random(seed)) は、インデックス列だけをシャッフルします。特徴量とラベルを別々にシャッフルすると対応関係が壊れるため、必ずインデックス経由で並べ替えます。

    正則化¶

    過学習したモデルの重みは、極端に大きな正と負の値が打ち消し合う形になりがちです。そこで 「誤差を減らす」ことに加えて「重みを小さく保つ」ことも目的に加える のが正則化です。

    種類 ペナルティ 勾配 効果
    L1（Lasso） λ Σ|wᵢ| λ · sign(wᵢ) 重みを ほぼ 0 まで押し下げる（スパースになる）
    L2（Ridge） λ Σwᵢ² 2λ · wᵢ 重み全体をなだらかに縮める 
    /** 正則化の種類。 */
enum class Regularization {
    NONE,
    L1,
    L2,
}

/** 正則化項の勾配。重みを 0 に引き戻す向きの力を返す。 */
fun regularizationGradient(weight: Double, kind: Regularization, strength: Double): Double =
    when (kind) {
        Regularization.NONE -> 0.0
        Regularization.L1 -> strength * when {
            weight > 0 -> 1.0
            weight < 0 -> -1.0
            else -> 0.0
        }
        Regularization.L2 -> strength * 2.0 * weight
    }

    enum class に対する when を 式として 使うと、Kotlin コンパイラが網羅性を検査します。else 節を書いていないことに注目してください。将来 ElasticNet を追加したら、この when はコンパイルエラーになり、実装漏れが即座に分かります。else を書いてしまうとこの利点が失われます。

    L1 の勾配は 重みの大きさによらず一定 です。だから小さな重みも同じ力で 0 へ押され、最終的にほぼ 0 に張り付きます。L2 の勾配は重みに比例するため、0 に近づくほど力が弱まり、完全な 0 にはなりません。

    正則化つきの二乗トリック¶

    /** 二乗トリックに正則化項を加えた 1 点分の更新。 */
fun squareTrick(
    model: PolynomialModel,
    x: Double,
    y: Double,
    learningRate: Double,
    kind: Regularization = Regularization.NONE,
    strength: Double = 0.0,
): PolynomialModel {
    val error = y - model.predict(x)
    val features = polynomialFeatures(x, model.degree)
    val weights = model.weights.zip(features) { w, feature ->
        w + learningRate * (error * feature - regularizationGradient(w, kind, strength))
    }
    return PolynomialModel(weights, model.bias + learningRate * error)
}

    zip は第 2 引数に変換関数を取れるため、Pair を作らずに 2 本のリストを同時に畳めます。

    バイアス（切片）には正則化を掛けません。 バイアスはモデルの複雑さではなく、データ全体の位置を表すためです。この設計判断はテストで固定しています。

    @Test
fun `squareTrick はバイアスを正則化しない`() {
    val model = PolynomialModel(listOf(2.0), 1.0)
    val plain = squareTrick(model, x = 3.0, y = 10.0, learningRate = 0.01)
    val regularized = squareTrick(
        model, x = 3.0, y = 10.0, learningRate = 0.01,
        kind = Regularization.L2, strength = 0.1,
    )
    assertEquals(plain.bias, regularized.bias, 1e-9)
}

    デフォルト引数のおかげで、正則化を使わない呼び出しは第 3 章と同じ書き味のままです。

    学習¶

    /** 確率的勾配降下法で多項式回帰を学習する。 */
fun polynomialRegression(
    features: List<Double>,
    labels: List<Double>,
    degree: Int,
    learningRate: Double = 0.01,
    epochs: Int = 20000,
    kind: Regularization = Regularization.NONE,
    strength: Double = 0.0,
    seed: Int = 0,
): PolynomialModel {
    val random = Random(seed)
    var model = PolynomialModel(List(degree) { 0.0 }, 0.0)
    repeat(epochs) {
        val i = random.nextInt(features.size)
        model = squareTrick(model, features[i], labels[i], learningRate, kind, strength)
    }
    return model
}

    第 3 章と違い、初期値をランダムではなく すべて 0 にしています。次数が上がるほど x^n の値が大きくなり、初期値によっては発散するためです。

    デフォルト引数が 5 つ並んでいますが、呼び出し側は名前付き引数で必要なものだけを指定できます。

    polynomialRegression(trainX, trainY, degree = 5, kind = Regularization.L2, strength = 0.01)

    実験¶

    y = 2x + 3 に小さなノイズを乗せた 10 点を、7 点の訓練データと 3 点のテストデータに分けます。

    次数を上げるとどうなるか¶

    次数 訓練 RMSE テスト RMSE 汎化ギャップ
    1 0.1371 0.3324 0.195
    3 0.0546 0.2922 0.238
    5 0.0631 0.2963 0.233

    真のデータは 1 次関数なので、1 次モデルで十分です。次数を上げると訓練誤差は 0.137 → 0.063 と下がる一方、汎化ギャップ（テスト誤差 − 訓練誤差）は 0.195 → 0.233 へ広がりました。訓練データのノイズまで再現してしまったのです。

    テストではこのギャップの拡大を検証しています。

    @Test
fun `高次モデルは過学習する`() {
    val split = trainTestSplit(features, labels, testRatio = 0.3, seed = 0)
    val simple = polynomialRegression(split.trainFeatures, split.trainLabels, degree = 1)
    val complex = polynomialRegression(split.trainFeatures, split.trainLabels, degree = 5)

    // 次数を上げると訓練誤差は下がる
    assertTrue(
        modelRmse(complex, split.trainFeatures, split.trainLabels) <
            modelRmse(simple, split.trainFeatures, split.trainLabels),
    )
    // しかし汎化ギャップ（テスト誤差 - 訓練誤差）は広がる
    val simpleGap = modelRmse(simple, split.testFeatures, split.testLabels) -
        modelRmse(simple, split.trainFeatures, split.trainLabels)
    val complexGap = modelRmse(complex, split.testFeatures, split.testLabels) -
        modelRmse(complex, split.trainFeatures, split.trainLabels)
    assertTrue(complexGap > simpleGap, "simpleGap=$simpleGap complexGap=$complexGap")
}

    テスト誤差そのものの大小ではなくギャップを見ているのは、そのほうが過学習の定義に忠実だからです。テスト誤差の絶対値は分割の運に左右されますが、ギャップの拡大は複雑さを上げれば起きます。

    正則化を掛けるとどうなるか¶

    5 次モデルに λ = 0.01 の正則化を掛けます。

    正則化 訓練 RMSE テスト RMSE 重みの絶対値合計 学習された重み
    なし 0.0631 0.2963 2.753 2.176, -0.267, 0.035, -0.094, -0.181
    L1 0.0814 0.2220 2.377 2.103, -0.199, 0.0001, 0.0002, -0.074
    L2 0.1252 0.1807 2.843 1.745, -0.341, 0.466, 0.121, -0.171

    読み取れることが 3 つあります。

    1. 訓練誤差は悪化し、テスト誤差は改善した。 正則化は訓練データへの当てはまりをわざと諦める代わりに、未知のデータへの当てはまりを買っています。
    2. L1 は 3 次と 4 次の重みをほぼ 0 にした。 「この次数は要らない」とモデル自身が判断したことになります。
    3. L2 は重みを 0 にはしないが、1 次の重みを 2.18 → 1.75 へ縮めた。 全体をなだらかに抑え込んでいます。
    @Test
fun `L1 正則化は不要な重みをほぼ 0 にする`() {
    ...
    assertTrue(weightMagnitude(regularized) < weightMagnitude(plain))
    assertTrue(regularized.weights.count { abs(it) < 5e-3 } >= 2)
    assertEquals(0, plain.weights.count { abs(it) < 5e-3 })
}

    「ちょうど 0」ではなく「5e-3 未満」で検証しているのは、劣勾配による確率的更新では厳密な 0 に張り付かないためです。数学的な理想ではなく 実装が実際に返す値 を基準にしています。

    なお、この表の値は Python 版・F# 版とは微妙に異なります。shuffled と乱数列が言語ごとに違うため、訓練データとテストデータの分かれ方も変わるからです。傾向（次数を上げるとギャップが広がる、L1 が重みを 0 にする、L2 がテスト誤差を改善する）は 3 言語で共通しています。

    テスト¶

    nix develop .#kotlin
cd apps/grokking-ml-kotlin
./gradlew test
# 22 tests passed

    まとめ¶

    • 過学習は訓練誤差だけでは検出できません。学習に使わないデータを必ず取り分けます。
    • 戻り値が 3 要素以上になったら Pair/Triple ではなく data class で名前を付けます。
    • enum class × 式としての when は網羅性を検査してくれます。else を書くとその利点が失われます。
    • L1 は重みをほぼ 0 にして次数を選び、L2 は全体をなだらかに縮めます。
    • バイアスは正則化しません。複雑さではなく位置を表すパラメータだからです。
