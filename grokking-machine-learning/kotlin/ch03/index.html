    第 3 章 線形回帰（Kotlin 版）¶

    原著第 3 章「Drawing a line close to our points」を Kotlin で実装します。部屋数から住宅価格を予測する 1 次元の線形回帰を、simple / absolute / square の 3 つのトリック で学習します。

    サンプル実装は apps/grokking-ml-kotlin/src/main/kotlin/ch03/LinearRegression.kt です。

    Kotlin Notebook で試す: この章の実験は ch03.ipynb にまとめてあります。実装本体を読み込んで動かすので、値を変えてその場で試せます。

    この章で作るもの¶

    • 直線モデル price = slope * rooms + intercept
    • 1 点の情報だけを使ってモデルを少し良くする「トリック」3 種類
    • 誤差を測る RMSE（二乗平均平方根誤差）
    • トリックを繰り返して直線を当てはめる学習ループ

    Kotlin 版では KotlinDL や Smile などの ML ライブラリを使わず、標準ライブラリだけで書きます。

    データセット¶

    原著と同じ 6 件の住宅データです。

    部屋数 価格
    1 155
    2 197
    3 244
    5 356
    6 407
    7 448

    学習の目標は、傾き 50・切片 100 前後という関係をデータだけから見つけることです。

    モデル¶

    モデルは data class で表します。Kotlin の data class は不変フィールドと equals / toString / copy を同時に手に入れられるため、この用途に向いています。

    /** 1 次元の線形モデル price = slope * rooms + intercept。 */
data class Model(val slope: Double, val intercept: Double) {
    fun predict(rooms: Double): Double = slope * rooms + intercept
}

    var を使わず val にしておくことで、「トリックはモデルを書き換えるのではなく、新しいモデルを返す関数である」という設計が型で保証されます。

    トリック 1: 単純なトリック¶

    予測が実際より低ければ直線を上げ、高ければ下げる。動かす量はランダムな微小値です。

    /** 単純なトリック。予測の上下だけを見て、ランダムな微小量だけ動かす。 */
fun simpleTrick(model: Model, rooms: Double, price: Double, random: Random): Model {
    val stepSlope = random.nextDouble() * 0.1
    val stepIntercept = random.nextDouble() * 0.1
    return if (price > model.predict(rooms)) {
        Model(
            slope = if (rooms > 0) model.slope + stepSlope else model.slope - stepSlope,
            intercept = model.intercept + stepIntercept,
        )
    } else {
        Model(
            slope = if (rooms > 0) model.slope - stepSlope else model.slope + stepSlope,
            intercept = model.intercept - stepIntercept,
        )
    }
}

    Kotlin の if は式なので、分岐の結果をそのまま return できます。値を一度変数に入れてから書き換える必要がありません。

    乱数生成器 kotlin.random.Random を引数で受け取っている点も重要です。テストでは Random(0) を渡して挙動を固定します。

    トリック 2: 絶対トリック¶

    動かす量に部屋数を掛けます。誤差の 符号だけ を使うトリックです。

    /** 絶対トリック。誤差の符号のみを使い、特徴量に比例した量だけ動かす。 */
fun absoluteTrick(model: Model, rooms: Double, price: Double, learningRate: Double): Model {
    val sign = if (price > model.predict(rooms)) 1.0 else -1.0
    return Model(
        slope = model.slope + sign * learningRate * rooms,
        intercept = model.intercept + sign * learningRate,
    )
}

    原著は「価格の上下 × 部屋数の正負」で 4 分岐していますが、符号を掛ける形にすれば 1 本の式で済みます。名前付き引数を使うことで、Model(a, b) の 2 引数がどちらの意味なのかがコード上ではっきりします。

    トリック 3: 二乗トリック¶

    動かす量に誤差そのものを掛けます。

    /** 二乗トリック。誤差の大きさに比例した量だけ動かす（二乗誤差の勾配降下法）。 */
fun squareTrick(model: Model, rooms: Double, price: Double, learningRate: Double): Model {
    val error = price - model.predict(rooms)
    return Model(
        slope = model.slope + learningRate * rooms * error,
        intercept = model.intercept + learningRate * error,
    )
}

    これは二乗誤差 (price - predict(rooms))² の勾配降下法に一致します。以降の章で使い続けるのはこのトリックです。

    トリック 動かす量 対応する損失
    simple ランダムな微小値 なし（ヒューリスティック）
    absolute 学習率 × 特徴量 絶対誤差
    square 学習率 × 特徴量 × 誤差 二乗誤差

    誤差を測る¶

    RMSE は zip と sumOf で素直に書けます。

    /** 二乗平均平方根誤差。 */
fun rmse(labels: List<Double>, predictions: List<Double>): Double {
    val total = labels.zip(predictions).sumOf { (label, prediction) ->
        val difference = label - prediction
        difference * difference
    }
    return sqrt(total / labels.size)
}

/** モデルの RMSE。 */
fun modelRmse(model: Model, features: List<Double>, labels: List<Double>): Double =
    rmse(labels, features.map { model.predict(it) })

    sumOf のラムダで (label, prediction) と分解宣言できるのは、zip が Pair を返すからです。total / labels.size は Double / Int ですが、Kotlin は数値演算子をオーバーロードしているため Double に昇格します。

    学習ループ¶

    「ランダムに 1 点選んでトリックを適用する」を繰り返します。

    /** 確率的勾配降下法で線形回帰を学習し、モデルとエポックごとの RMSE を返す。 */
fun linearRegression(
    features: List<Double>,
    labels: List<Double>,
    learningRate: Double = 0.01,
    epochs: Int = 1000,
    seed: Int = 0,
): Pair<Model, List<Double>> {
    val random = Random(seed)
    var model = Model(random.nextDouble(), random.nextDouble())
    val errors = mutableListOf<Double>()
    repeat(epochs) {
        errors += modelRmse(model, features, labels)
        val i = random.nextInt(features.size)
        model = squareTrick(model, features[i], labels[i], learningRate)
    }
    return model to errors
}

    ここだけは var と MutableList を使っています。学習ループは本質的に状態の更新であり、無理に畳み込みへ変換するとかえって読みにくくなるためです。可変性をこの関数の内部に閉じ込め、外へは不変の Model と List を返す ことでバランスを取っています。

    戻り値の Pair は呼び出し側で val (model, errors) = ... と分解できます。

    デフォルト引数のおかげで、linearRegression(features, labels) と呼ぶだけで原著と同じハイパーパラメータになります。

    実行結果¶

    学習率 0.01、1000 エポックで次の結果になりました。

    項目 値
    傾き（slope） 52.4794
    切片（intercept） 88.3304
    学習後の RMSE 7.2976
    初期の RMSE 317.01

    部屋数 4 の家の価格は約 298.25 と予測されます。

    Python 版・F# 版とは値が微妙に異なります。同じシード値でも 言語ごとに乱数アルゴリズムが違う ためです。真の関係（傾き 50、切片 100）にぴったり一致しないのは SGD の性質によるもので、どの言語でも同様です。数値の完全一致ではなく、同じくらいの誤差に収束すること を確認してください。

    テスト¶

    トリックの計算は手で検算できます。

    @Test
fun `squareTrick の移動量は誤差に比例する`() {
    val moved = squareTrick(Model(50.0, 100.0), rooms = 3.0, price = 300.0, learningRate = 0.01)
    assertEquals(51.5, moved.slope, 1e-9)
    assertEquals(100.5, moved.intercept, 1e-9)
}

    予測は 50 × 3 + 100 = 250、誤差は 50 なので、傾きは 50 + 0.01 × 3 × 50 = 51.5 です。浮動小数点の比較には必ず許容誤差（第 3 引数）を渡します。

    学習全体は範囲で検証します。

    @Test
fun `linearRegression は住宅データセットに適合する`() {
    val (model, errors) = linearRegression(features, labels, learningRate = 0.01, epochs = 1000, seed = 0)
    assertTrue(model.slope in 45.0..55.0, "slope=${model.slope}")
    assertTrue(model.intercept in 80.0..120.0, "intercept=${model.intercept}")
    assertTrue(modelRmse(model, features, labels) < 15.0)
    assertEquals(1000, errors.size)
    assertTrue(errors.last() < errors.first())
}

    in 45.0..55.0 という範囲リテラルが読みやすく、失敗時にはメッセージで実際の値がわかります。

    nix develop .#kotlin
cd apps/grokking-ml-kotlin
./gradlew test
# 8 tests passed

    バッククォートで囲んだ日本語のテスト名がそのままレポートに出るため、何を検証しているかが実行結果から読み取れます。

    まとめ¶

    • data class + val で、モデルの更新を「新しい値を返す関数」として表現できます。
    • if が式であること・名前付き引数・デフォルト引数によって、分岐や設定値の多いアルゴリズムを簡潔に書けます。
    • 学習ループの可変状態は関数内部に閉じ込め、外部には不変の値を返します。
    • 乱数はグローバルではなく引数で受け取り、テストではシードを固定します。
