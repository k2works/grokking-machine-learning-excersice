    第 12 章 アンサンブル学習（Kotlin 版）¶

    原著第 12 章「Combining models to maximize results」を Kotlin で実装します。弱い学習器をたくさん集めて、強い学習器を作ります。 集め方には多数決（バギング）と逐次的な重み付け（AdaBoost）の 2 つの流儀があります。

    サンプル実装は apps/grokking-ml-kotlin/src/main/kotlin/ch12/Ensembles.kt です。

    Kotlin Notebook で試す: この章の実験は ch12.ipynb にまとめてあります。実装本体を読み込んで動かすので、値を変えてその場で試せます。

    この章で作るもの¶

    • ブートストラップ標本（復元抽出）
    • 多数決で予測する森（バギング）
    • 重み付き誤り率と学習器の発言権
    • AdaBoost

    前章の実装を部品として使う¶

    本章は 第 9 章の決定木をそのまま部品として使います。

    import ch09.Impurity
import ch09.Leaf
import ch09.Point
import ch09.Tree
import ch09.buildTree
import ch09.giniImpurity
import ch09.majorityLabel

    第 10・11 章では前章の実装を「比較対象」として呼びましたが、本章では 構成部品 です。Tree 型も buildTree 関数も majorityLabel も、書き換えずに再利用できました。

    第 9 章で Impurity を差し替え可能にしておいたことが、ここで効きます。 アンサンブルの関数もすべて impurity を引数で受け取り、そのまま buildTree へ渡すだけで済みます。

    弱学習器としての切り株¶

    第 9 章の決定木で、深さを 1 に制限したものを 決定株（stump） と呼びます。「1 つの質問だけ」しかできない、非常に弱い学習器です。

    本章では次のデータを使います。1 次元上に 3 つの領域が並んでいます。

    x 1 2 3 4 5 6 7 8
    ラベル +1 +1 -1 -1 -1 -1 +1 +1

    1 本の切り株では絶対に解けません。 質問は 1 つだけなので、線を 1 本しか引けないからです。実際の正解率は 0.75 です。

    バギング（多数決）¶

    /** 復元抽出で元と同じ大きさの標本を作る。 */
fun bootstrapSample(
    points: List<Point>,
    labels: List<Int>,
    random: Random,
): Pair<List<Point>, List<Int>> {
    val indices = List(points.size) { random.nextInt(points.size) }
    return indices.map { points[it] } to indices.map { labels[it] }
}

    復元抽出（同じ点を何度でも選べる）が要点です。第 4 章の trainTestSplit と対比すると違いがはっきりします。あちらは shuffled で 重複なく分割 し、こちらは List(n) { random.nextInt(n) } で 重複ありで同じ大きさ を作ります。目的が「評価」と「多様性の確保」で違うためです。

    インデックス列を作ってから両方のリストを引く、という書き方は第 4 章と同じです。特徴量とラベルを別々に抽出すると対応が壊れます。

    /** 多数決で予測する木の集まり。 */
data class Forest(val trees: List<Tree>) {
    fun votes(point: Point): List<Int> = trees.map { it.predict(point) }

    fun predict(point: Point): Int = majorityLabel(votes(point))
}

    第 9 章で書いた majorityLabel をそのまま再利用しています。葉のラベルを決める多数決と、森の予測を決める多数決は同じ操作 です。

    バギングは効かなかった¶

    モデル 正解率
    切り株 1 本 0.75
    切り株 10 本のバギング 0.75

    改善しませんでした。 復元抽出でデータを揺らしても、どの標本でも「x = 2.5 で切る」のが最良 なので、10 本ともほぼ同じ木になります。同じ意見を 10 回聞いても結論は変わりません。

    バギングが効くのは、個々の学習器が「違う間違い方」をするとき です。切り株のように偏りが大きい（表現力が足りない）学習器では、何本集めても偏りは消えません。

    AdaBoost（逐次的な重み付け）¶

    発想を変えて、前の学習器が間違えた点を重点的に見る ように次の学習器を育てます。

    重み付き誤り率¶

    fun weightedError(
    tree: Tree,
    points: List<Point>,
    labels: List<Int>,
    weights: List<Double>,
): Double {
    val total = weights.sum()
    if (total == 0.0) return 0.0
    val wrong = points.indices
        .filter { tree.predict(points[it]) != labels[it] }
        .sumOf { weights[it] }
    return wrong / total
}

    「何個間違えたか」ではなく「どれだけ重い点を間違えたか」 を測ります。

    points.indices.filter { }.sumOf { } という書き方に注目してください。3 本のリスト（点・ラベル・重み）を同時に走査する必要があるため、zip を 2 回重ねるよりインデックス経由のほうが読みやすくなります。zip は 2 本までという制約が、ここで現れます。

    @Test
fun `weightedError は個数ではなく重みを数える`() {
    val tree = Leaf(1)
    val sample = listOf(listOf(0.0), listOf(1.0), listOf(2.0))
    val sampleLabels = listOf(1, 1, -1)
    assertEquals(0.8, weightedError(tree, sample, sampleLabels, listOf(0.1, 0.1, 0.8)), 1e-9)
    assertEquals(0.1, weightedError(tree, sample, sampleLabels, listOf(0.45, 0.45, 0.1)), 1e-9)
}

    同じ木・同じデータでも、重み次第で誤り率が 0.8 にも 0.1 にもなります。「今は何が重要か」を重みが表します。

    発言権¶

    fun learnerWeight(error: Double): Double {
    val epsilon = 1e-10
    val clamped = min(max(error, epsilon), 1.0 - epsilon)
    return 0.5 * ln((1.0 - clamped) / clamped)
}
    誤り率 発言権 意味
    0.05 1.47 よく当たるので強く聞く
    0.5 0.0 当てずっぽうなので無視
    0.7 -0.42 逆張りすれば役立つ

    誤り率 0.5 で発言権がちょうど 0 になる のが、この式の美しさです。第 7 章で AUC が 0.5 でランダムを意味したのと同じ構図です。

    クランプ（epsilon）が必要なのは、誤り率 0 のとき ln(1/0) が無限大になるためです。第 6 章の対数損失、第 8 章のナイーブベイズに続く 3 度目の同じ対処です。min(max(...)) という書き方も 3 度目です。

    学習ループ¶

    fun trainAdaBoost(
    points: List<Point>,
    labels: List<Int>,
    rounds: Int = 5,
    maxDepth: Int = 1,
    impurity: Impurity = giniImpurity,
): AdaBoost {
    var weights = List(points.size) { 1.0 / points.size }
    val learners = mutableListOf<WeightedTree>()
    repeat(rounds) {
        val tree = buildTreeWithWeights(points, labels, weights, maxDepth, impurity)
        val error = weightedError(tree, points, labels, weights)
        // 当てずっぽう以下の学習器は採用しない
        if (error < 0.5) {
            val alpha = learnerWeight(error)
            learners += WeightedTree(tree, alpha)
            val updated = points.indices.map { i ->
                weights[i] * exp(-alpha * labels[i] * tree.predict(points[i]))
            }
            val total = updated.sum()
            weights = updated.map { it / total }
        }
    }
    return AdaBoost(learners)
}

    labels[i] * tree.predict(points[i]) は、当たれば +1、外れれば -1 です（ラベルが +1 / -1 だから成立します。第 11 章と同じ理由でこの表現を選びました）。

    • 当たった点: exp(-alpha) 倍 → 重みが 減る
    • 外れた点: exp(+alpha) 倍 → 重みが 増える

    var weights を再代入していますが、代入するのは常に 新しい不変リスト です。要素を書き換えているわけではありません。第 3 章の学習ループと同じ方針で、可変性を関数内部に閉じ込めています。

    実行結果¶

    モデル 正解率
    切り株 1 本 0.75
    バギング（切り株 10 本） 0.75
    AdaBoost（切り株 10 本） 1.00

    同じ弱学習器を同じ本数使って、結果が分かれました。 束ね方の違いだけです。

    学習された切り株を見ると、動きが分かります。

    ラウンド 発言権 分割
    1 0.5493 x < 2.5 なら +1
    2 0.8047 x < 6.5 なら -1
    3 0.6931 （全部 +1 の葉）
    4 0.7332 x < 2.5 なら +1

    1 本目は左端、2 本目は右端に注目しました。 1 本目が右端の x = 7, 8 を外したので、その重みが上がり、2 本目が拾いに行ったのです。

    重み付き投票の結果、x = 7, 8 では「1 本目は -1、2 本目は +1」となり、発言権の大きい 2 本目が勝ちます。役割分担が自然に生まれました。

    これらの値は Python 版・F# 版と完全に一致します。AdaBoost には乱数がない ためです（バギングには乱数がありますが、結果は同じ 0.75 でした）。

    多重定義された accuracy¶

    fun accuracy(model: Forest, points: List<Point>, labels: List<Int>): Double = ...
fun accuracy(model: AdaBoost, points: List<Point>, labels: List<Int>): Double = ...

    Forest と AdaBoost に共通のインターフェースを持たせず、関数を多重定義 しました。predict を持つインターフェースを作ることもできますが、2 つのモデルの性質（多数決と重み付き投票）は根本的に違うので、あえて別扱いにしています。

    Kotlin は引数の型で解決するため、呼び出し側は accuracy(forest, ...) と accuracy(boosted, ...) を区別なく書けます。Python 版では Forest | AdaBoost という和型で 1 つの関数にしましたが、こちらのほうが型ごとの意図が明確です。

    バギングと AdaBoost の使い分け¶

    バギング AdaBoost
    学習器の作り方 並列（互いに独立） 逐次（前の結果に依存）
    データの扱い 復元抽出でばらつかせる 重みで注目点を変える
    減らせるもの 分散（過学習） 偏り（表現力不足）
    向く弱学習器 深い木（分散が大きい） 浅い木（偏りが大きい）
    並列化 できる できない

    本章のデータは「切り株では表現力が足りない」問題だったので、AdaBoost が勝ちました。どちらが優れているかではなく、何を減らしたいかで選びます。

    まとめ¶

    • 第 9 章の決定木を、書き換えずに部品として再利用できました。Impurity を差し替え可能にしておいた設計が効いています。
    • 復元抽出は List(n) { random.nextInt(n) }。第 4 章の shuffled による分割とは目的が違います。
    • 3 本のリストを同時に走査するときは、zip の重ねがけよりインデックス経由が読みやすくなります。
    • var に再代入していても、代入するのが新しい不変リストなら安全です。
    • 型ごとに関数を多重定義すると、和型より意図が明確になることがあります。
