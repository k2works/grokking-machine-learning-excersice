    第 6 章 ロジスティック回帰（F# 版）¶

    原著第 6 章「A continuous approach to splitting points」を F# で実装します。第 5 章のパーセプトロンは「0 か 1 か」という硬い予測でした。本章ではシグモイド関数を挟み、「0 から 1 の確率」 という連続的な予測に置き換えます。

    サンプル実装は apps/grokking-ml-fsharp/src/GrokkingMl/Ch06LogisticRegression.fs です。

    Polyglot Notebook で試す: この章の実験は ch06.ipynb にまとめてあります。実装本体を読み込んで動かすので、値を変えてその場で試せます。

    この章で作るもの¶

    • シグモイド関数
    • 確率を返すロジスティック分類器
    • 対数損失（ログロス）
    • すべての点を動かすロジスティックトリック

    なぜ確率が要るのか¶

    パーセプトロンには 2 つの弱点がありました。

    1. どれくらい確信しているか分からない。 境界線ぎりぎりの点も、遠く離れた点も、同じ「1」です。
    2. 正しく分類できた点からは何も学べない。 境界線の 1 ミリ内側にいる危うい点も、更新の対象外です。

    ロジスティック回帰は、予測を確率にすることで両方を解きます。

    シグモイド関数¶

    /// シグモイド関数。実数を 0 から 1 の範囲へ押し込む。
let sigmoid (x: float) =
    if x >= 0.0 then
        1.0 / (1.0 + exp (-x))
    else
        // x が大きな負の数のとき exp(-x) が溢れるため、数学的に等価な式へ切り替える
        let exponential = exp x
        exponential / (1.0 + exponential)

    教科書の定義は 1 / (1 + exp(-x)) の 1 行です。.NET の exp は例外を投げずに infinity を返すため素朴な実装でも落ちはしませんが、途中で infinity を経由する計算は避けるべきです。

    負の入力では、分子分母に exp(x) を掛けた等価な式 exp(x) / (1 + exp(x)) へ切り替えます。数学的に同じ式でも、浮動小数点の上では安全な形と危険な形があります。

    exp や log が System.Math 経由ではなく そのまま関数として使える のが F# の書き味です。Math.Exp(-x) ではなく exp (-x) と書けるため、数式との距離が近くなります。

    シグモイドの性質はテストで押さえます。

    [<Fact>]
let ``sigmoid の値域は 0 から 1`` () =
    for x in [ -1000.0; -10.0; 0.0; 10.0; 1000.0 ] do
        Assert.InRange(sigmoid x, 0.0, 1.0)

    確率として使う以上、値域を外れないことは仕様です。 対称性（sigmoid x + sigmoid -x = 1）も同様に固定しています。

    モデル¶

    /// ロジスティック分類器。予測は 0 から 1 の確率。
type LogisticClassifier =
    { Weights: float list
      Bias: float }

/// 重み付き和。
let score (model: LogisticClassifier) (point: Point) =
    List.map2 (*) model.Weights point
    |> List.sum
    |> (+) model.Bias

/// 0 から 1 の確率としての予測。
let predictProbability (model: LogisticClassifier) (point: Point) = sigmoid (score model point)

/// 閾値による 0 / 1 の分類。
let predictWith (threshold: float) (model: LogisticClassifier) (point: Point) =
    if predictProbability model point >= threshold then 1 else 0

/// 閾値 0.5 による分類。
let predict (model: LogisticClassifier) (point: Point) = predictWith 0.5 model point

    第 5 章のパーセプトロンとの違いは predictProbability が挟まったことだけです。score の計算はまったく同じです。

    閾値の扱いに注目してください。F# にはデフォルト引数がないため、Python や Kotlin のように predict(point, threshold = 0.8) とは書けません。代わりに 一般形（predictWith）を定義し、既定値を固定した特殊形（predict）を部分適用で作ります。

    let predict (model: LogisticClassifier) (point: Point) = predictWith 0.5 model point

    呼び出し側は用途に応じて選べます。

    predict model point            // 既定の 0.5
predictWith 0.8 model point    // 厳しめの判定

    デフォルト引数のある言語では 1 つの関数で済むところが、F# では 2 つの名前になります。そのぶん「既定はこれ」という決定が関数定義として明示される という利点もあります。

    この点の確率は 0.73 です。既定の 0.5 では「楽しい」と判定されますが、0.8 を要求すると「悲しい」になります。モデルを再学習せずに判定の厳しさだけを変えられる、という性質は第 7 章の主題につながります。

    対数損失¶

    第 5 章のパーセプトロン誤差には、全点が境界線上にある退化状態を 0 と評価する欠陥がありました。対数損失にはその問題がありません。

    /// 1 点分の対数損失。予測確率が正解から離れるほど大きくなる。
let logLoss (model: LogisticClassifier) (point: Point) (label: int) =
    // log(0) を避けるためにごくわずかに内側へ丸める
    let epsilon = 1e-15

    let probability =
        predictProbability model point
        |> max epsilon
        |> min (1.0 - epsilon)

    if label = 1 then
        -log probability
    else
        -log (1.0 - probability)

    |> max epsilon |> min (1.0 - epsilon) というパイプラインで範囲へのクランプを表しています。max と min を部分適用してパイプでつなぐと、「下限で切って上限で切る」という手順がそのまま並びます。 Python や Kotlin では min(max(x, lo), hi) と入れ子になり、内側から読む必要があります。

    クランプが必要なのは、log 0.0 が -infinity になるためです。シグモイドは数学的には 0 にも 1 にもなりませんが、浮動小数点では sigmoid -1000.0 = 0.0 になります。数学的に起きないことが実装では起きます。

    損失の値は次のようになります。

    正解 予測確率 損失 意味
    1 0.99 0.01 自信を持って正解
    1 0.51 0.67 当たってはいるが自信がない
    1 0.50 0.69 完全に五分五分
    1 0.01 4.61 自信を持って間違い

    当たったかどうかではなく、どれくらいの確信で当たったかを測ります。

    平均を取る側は部分適用で簡潔になります。

    let meanLogLoss (model: LogisticClassifier) (points: Point list) (labels: int list) =
    List.map2 (logLoss model) points labels |> List.average

    logLoss model でモデルを固定した Point -> int -> float の関数ができ、それを 2 本のリストに同時適用します。ラムダは不要です。

    ロジスティックトリック¶

    /// ロジスティックトリック。すべての点を、確率の外れ具合に比例して動かす。
let logisticTrick (learningRate: float) (model: LogisticClassifier) (point: Point) (label: int) =
    let error = float label - predictProbability model point

    { Weights = List.map2 (fun w x -> w + learningRate * error * x) model.Weights point
      Bias = model.Bias + learningRate * error }

    第 5 章と見比べてください。式は同じ形で、predict（0 か 1）が predictProbability（0 から 1）に変わっただけです。

    パーセプトロン ロジスティック
    error の値 -1, 0, +1 の 3 通り -1 から +1 の連続値
    正しい点 動かない（if の一方の腕） わずかに動く
    更新量 一定 確信のなさに比例

    第 5 章では if error = 0.0 then model else { ... } と分岐していましたが、本章では分岐そのものが消えました。すべての点が学習に寄与します。 確率が 0.999 の点はほとんど動かず、0.51 の点は大きく動く。「動く／動かない」という離散的な判断が、「どれだけ動くか」という連続量に置き換わりました。

    浮動小数点を 0 と厳密比較する分岐が消えたのは、実装としても健全です。

    [<Fact>]
let ``logisticTrick は正しく分類できた点でも動く`` () =
    // 予測は 1（正解）だが、確率は 0.73 なのでまだ動く
    let moved = logisticTrick 0.1 model [ 1.0; 2.0 ] 1
    Assert.NotEqual(model, moved)
    Assert.True(moved.Weights[0] > model.Weights[0])

    第 5 章では Assert.Equal(model, ...) で「動かないこと」を、本章では Assert.NotEqual で「動くこと」を検証しています。同じ形のテストで逆の性質を固定しているのが 2 つの章の対比そのものです。 どちらもレコードの構造的等価性があるから 1 行で書けます。

    なお、この更新式は対数損失をスコアで微分した結果と一致します。二乗トリックが二乗誤差の勾配降下法だったのと同じ関係です。

    実行結果¶

    第 5 章と同じ「悲しい／楽しい」データを使います。学習率 0.1、1000 エポックで次の結果になりました。

    項目 値
    aack の重み 2.1482
    beep の重み 1.5443
    バイアス -5.5948
    正解率 1.0
    初期の平均対数損失 0.6931
    最終の平均対数損失 0.1600

    第 5 章のパーセプトロンでは重みが 0.04 程度でしたが、本章では 2.15 まで大きくなりました。確率を使うと重みの絶対値に意味が生まれる ためです。重みを 2 倍にしても境界線の位置は変わりませんが、確率がより 0 と 1 に寄ります。つまり 重みの大きさが「確信の強さ」を表します。

    第 5 章では 3 言語が別々の境界線に到達しましたが、本章では 3 言語ともほぼ同じ重み（2.0〜2.3、1.5〜1.6）に収束しました。損失関数に最小点がひとつしかないため、どの経路を通っても同じ場所へ向かいます。 第 5 章の「正しい境界線が無数にある」状態との違いです。

    初期の損失 0.6931 は -log 0.5 です。全パラメータが 0 のとき、すべての予測は確率 0.5 になります。第 5 章のパーセプトロン誤差が初期状態で 0 だったのと対照的に、対数損失は「五分五分」を正しく「何も分かっていない状態」と評価します。

    [<Fact>]
let ``logisticRegression はデータを分離する`` () =
    let trained, losses = logisticRegression 0.1 1000 0 points labels
    Assert.Equal(1.0, accuracy trained points labels, 6)
    Assert.Equal(1000, List.length losses)
    // パーセプトロン誤差と違い、対数損失は初期状態でも 0 にならない
    Assert.Equal(-log 0.5, List.head losses, 6)
    Assert.True(List.last losses < List.head losses)

    第 5 章では書けなかった「損失が減った」という検証が、本章では素直に書けます。損失関数を替えたことで、第 3 章と同じ形のテストが戻ってきました。

    学習後のモデルは (3, 2) に 0.9809、(1, 0) に 0.0309 という確率を与えます。単に分類できているだけでなく、どちらがより確からしいかまで答えられる ようになりました。

    まとめ¶

    • シグモイドは教科書の 1 行をそのまま書くと infinity を経由します。等価な式へ切り替えます。
    • exp / log が関数としてそのまま使えるため、数式との距離が近くなります。
    • デフォルト引数の代わりに、一般形（predictWith）と既定値を固定した特殊形（predict）を用意します。
    • クランプは |> max lo |> min hi と書くと、手順がそのまま並びます。
    • 対数損失は「当たったか」ではなく「どれくらいの確信で当たったか」を測ります。
