    第 8 章 ナイーブベイズ（Python 版）¶

    原著第 8 章「Using probability to its maximum」を Python で実装します。第 5〜7 章の分類器は境界線を 学習 しました。本章の分類器は 数え上げるだけ です。それでいて実用的な精度が出ます。

    サンプル実装は apps/grokking-ml-python/src/grokking_ml/ch08_naive_bayes.py です。

    Jupyter Notebook で試す: この章の実験は ch08.ipynb にまとめてあります。実装本体を読み込んで動かすので、値を変えてその場で試せます。

    この章で作るもの¶

    • 文書を単語集合に分解するトークナイザ
    • 単語ごとのクラス別出現回数を数える学習
    • ラプラス平滑化つきの単語スパム確率
    • 対数空間での文書スパム確率の合成

    学習しない学習器¶

    これまでの章では、勾配降下法で少しずつ重みを動かしてきました。ナイーブベイズにその過程はありません。

    第 5〜6 章 第 8 章
    学習 エポックを回して重みを更新 数えるだけ（1 回のパス）
    ハイパーパラメータ 学習率、エポック数、シード 平滑化の強さのみ
    乱数 使う 使わない
    結果の再現性 シード依存 常に同一

    そのため本章の実装は、3 言語すべてで数値が完全に一致します。

    ベイズの定理と「ナイーブ」な仮定¶

    知りたいのは「この文書がスパムである確率」です。ベイズの定理により、これは「スパムの文書にこの単語列が現れる確率」から計算できます。

    ただし単語列全体の出現確率を数えるのは不可能です。「lottery winning sale」という並びが訓練データに何回現れたか、を数えても、ほとんどの並びは 0 回です。

    そこで 「単語は互いに独立に出現する」 と仮定します。これがナイーブ（素朴）と呼ばれる所以です。実際の文章で単語は独立ではありません（「machine」の後には「learning」が来やすい）。明らかに間違った仮定ですが、それでも実用的に機能します。

    この仮定のおかげで、単語ごとの確率を掛け合わせるだけで済みます。

    トークナイズと文書の表現¶

    def tokenize(text: str) -> list[str]:
    """文章を小文字の単語列に分解する。"""
    return text.lower().split()

    学習側では、単語を 集合 に変換します。

        for document, label in zip(documents, labels):
        # 同じ単語が何度出ても 1 文書につき 1 回だけ数える（ベルヌーイ型）
        words = set(tokenize(document))

    「spam spam spam」という文書で spam を 3 回数えるか 1 回数えるかは、モデルの種類の違いです。回数を数えるのが多項分布型、出現の有無だけを見るのがベルヌーイ型です。ここではベルヌーイ型を選びました。「1 通のメールに lottery が 3 回出る」ことより「lottery を含むメールか否か」のほうが、スパム判定では素直だからです。

    この選択はテストで固定します。

    def test_train_counts_each_word_once_per_document():
    # 同じ単語が 2 回出ても 1 文書として 1 回だけ数える
    model = train(["spam spam spam"], [1])
    assert model.spam_word_counts["spam"] == 1

    モデル¶

    @dataclass(frozen=True)
class NaiveBayesClassifier:
    """ナイーブベイズ分類器。単語ごとの出現回数からスパム確率を求める。"""

    spam_word_counts: Counter[str] = field(default_factory=Counter)
    ham_word_counts: Counter[str] = field(default_factory=Counter)
    spam_documents: int = 0
    ham_documents: int = 0

    @property
    def total_documents(self) -> int:
        return self.spam_documents + self.ham_documents

    @property
    def vocabulary(self) -> set[str]:
        return set(self.spam_word_counts) | set(self.ham_word_counts)

    Counter は dict のサブクラスで、存在しないキーに 0 を返します。model.spam_word_counts["unseen"] が KeyError ではなく 0 になるので、後述の確率計算が素直に書けます。

    field(default_factory=Counter) が必要なのは、可変オブジェクトを既定値にできないためです（すべてのインスタンスで同じ Counter を共有してしまいます）。frozen=True は再代入を禁じますが、Counter の中身は変更可能なままです。第 4 章の tuple を選んだ判断と同じ問題 ですが、ここでは辞書型が必要なので、生成後に変更しない規律で対応しています。

    学習¶

    def train(documents: Sequence[str], labels: Sequence[int]) -> NaiveBayesClassifier:
    """文書とラベル（1 がスパム）から分類器を学習する。"""
    spam_word_counts: Counter[str] = Counter()
    ham_word_counts: Counter[str] = Counter()
    spam_documents = 0
    ham_documents = 0
    for document, label in zip(documents, labels):
        words = set(tokenize(document))
        if label == 1:
            spam_word_counts.update(words)
            spam_documents += 1
        else:
            ham_word_counts.update(words)
            ham_documents += 1
    return NaiveBayesClassifier(...)

    Counter.update(集合) は、集合の各要素の数を 1 ずつ増やします。ループを 1 回まわすだけで学習は終わりです。

    ラプラス平滑化¶

    ある単語がスパム文書に 3 回、通常文書に 0 回現れたとします。素朴に計算すると、その単語のスパム確率は 3 / (3 + 0) = 1.0 です。

    これは危険です。確率 1.0 は「絶対にスパム」を意味し、他のどんな単語が来ても覆せません。0 を掛ければすべてが 0 になるのと同じで、たった 1 つの単語が判定を支配してしまいます。

    そこで、すべてのカウントに 1 を足します。

    def word_spam_probability(
    model: NaiveBayesClassifier,
    word: str,
    smoothing: float = 1.0,
) -> float:
    """その単語を含む文書がスパムである確率。ラプラス平滑化つき。"""
    spam = model.spam_word_counts[word] + smoothing
    ham = model.ham_word_counts[word] + smoothing
    return spam / (spam + ham)

    def test_word_spam_probability_uses_laplace_smoothing():
    model = train(DOCUMENTS, LABELS)
    # lottery はスパム 3 件、ハム 0 件。平滑化なしなら 1.0 になってしまう
    assert model.spam_word_counts["lottery"] == 3
    assert model.ham_word_counts["lottery"] == 0
    # (3+1) / ((3+1) + (0+1)) = 0.8
    assert word_spam_probability(model, "lottery") == pytest.approx(0.8)

    「まだ見ていないだけかもしれない」という保険を各カテゴリに 1 件分ずつ入れる、と考えると腑に落ちます。確率を両端（0 と 1）から引き離すのが平滑化の役目です。

    def test_smoothing_keeps_probabilities_away_from_the_extremes():
    model = train(DOCUMENTS, LABELS)
    for word in model.vocabulary:
        probability = word_spam_probability(model, word)
        assert 0.0 < probability < 1.0

    未知語はスパム 0 件・通常 0 件なので、平滑化後はちょうど 0.5 になります。「何も知らない単語は判定に寄与しない」 という望ましい性質が自然に出ます。

    対数空間で合成する¶

    各単語の確率を掛け合わせるのが素直な実装ですが、そのまま書くと壊れます。0.1 のような値を 100 語分掛けると 1e-100 になり、浮動小数点の下限に触れてアンダーフローします。

    そこで対数を取り、掛け算を足し算に変えます。

    def predict_probability(
    model: NaiveBayesClassifier,
    document: str,
    smoothing: float = 1.0,
) -> float:
    """文書がスパムである確率。対数空間で計算する。"""
    if model.total_documents == 0:
        return 0.0
    words = set(tokenize(document))
    log_spam = math.log(_safe(prior_spam_probability(model)))
    log_ham = math.log(_safe(1.0 - prior_spam_probability(model)))
    for word in words:
        if word not in model.vocabulary:
            # 学習時に見ていない単語は何も語らないので無視する
            continue
        spam_given_word = word_spam_probability(model, word, smoothing)
        log_spam += math.log(_safe(spam_given_word))
        log_ham += math.log(_safe(1.0 - spam_given_word))
    # log の差から確率へ戻す（シグモイドと同じ形）
    return 1.0 / (1.0 + math.exp(min(max(log_ham - log_spam, -700.0), 700.0)))

    最後の 1 行に注目してください。1 / (1 + exp(差)) は 第 6 章のシグモイドとまったく同じ形 です。ロジスティック回帰では重み付き和をシグモイドに通しました。ここでは対数確率の差を通しています。まったく違う道筋で同じ関数に辿り着きます。

    min(max(..., -700.0), 700.0) のクランプは、第 6 章と同じ理由（exp のオーバーフロー）です。exp(710) は Python では OverflowError になります。第 6 章では入力側で分岐しましたが、ここでは指数の範囲を直接制限しています。

    未知語をスキップしているのは意図的な設計です。平滑化により未知語の確率は 0.5 なので、含めても log(0.5) が両方に等しく足され、差は変わりません。結果は同じですが、明示的にスキップすることで意図が読み取れます。

    def test_unknown_words_do_not_change_the_prediction():
    model = train(DOCUMENTS, LABELS)
    known = predict_probability(model, "lottery")
    with_unknown = predict_probability(model, "lottery zzzz qqqq")
    assert with_unknown == pytest.approx(known)

    空の文書は、単語による更新が 1 つも起きないので 事前確率そのもの を返します。これも仕様としてテストしました。

    def test_empty_document_returns_the_prior():
    model = train(DOCUMENTS, LABELS)
    assert predict_probability(model, "") == pytest.approx(prior_spam_probability(model))

    文書ごとのスパム確率¶

    文書 確率
    （空） 0.3750
    project deadline 0.0909
    sale today 0.2308
    lottery 0.7059

    スパム語が重なるほど確率が上がります。これは掛け算の効果です。

    def test_stacking_spam_words_increases_confidence():
    model = train(DOCUMENTS, LABELS)
    one_word = predict_probability(model, "lottery")
    two_words = predict_probability(model, "lottery winning")
    assert two_words > one_word

    「lottery」単独では 0.71 ですが、「winning」が加わると 0.88 になります。単語の証拠が積み重なる のがナイーブベイズの動きです。

    空の文書の 0.375 は事前確率（3/8）と一致します。

    まとめ¶

    • ナイーブベイズに学習ループはありません。数え上げの 1 パスで終わります。
    • 「単語は独立」という明らかに間違った仮定が、計算を掛け算に単純化します。
    • 平滑化がないと、1 つの単語の確率 1.0 が判定を支配します。すべてのカウントに 1 を足して防ぎます。
    • 確率の積は対数の和に変換します。そうしないとアンダーフローします。
    • 最後の 1 / (1 + exp(差)) は第 6 章のシグモイドと同じ形です。別の道筋で同じ関数に辿り着きます。
