    第 9 章 決定木（Kotlin 版）¶

    原著第 9 章「Splitting data by asking questions」を Kotlin で実装します。これまでの分類器はすべて 直線 でデータを分けてきました。決定木は「質問を積み重ねる」ことで、直線では表せない領域を切り出します。

    サンプル実装は apps/grokking-ml-kotlin/src/main/kotlin/ch09/DecisionTrees.kt です。

    Kotlin Notebook で試す: この章の実験は ch09.ipynb にまとめてあります。実装本体を読み込んで動かすので、値を変えてその場で試せます。

    この章で作るもの¶

    • ジニ不純度とエントロピー（分割の良さを測る 2 つの指標）
    • 情報利得
    • 分割候補の列挙と最良分割の選択
    • 再帰的な木の構築

    これまでとの違い¶

    第 5〜6 章 第 8 章 第 9 章
    モデル 重みベクトル 単語ごとの確率表 木構造
    学習 勾配降下法 数え上げ 貪欲な再帰探索
    決定境界 直線 （確率の等高線） 軸に平行な階段状
    人間が読めるか 重みの大小だけ 単語ごとの確率 「もし〜なら」で説明できる

    決定木の最大の利点は 説明可能性 です。「20 歳未満だから推薦した」と言えます。

    データセット¶

    原著と同じアプリ推薦データを使います。特徴量は性別（0=女性、1=男性）と年齢、ラベルは 1 が「推薦する」です。

    性別 年齢 推薦
    1 15 1
    0 25 0
    0 32 0
    1 35 0
    0 12 1
    1 14 1
    1 55 0
    0 40 0

    「若い人には推薦する」という規則が見えます。性別は関係ありません。 決定木がそれを自力で見つけられるかが本章の焦点です。

    不純度を関数型として扱う¶

    /** 不純度の測り方。 */
typealias Impurity = (List<Int>) -> Double

/** ジニ不純度。ランダムに 2 つ選んだとき、ラベルが食い違う確率。 */
val giniImpurity: Impurity = { labels ->
    if (labels.isEmpty()) {
        0.0
    } else {
        val total = labels.size.toDouble()
        1.0 - labels.groupingBy { it }.eachCount().values.sumOf { count ->
            val share = count / total
            share * share
        }
    }
}

/** エントロピー。ラベルの散らばりを情報量で測る。 */
val entropy: Impurity = { labels ->
    if (labels.isEmpty()) {
        0.0
    } else {
        val total = labels.size.toDouble()
        -labels.groupingBy { it }.eachCount().values.sumOf { count ->
            val share = count / total
            share * (ln(share) / ln(2.0))
        }
    }
}

    fun ではなく val として関数型の値で定義しています。 typealias Impurity = (List<Int>) -> Double に適合する値なので、そのまま引数として渡せます。

    fun giniImpurity(labels: List<Int>): Double と定義しても ::giniImpurity で関数参照を作れますが、「これは差し替え可能な戦略である」という意図は val ...: Impurity のほうが明確です。型注釈が設計の宣言になります。

    Kotlin には log2 が kotlin.math にありますが、ここでは ln(share) / ln(2.0) と底の変換を明示しました。3 言語で同じ式にするためです（F# には log2 がありません）。

    集合 ジニ不純度 エントロピー
    [1, 1, 1]（純粋） 0.0 0.0
    [1, 1, 1, 0]（偏り） 0.375 0.811
    [1, 1, 0, 0]（均等） 0.5 1.0
    [0, 1, 2, 3]（4 クラス均等） 0.75 2.0

    ジニ不純度は「ランダムに 2 つ選んだとき、ラベルが食い違う確率」、エントロピーは「ラベルを 1 つ伝えるのに必要なビット数」 と読めます。

    分割とその適用¶

    /** 1 つの質問による分割。「feature 番目の特徴量が threshold 未満か」を問う。 */
data class Split(val feature: Int, val threshold: Double) {
    /** 左（true）へ進むか。 */
    fun matches(point: Point): Boolean = point[feature] < threshold
}

/** 分割で振り分けられた左右のデータ。 */
data class Partition(
    val leftPoints: List<Point>,
    val leftLabels: List<Int>,
    val rightPoints: List<Point>,
    val rightLabels: List<Int>,
)

/** 分割を適用して左右に振り分ける。 */
fun applySplit(points: List<Point>, labels: List<Int>, split: Split): Partition {
    val (left, right) = points.zip(labels).partition { (point, _) -> split.matches(point) }
    return Partition(
        leftPoints = left.map { it.first },
        leftLabels = left.map { it.second },
        rightPoints = right.map { it.first },
        rightLabels = right.map { it.second },
    )
}

    partition { } が標準にあるおかげで、振り分けが 1 行で済みます。Python 版では for ループで 4 本のリストに append していた箇所です。

    戻り値は 4 本のリストなので、第 4 章の Split（訓練／テスト分割）と同じく data class で名前を付けました。Quadruple は存在しませんし、あっても first/third では意味が伝わりません。

    なお、第 4 章のデータ分割型も本章の質問型も「Split」と呼びたくなりますが、名前が衝突します。本章では質問を Split、振り分け結果を Partition としました。同じ語が章をまたいで別の意味を持つときは、パッケージが分かれていても混乱の元になります。

    候補の列挙¶

    /** 試す価値のある分割の候補。隣り合う値の中点を閾値にする。 */
fun candidateSplits(points: List<Point>): List<Split> =
    points.first().indices.flatMap { feature ->
        points.map { it[feature] }.distinct().sorted()
            .zipWithNext { low, high -> Split(feature, (low + high) / 2) }
    }

    flatMap と zipWithNext の組み合わせで、二重ループが式 1 つになりました。第 7 章の台形則と同じく、zipWithNext が変換まで同時に行うのが効いています。

    閾値に中点を使うのは、どちらの点にも寄らない位置を選ぶため です。年齢 14 と 15 の間なら 14.5 を試します。

    最良分割の探索¶

    /** 情報利得がもっとも大きい分割。改善しないなら null。 */
fun bestSplit(
    points: List<Point>,
    labels: List<Int>,
    impurity: Impurity = giniImpurity,
): Pair<Split, Double>? =
    candidateSplits(points)
        .mapNotNull { split ->
            val partition = applySplit(points, labels, split)
            if (partition.leftLabels.isEmpty() || partition.rightLabels.isEmpty()) {
                null
            } else {
                split to informationGain(labels, partition.leftLabels, partition.rightLabels, impurity)
            }
        }
        .maxByOrNull { it.second }
        ?.takeIf { it.second > 0.0 }

    mapNotNull → maxByOrNull → takeIf という 3 段のパイプライン で、「候補を評価し、最大を取り、条件を満たさなければ捨てる」が宣言的に書けます。

    • mapNotNull: 片側が空になる分割を null で捨てる
    • maxByOrNull: 候補が 1 つもなければ null
    • ?.takeIf { }: 利得が 0 以下なら null に落とす

    戻り値の Pair<Split, Double>? が 「良い分割が存在しないかもしれない」ことを型で表現します。 Kotlin の null 安全性により、呼び出し側は ?: や let で必ず不在のケースを扱うことになります。

    実際のデータで各候補の利得を計算すると、次のようになります（根の不純度は 0.4688）。

    特徴量 閾値 情報利得
    性別 0.5 0.0312
    年齢 14.5 0.2604
    年齢 20.0 0.4688
    年齢 28.5 0.2812
    年齢 47.5 0.0402

    「年齢 < 20」の利得が根の不純度と等しく、この 1 回の質問で不純度が 0 になります。性別の利得は 0.0312 しかありません。決定木は自力で「年齢が効く、性別は関係ない」を見つけました。

    木の表現¶

    /** 決定木。葉か内部ノードのいずれか。 */
sealed interface Tree {
    fun predict(point: Point): Int
}

/** 葉。多数決で決めたラベルを返す。 */
data class Leaf(val label: Int) : Tree {
    override fun predict(point: Point): Int = label
}

/** 内部ノード。質問に応じて左右の枝へ進む。 */
data class Node(val split: Split, val left: Tree, val right: Tree) : Tree {
    override fun predict(point: Point): Int =
        if (split.matches(point)) left.predict(point) else right.predict(point)
}

    sealed interface により、Tree の実装は Leaf と Node の 2 つだけ とコンパイラが知ります。第 4 章の enum class と同じく、when での網羅性検査が効きます。

    /** 木の深さ。葉だけなら 0。 */
fun depth(tree: Tree): Int = when (tree) {
    is Leaf -> 0
    is Node -> 1 + maxOf(depth(tree.left), depth(tree.right))
}

    else 節がありません。 将来 Tree に第 3 のケースを追加したら、この when はコンパイルエラーになります。スマートキャストにより、is Node -> の枝では tree.left に型注釈なしでアクセスできます。

    predict だけはインターフェースのメソッドにしました。木を辿る処理は再帰の中心なので、多態で解くほうが自然です。「構造を調べる操作は when、振る舞いはメソッド」という使い分け です。

    木の構築¶

    fun buildTree(
    points: List<Point>,
    labels: List<Int>,
    maxDepth: Int = 5,
    minSamples: Int = 1,
    impurity: Impurity = giniImpurity,
): Tree {
    if (maxDepth <= 0 || labels.size <= minSamples || labels.distinct().size == 1) {
        return Leaf(majorityLabel(labels))
    }
    val (split, _) = bestSplit(points, labels, impurity) ?: return Leaf(majorityLabel(labels))
    val partition = applySplit(points, labels, split)
    return Node(
        split = split,
        left = buildTree(partition.leftPoints, partition.leftLabels, maxDepth - 1, minSamples, impurity),
        right = buildTree(partition.rightPoints, partition.rightLabels, maxDepth - 1, minSamples, impurity),
    )
}

    val (split, _) = bestSplit(...) ?: return Leaf(...) の 1 行に注目してください。エルビス演算子による早期リターンと分解宣言が同時に書けます。 「良い分割がなければ葉にする」という判断が 1 行に収まりました。

    停止条件は 4 つです。

    条件 理由
    maxDepth <= 0 深すぎる木は過学習する（第 4 章の次数と同じ）
    labels.size <= minSamples 少なすぎるデータからの分割は信用できない
    labels.distinct().size == 1 すでに純粋なので分ける必要がない
    bestSplit が null どう分けても改善しない

    上 2 つは第 4 章の正則化と同じ役割です。 木は放っておくと訓練データを丸暗記するまで育ちます。

    実行結果¶

    深さ 1、葉 2 枚の木で 正解率 1.0 に達しました。

    Node(split=Split(feature=1, threshold=20.0), left=Leaf(label=1), right=Leaf(label=0))

    「20 歳未満なら推薦、そうでなければ推薦しない」という 1 つの質問だけです。最大深さを 5 に設定していますが、根で完全に分かれたのでそれ以上は伸びませんでした。

    data class が toString を生成しているので、木の構造が println するだけで読めます。モデルを目で見て検証できるのは決定木ならではです。

    この結果は Python 版・F# 版と完全に一致します。第 7・8 章と同じく、乱数を使わないアルゴリズム だからです。

    ジニとエントロピーの比較¶

    @Test
fun `ジニとエントロピーはこのデータで同じ木を作る`() {
    assertEquals(
        buildTree(points, labels, impurity = giniImpurity),
        buildTree(points, labels, impurity = entropy),
    )
}

    このデータでは どちらの指標を使っても同じ木になりました。値の絶対値は違う（0.4688 と 0.9544）のに、順序が同じだからです。

    data class の equals が再帰的に生成されるため、木全体の等価性が 1 行で比較できます。手で書くと再帰関数が必要になる比較です。

    まとめ¶

    • 差し替え可能な戦略は val ...: Impurity として関数型の値で持つと、意図が型に現れます。
    • partition / flatMap / zipWithNext により、振り分けと候補列挙が式 1 つで書けます。
    • mapNotNull → maxByOrNull → takeIf の 3 段で、「なければ null」を宣言的に組み立てられます。
    • sealed interface により when の網羅性が検査されます。構造の走査は when、振る舞いはメソッドで解きます。
    • ?: return と分解宣言の組み合わせで、早期リターンが 1 行に収まります。
