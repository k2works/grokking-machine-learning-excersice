## 分離直線を型にする

Python 版は `weights` と `bias` を持ち回り、タプルで返していました。
Kotlin では `Boundary` にまとめ、スコア・予測・誤差をメンバーにします。

```kotlin
/** 分離直線。重みとバイアスの組 */
data class Boundary(val weights: DoubleArray, val bias: Double) {
    /** 重み付き和にバイアスを足したもの。直線からの符号つき距離に比例する */
    fun score(features: IntArray): Double =
        bias + weights.indices.sumOf { weights[it] * features[it] }

    /** スコアをステップ関数に通した予測ラベル */
    fun predict(features: IntArray): Int = step(score(features))

    /** パーセプトロン誤差。当たっていれば 0、外れていればスコアの絶対値 */
    fun error(features: IntArray, label: Int): Double =
        if (predict(features) == label) 0.0 else abs(score(features))

    // data class に配列を持たせると equals が参照比較になるので明示的に実装する
    override fun equals(other: Any?): Boolean =
        other is Boundary && weights.contentEquals(other.weights) && bias == other.bias

    override fun hashCode(): Int = 31 * weights.contentHashCode() + bias.hashCode()
}
```

### `data class` に配列を入れる罠

`data class` が生成する `equals` は、**配列については参照比較** になります。
中身が同じ 2 つの `DoubleArray` を持つ `Boundary` は等しくならないのです。

これは [#01](nb01.md) で `Line` の構造的等価性が効いた場面と正反対です。
`Line` は `Double` を 2 つ持つだけだったので何もしなくてよかったのに、
配列を 1 つ入れた途端に自前実装が要ります。

放置すると「当たっているときは何も動かない」のテストが静かに落ちます。

```kotlin
@Test
fun `当たっているときは何も動かない`() {
    // FEATURES[4] = [1, 3] は重み [1, 2] バイアス -4 で予測 1、ラベルも 1
    val updated = perceptronTrick(start, FEATURES[4], 1)

    assertEquals(start, updated)
}
```

`equals` を書いたので、この 1 行で書けます。書かなければ
「重みとバイアスをそれぞれ比較する」3 行になっていました。

`List<Double>` を使えば `equals` は自動で正しくなりますが、
数値計算のループで毎回ボクシングが起きます。ここでは配列を選び、`equals` を書きました。

## 原著の 2 つのトリックは挙動が違う

[Python 版](../python/nb04.md) と同じ話です。
原著は「短く書いた版」でバイアスの更新を重みのループの内側に置いており、
特徴量の数だけ繰り返し適用されます。

Kotlin でもそのまま写しました。

```kotlin
fun perceptronTrick(
    boundary: Boundary,
    features: IntArray,
    label: Int,
    learningRate: Double = 0.05,
): Boundary {
    val pred = boundary.predict(features)
    val weights = boundary.weights.copyOf()
    var bias = boundary.bias
    for (i in weights.indices) {
        weights[i] += (label - pred) * features[i] * learningRate
        bias += (label - pred) * learningRate
    }
    return Boundary(weights, bias)
}
```

`boundary.weights.copyOf()` で複製してから更新します。
原著は引数のリストをその場で書き換えており、同じセルを 2 回実行すると結果が変わります。

原著のセル出力と一致します。

```kotlin
@Test
fun `短く書いた版のトリックは原著と同じ数値になる`() {
    // 原著の出力: ([0.9, 1.85], -4.1)
    val updated = perceptronTrick(start, FEATURES[6], 0)

    assertEquals(0.9, updated.weights[0], 1e-12)
    assertEquals(1.85, updated.weights[1], 1e-12)
    assertEquals(-4.1, updated.bias, 1e-12)
}
```

明示的な版との差もテストで固定しています。

```kotlin
@Test
fun `短く書いた版はバイアスを特徴量の数だけ動かす`() {
    // 原著の 2 つの実装は挙動が違う。短く書いた版はバイアスの更新が
    // 重みのループの内側にあり、特徴量が 2 つなので 2 回適用される
    val explicit = perceptronTrickExplicit(start, FEATURES[6], 0)
    val short = perceptronTrick(start, FEATURES[6], 0)

    // 重みの更新は一致する
    assertTrue(explicit.weights.contentEquals(short.weights))
    // バイアスだけ 2 倍動く
    assertEquals(-4.05, explicit.bias, 1e-12)
    assertEquals(-4.1, short.bias, 1e-12)
}
```

### `when` を式として使う

明示的な版は、分岐のなかで重みを更新しつつバイアスを返す形にしました。

```kotlin
val bias = when {
    label == 1 && pred == 0 -> {
        for (i in weights.indices) weights[i] += features[i] * learningRate
        boundary.bias + learningRate
    }
    else -> {
        for (i in weights.indices) weights[i] -= features[i] * learningRate
        boundary.bias - learningRate
    }
}
```

`when` はブロックの最後の式を値として返すので、
「重みを更新して、バイアスの新しい値を返す」が 1 つの式に収まります。
Python 版は `bias += ...` の副作用で書くしかなかったところです。

## Smile にパーセプトロンが無い

ここが Kotlin 版の本題です。`smile.classification` の中身を列挙すると次のとおりです。

```text
AdaBoost, DecisionTree, DiscreteNaiveBayes, DiscriminantAnalysis, FLD,
GradientTreeBoost, KNN, LDA, LogisticRegression, MLP, Maxent, NaiveBayes,
QDA, RBFNetwork, RDA, RandomForest, SVM, SparseLogisticRegression
```

**`Perceptron` はありません。** `MultilayerPerceptron` は `smile.base.mlp` にありますが、
これは多層のニューラルネットワークで、この章の単層パーセプトロンとは別物です。

線形分離できるデータに対して分離超平面を求める、という役割がいちばん近いのは
**線形カーネルの SVM** です。それで代替しました。

```kotlin
/**
 * 同じ問題を Smile に解かせる。
 *
 * **Smile にはパーセプトロンの実装が無い**（`smile.classification` に
 * `Perceptron` は存在しない）。線形分離できるデータに対して分離超平面を
 * 求めるという役割がいちばん近いのは線形カーネルの [SVM] なので、
 * それで代替する。得られる直線はパーセプトロンとは違うが、
 * 「ライブラリに任せると全点が正しく分類できる」という原著の主張は確かめられる。
 *
 * Smile の SVM はラベルを **-1 / +1** で要求する。scikit-learn は 0 / 1 を
 * そのまま受け取るので、ここで変換が要る。
 */
fun fitWithSmile(
    features: Array<IntArray> = FEATURES,
    labels: IntArray = LABELS,
    regularization: Double = 1.0,
    tolerance: Double = 1e-4,
): Classifier<DoubleArray> {
    val x = Array(features.size) { row ->
        DoubleArray(features[row].size) { features[row][it].toDouble() }
    }
    val signed = IntArray(labels.size) { if (labels[it] == 1) 1 else -1 }
    return SVM.fit(x, signed, regularization, tolerance)
}
```

### ラベルの符号で一度落ちた

`SVM.fit` に 0 / 1 のラベルを渡すと、実行時に落ちます。

```text
java.lang.IllegalArgumentException: Invalid label: 0
    at smile.base.svm.LASVM.process(LASVM.java:370)
```

SVM の定式化はラベルが $\pm 1$ であることを前提にしています。
scikit-learn は内部で変換してくれますが、Smile は要求をそのまま押し付けてきます。
**メッセージが具体的なので原因はすぐ分かりました** が、
同じ `int` 型なのでコンパイル時には止まりません。

予測を戻すときも 0 / 1 に直します。

```kotlin
/** Smile のモデルで全点を予測し、ラベルを 0 / 1 に戻す */
fun predictWithSmile(
    model: Classifier<DoubleArray>,
    features: Array<IntArray> = FEATURES,
): List<Int> = features.map { row ->
    val predicted = model.predict(DoubleArray(row.size) { row[it].toDouble() })
    if (predicted == 1) 1 else 0
}
```

結果は原著の予測と一致します。

```kotlin
@Test
fun `Smile の線形 SVM も全点を正しく分類する`() {
    // 原著 scikit-learn の出力: Predictions: [0 0 0 0 1 1 1 1]
    // Smile にパーセプトロンは無いので線形 SVM で代替している
    assertEquals(LABELS.toList(), predictWithSmile(fitWithSmile()))
}
```

係数は比べません。SVM はマージンを最大にする直線を選び、
パーセプトロンは見つけた 1 本を返すだけなので、**そもそも別の直線** です。
原著の `[4, 2] / -9` と突き合わせても意味がありません。

## 手書きの学習は原著に近い直線に行き着いた

原著の出力 `([0.55, 0.25], -1.1)` は、
[Python 版](../python/nb04.md) で述べたとおり再現できません。
原著が点の選択に使う `random` に種を与えていないためです。

それでも参考までに並べると、Kotlin の学習結果は原著によく似た値になりました。

| 実装 | 重み | バイアス |
| :--- | :--- | ---: |
| 原著（1 回きりの出力） | [0.55, 0.25] | -1.10 |
| Kotlin（種 0・500 エポック） | [0.59, 0.23] | **-1.10** |
| Python（種 0・500 エポック） | [0.63, 0.18] | -1.04 |

バイアスがぴたりと `-1.1` で揃ったのは偶然です。
学習率 0.01 でバイアスが 2 ずつ動くので、**到達しうる値が 0.02 の倍数に限られる**
ためでもあります。数値そのものに意味は持たせず、テストは収束で書いています。

```kotlin
@Test
fun `学習後は全点を正しく分類できる`() {
    val result = perceptronAlgorithm(epochs = 500)

    assertEquals(LABELS.toList(), FEATURES.map { result.boundary.predict(it) })
}
```

## この章で Kotlin が効いた場面・効かなかった場面

| 場面 | 評価 |
| :--- | :--- |
| 分離直線の型 | **効いた** — スコア・予測・誤差がメンバーにまとまる |
| 明示的な版のトリック | **効いた** — `when` を式として使い副作用を減らせる |
| 不変な更新 | **効いた** — `copyOf()` で原著の破壊的更新を避けられる |
| `data class` + 配列 | **効かなかった** — `equals` を自分で書く必要がある |
| パーセプトロンの実装 | **効かなかった** — Smile に無く線形 SVM で代替 |
| ラベルの符号 | **効かなかった** — ±1 が要求され、実行時まで分からない |

前章までは「ライブラリの語彙が薄い」でしたが、この章は
**そもそもアルゴリズムが無い** という段階でした。
自前で書いたトリックのほうが原著に忠実、という逆転が起きています。
