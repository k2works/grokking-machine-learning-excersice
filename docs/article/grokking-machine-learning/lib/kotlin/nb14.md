# #14 ニューラルネットワークで住宅価格を予測（Kotlin）

原著ノートブック: `Chapter_10_Neural_Networks/House_price_predictions_neural_network.ipynb`

ニューラルネットワークを **回帰** に使う回です。
ハイデラバードの住宅データ 2518 件を 3 層のネットワークで予測します。

**この章の発見は「標準化しないと RMSE が 10²⁹ に達する」こと** です。
[Python 版](../python/nb14.md) は標準化なしで動きましたが、Smile では発散しました。

## 分類と回帰でクラスが分かれる

```kotlin
import smile.regression.MLP
```

[#13](nb13.md) では `smile.classification.MLP` を使いました。
回帰は `smile.regression.MLP` です。

**クラス名が同じで、パッケージだけ違います。**
IDE の補完で選び間違えると、コンパイルは通っても意味が変わります。

[#12](nb12.md) の決定木は `smile.classification.DecisionTree` と
`smile.regression.RegressionTree` で **名前が違いました**。
Smile のなかでも命名が揃っていません。

## 出力層のビルダーも変わる

最初に `Layer.mle(1, OutputFunction.LINEAR)` と書いて落ちました。

```text
java.lang.IllegalArgumentException: Linear output function is not allowed with likelihood cost function
```

```kotlin
/**
 * **出力層のビルダーも変える必要がある。** 分類で使った `Layer.mle`
 * （最尤法）に `LINEAR` を渡すと `Linear output function is not allowed
 * with likelihood cost function` で落ちる。回帰は `Layer.mse`
 * （平均二乗誤差）を使う。損失関数と出力関数の組み合わせに制約がある。
 */
```

Keras は `Dense(1)` と書いて `loss='mean_squared_error'` を指定するだけです。
Smile は **出力層のビルダー自体が損失関数を表しています**。

| | Keras | Smile |
| :--- | :--- | :--- |
| 分類 | `Dense(2, activation='softmax')` + `categorical_crossentropy` | `Layer.mle(1, SIGMOID)` |
| 回帰 | `Dense(1)` + `mean_squared_error` | `Layer.mse(1, LINEAR)` |

**組み合わせの制約が例外で分かる** のは、黙って間違うよりましです。
メッセージも具体的でした。

## 標準化しないと 10²⁹ に発散する

最初は原著どおり、標準化せずに学習しました。

| エポック | RMSE |
| ---: | ---: |
| 10 | 6.74 × 10²⁹ |
| 200 | 6.74 × 10²⁹ |
| 1000 | 6.74 × 10²⁹ |

**発散しています。** 学習率を `1e-9` まで下げても変わりませんでした。

原因は 2 つ重なっています。

1. **特徴量の桁が揃っていない** — `Area` は 1000 台、`Resale` は 0 か 1
2. **目的変数が 1000 万の桁** — 勾配がそのまま掛かる

Keras の Adam はパラメータごとに学習率を調整するので、この状況を吸収します。
Smile の確率的勾配降下にはその仕組みがありません。

標準化して解決しました。

```kotlin
/**
 * 標準化した特徴量と価格、そして元に戻すための係数。
 *
 * **原著は標準化していない。** Keras の Adam は勾配の大きさを自動で調整するので、
 * 桁の違う特徴量（`Area` は 4 桁、`Resale` は 0 か 1）でも学習できる。
 * Smile の確率的勾配降下にはその仕組みが無く、標準化しないと発散する
 * （実測で RMSE が 10^29 に達した）。
 */
class Scaled(
    val x: Array<DoubleArray>,
    val prices: DoubleArray,
    val priceScaler: Scaler,
)
```

標準化のための平均と標準偏差は `Scaler` にまとめました。

```kotlin
/** 平均と標準偏差。学習時と予測時で同じ値を使う必要がある */
data class Scaler(val mean: Double, val std: Double) {
    fun scale(value: Double): Double = if (std == 0.0) 0.0 else (value - mean) / std
    fun unscale(value: Double): Double = value * std + mean
}
```

**`std == 0.0` の分岐が要ります。** 38 列のなかには、
全行で同じ値の列（すべて 0 の設備フラグなど）があります。
`0 / 0` は NaN になり、そこから全体に伝播します。

[#02](nb02.md) の `Standardizer` は 2 列だけだったので、この問題は起きませんでした。
**列が増えると、定数列に当たる確率も上がります。**

`unscale` は予測を円単位に戻すために使います。

```kotlin
/** 全物件の価格を予測する。標準化を戻して円単位にする */
fun predict(model: MLP, scaled: Scaled): DoubleArray =
    DoubleArray(scaled.prices.size) { scaled.priceScaler.unscale(model.predict(scaled.x[it])) }
```

**標準化した空間で学習し、元の空間で評価する** という往復が必要です。
Keras なら標準化しないので、この往復自体がありません。

## 標準化すれば原著より良くなる

| エポック | RMSE |
| ---: | ---: |
| 10（原著と同じ） | 797 万 |
| 50 | 633 万 |
| 200 | **490 万** |

原著の `evaluate` は **554 万** です。

```kotlin
@Test
fun `200エポックなら原著より良い予測になる`() {
    // 原著の evaluate は RMSE 約 554 万。Smile は 200 エポックで約 490 万
    assertTrue(rmse(fit(scaled, EPOCHS), data, scaled) < 5_540_000.0)
}
```

**標準化したぶん、原著より良くなりました。**
原著が標準化していれば、もっと良い結果が出ていたはずです。

[#13](nb13.md) の分類では Smile が原著に届きませんでしたが、
今回は逆転しています。**前処理が効くかどうかは問題によって違う** ということです。

原著と同じ 10 エポックでも、基準（877 万）は下回ります。

```kotlin
@Test
fun `原著の10エポックでも基準を下回る`() {
    // 原著と同じ 10 エポック。RMSE 約 797 万で、基準の 877 万は下回る
    assertTrue(rmse(fit(scaled, ORIGINAL_EPOCHS), data, scaled) < baselineRmse(data))
}
```

## この章で Kotlin が効いた場面・効かなかった場面

| 場面 | 評価 |
| :--- | :--- |
| 標準化の表現 | **効いた** — `Scaler` が `scale` / `unscale` を対で持てる |
| 組み合わせの制約 | **効いた** — 例外メッセージが具体的で原因がすぐ分かる |
| クラスの配置 | **効かなかった** — 分類と回帰で同名・別パッケージ |
| 出力層のビルダー | **効かなかった** — 損失関数と結び付いていて分類から書き換えが要る |
| 最適化 | **効かなかった** — Adam が無く、標準化しないと 10²⁹ に発散 |
| 定数列 | **効かなかった** — 標準偏差 0 の列があり NaN が伝播しかけた |
