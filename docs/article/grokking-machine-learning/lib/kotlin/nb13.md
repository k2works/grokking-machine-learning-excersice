# #13 ニューラルネットワークの境界（Kotlin）

原著ノートブック: `Chapter_10_Neural_Networks/Graphical_example.ipynb`

円形に分布した 110 点を、2 層の隠れ層を持つネットワークで分類し、決定境界を見ます。

Smile の `MLP` には **Dropout も ReLU 以外の選択肢も揃っていません**。
そして最適化が単純なため、**原著の 100 エポックでは学習が始まりません**。

## 層はビルダーで組む

```kotlin
val network = MLP(
    Layer.input(2),
    Layer.rectifier(HIDDEN_UNITS[0]),
    Layer.rectifier(HIDDEN_UNITS[1]),
    Layer.mle(1, OutputFunction.SIGMOID),
)
```

Keras の `Sequential` に層を `add` していくのと同じ形です。
`Layer.rectifier` が ReLU、`Layer.mle` が出力層にあたります。

**`Layer.input(2)` を忘れると落ちます。** Keras は `input_shape` を
省略しても最初の `fit` で形が決まりますが、Smile は最初に宣言が要ります。

出力は 1 ユニットのシグモイドにしました。
原著は 2 ユニットの softmax ですが、**2 クラスならシグモイドと同じ境界** を与えます。
Smile に softmax の出力層はありますが、その場合ラベルを one-hot にする必要があり、
`MLP` の `update` が受け取る形と噛み合いません。

## Dropout が無い

原著は `Dropout(0.2)` を 2 か所に入れています。Smile にはありません。

8770 個のパラメータを 110 点で学習する設定なので、
**過学習を抑える仕組みが 1 つ減る** ことになります。
代わりに学習回数で調整することになりました。

## 原著の 100 エポックでは学習が始まらない

```kotlin
@Test
fun `原著の100エポックでは学習が進まない`() {
    // 常に多数派（0）を答えるだけの 84/110 = 0.7636 にとどまる。
    // Keras の Adam に対し Smile は単純な確率的勾配降下なので収束が遅い
    val shallow = fit(data, ORIGINAL_EPOCHS)

    assertEquals(84.0 / 110.0, accuracy(shallow, data), 1e-12)
}
```

**正解率 0.7636 は「常にクラス 0 を答える」のと同じ値** です。
110 点のうち 84 点がクラス 0 なので、何も学習していないのと変わりません。

原因は最適化の違いです。

| | Keras | Smile |
| :--- | :--- | :--- |
| 最適化 | Adam（学習率を自動調整） | 確率的勾配降下 |
| 100 エポック後 | 0.88 前後 | **0.7636（学習せず）** |
| 2000 エポック後 | — | 0.891 |

```kotlin
/**
 * 原著の学習回数は 100 だが、Smile では足りない。
 *
 * Keras は Adam（学習率を自動調整する最適化）を使うのに対し、Smile の [MLP] は
 * 単純な確率的勾配降下である。実測すると 100 回では多数派を答えるだけの
 * 正解率 0.764 にとどまり、2000 回で 0.891 に届いた。
 */
const val EPOCHS = 2000

/** 原著が指定している学習回数。比較用に残す */
const val ORIGINAL_EPOCHS = 100
```

**原著の設定と実際に使う設定を、両方とも定数として残しました。**
「なぜ 2000 なのか」が定数の名前とドキュメントから読めます。

20 倍のエポックを掛けて、ようやく Keras の 100 エポックに追いつきます。
**Adam の効きめが数字で見える** 場面でした。

## 種を固定しないと再現しない

```kotlin
// Smile の MLP は内部で乱数を使うので、種を固定して再現性を確保する
smile.math.MathEx.setSeed(seed.toLong())
```

Smile の乱数は **`MathEx` のグローバルな状態** です。
`MLP` のコンストラクタに種を渡す口はありません。

```kotlin
@Test
fun `種を固定すれば同じ結果になる`() {
    // Smile の MLP は重みの初期化に乱数を使う。MathEx.setSeed で固定できる
    assertEquals(accuracy(fit(data, 200, seed = 7), data), accuracy(fit(data, 200, seed = 7), data), 1e-12)
}
```

グローバル状態なので、**並列にテストを走らせると壊れます**。
scikit-learn の `random_state` 引数のようにモデルごとに閉じている設計とは対照的です。

## 境界は曲線になる

```kotlin
@Test
fun `境界は行ごとに変わる`() {
    // 決定木（#10）の境界は軸に平行で、切り替わる位置が行によらなかった。
    // ニューラルネットワークは曲線を引けるので、行ごとに変わる
    val changes = boundaryChangesPerRow(decisionGrid(fit(data, EPOCHS), data))

    assertTrue(changes.toSet().size > 1, "changes=$changes")
}
```

```kotlin
@Test
fun `境界は閉じた形になる`() {
    // 円形のデータなので、内側を囲む境界ができる。
    // 少なくとも 1 行は「外・内・外」と 2 回切り替わる
    val changes = boundaryChangesPerRow(decisionGrid(fit(data, EPOCHS), data))

    assertTrue(changes.max() >= 2, "changes=$changes")
}
```

**Python と同じ 2 つのテストが、そのまま通りました。**
ライブラリも最適化も違いますが、
「曲線を引ける」「円を囲める」という性質は同じです。

学習が足りないと `changes` がすべて 0（境界が格子の外）になるので、
このテストは **学習の進み具合の指標にもなっています**。
実際、100 エポックのモデルでは `max = 0` でした。

## この章で Kotlin が効いた場面・効かなかった場面

| 場面 | 評価 |
| :--- | :--- |
| 層の組み立て | **効いた** — `Layer` のビルダーが Keras と同じ読み味 |
| 設定の記録 | **効いた** — 原著の値と実際の値を定数 2 つで残せる |
| 境界の検証 | **効いた** — Python と同じテストがそのまま通る |
| Dropout | **効かなかった** — 無いので過学習を抑える手段が減る |
| 最適化 | **効かなかった** — Adam が無く 20 倍のエポックが要る |
| 乱数の種 | **効かなかった** — グローバル状態で並列テストに弱い |
| softmax 出力 | **効かなかった** — `update` の受け取る形と噛み合わない |
