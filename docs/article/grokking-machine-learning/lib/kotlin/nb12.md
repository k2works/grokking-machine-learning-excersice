# #12 回帰木（Kotlin）

原著ノートブック: `Chapter_09_Decision_Trees/Regression_decision_tree.ipynb`

決定木を **回帰** に使う回です。年齢からアプリの利用日数を予測します。

[#09](nb09.md)・[#10](nb10.md)・[#11](nb11.md) と分類木で食い違いが続きましたが、
**回帰木は scikit-learn と完全に一致** しました。

## 回帰木は別のパッケージの別のクラス

```kotlin
/**
 * 回帰木を学習する。
 *
 * 分類木は [smile.classification.DecisionTree] だったが、回帰木は
 * `smile.regression.RegressionTree` と **別のパッケージの別のクラス** である。
 * 分類木は `SplitRule` を取ったが、回帰木は取らない。
 * 回帰の分割基準は最小二乗しか無いので、選ぶ余地が無いためである。
 */
fun fit(maxDepth: Int = 3): RegressionTree =
    RegressionTree.fit(Formula.lhs("Days"), frame(), maxDepth, 100, 1)
```

scikit-learn は `DecisionTreeClassifier` / `DecisionTreeRegressor` と
**名前で対になっています**。Smile は `smile.classification.DecisionTree` と
`smile.regression.RegressionTree` で、名前も置き場所も揃っていません。

引数も違います。分類木は `SplitRule` を取りましたが、回帰木は取りません。
**回帰の分割基準は最小二乗しかない** ので、選ぶ余地が無いためです。
最初 `Loss.ls()` を渡そうとしてコンパイルエラーになり、`javap` で確かめました。

## 手計算の 9 通りが完全に一致

```kotlin
@Test
fun `各分割の重み付きMSEは原著と同じ`() {
    // 原著のセル出力をそのまま期待値にしている
    val expected = listOf(
        5.25, 3.9642857142857144, 3.916666666666667, 1.9833333333333334,
        4.25, 4.983333333333333, 5.166666666666667, 5.25, 5.25,
    )
    val splits = splitMses()

    expected.forEachIndexed { index, value ->
        assertEquals(value, splits[index].weightedMse, 1e-14, "index $index")
    }
}
```

許容誤差 `1e-14` で 9 個すべて通りました。
NumPy の内積で計算した値と、Kotlin の `sumOf` で計算した値が
**15 桁一致** しています。

`forEachIndexed` に添字を渡してメッセージに入れているので、
落ちたときにどの分割かがすぐ分かります。

## NaN の扱いを型で表さない

```kotlin
/** 空の配列の平均は NaN。原著も NumPy の警告つきで NaN を出している */
private fun meanOrNaN(values: List<Double>): Double =
    if (values.isEmpty()) Double.NaN else values.average()
```

`Double?` にして `null` を返す選択肢もありましたが、**NaN のままにしました**。
原著が NaN を出していることと、`(v - NaN)` が NaN になって
二乗和に 0 が足される挙動をそのまま再現したいからです。

`Double?` にすると呼び出し側で `?:` が必要になり、
「空なら二乗誤差は 0」という判断がコードに散らばります。

```kotlin
@Test
fun `空の側の平均はNaNになる`() {
    // 原著も NumPy の RuntimeWarning つきで nan を出している
    assertTrue(splitMses()[0].leftMean.isNaN())
    assertTrue(splitMses()[8].rightMean.isNaN())
}
```

`isNaN()` で確かめます。**`== Double.NaN` は必ず false** になるので使えません。
NaN を扱うときの定番の落とし穴です。

## 木も予測も完全に一致

```kotlin
/** Smile の深さは根を 1 と数えるので、scikit-learn の深さ 2 は 3 になる */
private val sklearnDepth2 = 3
```

[#10](nb10.md) で見つけた +1 の対応則が、ここでは成り立ちます。
[#11](nb11.md) の 400 件データでは通じませんでしたが、
**8 点の小さいデータでは素直に対応します**。

```kotlin
@Test
fun `深さ2の木は scikit-learn と同じ3回の分割になる`() {
    // 根で 35.0、左で 15.0、右で 65.0
    assertEquals(listOf(35.0, 15.0, 65.0), splitThresholds(fit(sklearnDepth2)))
}
```

```kotlin
@Test
fun `予測は scikit-learn と完全に一致する`() {
    // 10 歳 -> 7、20〜30 歳 -> 6、40〜60 歳 -> 1.333、70〜80 歳 -> 4.5
    val expected = listOf(7.0, 6.0, 6.0, 4.0 / 3, 4.0 / 3, 4.0 / 3, 4.5, 4.5)

    predictAll(fit(sklearnDepth2)).forEachIndexed { index, value ->
        assertEquals(expected[index], value, 1e-12, "index $index")
    }
}
```

**8 点すべての予測が一致しました。**

分類木では [#09](nb09.md) で 2 段目が違い、[#11](nb11.md) では深さの対応が崩れました。
回帰木で一致したのは、**同点の分割が起きにくい** からです。
連続値のラベルは、ジニ不純度と違って偶然同じ値になることがほとんどありません。

## この章で Kotlin が効いた場面・効かなかった場面

| 場面 | 評価 |
| :--- | :--- |
| 手計算の再現 | **効いた** — `sumOf` で NumPy と 15 桁一致 |
| テストの失敗メッセージ | **効いた** — `forEachIndexed` で添字を添えられる |
| 深さの対応 | **効いた** — 小さいデータでは +1 の対応則が通じる |
| クラスの配置 | **効かなかった** — 分類木と回帰木で名前も置き場所も揃わない |
| 引数の違い | **効かなかった** — 分類木の `SplitRule` が回帰木に無い |

分類木で 3 本続いた食い違いのあと、回帰木はあっさり一致しました。
**Smile の弱点は決定木そのものではなく、分類木まわりの API と挙動** だったと分かります。
