# #03 多項式回帰と L1・L2 正則化（Kotlin）

原著ノートブック: `Chapter_04_Testing_Overfitting_Underfitting/Polynomial_regression_regularization.ipynb`

二次関数 $-x^2 + 2$ の周りに散らした 40 点へ、**次数 20** の多項式を当てはめます。
正則化なしでは激しく過学習し、L1（LASSO）・L2（Ridge）を入れると収まります。

Kotlin でこの章を書くと、Smile が scikit-learn とどこまで同じでどこから違うかが
はっきりします。結論を先に言うと、**Smile の LASSO は係数を厳密なゼロにしません**。

## データセットを作る

```kotlin
/** 元にした多項式 -x^2 + 2 の係数。添字が次数に対応する */
val POLYNOMIAL_COEFFICIENTS = intArrayOf(2, 0, -1)

/** 多項式の値を求める。`coefficients[i]` が x^i の係数 */
fun polynomial(coefficients: IntArray, x: Double): Double =
    coefficients.withIndex().sumOf { (i, c) -> c * x.pow(i) }
```

`withIndex()` と分解宣言 `(i, c)` で、Python の `sum(coefficients[i] * x**i for i in range(n))` を
そのまま写せます。添字を明示的に回すより短く、意図も同じです。

### 正規乱数を自分で作る

ここで最初の壁に当たりました。**`kotlin.random.Random` に正規分布がありません。**

```kotlin
/**
 * kotlin.random.Random は正規分布を持たないので、Box-Muller 法で作る。
 *
 * java.util.Random には `nextGaussian()` があるが、乱数列を 1 つの生成器に
 * 揃えたいのでここで定義する。
 */
private fun Random.nextGaussian(): Double {
    val u1 = nextDouble()
    val u2 = nextDouble()
    return sqrt(-2.0 * kotlin.math.ln(u1)) * kotlin.math.cos(2.0 * Math.PI * u2)
}
```

`java.util.Random` を使えば `nextGaussian()` がありますが、
一様乱数と正規乱数で別の生成器を使うと、種を固定しても再現性の管理が面倒になります。
拡張関数で `kotlin.random.Random` に生やして、生成器を 1 つに揃えました。

### `train_test_split` も自分で書く

scikit-learn の 1 行に相当する処理です。

```kotlin
// train_test_split と同じく、添字をシャッフルしてから分ける
val indices = (0 until size).shuffled(random)
val testSize = (size * testRatio).toInt()
val testIndices = indices.take(testSize)
val trainIndices = indices.drop(testSize)
```

`shuffled(random)` に生成器を渡せるので、データ生成と同じ乱数列を共有できます。
`take` / `drop` で分けるのは Kotlin らしい書き方で、`train_test_split` より
**何をしているかが直接読めます**。

## 多項式特徴量

`PolynomialFeatures` にあたるものは Smile にありません。3 行で書けます。

```kotlin
/**
 * x を x, x^2, ..., x^degree の列に展開する。
 *
 * scikit-learn の `PolynomialFeatures(include_bias=False)` にあたる。
 * 定数 1 の列を作らないのは、切片を回帰側に任せるためである。
 */
fun polynomialFeatures(x: DoubleArray, degree: Int = DEGREE): Array<DoubleArray> =
    Array(x.size) { row -> DoubleArray(degree) { column -> x[row].pow(column + 1) } }
```

`Array(n) { ... }` の初期化ラムダが二重に入れ子になるだけで、行列が作れます。
`column + 1` で 1 次から始めているのが `include_bias=False` に対応します。

## 正則化の切り替え

原著の文字列分岐を `enum class` にします。

```kotlin
/** 正則化の種類。原著は文字列 'L1' / 'L2' / None で切り替えていた */
enum class Regularization { NONE, L1, L2 }
```

```kotlin
val model = when (regularization) {
    // Smile は正則化なしの OLS だけ Properties でソルバを選ぶ。
    // 次数 20 の特徴量は条件数が悪いので、ここでも SVD を使う
    Regularization.NONE -> OLS.fit(
        formula,
        df,
        java.util.Properties().apply { setProperty("smile.ols.method", "svd") },
    )
    Regularization.L1 -> LASSO.fit(formula, df, alpha)
    Regularization.L2 -> RidgeRegression.fit(formula, df, alpha)
}
```

`when` が網羅性を検査するので、ケースを足し忘れるとコンパイルエラーになります。
Python の `match` にはこの保護がありません。

Smile は 3 つとも **別のクラスの静的メソッド** です（`OLS` / `LASSO` / `RidgeRegression`）。
scikit-learn が `LinearRegression` / `Lasso` / `Ridge` と、
共通のインターフェースを持つクラスで揃えているのに比べると、
**`OLS` だけ `Properties` を取る** など呼び出し方が不揃いです。

## Smile の LASSO は厳密なゼロを出さない

ここがこの章の発見でした。

scikit-learn の `Lasso` は座標降下法を使い、**軟判定しきい値関数**によって
係数をちょうど 0 にします。原著では 20 個中 19 個が 0 になりました。

Smile の `LASSO` は 0 を 1 つも出しません。

```kotlin
@Test
fun `Smile の L1 は係数を縮めるが厳密なゼロにはしない`() {
    val model = trainPolynomialRegression(
        dataset.xTrain, dataset.yTrain, DEGREE, Regularization.L1, alpha = 0.01,
    )

    // scikit-learn の Lasso は座標降下で厳密に 0 を出すが、Smile の LASSO は
    // 出さない。実測で 20 個中 8 個が 1e-3 を下回るところまで縮むだけである
    assertEquals(0, model.coefficients.count { it == 0.0 })
    assertTrue(
        model.coefficients.count { abs(it) < 1e-3 } >= 5,
        "small=${model.coefficients.count { abs(it) < 1e-3 }}",
    )
    // L2 と違い、値の大きさが桁で散らばる
    assertTrue(model.coefficients.maxOf { abs(it) } < 10.0)
}
```

実測では 20 個中 8 個が `1e-3` を下回るところまで縮みますが、`1e-5` 程度の値が残ります。

**L1 の「特徴量選択ができる」という性質は、実装に依存します。**
「Lasso を使えば疎な解が得られる」と覚えていると、Smile では期待が外れます。
係数が 0 かどうかで特徴量を選ぶコードを書くなら、しきい値による打ち切りが必要です。

[F# 版](../fsharp/nb03.md) では座標降下法を自分で書いたので、
scikit-learn と同じく厳密なゼロが出ます。3 実装が綺麗に分かれました。

## 3 言語の比較

同じ問題を解いた結果です。データ生成の乱数列が言語ごとに違うので、
数値そのものは比較できません。**性質を比べます**。

| 実装 | 正則化なし RMSE | 正則化なしの最大係数 | L1 RMSE | L1 の厳密なゼロ | L2 RMSE |
| :--- | ---: | ---: | ---: | ---: | ---: |
| 原著 | 1862.044 | 約 1.0e7 | 0.152773 | 19 / 20 | 0.103708 |
| Python | 12.924 | 8,633 | 0.152773 | 19 / 20 | 0.103708 |
| **Kotlin** | **0.122** | **76,037** | 0.105 | **0 / 20** | 0.099 |
| F# | 1.164 | 2,074,928 | 0.129 | 18 / 20 | 0.125 |

Kotlin だけ **正則化なしのテスト誤差が小さい** のが目を引きます。
係数は 76,037 まで爆発しているのに、テスト誤差は 0.122 しかありません。

理由は単純で、**この乱数列ではテスト用の 8 点がたまたま振動の穏やかな位置に落ちた**
からです。過学習したモデルは訓練点の間で激しく振動しますが、
テスト点がその谷を踏まなければ誤差は出ません。

だからテストは「正則化なしは桁違いに悪い」ではなく、
**「係数が爆発する」** と **「正則化を入れると誤差が下がる」** の 2 つに分けています。
前者は必ず成り立ち、後者も測って確かめた事実です。

```kotlin
@Test
fun `正則化なしは係数が爆発する`() {
    val model = trainPolynomialRegression(dataset.xTrain, dataset.yTrain, DEGREE)

    // 元の多項式の係数は -1 と 2 だけなのに、桁違いの係数が現れる
    assertTrue(
        model.coefficients.maxOf { abs(it) } > 100.0,
        "max=${model.coefficients.maxOf { abs(it) }}",
    )
}
```

## この章で Kotlin が効いた場面・効かなかった場面

| 場面 | 評価 |
| :--- | :--- |
| 多項式の評価 | **効いた** — `withIndex()` + 分解宣言で Python と同じ短さ |
| 訓練・テスト分割 | **効いた** — `shuffled` / `take` / `drop` で処理が直接読める |
| 多項式特徴量 | **効いた** — 入れ子の `Array { }` で 1 式 |
| 正則化の切り替え | **効いた** — `when` の網羅性検査 |
| 正規乱数 | **効かなかった** — 標準ライブラリに無く Box-Muller を自前で書く |
| Smile の API の不揃い | **効かなかった** — `OLS` だけ `Properties` を取る |
| LASSO の疎性 | **効かなかった** — 厳密なゼロが出ない |

言語としての Kotlin はよく効きましたが、**ライブラリの語彙と品質** が
scikit-learn に追いついていない場面が続きました。
