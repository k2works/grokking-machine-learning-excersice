## なぜ自前で書いたか

```fsharp
/// F# には決定木のライブラリとして Accord.MachineLearning がある。
/// ランダムフォレストと決定木は持っているが、**AdaBoost は分類に使える形で
/// 揃っていない**（`Boost<TModel>` はあるが弱学習器の重み付き学習が要る）。
/// そこは [#11](Nb11UniversityAdmissions.fs) の自前 CART を土台に
/// **AdaBoost を書き下ろす**。原著のアルゴリズムをそのまま写せるので、
/// かえって中身が見える形になった。
```

もう 1 つ理由があります。[Kotlin 版](../kotlin/nb20.md) で分かったとおり、
Smile のランダムフォレストは **種を固定しても結果が変わります**。
Accord も同じ作りなので、使えば同じ問題を抱えます。

**「ライブラリを使う」がこのシリーズの主旨ですが、
ライブラリが答えを返せないなら自前で書くほうが誠実です。**

## CART を重み付きに拡張する

[#11](nb11.md) で書いた CART に、点ごとの重みを足しました。

```fsharp
/// 重み付きのジニ不純度。AdaBoost では点ごとに重みが付く
let private weightedGini (labels: int[]) (weights: float[]) (indices: int[]) =
    let total = indices |> Array.sumBy (fun i -> weights.[i])

    if total = 0.0 then
        0.0
    else
        let ofLabel label =
            indices |> Array.filter (fun i -> labels.[i] = label) |> Array.sumBy (fun i -> weights.[i])

        let p1 = ofLabel 1 / total
        let p0 = ofLabel 0 / total
        1.0 - p1 * p1 - p0 * p0
```

件数を数えていたところを、**重みの和に置き換えるだけ** です。
すべての重みを 1 にすれば元の実装と同じ値になるので、
[#11](nb11.md) のテストを壊さずに拡張できました。

分割の選び方も [#11](nb11.md) の規則をそのまま使います。

```fsharp
/// 分割の候補。scikit-learn と同じく **隣り合う値の中点** を使う
let private candidateThresholds (values: float[]) =
    values |> Array.distinct |> Array.sort |> Array.pairwise |> Array.map (fun (a, b) -> (a + b) / 2.0)
```

その結果、3 本の弱学習器が選ぶ分割が scikit-learn と一致しました。

```fsharp
[<Fact>]
let ``弱学習器が選ぶ分割はscikit-learnと完全に一致する`` () =
    // 特徴量もしきい値も同じところを選んだ。CART の分割規則が同じなら、
    // 6 点しかないデータでは解が一意に決まる。3 言語すべてで一致する
    let splits = [ 0..2 ] |> List.map (fun index -> splitOf (fitTree (batch index) 1))

    Assert.Equal<(string * float) option list>(
        [ Some("Lottery", 4.5); Some("Sale", 8.0); Some("Sale", 5.5) ],
        splits
    )
```

## AdaBoost をアルゴリズムどおりに書く

```fsharp
/// AdaBoost（SAMME）を原著のアルゴリズムどおりに実装する。
///
/// 1. すべての点に等しい重みを与える
/// 2. 重み付きで切り株を学習する
/// 3. 誤り率 ε から発言力 α = log((1-ε)/ε) を計算する
/// 4. 外した点の重みを exp(α) 倍する
/// 5. 重みを正規化して 2 に戻る
///
/// scikit-learn が 1.6 で削除した `SAMME.R`（確率出力を使う実数版）ではなく、
/// **いま scikit-learn に残っているのと同じ離散版** である。
```

書いてみると 25 行です。本の説明がそのままコードになります。

```fsharp
        let errorRate =
            Array.init data.Size (fun i ->
                if predictTree tree data.X.[i] <> data.Y.[i] then weights.[i] else 0.0)
            |> Array.sum

        // 完全に当ててしまうと α が無限大になる。scikit-learn も同じ扱いで打ち切る
        if errorRate <= 0.0 || errorRate >= 0.5 then
            stages.Add { Tree = tree; Alpha = 1.0 }
        else
            let alpha = log ((1.0 - errorRate) / errorRate)
```

`ε = 0` のとき `α = log(1/0) = ∞` になります。
本には書かれていない境界条件で、**実装して初めて出てくる** ものです。

## そして値が一致した

```fsharp
[<Fact>]
let ``AdaBoostはいまのscikit-learnと一致する`` () =
    // 原著の出力は 0.8888888888888888 だが、それは削除された SAMME.R の値。
    // 離散版 SAMME をアルゴリズムどおりに書くと 0.7777777777777778 になり、
    // **いまの scikit-learn の出力と一致する**
    Assert.Equal(0.7777777777777778, accuracy (predictAdaBoost (fitAdaBoost allData 6)) allData, 15)
```

| | 正解率 |
| :--- | ---: |
| 原著（`SAMME.R`） | 0.8889 |
| 現在の scikit-learn（`SAMME`） | 0.7778 |
| Kotlin / Smile | 0.8333 |
| **F# 自前実装（`SAMME`）** | **0.7778** |

**自前実装が現在の scikit-learn と 16 桁一致しました。**

これは強い裏付けになります。[Python 版](../python/nb20.md) では
「`SAMME.R` が削除されたから値が変わった」と **推測** していました。
本を読んで書いた `SAMME` が Python と同じ値を出したことで、
**現在の scikit-learn が確かに離散版を使っている** ことが確かめられます。

## 発言力は段を追うごとに下がる

```fsharp
[<Fact>]
let ``AdaBoostの発言力は段を追うごとに下がる`` () =
    // 前の段が外した点を重点的に見るので、後の段ほど難しい問題を解く。
    // 誤り率が上がるぶん発言力 α は小さくなる
    let alphas = fitAdaBoost allData 6 |> List.map (fun stage -> stage.Alpha)

    Assert.True(List.head alphas > List.last alphas)
    Assert.All(alphas, fun alpha -> Assert.True(alpha > 0.0))
```

実測した α の並びです。

```text
[1.2528; 1.1963; 0.7364; 0.6774; 0.3305; 0.4459]
```

**きれいに減っていきます**（最後だけ少し戻りますが）。
AdaBoost は前の段が外した点の重みを上げるので、
後の段ほど難しい問題を解くことになり、誤り率が上がり、発言力が下がります。

自前で書いたからこそ、**中間の値を検証できました**。
ライブラリを使うと `estimator_weights_` のような属性を探す必要があり、
無ければ諦めるしかありません（[#18](nb18.md) の Smile がそうでした）。

## 手で作るランダムフォレスト

原著は「Training a random forest by hand」の節で 3 組の切り株を作りますが、
**多数決を取るところまでは書いていません**。図を並べて終わりです。

```fsharp
/// 原著の「手で作るランダムフォレスト」。
///
/// 原著は 6 通ずつ 3 組に分けて切り株を 3 本作り、図で並べて見せる。
/// **多数決を取るところまでは書いていない** ので、ここで補った。
let handMadeForest () =
    [ 0; 1; 2 ] |> List.map (fun index -> fitTree (batch index) 1)
```

```fsharp
[<Fact>]
let ``手で作るランダムフォレストは原著と完全に一致する`` () =
    // 原著の RandomForestClassifier は 0.8333333333333334。
    // 原著が手で切った 3 組の切り株を多数決すると、同じ値になる
    Assert.Equal(0.8333333333333334, accuracy (predictHandMadeForest (handMadeForest ())) allData, 15)
```

**0.8333。原著の `RandomForestClassifier` とまったく同じ値です。**

原著が「手で作る」と「ライブラリで作る」を並べて見せたのは、
まさにこの一致を期待してのことでしょう。
しかし **原著自身はその一致を示していません**（多数決を書いていないので）。

補って初めて、章の構成の意図が完成しました。
**しかもこちらは決定的です。** Kotlin 版のランダムフォレストが
0.500〜0.889 に散らばったのとは対照的です。
