## `.npy` を読む

`.npz` は `.npy` を集めた ZIP です。`System.IO.Compression` で開けます。

```fsharp
/// `.npy` を読む。原著の MNIST は `|u1`（符号なし 1 バイト）だけなのでそこだけ扱う
let parseNpy (bytes: byte[]) =
    if bytes.[0] <> 0x93uy || System.Text.Encoding.ASCII.GetString(bytes, 1, 5) <> "NUMPY" then
        failwith "npy のマジックナンバーが違います"

    // 版が 1 ならヘッダ長は 2 バイト、2 以降は 4 バイト（どちらもリトルエンディアン）
    let major = int bytes.[6]
    let lengthSize = if major = 1 then 2 else 4

    let headerLength =
        if lengthSize = 2 then
            int (System.BitConverter.ToUInt16(bytes, 8))
        else
            int (System.BitConverter.ToUInt32(bytes, 8))
```

**`System.BitConverter` がリトルエンディアンの読み出しを持っている** ので、
Kotlin 版のようにビットシフトを書く必要がありません。

```kotlin
// Kotlin 版はこう書いた
var headerLength = 0
for (i in 0 until headerLengthBytes) {
    headerLength = headerLength or ((bytes[8 + i].toInt() and 0xFF) shl (8 * i))
}
```

## `byte` が符号なしなので `and 0xFF` が要らない

Kotlin 版で最も危なかったのは、JVM の `byte` が符号付きで、
`and 0xFF` を忘れると画素値 200 が −56 になるところでした。

.NET の `byte` は **0〜255 の符号なし** です。

```fsharp
    let images name =
        let array = readNpz name

        Array.init array.Shape.[0] (fun row -> Array.init InputDim (fun column -> float array.Data.[row * InputDim + column]))

    let labels name =
        let array = readNpz name
        Array.init array.Shape.[0] (fun i -> int array.Data.[i])
```

`float` / `int` に変換するだけで済みます。
**型の設計が違うだけで、間違えようのないコードになります。**
JVM で `byte` を符号付きにしたのは初期の判断ミスとしてよく挙げられますが、
その代償がこういう形で出ます。

## 出力層はソフトマックスではなくシグモイド 10 個

Accord.Neuro の `ActivationNetwork` は、全層に同じ活性化関数を使います。
ソフトマックスはありません。

```fsharp
/// ラベルを one-hot に直す。Accord の出力層はクラスごとに 1 つのシグモイドになる
let private oneHot (label: int) =
    Array.init Classes (fun i -> if i = label then 1.0 else 0.0)
```

```fsharp
    let network =
        ActivationNetwork(SigmoidFunction(), InputDim, hiddenUnits.[0], hiddenUnits.[1], Classes)
```

出力は「10 個の独立したシグモイド」で、**合計が 1 になりません**。
確率としては読めませんが、`argmax` を取るだけなら困りません。

```fsharp
/// 1 枚を予測する。出力 10 個のうち最大のものを選ぶ
let predict (network: ActivationNetwork) (image: float[]) =
    let scaled = image |> Array.map (fun v -> v / 255.0)
    let output = network.Compute scaled
    output |> Array.mapi (fun index value -> index, value) |> Array.maxBy snd |> fst
```

原著の `np.argmax(pred)` に対応する部分です。
F# には `argmax` が無いので、添字を付けてから `maxBy snd` して `fst` を取ります。

## `NguyenWidrow` を忘れると学習しない（再び）

```fsharp
/// 2. **`NguyenWidrow(network).Randomize()` が必須。**
///    [#13](Nb13NeuralNetworkBoundary.fs) と同じで、呼ばないと重みが初期化されず
///    何エポック回しても正解率が動かない。エラーも警告も出ない。
```

[#13](nb13.md) で見つけたのと同じ罠です。
Accord は重みを初期化しないまま学習を始められてしまい、
**エラーも警告も出さずに、正解率が最初から動きません**。

Keras や scikit-learn は初期化を必ずやるので、この段は存在すら意識しません。
**「呼ばないと動かないが、呼ばなくてもコンパイルは通る」** 種類の依存は、
移植で最も見つけにくい部類です。

## 画素値は 0〜1 に直す

```fsharp
/// 1. **画素値を 0〜1 に直してから渡す。** 0〜255 のままだとシグモイドが飽和して
///    学習が進まない。
```

Kotlin 版（Smile では発散する）と理由は違いますが、対処は同じです。
シグモイドは入力が大きいと出力が 1 に張り付き、**勾配がほぼ 0 になります**。
784 個の入力が最大 255 なら、合計は簡単に 1 万を超えます。

## 学習は速い

```fsharp
[<Fact>]
let ``小さく学習しても当てずっぽうより十分に良い`` () =
    if mnistAvailable () then
        let data = mnist.Value
        let network = fit data 5 2000 0

        // 10 クラスなので当てずっぽうは 0.1
        Assert.True(testAccuracy network data 500 > 0.7)
```

2000 枚・5 エポックで、テスト 500 枚に対して 0.7 を超えます。
7 テスト全体で **5 秒** です。Kotlin 版（1 万件・3 エポックで 30 秒）より軽いのは、
Accord が `RunEpoch` で 1 件ずつ更新するためです。

**Smile と Accord で `epochs` の意味が違います。**
Smile の `update` は「1 バッチぶんの更新」、Accord の `RunEpoch` は
「データ全体を 1 周」。同じ「エポック」という言葉で、粒度が違います。

## パラメータ数は計算で合わせる

```fsharp
/// 学習した重みの総数。原著の `model.summary()` が出す 109,386 と突き合わせる
let parameterCount =
    (InputDim * hiddenUnits.[0] + hiddenUnits.[0])
    + (hiddenUnits.[0] * hiddenUnits.[1] + hiddenUnits.[1])
    + (hiddenUnits.[1] * Classes + Classes)
```

```fsharp
[<Fact>]
let ``重みの総数は原著と同じ109386`` () =
    // 原著の model.summary() が出す Total params
    Assert.Equal(109386, parameterCount)
```

`let` 束縛なので **計算は 1 回だけ** です。Kotlin 版は関数にしましたが、
F# では値として書けます。
