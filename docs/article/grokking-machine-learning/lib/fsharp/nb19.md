# ノートブック #19 カーネルとハイパーパラメータを比べる（F# 版）

原著ノートブック: `Chapter_11_Support_Vector_Machines/SVM_graphical_example.ipynb`

[#17](nb17.md) で作った 3 つのデータセットに、いろいろな SVM を当てる回です。
原著は 9 つの正解率を印刷します。

[#18](nb18.md) では ML.NET を使いましたが、**ML.NET はカーネル SVM を持ちません**。
ここは Accord.MachineLearning の `SequentialMinimalOptimization` を使います。
scikit-learn が内部で呼ぶ libsvm と **同じ SMO アルゴリズム** なので、
いちばん近い対応になるはずでした。

結果は 9 つ中 3 つが完全一致。そこに至るまでに 2 つの問題を踏みました。

## 問題 1 — Accord も毎回違う答えを出す

`LinearDualCoordinateDescent` を `C = 100` で 2 回走らせた結果です。

```text
FS19 lin C=100.000000 acc=0.916667
FS19 lin C=100.000000 acc=0.683333
```

**0.917 と 0.683。** Kotlin（Smile）とまったく同じ問題です。

```fsharp
/// 既定の乱数の種。
///
/// **Accord の学習器は種を固定しないと実行のたびに結果が変わる。**
/// `LinearDualCoordinateDescent` を `C = 100` で走らせたところ、
/// 同じデータで 0.917 と 0.683 が出た。scikit-learn の `SVC` は決定的なので、
/// この違いは移植で必ず踏む。
[<Literal>]
let Seed = 0

let private useSeed () =
    Accord.Math.Random.Generator.Seed <- System.Nullable Seed
```

[#13](nb13.md)・[#14](nb14.md) で `Accord.Math.Random.Generator.Seed` を
設定していたのと同じ仕組みです。**Accord は乱数を 1 つのグローバルな生成器で
管理している** ので、そこを固定すれば全体が決定的になります。

種を固定すると `C = 100` は 0.85 に落ち着きました。
（先ほどの 0.917 は、たまたま原著と一致していただけです。）

**「たまたま一致した値を成果として書かなくてよかった」** と言える瞬間でした。
1 回しか実行しない検証は、こういう嘘を通します。

## 問題 2 — Accord の多項式カーネルには gamma が無い

```fsharp
/// scikit-learn は `(gamma * <x, y> + coef0)^degree`、`coef0` の既定は 0。
/// Accord の `Polynomial(degree, constant)` は `(<x, y> + constant)^degree` で
/// **gamma に相当する係数を持たない**。
let polynomialKernel (degree: int) = Polynomial(degree, 0.0)
```

そのまま渡すと、4 次で正解率が **0.318** まで落ちました。

```fsharp
[<Fact>]
let ``gammaを特徴量に畳み込まないと4次で破綻する`` () =
    // 座標をそのまま渡すと内積が最大 18 になり、4 乗で 10 万を超える。
    // カーネル行列の値が大きすぎて SMO が解けず、正解率 0.318 まで落ちる
    let model = fitKernel oneCircle (polynomialKernel 4) 1.0

    Assert.Equal(0.3181818181818182, accuracy (fun row -> model.Decide row) oneCircle, 15)
```

座標は -3〜3 なので内積は最大 18。その 4 乗は 10 万を超えます。
カーネル行列の値が大きくなりすぎて、SMO が解けません。

scikit-learn の `gamma='scale'` は、まさにこれを防ぐための既定値です。

### 解決 — gamma を特徴量に畳み込む

カーネルに gamma が無いなら、**データ側に入れてしまえば同じことです**。

```fsharp
/// 多項式カーネルの gamma を、**特徴量側に畳み込む**。
///
/// `(γ<x, y>)^d = (<√γ x, √γ y>)^d` なので、座標を √γ 倍しておけば
/// gamma を持たないカーネルでも scikit-learn と同じ式になる。
let scaledForPolynomial (data: Dataset) =
    let factor = sqrt (scaleOf data)
    { data with X = data.X |> Array.map (Array.map (fun v -> v * factor)) }
```

`(γ⟨x, y⟩)^d = (⟨√γ x, √γ y⟩)^d`。内積は双線形なので、
**係数を片方ずつに分けて掛けられます**。

結果、4 次が **0.900 で原著と完全一致** しました。

```fsharp
    Assert.Equal(0.9, score 2, 15)
    Assert.Equal(0.9, score 4, 15) // 原著と完全に一致
```

**ライブラリに機能が無いときは、式を変形して同じものを作れないか考える。**
今回はカーネルの定義に立ち返ったことで解決しました。

## 一致したもの、しなかったもの

| データ | 設定 | 原著 | Accord |
| :--- | :--- | ---: | ---: |
| `linear` | 線形 `C=1` | 0.9333333 | 0.8833333 |
| `linear` | 線形 `C=0.01` | 0.8666667 | 0.8833333 |
| `linear` | 線形 `C=100` | 0.9166667 | 0.85 |
| `one_circle` | 多項式 2 次 | 0.8909091 | 0.9 |
| `one_circle` | 多項式 4 次 | 0.9 | **0.9**（完全一致） |
| `two_circles` | RBF `γ=0.1` | 0.8772727 | 0.8818182 |
| `two_circles` | RBF `γ=1` | 0.9045455 | 0.9090909 |
| `two_circles` | RBF `γ=10` | 0.9636364 | **0.9636364**（完全一致） |
| `two_circles` | RBF `γ=100` | 0.9909091 | **0.9909091**（完全一致） |

Kotlin（Smile）と比べると **傾向が違います**。

| | Smile | Accord |
| :--- | :--- | :--- |
| 線形 `C=1` | **完全一致** | 0.05 低い |
| 極端な `C` | **破綻**（0.5 / 0.667） | 妥当な範囲に収まる |
| 多項式 | どちらも外れる | **4 次は完全一致** |
| RBF | 4 つ中 3 つ一致 | 4 つ中 2 つ一致 |

Smile は極端な `C` で壊れ、Accord は壊れません。
Accord のほうが **同じ SMO を使っている** ぶん、素性が近いのだと思われます。

一方で線形カーネルは、Accord 側が `LinearDualCoordinateDescent`
（座標降下法）という別の解法を使うので揃いません。

**「同じ SVM」と一口に言っても、解法が 3 通りありました。**
libsvm の SMO、LASVM のオンライン近似、座標降下法。
どれも同じ最適化問題を解きますが、**近似の仕方も既定値の意味も違います**。

## 傾向は再現できる

```fsharp
[<Fact>]
let ``gammaを上げるほど正解率が単調に上がる`` () =
    // 原著と同じ傾向。値がずれても、章が示したい性質は再現できている
    let scores =
        [ 0.1; 1.0; 10.0; 100.0 ]
        |> List.map (fun gamma ->
            let model = fitKernel twoCircles (rbfKernel gamma) 1.0
            accuracy (fun row -> model.Decide row) twoCircles)

    Assert.Equal<float list>(List.sort scores, scores)
```

## 型パラメータでカーネルを受け取る

```fsharp
let fitKernel (data: Dataset) (kernel: 'K when 'K :> IKernel<float[]>) (c: float) =
    useSeed ()
    let teacher =
        SequentialMinimalOptimization<'K>(Kernel = kernel, Complexity = c)

    teacher.Learn(data.X, data.Decisions)
```

Accord の `SequentialMinimalOptimization<'K>` は **カーネルの型を型パラメータに取ります**。
`IKernel` のインターフェース越しではなく、具体型で受けるので、
カーネルの評価がインライン化できる設計です。

F# の型制約 `'K when 'K :> IKernel<float[]>` がそのまま書けるので、
`Polynomial` でも `Gaussian` でも同じ関数で扱えます。
Kotlin 版は `MercerKernel<DoubleArray>` というインターフェース型 1 つで済みました。
どちらが良いという話ではなく、**性能を取るか単純さを取るかの設計判断** の違いです。

## まとめ

| 項目 | 原著と一致するか |
| :--- | :--- |
| 多項式 4 次 | **完全一致**（gamma を特徴量に畳み込んだうえで） |
| RBF `γ=10` / `100` | **完全一致** |
| RBF `γ=0.1` / `1` | 近いが一致しない |
| 多項式 2 次 | 近いが一致しない |
| 線形カーネル 3 通り | 一致しない（解法が座標降下法） |
| gamma と正解率の単調性 | 一致 |
| 決定性 | **種を固定しないと毎回変わる**（原著は決定的） |
