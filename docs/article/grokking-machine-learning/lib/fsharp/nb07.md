## 単語集合を `Set` で持つ

```fsharp
let private whitespace = Regex(@"\s+", RegexOptions.Compiled)

/// メール本文を、重複を除いた小文字の単語集合にする。
///
/// 原著は `list(set(text.lower().split()))`。**同じ単語が何度出ても 1 回** と
/// 数えるのがこの実装の前提である。
///
/// Python の `split()` は空白の連続をまとめて区切る。`Regex.Split` は
/// 空文字列を残すので、そこを落とす必要がある。
let processEmail (text: string) =
    whitespace.Split(text.ToLowerInvariant())
    |> Array.filter (fun token -> token <> "")
    |> Set.ofArray
```

[Kotlin 版](../kotlin/nb07.md) と同じ落とし穴です。
`Regex.Split` は先頭が空白のとき空文字列を残すので、`Array.filter` で落とします。

F# の `Set` は **不変で、要素が順序づけられている** 二分木です。
Python の `set` や Kotlin の `HashSet` はハッシュ表なので、
**反復の順序が違います**。この違いは後で効いてきます。

## レコードの既定値がないぶん、定数で表す

Kotlin は `data class WordCounts(var spam: Int = 1, var ham: Int = 1)` と
既定値でラプラス平滑化を表せました。F# のレコードに既定値はありません。

```fsharp
/// ある単語が、スパムとハムそれぞれ何通に現れたか。
///
/// 原著は 1 から数え始める。ラプラス平滑化にあたり、
/// 「一度も見ていない側」の確率が 0 になるのを防ぐ。
type WordCounts = { Spam: int; Ham: int }

/// 数え始めの値
let initialCounts = { Spam = 1; Ham = 1 }
```

名前付きの定数にしました。**`initialCounts` という名前があるぶん、
「なぜ 1 なのか」を説明する場所ができます**。既定値より説明的です。

テストもこの定数を対象に書けます。

```fsharp
[<Fact>]
let ``出現数は1から数え始める`` () =
    // ラプラス平滑化。一度も見ていない側の確率が 0 にならないようにする
    Assert.Equal({ Spam = 1; Ham = 1 }, initialCounts)
```

## 不変レコードを更新しながら数える

Kotlin は `var` を持つ `data class` を書き換えました。F# は不変なので、
`with` 式で新しいレコードを作って辞書に入れ直します。

```fsharp
let train (emails: Emails) =
    let words = Dictionary<string, WordCounts>()

    for i in 0 .. emails.Texts.Length - 1 do
        for word in processEmail emails.Texts.[i] do
            let current =
                match words.TryGetValue word with
                | true, counts -> counts
                | _ -> initialCounts

            words.[word] <-
                if emails.Spam.[i] = 1 then
                    { current with Spam = current.Spam + 1 }
                else
                    { current with Ham = current.Ham + 1 }
```

`match words.TryGetValue word with` の **タプルパターン** が F# らしいところです。
.NET の `TryGetValue(key, out value)` という古い形の API を、
`(bool * 'T)` のタプルとして受けられます。

`{ current with Spam = ... }` は毎回レコードを作りますが、
フィールド 2 つの小さな値なので実測でも問題になりませんでした。
5728 通 × 数百語で 1 秒前後です。

辞書だけは `Dictionary`（可変）を使っています。
`Map`（不変）にすると 100 万回以上の再構築が発生します。
**局所的に閉じた可変性は許容する** という判断です。

## 多倍長整数の扱い

原著の `np.compat.long` は Python の `int` そのもので、
**小数点以下を切り捨てる** うえに **多倍長** です。

```fsharp
    // 原著の np.compat.long と同じ切り捨て。値は 10^20 を超えることがあるので
    // int64 では溢れる。Python の int は多倍長なので BigInteger で受ける
    let truncatedSpams = BigInteger productSpams
    let truncatedHams = BigInteger productHams

    // Python は int / int を多倍長のまま計算してから float にする。
    // decimal では桁が足りないので、比を BigInteger の割り算で作ってから float にする
    let scale = BigInteger.Pow(BigInteger 10, 20)
    float (truncatedSpams * scale / (truncatedSpams + truncatedHams)) / 1e20
```

**`BigInteger` のコンストラクタが `float` を受け取って切り捨ててくれます。**
Kotlin は `BigDecimal(double).toBigInteger()` と 2 段でしたが、F# は 1 段で済みました。

割り算のほうは工夫が要りました。`BigInteger` 同士の除算は **整数除算** なので、
そのままでは 0 か 1 にしかなりません。10²⁰ を掛けてから割り、最後に戻します。

```fsharp
let scale = BigInteger.Pow(BigInteger 10, 20)
float (truncatedSpams * scale / (truncatedSpams + truncatedHams)) / 1e20
```

`decimal` を使う手もありますが、有効桁が 28〜29 桁しかなく、
10²⁰ 台の値を扱うと精度が足りません。整数のまま桁を持ち上げるほうが確実です。

[Kotlin 版](../kotlin/nb07.md) は `BigDecimal.divide` に `MathContext.DECIMAL128` を
渡しました。**同じ問題に対して、3 言語で 3 通りの解き方になった** 箇所です。

| 言語 | 切り捨て | 除算 |
| :--- | :--- | :--- |
| Python | `int(x)`（言語組み込み） | `int / int` が自動で多倍長 → float |
| Kotlin | `BigDecimal(x).toBigInteger()` | `BigDecimal.divide(..., DECIMAL128)` |
| F# | `BigInteger x` | 10²⁰ を掛けてから整数除算 |

## 集合の反復順序は結果に影響しない

F# の `Set` は順序づけられた木、Python の `set` はハッシュ表です。
掛け算の順序が違うので、浮動小数点の丸め方も変わります。

```fsharp
    let productSpams, productHams =
        processEmail email
        |> Set.fold
            (fun (spams, hams) word ->
                match model.Words.TryGetValue word with
                | true, counts ->
                    spams * (float counts.Spam / float corpus.Spam * float corpus.Total),
                    hams * (float counts.Ham / float corpus.Ham * float corpus.Total)
                | _ -> spams, hams)
            (float corpus.Spam, float corpus.Ham)
```

それでも **結果は 16 桁まで一致しました**。
最後の切り捨てが、順序による最下位ビットの違いを吸収しているためです。

`Set.fold` で 2 つの累積値をタプルで持ち回っています。
Python は `spams` と `hams` の 2 つのリストに `append` していましたが、
F# では畳み込み 1 回にまとめられます。

## 結果は原著と完全一致する

```fsharp
[<Fact>]
let ``メール全体の予測は原著と同じ`` () =
    if emailsAvailable () then
        let model = train (loadEmails ())

        // 原著のセル出力をそのまま期待値にしている
        let expected =
            [ "lottery sale", 0.9638144992048691
              "Hi mom how are you", 0.12554358867164464
              "meet me at the lobby of the hotel at nine am", 6.964603508395961e-05
              "enter the lottery to win three million dollars", 0.9995234218677428
              "buy cheap lottery easy money now", 0.999973472265966
              "Grokking Machine Learning by Luis Serrano", 0.4197107645488719
              "asdfgh", 0.2388268156424581 ]

        for (email, value) in expected do
            let actual = predictNaiveBayes model email
            Assert.True(abs (actual - value) <= abs value * 1e-14, $"{email}: {actual} <> {value}")
```

`Assert.Equal(expected, actual, digits)` は **小数点以下の桁数** を取るので、
`6.96e-05` のような小さい値には使えません。相対誤差で比べたいので
`Assert.True` にメッセージを添える形にしました。

[#01](nb01.md) で `Assert.Equal` の第 3 引数の多重定義に引っかかりましたが、
ここでは **そもそも使わない** のが正解でした。

## 3 言語の比較

| 実装 | 原著の数値 | つまずいた箇所 |
| :--- | :--- | :--- |
| Python | **完全一致** | `np.compat.long` の切り捨て（`np.compat` は NumPy 2.0 で削除） |
| Kotlin | **完全一致** | `split()` の意味、`BigDecimal` の精度指定 |
| **F#** | **完全一致** | `Regex.Split` の空文字列、`BigInteger` の整数除算 |

**3 言語すべてが原著の数値を再現した、この連載で初めての回** です。
理由ははっきりしています。**原著がライブラリを使っていないから** です。

ライブラリを呼ぶ回では、版差・ソルバの実装・既定の正則化といった
「自分で書いていない部分」が数値を動かしていました。
それが無くなると、残るのは言語の標準ライブラリの差だけで、
そこは意識すれば揃えられます。

## この章で F# が効いた場面・効かなかった場面

| 場面 | 評価 |
| :--- | :--- |
| ラプラス平滑化 | **効いた** — 名前付き定数が「なぜ 1 か」の説明の場になる |
| `TryGetValue` | **効いた** — タプルパターンで .NET の out 引数を自然に受けられる |
| 畳み込み | **効いた** — 2 つの累積値をタプルで持ち、`Set.fold` 1 回にまとまる |
| 切り捨て | **効いた** — `BigInteger x` が 1 段で済む（Kotlin は 2 段） |
| `Regex.Split` | **効かなかった** — 空文字列が残る |
| `BigInteger` の除算 | **効かなかった** — 整数除算なので桁を持ち上げる小細工が要る |
| `Assert.Equal` の許容誤差 | **効かなかった** — 桁数指定なので相対誤差に使えない |
