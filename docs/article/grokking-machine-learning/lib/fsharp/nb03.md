# #03 多項式回帰と L1・L2 正則化（F#）

原著ノートブック: `Chapter_04_Testing_Overfitting_Underfitting/Polynomial_regression_regularization.ipynb`

二次関数 $-x^2 + 2$ の周りに散らした 40 点へ、**次数 20** の多項式を当てはめます。
正則化なしでは激しく過学習し、L1（Lasso）・L2（Ridge）を入れると収まります。

**この章は F# だけ、正則化そのものを自分で実装することになりました。**
Math.NET には正則化つき回帰がなく、ML.NET の回帰トレーナーは
多項式特徴量を直接扱う形になっていないからです。
結果として、L1 の中身がいちばんよく見える回になりました。

## データセットを作る

```fsharp
/// 元にした多項式 -x^2 + 2 の係数。添字が次数に対応する
let polynomialCoefficients = [| 2; 0; -1 |]

/// 多項式の値を求める。`coefficients.[i]` が x^i の係数
let polynomial (coefficients: int[]) (x: float) =
    coefficients |> Array.mapi (fun i c -> float c * x ** float i) |> Array.sum
```

`float c` と `float i` の変換が 2 つ要ります。係数は `int`、指数も `int` ですが、
`**` 演算子は `float` を要求します。Python なら気づかずに済むところが、
F# では型で明示されます。

正規乱数は Kotlin と同じく Box-Muller 法で作ります。

```fsharp
    // Box-Muller 法で正規乱数を作る。.NET の Random は一様分布しか持たない
    let nextGaussian () =
        let u1 = random.NextDouble()
        let u2 = random.NextDouble()
        sqrt (-2.0 * log u1) * cos (2.0 * Math.PI * u2)
```

`train_test_split` にあたる添字のシャッフルは、Fisher-Yates を書きます。

```fsharp
    // train_test_split と同じく、添字をシャッフルしてから分ける
    let indices = Array.init size id
    for i in size - 1 .. -1 .. 1 do
        let j = random.Next(i + 1)
        let tmp = indices.[i]
        indices.[i] <- indices.[j]
        indices.[j] <- tmp
```

`for i in size - 1 .. -1 .. 1 do` の下降ループが、F# ではやや読みにくいところです。
Kotlin の `shuffled(random)` が 1 語で済んだのと比べると差が出ます。

## 多項式特徴量

Math.NET の `DenseMatrix.init` で 1 式です。

```fsharp
/// x を x, x^2, ..., x^degree の列に展開する。
///
/// scikit-learn の `PolynomialFeatures(include_bias=False)` にあたる。
/// 定数 1 の列を作らないのは、切片を回帰側に任せるためである。
let polynomialFeatures (x: float[]) (degree: int) : Matrix<float> =
    DenseMatrix.init x.Length degree (fun row col -> x.[row] ** float (col + 1))
```

行と列の添字から値を返す関数を渡すだけで行列ができます。
Kotlin の入れ子 `Array { }` より宣言的で、この章でいちばん気持ちよく書けた箇所です。

## 正則化を自分で実装する

Math.NET の `MultipleRegression` には Ridge も Lasso もありません。
[#02](nb02.md) で使った `Svd` は正則化なしの最小二乗だけです。

### 切片を罰則の対象にしない

まず、正則化つき回帰の共通の前処理です。

```fsharp
/// 中心化した特徴量とラベル。正則化つき回帰は切片を罰則の対象にしないので、
/// 平均を引いてから解き、最後に切片を復元する
let private center (features: Matrix<float>) (y: float[]) =
    let means = Array.init features.ColumnCount (fun c -> features.Column(c) |> Vector.sum |> fun s -> s / float features.RowCount)
    let yMean = Array.average y
    let centered =
        DenseMatrix.init features.RowCount features.ColumnCount (fun r c ->
            features.[r, c] - means.[c])

    centered, DenseVector.ofArray (y |> Array.map (fun v -> v - yMean)), means, yMean
```

scikit-learn の `Ridge` / `Lasso` は切片を罰則に含めません。
含めてしまうと、データ全体を上下にずらしただけでモデルが変わってしまいます。
中心化してから解き、最後に切片を復元することで同じ挙動にします。

ライブラリを使っていると意識しない設計判断ですが、自分で書くと避けて通れません。

### Ridge は解析解

L2 は閉じた式で解けます。

```fsharp
/// L2 正則化（Ridge）の解析解。(X^T X + alpha I)^-1 X^T y
let private fitRidge (features: Matrix<float>) (y: float[]) (alpha: float) =
    let centered, centeredY, means, yMean = center features y
    let gram = centered.TransposeThisAndMultiply centered
    let regularized = gram + DenseMatrix.identity<float> gram.ColumnCount * alpha
    let coefficients = regularized.Solve(centered.TransposeThisAndMultiply(centeredY))
    restoreIntercept means yMean coefficients
```

`X^T X` に `alpha * I` を足すだけです。この 1 行が、
**[#02](nb02.md) で見たランク落ちを解消する仕組みそのもの** です。
対角に正の値を足せば、どんな行列も正則になります。
「正則化」という訳語が、ここでは字義どおりの意味を持ちます。

### Lasso は座標降下

L1 には閉じた式がありません。scikit-learn と同じ座標降下法を書きます。

```fsharp
    /// 軟判定しきい値関数。|value| が threshold 以下なら 0 を返す
    let softThreshold value threshold =
        if value > threshold then value - threshold
        elif value < -threshold then value + threshold
        else 0.0

    let mutable residual = centeredY - centered * coefficients

    for _ in 1..1000 do
        for c in 0 .. columns - 1 do
            if normalizers.[c] > 1e-12 then
                let column = centered.Column c
                // c 番目の寄与を残差に戻してから、その座標だけを解き直す
                let partial = residual + column * coefficients.[c]
                let rho = column * partial / n
                let updated = softThreshold rho alpha / normalizers.[c]
                residual <- partial - column * updated
                coefficients.[c] <- updated
```

**`softThreshold` の `else 0.0` が、L1 が疎な解を出す理由のすべてです。**
座標を 1 つずつ解き直すとき、その座標の寄与 `rho` が罰則 `alpha` を超えなければ、
係数はちょうど 0 に落とされます。

L2 の解析解にはこの分岐がないので、値は小さくなっても 0 にはなりません。
「L1 は特徴量選択になり、L2 はならない」という教科書的な説明の中身が、
この 4 行に収まっています。

残差 `residual` を更新しながら回すのは計算量のためです。
毎回 `centeredY - centered * coefficients` を計算し直すと、
1 座標あたり行列積が発生します。差分だけ更新すればベクトル演算 2 回で済みます。

## 結果は scikit-learn と同じ性質になる

自前実装の Lasso は、原著と同じく **係数を厳密にゼロにします**。

```fsharp
[<Fact>]
let ``自前の Lasso は係数を厳密なゼロにする`` () =
    let model = trainPolynomialRegression dataset.XTrain dataset.YTrain Degree L1 0.01

    // 軟判定しきい値関数を通すので、多くの係数がちょうど 0 になる
    let zeros = model.Coefficients |> Array.filter (fun c -> c = 0.0) |> Array.length
    Assert.True(zeros >= Degree / 2, $"zeros={zeros}")
```

実測で 20 個中 **18 個が 0** になりました。原著（19 個）とほぼ同じ挙動です。
既製ライブラリを使った Kotlin 版が 0 個だったのと対照的です。

## 3 言語の比較

データ生成の乱数列が言語ごとに違うので、数値そのものは比較できません。**性質を比べます**。

| 実装 | L1 の実装 | 正則化なし RMSE | 正則化なしの最大係数 | L1 RMSE | L1 の厳密なゼロ | L2 RMSE |
| :--- | :--- | ---: | ---: | ---: | ---: | ---: |
| 原著 | scikit-learn | 1862.044 | 約 1.0e7 | 0.152773 | 19 / 20 | 0.103708 |
| Python | scikit-learn | 12.924 | 8,633 | 0.152773 | 19 / 20 | 0.103708 |
| Kotlin | Smile | 0.122 | 76,037 | 0.105 | 0 / 20 | 0.099 |
| **F#** | **自前の座標降下** | 1.164 | **2,074,928** | 0.129 | **18 / 20** | 0.125 |

正則化なしの最大係数が **207 万** と、3 言語でいちばん大きくなりました。
[#02](nb02.md) と同じく、Math.NET の SVD が特異値の打ち切りを行わないためです。
条件数が 9 億に達する多項式特徴量では、その差がそのまま係数に出ます。

**皮肉なことに、この不安定さのおかげで原著の「正則化なしは壊滅的」という主張が
いちばんよく再現できました。** Python の 12.9、Kotlin の 0.12 に対し、F# は 1.16 です。

## この章で F# が効いた場面・効かなかった場面

| 場面 | 評価 |
| :--- | :--- |
| 多項式特徴量 | **効いた** — `DenseMatrix.init` が宣言的 |
| 軟判定しきい値関数 | **効いた** — 3 分岐の式が仕様そのままの形 |
| 正則化の切り替え | **効いた** — 判別共用体 + `match` の網羅性検査 |
| 型変換 | 引き分け — `float` 変換が要るが、意図が明示される |
| 添字のシャッフル | **効かなかった** — 下降ループが読みにくい |
| 正規乱数 | **効かなかった** — Box-Muller を自前で書く |
| 正則化つき回帰 | **効かなかった** — ライブラリに無く Ridge も Lasso も自前 |
| SVD の数値安定性 | **効かなかった** — #02 と同じく係数が発散する |

ライブラリの手当てはいちばん薄い言語ですが、**その代わりアルゴリズムがよく見えます**。
「ライブラリ版」の連載でありながら、この章の F# は自前実装版に近い読み味になりました。
