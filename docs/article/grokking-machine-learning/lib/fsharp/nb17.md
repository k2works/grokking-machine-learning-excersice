# ノートブック #17 SVM 用のデータセットを作る（F# 版）

原著ノートブック: `Chapter_11_Support_Vector_Machines/Building_the_datasets.ipynb`

第 11 章（SVM）で使う 3 つのデータセットを **乱数で作る** 回です。

原著は乱数の種を固定していないので、**生成そのものは再現できません**。
代わりに「配布されている CSV が本当にその規則で作られたのか」を検算しました。
考え方は [Python 版](../python/nb17.md) に書いています。ここでは F# 側の話をします。

## 規則をレコードに持たせる

原著は 3 つのデータセットを **コピペで 3 回書いて** います。
違うのはループ回数と `z = ...` の 1 行だけなので、その違いだけをレコードにまとめました。

```fsharp
/// 1 つのデータセットの作り方
type Spec =
    { Name: string
      /// 規則どおりに作る点の数
      Points: int
      /// ラベルを乱数にする点（ノイズ）の数
      Noise: int
      /// ラベルを決める規則
      Rule: float -> float -> int }

    member this.Total = this.Points + this.Noise
```

```fsharp
let linear =
    { Name = "linear"
      Points = 50
      Noise = 10
      Rule = linearRule }
```

**関数がレコードのフィールドになる** のは F# では自然な書き方です。
Kotlin 版は `::linearRule` と関数参照を書きますが、F# は関数名をそのまま置けます。

## 生成器は 1 つで済む

```fsharp
let generate (spec: Spec) (seed: int) =
    let random = System.Random(seed)
    let coordinate () = CoordScale * random.NextDouble() + CoordOffset

    let points =
        List.init spec.Points (fun _ ->
            let x = coordinate ()
            let y = coordinate ()
            { X1 = x; X2 = y; Y = spec.Rule x y })

    let noise =
        List.init spec.Noise (fun _ ->
            let x = coordinate ()
            let y = coordinate ()
            { X1 = x; X2 = y; Y = random.Next(0, 2) })

    points @ noise
```

`coordinate ()` に **空の括弧が必須** なのが F# らしいところです。
`let coordinate = ...` と書くと、それは「1 回だけ評価された値」になり、
4 か所すべてに同じ座標が入ってしまいます。

`unit` 引数の有無が「毎回計算する」か「1 回だけ計算する」かを分けます。
[#16](nb16.md) で `let axis = ...` を値として書いたのと、ちょうど逆の使い分けです。
**副作用のある関数は、括弧で「これは呼び出しだ」と示す** 必要があります。

## 検算の結果は Python 版と完全に一致する

```fsharp
[<Fact>]
let ``違反はすべてノイズ部分にあり約半数`` () =
    // ノイズはラベルを 0 か 1 で振り直すので、規則と食い違うのは約半分
    let expected = dict [ "linear", 5; "one_circle", 7; "two_circles", 12 ]

    for spec in specs do
        let violations = ruleViolations spec (load spec)
        Assert.Equal(expected.[spec.Name], violations.Length)
        Assert.True(violations |> List.forall (fun i -> i >= spec.Points))
        let ratio = float violations.Length / float spec.Noise
        Assert.True(ratio >= 0.2 && ratio <= 0.8)
```

| データセット | ノイズの数 | 規則に違反した数 |
| :--- | ---: | ---: |
| `linear` | 10 | 5 |
| `one_circle` | 10 | 7 |
| `two_circles` | 20 | 12 |

**3 言語すべてで同じ数** です。規則は四則演算と比較だけなので、
与えられた点をそのまま判定する限り、言語差の入る余地がありません。

## `**` は `pown` ではない

```fsharp
let twoCirclesRule (x: float) (y: float) =
    let left = (x - 1.0) ** 2.0 + y * y < 2.0
    let right = (x + 1.0) ** 2.0 + y * y < 2.0
    if left || right then 1 else 0
```

F# の `**` は浮動小数点の冪乗（`Math.Pow`）です。
指数も `float` でなければならないので `2.0` と書きます。`2` では型エラーです。

整数の冪乗が要るときは `pown x 2` を使いますが、ここでは `float` なので `**` のままです。
`y * y` と書いている箇所は、単に掛け算のほうが速く、精度も同じだからです。

## 種を揃えても Python とは違う点が出る

```fsharp
[<Fact>]
let ``同じ種でもPythonとは違う点が出る`` () =
    // .NET の Random と Python の random は別のアルゴリズム（Python は
    // メルセンヌツイスタ）。種を揃えても一致しない。
    // Python 版の同じ種での 1 点目は 2.0665311091502883
    Assert.NotEqual(2.0665311091502883, (generate linear 0).Head.X1)
```

Python の `random` はメルセンヌツイスタ、.NET の `System.Random` は別方式です。
**種を揃えても同じ数列は出ません。**

つまり **もし原著が種を固定していたとしても、移植では再現できませんでした。**
このノートブックが再現不能なのは原著の不備というより、
乱数列を言語をまたいで一致させることが原理的に難しいためです。

なお .NET の `System.Random` は **.NET Core 3.0 で実装が変わりました**。
同じ .NET でも版によって数列が違います。
乱数列に依存したテストは、言語をまたがなくても壊れます。
