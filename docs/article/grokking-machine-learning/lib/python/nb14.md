# #14 ニューラルネットワークで住宅価格を予測（Python）

原著ノートブック: `Chapter_10_Neural_Networks/House_price_predictions_neural_network.ipynb`

ニューラルネットワークを **回帰** に使う回です。
[#02](nb02.md) と同じハイデラバードの住宅データを、今度は 3 層のネットワークで予測します。

分類（[#13](nb13.md)）との違いは 2 つだけです。
**出力層に活性化関数を付けない** ことと、**損失を平均二乗誤差にする** こと。

## 特徴量の作り方が #02 と違う

```python
def features(housing: pd.DataFrame) -> pd.DataFrame:
    """`Location`（文字列）と `Price`（目的変数）を落とした 38 列。

    [#02](nb02.md) は `Location` を one-hot 符号化して 277 列にしたが、
    ここでは **捨てている**。ニューラルネットワークは特徴量が増えると
    パラメータも増えるので、原著は簡単なほうを選んだと思われる。
    """
    return housing.drop(["Location", "Price"], axis=1)
```

同じデータ・同じ著者なのに、章によって前処理が違います。

| | [#02](nb02.md)（線形回帰） | #14（ニューラルネットワーク） |
| :--- | :--- | :--- |
| `Location` | one-hot で 239 列に展開 | **捨てる** |
| 数値列の標準化 | `Area` と `No. of Bedrooms` を標準化 | **しない** |
| 欠損行 | 末尾 84 行を落とす | **落とさない** |
| 最終的な列数 | 277 | 38 |
| 行数 | 2434 | 2518 |

**同じ問題の前処理が、章をまたぐと揃っていません。**
本としては各章で完結させたいのでしょうが、
読者が「どちらが正しいのか」と迷う箇所です。

## 出力層に活性化関数を付けない

```python
def build_model(input_dim: int = 38):
    """原著と同じ形のネットワークを組む。

    出力層 `Dense(1)` に活性化関数を指定していないのが回帰の書き方。
    指定しないと恒等関数になり、**値をそのまま出す**。
    分類（[#13](nb13.md)）では `softmax` を付けて確率にしていた。
    """
```

```python
def test_出力層は活性化関数を持たない() -> None:
    # 回帰なので値をそのまま出す。分類（#13）は softmax を付けていた
    output_layer = build_model().layers[-1]

    assert output_layer.units == 1
    assert output_layer.activation.__name__ == "linear"
```

Keras は活性化関数を省略すると `linear`（恒等関数）になります。
**「何も書かない」ことが「そのまま出す」を意味する** という規約です。
明示的に `activation="linear"` と書くこともできますが、原著は省略しています。

## パラメータ数は完全に一致する

```python
def test_パラメータ数は原著と同じ14795() -> None:
    # 原著の model.summary() が出す Total params: 14,795
    assert build_model().count_params() == 14795
    assert (38 * 38 + 38) + (38 * 128 + 128) + (128 * 64 + 64) + (64 * 1 + 1) == 14795
```

| 層 | 重み | バイアス | 小計 |
| :--- | ---: | ---: | ---: |
| Dense(38) | 38 × 38 = 1444 | 38 | 1482 |
| Dense(128) | 38 × 128 = 4864 | 128 | 4992 |
| Dense(64) | 128 × 64 = 8192 | 64 | 8256 |
| Dense(1) | 64 × 1 = 64 | 1 | 65 |
| **合計** | | | **14795** |

[#13](nb13.md) と同じく、**パラメータ数だけは版によらず決まります**。
学習結果は再現できなくても、ここは固定できます。

## RMSE を指標に足す理由

```python
def compile_model(model):
    """損失を平均二乗誤差にし、指標に RMSE を足す。

    原著のコメントどおり、`metrics` に RMSE を入れると
    エポックごとに「平均どれくらい外したか」が円単位で読める。
    損失（MSE）は 2 乗なので桁が大きすぎて読めない。
    """
```

原著の学習ログを見ると、その意味が分かります。

```text
Epoch 1/10  loss: 181014534029312.0000 - root_mean_squared_error: 13430808.0000
```

**損失は 1.8 × 10¹⁴。読めません。** 価格が 1000 万の桁なので、
2 乗すると 10¹⁴ になります。RMSE なら 1343 万円と、意味のある単位です。

原著はこの理由をコードのコメントに書いています。

```python
# The metrics flag is added for the model to report the root mean squared error at each epoch.
```

## 「平均を答えるだけ」を基準にする

```python
def baseline_rmse(housing: pd.DataFrame) -> float:
    """常に平均価格を答えたときの RMSE。

    これを下回れなければ、ネットワークは何も学習できていない。
    値は価格の標準偏差（母分散のほう）と一致する。
    """
    prices = labels(housing).to_numpy(dtype=float)
    return float(np.sqrt(np.mean((prices - prices.mean()) ** 2)))
```

```python
def test_平均を答えるだけの基準は約877万(housing) -> None:
    # 価格の標準偏差。ネットワークはこれを下回る必要がある
    assert baseline_rmse(housing) == pytest.approx(8_775_370, rel=1e-3)
```

**877 万円** です。何も学習せず常に平均を答えるだけで、この誤差になります。

原著の `evaluate` は RMSE **554 万円**。基準を 37% 改善しています。
「554 万円も外している」と見るか「877 万から下げた」と見るかで印象が変わりますが、
**基準を出さないと判断できません**。

[#13](nb13.md) の分類では「常に多数派を答える」が基準でした。
回帰では「常に平均を答える」が対応します。
どちらも **特徴量を一切見ないモデル** です。

```python
def test_学習後のRMSEは平均を答えるより良い(housing, trained) -> None:
    # 常に平均価格を答えると約 877 万円外す。それより良くなければ意味がない
    assert evaluate_rmse(trained, housing) < baseline_rmse(housing)
```

## 標準化していないのに動く

```python
def test_特徴量を標準化していない(housing) -> None:
    # 原著は前処理をしていない。Area は 4 桁、Resale は 0 か 1 と桁が違う。
    # #02 の線形回帰では標準化していたのに、ここではしていない
    numeric = features(housing)

    assert numeric["Area"].max() > 1000
    assert set(numeric["Resale"].unique()) <= {0, 1}
```

`Area` は 1000 台、`Resale` は 0 か 1。**桁が 3 つ違います**。

普通なら学習が不安定になるところですが、Adam は
**パラメータごとに学習率を調整する** ので、この程度の差は吸収します。

Kotlin と F# ではこれが効きました。両方とも標準化しないと発散します。
**「前処理しなくても動く」のは Adam のおかげ** だったと、
移植して初めて分かりました。
