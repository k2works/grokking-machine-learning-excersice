# #06 IMDB レビューの感情分析（Python）

原著ノートブック: `Chapter_06_Logistic_Regression/Sentiment_analysis_IMDB.ipynb`

映画レビュー 50000 件を、単語の出現回数だけからロジスティック回帰で肯定・否定に分類します。
[#05](nb05.md) と同じアルゴリズムを、8 点から 50000 件・2000 次元へ拡大した回です。

**読みどころは、学習した係数がそのまま「単語の感情スコア」として読めること。**
`wonderfully` は +1.38、`waste` は -1.90。モデルが何を根拠に判断しているかが、
係数の並びを見るだけで分かります。

## CountVectorizer が何をしているか

この章の実質は `CountVectorizer` です。**既定の挙動が結果をすべて決めています。**

```python
def build_vectorizer(max_features: int = MAX_FEATURES) -> CountVectorizer:
    """原著と同じ設定の `CountVectorizer` を作る。

    既定の挙動が結果を決めているので、明示しておく。
    - 小文字化する
    - トークンは正規表現 `(?u)\\b\\w\\w+\\b`（2 文字以上の単語）
    - `stop_words='english'` で scikit-learn 内蔵の 318 語を除く
    - 残った語を **コーパス全体の出現回数** で並べ、上位 `max_features` 語を採る
    """
    return CountVectorizer(max_features=max_features, stop_words="english")
```

4 つの規則をそれぞれテストで固定しました。ドキュメントを読むより、
テストのほうが挙動が確実に分かります。

```python
def test_ベクトル化は2文字以上の単語だけを拾う() -> None:
    # 既定のトークン正規表現は (?u)\b\w\w+\b なので 1 文字の語は落ちる
    vectorizer = build_vectorizer(max_features=50)
    vectorizer.fit(["a wonderful movie", "I saw it"])

    assert "wonderful" in vectorizer.get_feature_names_out()
    assert "a" not in vectorizer.get_feature_names_out()
```

```python
def test_max_featuresは出現回数の上位を採る() -> None:
    vectorizer = build_vectorizer(max_features=2)
    # rare は 1 回、common は 3 回、middle は 2 回
    vectorizer.fit(["common middle rare", "common middle", "common"])

    assert sorted(vectorizer.get_feature_names_out().tolist()) == ["common", "middle"]
```

**語彙は最後に辞書順に並べ替えられます。** `get_feature_names_out()` の順序が
そのまま特徴量の添字なので、`model.coef_[0][i]` と `feature_names[i]` が対応します。
この対応があるからこそ、係数を単語の重みとして読めます。

## 係数を単語の重みとして読む

```python
def word_sentiments(trained: SentimentModel) -> pd.DataFrame:
    """単語と、その係数（感情スコア）の対応表。

    ロジスティック回帰の係数がそのまま「この単語が出ると肯定に傾く度合い」になる。
    出現回数を特徴量にしているからこそ、係数を単語の重みとして読める。
    """
    return pd.DataFrame(
        {"word": trained.vocabulary, "weight": trained.model.coef_[0]}
    )
```

原著の上位 10 語と、実測を並べます。

| ---: | :--- | ---: | :--- | ---: |
| 1 | wonderfully | 1.406897 | wonderfully | 1.384286 |
| 2 | funniest | 1.180192 | funniest | 1.175593 |
| 3 | gem | 1.167712 | gem | 1.170125 |
| 4 | brilliantly | 1.133609 | brilliantly | 1.096957 |
| 5 | subtle | 1.089913 | subtle | 1.088578 |
| 6 | superb | 1.057145 | superb | 1.043858 |
| 7 | excellent | 1.041048 | excellent | 1.040871 |

| 9 | delightful | 1.022307 | delightful | 0.993231 |

**10 語すべて、順序まで一致しました。** 係数は小数第 2 位あたりで分かれますが、
[#05](nb05.md) と同じく lbfgs の収束判定の差です。

```python
@imdb_required

    #   wonderfully funniest gem brilliantly subtle superb excellent finest
    #   delightful underrated

    assert most_positive_words(trained)["word"].tolist() == [
        "wonderfully", "funniest", "gem", "brilliantly", "subtle",

```

### 否定側は順序が入れ替わる

| 原著 | 原著の係数 | 実測 | 実測の係数 |
| :--- | ---: | :--- | ---: |
| waste | -1.909643 | waste | -1.903540 |
| disappointment | -1.702930 | disappointment | -1.698846 |
| worst | -1.572323 | worst | -1.573172 |
| unfunny | -1.516260 | **laughable** | -1.477971 |
| dreadful | -1.487464 | **awful** | -1.440656 |
| laughable | -1.476227 | **dreadful** | -1.438085 |
| awful | -1.444837 | **unfunny** | -1.424104 |
| redeeming | -1.417769 | **poorly** | -1.407998 |
| poorly | -1.416011 | **redeeming** | -1.402523 |
| tedious | -1.412575 | tedious | -1.382008 |

上位 3 語は一致し、4 位以下で入れ替わります。
係数が **-1.48 から -1.38 の 0.1 の幅に 7 語が固まっている** ので、
収束判定のわずかな差が順位を動かします。

テストは「集合として一致すること」と「上位 3 語は順序も一致すること」に分けました。

```python
@imdb_required
def test_もっとも否定的な10語は原著と同じ集合になる(trained) -> None:
    # 係数が -1.48 から -1.38 の狭い範囲に固まっているため、lbfgs の収束差で
    # 4 位以下の順序が入れ替わる。集合としては一致する

    assert sorted(most_negative_words(trained)["word"].tolist()) == sorted([...])
    # 上位 3 語は順序まで一致する
    assert most_negative_words(trained)["word"].tolist()[:3] == [
        "waste", "disappointment", "worst",
    ]
```

**「一致する」の粒度を、データの性質に合わせて選ぶ** のがこの章のテスト設計です。
順序まで固定すると、意味のない差でテストが赤くなります。

## 語彙の添字まで一致した

原著の出力には、上位語の **行番号** が残っています。

```text
1964  wonderfully  1.406897
1921  waste       -1.909643
```

実測でも `wonderfully` は 1964、`waste` は 1921 でした。
語彙は辞書順なので、**添字が一致するということは 2000 語の並びがほぼ同じ** ということです。

ただし完全には一致しません。`laughable` が原著の 1009 に対し実測は 1010、
`poorly` が 1337 に対し 1338、`redeeming` が 1440 に対し 1441 と、
**3 語だけ 1 つずれています**。一方 `tedious`（1756）や `unfunny`（1858）はずれていません。

添字 1009 のあたりに語が 1 つ増え、1441 と 1756 のあたりで 1 つ減った、
という形です。scikit-learn の版が上がる過程で、
上位 2000 語の境目付近にある語の扱いが変わったと考えられます。

## 極端なレビューは完全に一致する

```python
def extreme_review_indices(trained: SentimentModel) -> tuple[int, int]:
    """もっとも肯定的・否定的と判定されたレビューの行番号を返す。"""
    probabilities = predicted_probabilities(trained)
    return int(np.argmax(probabilities)), int(np.argmin(probabilities))
```

```python
@imdb_required
def test_極端なレビューの行番号は原著と同じ(trained) -> None:
    # 原著の出力
    #   Most Positive Review: 42946（ジブリ「天空の城ラピュタ」英語吹替のレビュー）
    #   Most Negative Review: 13452（ゾンビ映画 Zombi 3 のレビュー）
    positive, negative = extreme_review_indices(trained)

    assert positive == 42946
    assert negative == 13452
```

**行番号がぴったり一致します。** 係数が小数第 2 位で違っても、
50000 件のなかで「もっとも肯定的」と判定されるレビューは変わりません。
極端な例は、モデルのわずかな違いでは動かないということです。

否定側の予測確率は `2.6e-17`。原著の `2.35e-17` と同じ桁です。
シグモイドの出力がここまで 0 に張り付くのは、
このレビューに否定語が大量に含まれているためです。

## まとめ

| 項目 | 原著と一致するか |
| :--- | :--- |
| 語彙のサイズ（2000 語） | 完全一致 |
| 語彙の添字 | ほぼ一致（2000 語中 3 語が 1 つずれる） |
| 肯定的な上位 10 語 | **順序まで完全一致** |
| 否定的な上位 10 語 | 集合は一致、4 位以下の順序が入れ替わる |
| 係数の値 | 小数第 2 位で分かれる（lbfgs の収束差） |
| 極端なレビューの行番号 | **完全一致**（42946 / 13452） |

Kotlin 版・F# 版では、そもそも `CountVectorizer` に相当するものがありません。
語彙の作り方から自前で書くことになりますが、
**この記事で挙げた 4 つの規則を守れば添字まで再現できました**。
