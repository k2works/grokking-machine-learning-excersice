# #19 カーネルとハイパーパラメータを比べる（Python）

原著ノートブック: `Chapter_11_Support_Vector_Machines/SVM_graphical_example.ipynb`

[#17](nb17.md) で作った 3 つのデータセットに、いろいろな SVM を当てる回です。

- 直線データに線形カーネル。`C` を変えて正則化の効き方を見る
- 円データに多項式カーネル。`degree` を変える
- 二重円データに RBF カーネル。`gamma` を変える

原著は図を 9 枚並べますが、**正解率も数字で印刷されています**。
その 9 つがすべて突き合わせの対象になります。

## 9 通りを 1 つの関数にまとめる

原著は 9 通りをコピペで並べています。

```python
svm_gamma_01 = SVC(kernel='rbf', gamma=0.1)
svm_gamma_01.fit(features, labels)
print("Gamma = 0.1")
print("Accuracy:", svm_gamma_01.score(features, labels))
plot_model(features, labels, svm_gamma_01)
```

これが 4 回続きます。実装では引数だけを変える形にしました。

```python
def fit(data: pd.DataFrame, **kwargs) -> SVC:
    """`SVC` に渡す引数だけを変えて学習する。

    原著は 9 通りをコピペで並べているので、ここでは 1 つにまとめた。
    """
    model = SVC(**kwargs)
    model.fit(features(data), labels(data))
    return model
```

`**kwargs` をそのまま `SVC` に渡すので、**原著のどの呼び出しも書ける** ままです。
テストは `parametrize` で 9 通りを回します。

```python
@pytest.mark.parametrize(
    ("gamma", "expected"),
    [
        (0.1, 0.8772727272727273),
        (1, 0.9045454545454545),
        (10, 0.9636363636363636),
        (100, 0.990909090909091),
    ],
)
def test_RBFのgammaを変える(gamma, expected) -> None:
    # 原著の出力: gamma を 0.1 -> 1 -> 10 -> 100 と上げると正解率も上がる
    assert fit_and_score("two_circles", kernel="rbf", gamma=gamma) == pytest.approx(
        expected, rel=1e-15
    )
```

**9 つとも 16 桁一致です。**

原著が実行したのは scikit-learn 0.22 頃（`SVC` の repr から分かります）、
こちらは 1.9。**7 年ぶんの版差を挟んでも数字が動きません。**

SVM は凸最適化で解が一意に決まり、libsvm の実装も安定しているためです。
[#13](nb13.md)〜[#15](nb15.md) のニューラルネットワークが
1 回も再現できなかったのと対照的です。

## `C` は既定値がいちばん良い

```python
def test_Cは既定値が一番良い() -> None:
    # C = 1（既定）が 0.933 で、0.01 と 100 のどちらより良い。
    # 小さすぎると正則化が強すぎ、大きすぎると外れ値に引きずられる
    default = fit_and_score("linear", kernel="linear")

    assert default > fit_and_score("linear", kernel="linear", C=0.01)
    assert default > fit_and_score("linear", kernel="linear", C=100)
```

`C = 1`（既定）が 0.933、`C = 0.01` が 0.867、`C = 100` が 0.917。

原著は図で「`C` が小さいと誤分類を許す幅の広い境界、
大きいと誤分類を許さない狭い境界」と説明します。
**その両極端はどちらも既定より悪い** ことが、数字で確かめられます。

このデータは [#17](nb17.md) で **ノイズを 10 件混ぜて** 作られています。
`C = 100` はそのノイズまで正しく分けようとして、かえって全体を崩します。

## `gamma` は上げるほど「良く」なる

```python
def test_gammaを上げるほど正解率が単調に上がる() -> None:
    # 0.877 -> 0.905 -> 0.964 -> 0.991。
    # ただしこれは **学習データに対する** 正解率で、過学習が進んでいるだけ
    scores = [
        fit_and_score("two_circles", kernel="rbf", gamma=gamma)
        for gamma in (0.1, 1, 10, 100)
    ]

    assert scores == sorted(scores)
```

きれいな単調増加です。しかし **これは良い知らせではありません**。

```python
def test_gamma100は221件中2件しか外さない() -> None:
    # 0.990909... = 218/220。データにはノイズを 20 件混ぜてあるのに、
    # そのほとんどを覚えてしまっている
    data = load("two_circles")
    model = fit(data, kernel="rbf", gamma=100)
    wrong = (model.predict(data[["x_1", "x_2"]].to_numpy()) != labels(data)).sum()

    assert wrong == 2
```

220 件のうち **外したのは 2 件だけ**。
このデータには [#17](nb17.md) で **でたらめなラベルを 20 件** 混ぜてあります。
規則では説明できないはずの点まで当てているのですから、
**丸暗記している** ということです。

原著もこの図を「gamma を上げすぎると過学習する」例として使っています。
ただし **原著は検証データを用意していません**。
「学習データの正解率が上がる = 良い」と読めてしまう並びなので、
ここは数字の意味をテスト名に書き込みました。

## RBF は遠くを見ない

```python
def test_gamma100はデータの外側では何も答えられない() -> None:
    # RBF は局所的で、gamma が大きいほど影響範囲が狭い。
    # データの範囲（-3〜3）から離れると、決定関数はほぼ 0 になる
    data = load("two_circles")
    model = fit(data, kernel="rbf", gamma=100)

    assert abs(model.decision_function([[10.0, 10.0]])[0]) < 1.0
```

[#18](nb18.md) で見た「RBF は外挿しない」性質が、
`gamma = 100` ではさらに強く出ます。`gamma` が大きいほど各点の影響範囲が狭く、
**データが 1 つも無い場所では判断を放棄します**。

過学習したモデルほど、知らない場所で自信を持たない。
これ自体は悪くない性質です。
