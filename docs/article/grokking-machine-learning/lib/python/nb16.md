## 図しか出ないノートブックをどう検証するか

原著は `plot_function(line_1)` のように関数を渡して図を描くだけです。
`assert` すべき数値がありません。

そこで、原著の描画コードから **判定の部分だけを取り出しました**。

```python
def classify(f, a: float, b: float) -> int:
    """原著の `h(x, y) = f(x, y) >= 0.5`。境界はこの判定で決まる。"""
    return 1 if f(a, b) >= DECISION_THRESHOLD else 0
```

原著の `plot_function` の中身は、この `h` を格子上で評価して
`contourf` に渡しているだけです。**図の色は `h` の値そのもの** なので、
`h` を数えれば図を数値化できます。

```python
def region_ratio(f) -> float:
    """格子のうち、1 と判定される点の割合。

    図を見なくても「境界がどこにあるか」を数値で比べられる。
    """
    xx, yy = grid()
    values = np.array([classify(f, x, y) for x, y in zip(xx.ravel(), yy.ravel(), strict=True)])
    return float(values.mean())
```

**図を「青い領域が全体の何割か」という 1 つの数に潰します。**
境界の形までは分かりませんが、「広がったか狭まったか」は追えます。

## 2 層目は OR ではなく AND

```python
def nn_with_step(a: float, b: float) -> int:
    """階段関数だけで組んだネットワーク。

    2 層目は `line_1 + line_2 - 1.5 >= 0`。1 層目の出力は 0 か 1 なので、
    和が 1.5 以上になるのは **両方とも 1 のときだけ**。つまり AND である。
    しきい値が 0.5 でも 1.5 でもなく **1.5 であることが AND を作っている**。
    """
```

```python
def test_2層目はANDになっている(dataset) -> None:
    # 1 層目の出力は 0 か 1。その和が 1.5 以上になるのは両方 1 のときだけ
    assert nn_with_step(1, 1) == 1
    assert nn_with_step(2, 0) == 0  # line_2 だけが 1
    assert nn_with_step(0, 2) == 0  # line_1 だけが 1
```

バイアス `-1.5` の 1 つの数が、論理演算の種類を決めています。
`-0.5` なら OR、`-1.5` なら AND です。

領域の割合でも確かめられます。

```python
def test_ANDの領域は各直線より狭い() -> None:
    assert region_ratio(nn_with_step) == pytest.approx(0.5544, abs=1e-4)
    assert region_ratio(nn_with_step) < region_ratio(line_1)
```

| 関数 | 1 と判定される割合 |
| :--- | ---: |
| `line_1` | 0.6419 |
| `line_2` | 0.6419 |
| `bias` | 1.0 |
| `nn_with_step` | **0.5544**（各直線より狭い） |

AND なら共通部分なので狭くなるはずで、実際に狭くなりました。

## シグモイド版は 1 点だけ外している

これが最大の発見です。

```python
def test_シグモイド版は1点だけ外す(dataset) -> None:
    # aack=1 beep=1 の点だけ 0 と答える。正解は 1
    assert predictions(nn_with_sigmoid, dataset) == [0, 0, 0, 0, 0, 1, 1, 1]
    assert accuracy(nn_with_sigmoid, dataset) == 0.875
```

| ネットワーク | 8 点の正解率 |
| :--- | ---: |
| `nn_with_step`（階段関数） | **1.0** |
| `nn_with_sigmoid`（シグモイド） | **0.875** |

原著は 2 つの図を並べて「同じ境界が滑らかになった」と見せますが、
**シグモイド版は `aack=1, beep=1` のエイリアンを不幸せと判定します。**
正解は幸せです。

なぜか。

```python
def test_外した点は判定の境目にある() -> None:
    # 0.4905 で、しきい値 0.5 をわずかに下回る
    assert nn_with_sigmoid(1, 1) == pytest.approx(0.4905304218, rel=1e-9)
    assert classify(nn_with_sigmoid, 1, 1) == 0
```

**0.4905。しきい値 0.5 を 0.0095 だけ下回っています。**
図の上ではこの点は境界線のほぼ真上にあり、
どちら側にあるか目では判別できません。

原著が悪いわけではありません。この章の目的は
「シグモイドにすると境界が滑らかになる」を見せることで、
分類の正しさは論点ではないからです。
ただ **図だけを見ていたら気付けない差** でした。

## シグモイドは飽和する

外した理由をもう少し追うと、シグモイドの性質に行き着きます。

```python
def test_シグモイドは出力が飽和する() -> None:
    # 内側のシグモイドが 1 に近づくので、外側は sigmoid(0.5) で頭打ちになる
    assert nn_with_sigmoid(2, 2) == pytest.approx(0.6224593117, rel=1e-9)
    assert nn_with_sigmoid(3, 3) == pytest.approx(0.6224593312, rel=1e-9)
    # 3 倍離れてもほとんど変わらない
    assert nn_with_sigmoid(3, 3) - nn_with_sigmoid(2, 2) < 1e-7
```

内側のシグモイドは最大でも 1 なので、外側に入る値は最大 `1 + 1 - 1.5 = 0.5`。
**出力は `sigmoid(0.5) = 0.6225` で頭打ち** です。

つまりこのネットワークの出力は **0.18〜0.62 の範囲しか動きません**。
しきい値 0.5 はその範囲の上のほうにあり、境界が階段版よりわずかに内側に寄ります。
`(1, 1)` はちょうどその「わずか」の中に落ちました。

階段関数を同じ重みでシグモイドに置き換えると、
**バイアスの意味が変わってしまう** ということです。

def test_2つのネットワークの境界はほぼ重なる() -> None:

49 万点のうち **0.48%（約 2350 点）だけ** 判定が違います。

そしてデータの 8 点のうち 1 点が、その 0.48% の中にありました。

## `exp(x) / (1 + exp(x))` という書き方

```python
def sigmoid(x: float) -> float:
    """原著の書き方 `exp(x) / (1 + exp(x))` をそのまま使う。

    数学的には `1 / (1 + exp(-x))` と同じだが、**桁あふれの向きが逆**になる。
    こちらは x が大きいときに `exp(x)` が無限大になり、
    `inf / inf` で NaN を返す。原著が図を描く範囲（-0.5〜3）では
    最大でも `exp(45)` なので問題は起きない。
    """
    return float(np.exp(x) / (1.0 + np.exp(x)))
```

一般に使われるのは `1 / (1 + exp(-x))` です。こちらは x が **小さい** ときに
`exp(-x)` が発散しますが、分母が無限大なら結果は 0 になるだけで NaN にはなりません。

原著の書き方は x が **大きい** ときに `inf / inf` で NaN になります。
この章の範囲では起きませんが、**同じ関数を別の場面に持ち込むと壊れます**。
原著どおりに写しつつ、理由をコメントに残しました。
