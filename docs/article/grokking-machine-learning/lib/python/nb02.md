## 面積だけの単回帰

```python
def fit_area_only(data: pd.DataFrame) -> LinearRegression:
    """面積 1 列だけで価格を予測する単回帰。

    `data[['Area']]` と二重の括弧で取り出しているのは、scikit-learn が 2 次元の
    特徴量行列を要求するためである。`data['Area']` では 1 次元になって弾かれる。
    """
    return LinearRegression().fit(data[["Area"]], data["Price"])
```

原著の数値と完全に一致します。

## 前処理

原著は 3 つの手順を踏みます。

```python
def preprocess(data: pd.DataFrame) -> Preprocessed:
    """原著の前処理 3 手順をそのまま行う。"""
    truncated = data[:VALID_ROWS].copy()

    # pandas の std() は既定で不偏分散（ddof=1）を使う。原著もこの既定に乗っている
    standardizer = Standardizer(
        area_mean=truncated["Area"].mean(),
        area_std=truncated["Area"].std(),
        bedrooms_mean=truncated["No. of Bedrooms"].mean(),
        bedrooms_std=truncated["No. of Bedrooms"].std(),
    )
    truncated["Area"] = (truncated["Area"] - standardizer.area_mean) / standardizer.area_std
    truncated["No. of Bedrooms"] = (
        truncated["No. of Bedrooms"] - standardizer.bedrooms_mean
    ) / standardizer.bedrooms_std

    encoded = pd.get_dummies(truncated, columns=["Location"], prefix="Location", dtype=int)

    return Preprocessed(
        features=encoded.drop("Price", axis=1),
        labels=encoded["Price"],
        standardizer=standardizer,
    )
```

### 1. 末尾の 84 行を落とす

```python
#: 原著が欠損ありとして切り落とす位置。これ以降の行は `9` で符号化された欠損を含む
VALID_ROWS = 2434
```

原著は `data[:2434]` と決め打ちで切っています。欠損値が `9` で符号化されている行が
末尾にまとまっているためです。マジックナンバーですが、由来をコメントに残して原著どおりにしました。

### 2. 標準化

`Area` と `No. of Bedrooms` だけを平均 0・標準偏差 1 に揃えます。
ここで **`std()` の既定が `ddof=1`（不偏分散）** であることが効いてきます。
NumPy の `np.std()` は `ddof=0` なので、うっかり混ぜると 3 言語で値が食い違います。

```python
def test_標準化した列は平均0分散1になる(prepared) -> None:
    for column in ["Area", "No. of Bedrooms"]:
        assert prepared.features[column].mean() == pytest.approx(0.0, abs=1e-12)
        # pandas の std() は不偏分散（ddof=1）なのでちょうど 1 になる
        assert prepared.features[column].std() == pytest.approx(1.0, rel=1e-12)
```

平均と標準偏差は `Standardizer` に保持します。**新しい物件を予測するときも、
学習時とまったく同じ値で変換しなければならない** からです。

```python
@dataclass
class Standardizer:
    area_mean: float
    area_std: float
    bedrooms_mean: float
    bedrooms_std: float

    def transform(self, area: float, bedrooms: float) -> tuple[float, float]:
        return (
            (area - self.area_mean) / self.area_std,
            (bedrooms - self.bedrooms_mean) / self.bedrooms_std,
        )
```

原著は `area_mean` などをノートブックのグローバル変数に置き、予測のセルでそれを参照していました。
セルの実行順に依存する書き方なので、値として持ち回る形に変えています。

### 3. one-hot 符号化

`Location` 列を `pd.get_dummies` で 239 個の 0/1 列に展開します。
元の 40 列から `Price` と `Location` を除いた 38 列と合わせて **277 列** になります。

```python
def test_one_hot符号化で277列になる(prepared) -> None:
    # 原著の出力: X_full.loc[0] ... Length: 277
    assert prepared.features.shape == (2434, 277)

    location_columns = [c for c in prepared.features.columns if c.startswith("Location_")]
    # 元の 40 列から Price と Location を除いた 38 列 + 地域の one-hot
    assert len(location_columns) == 277 - 38
```

## 切片が 7.29e17 になる理由

ここが本題です。原著の全特徴量モデルは、切片に `7.289475066216182e+17`
（**7 京 2894 兆**）という値を出しています。住宅価格の予測としては明らかにおかしい数字です。

原因は **one-hot 符号化した地域の列を 1 つも落としていないこと** です。
239 個の地域列は、どの行でもちょうど 1 つだけが 1 になります。つまり **全部足すと常に 1**。
これは切片の列（常に 1）とまったく同じベクトルです。

設計行列がランク落ちし、最小二乗解が **一意に決まりません**。
「切片を 100 増やして地域列を全部 100 減らす」解も同じ当てはまりを持ちます。
どの解が返るかはソルバの実装次第です。

テストで直接確かめています。

```python
def test_設計行列はランク落ちしている(prepared) -> None:
    # one-hot 符号化した地域の列は合計すると常に 1 になり、切片と線形従属になる。
    # そのため最小二乗解が一意に決まらない。原著の切片が 7.29e17 という
    # 非常識な値になっているのはこのため
    design = np.c_[np.ones(len(prepared.features)), prepared.features.values.astype(float)]

    assert np.linalg.matrix_rank(design) == design.shape[1] - 1
```

278 列に対してランクが 277。**きっかり 1 だけ足りません**。
`pd.get_dummies(drop_first=True)` を使えば解消しますが、原著がそうしていないので直しません。
代わりに、この性質をテストで明示しました。

## 一致するもの・しないもの

係数が一意でない以上、**係数を原著と突き合わせても意味がありません**。
一方で **当てはまりの良さ（RMSE）は解の取り方によらず決まります**。そこで検証します。

```python
def test_全特徴量モデルのRMSEは原著とほぼ同じ(prepared, full_model) -> None:
    # 原著の出力: Root Mean Squared Error (RMSE) of the model: 3981401.4927888927
    # 係数は一意でないが、当てはまりの良さは解の取り方によらずほぼ同じになる。
    # 完全一致しないのは最小二乗ソルバの実装差による
    predictions = full_model.predict(prepared.features)

    assert rmse(prepared.labels, predictions) == pytest.approx(3981401.4927888927, rel=1e-5)
```

実測は `3981396.2916407348`。原著の `3981401.4927888927` と **6 桁目で分かれます**。
原著は当時の scikit-learn（`normalize=False` が引数に残っている古い版）で走らせており、
最小二乗ソルバの実装が変わっているためです。

そして単回帰より当てはまりが良くなっていることも確認します。

```python
def test_全特徴量モデルは単回帰より当てはまりが良い(data, prepared, full_model) -> None:
    simple = fit_area_only(data)
    simple_rmse = rmse(data["Price"], simple.predict(data[["Area"]]))
    full_rmse = rmse(prepared.labels, full_model.predict(prepared.features))

    assert full_rmse < simple_rmse
```

## 新しい物件を予測する

原著のこのセルは、コメントに `# prompt: use the model_predict_all to predict...` と
残っており、生成 AI に書かせたコードがそのまま入っています。
条件分岐と警告出力が入り混じって 40 行近くありました。やっていることは 3 つだけです。

```python
def predict_new_house(
    model: LinearRegression,
    prepared: Preprocessed,
    area: float,
    bedrooms: int,
    location: str = "Gachibowli",
) -> float:
    """新しい物件の価格を予測する。

    学習時と同じ列・同じ順序の 1 行を組み立てるのが要点である。one-hot 符号化した
    地域の列は 277 列中 275 列あり、そのうち 1 つだけを 1 にして残りは 0 にする。
    列が 1 つでも欠けたり順序が違ったりすると、scikit-learn が弾くか、
    弾かずに別の特徴量として解釈してしまう。
    """
    columns = prepared.features.columns
    location_column = f"Location_{location}"
    if location_column not in columns:
        raise ValueError(f"学習データに無い地域です: {location}")

    scaled_area, scaled_bedrooms = prepared.standardizer.transform(area, bedrooms)
    row = pd.DataFrame({column: [0] for column in columns})
    row["Area"] = scaled_area
    row["No. of Bedrooms"] = scaled_bedrooms
    row[location_column] = 1

    return float(model.predict(row[columns])[0])
```

原著は地域が見つからないとき警告を出して **そのまま続行** していました。
全地域列が 0 の行は学習データに存在しない形なので、意味のある予測になりません。
ここでは例外にしています。

```python
def test_学習データに無い地域はエラーになる(prepared, full_model) -> None:
    with pytest.raises(ValueError, match="学習データに無い地域"):
        predict_new_house(full_model, prepared, area=1000, bedrooms=3, location="Atlantis")
```

予測値は原著の `6,006,016.00` に対して `6,004,735.31`。0.02% の差です。

```python
def test_新しい物件の予測は原著とほぼ同じ(prepared, full_model) -> None:
    # 原著の出力: Predicted price for a house with size 1000 and 3 bedrooms: 6,006,016.00
    # 係数が一意でないぶん、学習データに無い点の予測もわずかにぶれる
    predicted = predict_new_house(full_model, prepared, area=1000, bedrooms=3)

    assert predicted == pytest.approx(6006016.00, rel=1e-3)
```

学習データの中の点なら解の取り方によらず予測が一致しますが、**この 1 行は学習データに無い点**
なので、選ばれた解の違いがそのまま出ます。

## この章のまとめ

| 求め方 | 切片 | RMSE |
| :--- | ---: | ---: |
| 面積のみの単回帰 | -6,222,669.08 | 原著と完全一致 |
| 全特徴量の重回帰 | 8,947,283.55（原著は 7.29e17） | 3,981,396.29（原著は 3,981,401.49） |

**係数が一意でないモデルを作ってしまうと、再現性が失われます。**
原著が意図した教材ポイントではないと思いますが、実データで前処理をすると
こういうことが起きるという、なかなか良い実例になっています。
