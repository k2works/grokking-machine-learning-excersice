# #03 多項式回帰と L1・L2 正則化（Python）

原著ノートブック: `Chapter_04_Testing_Overfitting_Underfitting/Polynomial_regression_regularization.ipynb`

二次関数 $-x^2 + 2$ の周りに散らした 40 点へ、**次数 20** の多項式を当てはめます。
40 点に 20 次は明らかに過剰です。正則化なしでは激しく過学習し、
L1（Lasso）・L2（Ridge）を入れると収まります。

[#02](nb02.md) では設計行列がランク落ちして解が一意に決まらない問題を見ました。
この章はその **処方箋** にあたります。しかも副産物として、
**正則化を入れると数値が再現するようになる** ことまで見えます。

## データセットを作る

原著は元の多項式を係数のリストで表しています。

```python
#: 元にした多項式 -x^2 + 2 の係数。添字が次数に対応する
POLYNOMIAL_COEFFICIENTS = [2, 0, -1]


def polynomial(coefficients: list[int], x: float) -> float:
    """多項式の値を求める。`coefficients[i]` が x^i の係数。"""
    return sum(coefficients[i] * x**i for i in range(len(coefficients)))
```

添字が次数に対応する並びなので、`[2, 0, -1]` は $2 + 0x - x^2$ です。
定数項が先頭に来るのは慣れるまで読み違えやすいところなので、テストで固定しました。

```python
def test_多項式は係数の添字が次数に対応する() -> None:
    # -x^2 + 2 なので x = 0 で 2、x = 1 で 1、x = 2 で -2
    assert polynomial(POLYNOMIAL_COEFFICIENTS, 0) == 2
    assert polynomial(POLYNOMIAL_COEFFICIENTS, 1) == 1
    assert polynomial(POLYNOMIAL_COEFFICIENTS, 2) == -2
```

40 点を生成し、訓練 32 点・テスト 8 点に分けます。

```python
def generate_dataset(
    size: int = SAMPLE_SIZE,
    seed: int | None = 0,
    test_size: float = 0.2,
    random_state: int = 0,
) -> Dataset:
    """-x^2 + 2 の周りにガウスノイズを載せた点を生成し、訓練とテストに分ける。

    乱数の消費順序は原著と同じ（1 点につき `uniform` → `gauss` の順）。
    順序が変わると生成される点がずれる。
    """
    if seed is not None:
        random.seed(seed)

    x: list[float] = []
    y: list[float] = []
    for _ in range(size):
        sampled = random.uniform(-1, 1)
        x.append(sampled)
        y.append(polynomial(POLYNOMIAL_COEFFICIENTS, sampled) + random.gauss(0, NOISE_STD))

    x_train, x_test, y_train, y_test = train_test_split(
        x, y, test_size=test_size, random_state=random_state
    )
    return Dataset(x, y, x_train, x_test, y_train, y_test)
```

[#01](nb01.md) と同じく、乱数の消費順序が数値の再現を左右します。
生成される点が原著と同じになることを直接確かめています。

```python
def test_生成される点は原著と同じ乱数列になる(dataset) -> None:
    # random.seed(0) のあと uniform → gauss の順で消費する
    assert dataset.x[:4] == pytest.approx([0.688844, -0.482166, 0.022549, -0.393375], abs=1e-6)
```

`train_test_split` は `random_state=0` を渡せば決定的です。
scikit-learn 側の乱数なので、`random.seed()` とは別の系統である点に注意します。

## 多項式特徴量

`PolynomialFeatures` が $x$ を $x, x^2, \dots, x^{20}$ の 20 列に展開します。

```python
def polynomial_features(x: list[float], degree: int) -> NDArray[np.float64]:
    """x を x, x^2, ..., x^degree の列に展開する。

    `include_bias=False` にしているのは、切片を線形回帰側に任せるためである。
    True にすると定数 1 の列が特徴量として入り、切片と二重になる。
    """
    return PolynomialFeatures(degree=degree, include_bias=False).fit_transform(
        np.array(x).reshape(-1, 1)
    )
```

`include_bias=False` は重要です。既定の `True` だと定数 1 の列が入り、
`LinearRegression` が持つ切片と二重になります。まさに [#02](nb02.md) で見た
ランク落ちを、ここで自分から作ってしまうことになります。

## 正則化の切り替え

原著は文字列 `'L1'` / `'L2'` / `None` で分岐していました。`Enum` にします。

```python
class Regularization(Enum):
    """正則化の種類。原著は文字列 'L1' / 'L2' / None で切り替えていた。"""

    NONE = "none"
    L1 = "L1"
    L2 = "L2"
```

```python
    features = polynomial_features(x, degree)
    match regularization:
        case Regularization.L1:
            model = Lasso(alpha=alpha)
        case Regularization.L2:
            model = Ridge(alpha=alpha)
        case Regularization.NONE:
            model = LinearRegression()

    return model.fit(features, np.array(y))
```

`match` 文で書くと、原著の `if / elif / else` より対応が読みやすくなります。
ただし Python の `match` は **網羅性を検査しません**。`Regularization` にケースを足しても
コンパイル時には何も言われず、実行時に `model` が未定義で落ちます。
Kotlin の `when` や F# の `match` とはここが違います。

## L1・L2 の結果は原著と完全に一致する

```python
def test_L1正則化のテスト誤差は原著と同じ数値になる(dataset) -> None:
    # 原著の出力: Square loss on the test set (degree 20): 0.15277291798691608
    model = train_polynomial_regression(
        dataset.x_train, dataset.y_train, DEGREE, Regularization.L1, alpha=0.01
    )

    assert evaluate_model(model, dataset.x_test, dataset.y_test) == pytest.approx(
        0.15277291798691608
    )
```

```python
def test_L2正則化のテスト誤差は原著と同じ数値になる(dataset) -> None:
    # 原著の出力: Square loss on the test set (degree 20): 0.10370797950325954
    model = train_polynomial_regression(
        dataset.x_train, dataset.y_train, DEGREE, Regularization.L2, alpha=0.01
    )

    assert evaluate_model(model, dataset.x_test, dataset.y_test) == pytest.approx(
        0.10370797950325954
    )
```

係数まで一致します。L1 は 20 個の係数のうち **19 個をちょうど 0 にします**。

```python
def test_L1正則化の係数は原著と同じくほとんどゼロになる(dataset) -> None:
    # 原著の出力
    #   1.9373689727450651
    #   [0. -0.83079676 0. -0. ... ]
    model = train_polynomial_regression(
        dataset.x_train, dataset.y_train, DEGREE, Regularization.L1, alpha=0.01
    )

    assert float(model.intercept_) == pytest.approx(1.9373689727450651)
    assert np.count_nonzero(model.coef_) == 1
    # 残った 1 つは x^2 の係数。元の多項式 -x^2 + 2 の -1 に向かっている
    assert model.coef_[1] == pytest.approx(-0.83079676, abs=1e-8)
```

**残った 1 つが `x^2` の係数** というのが、この章のいちばん気持ちのいいところです。
元の多項式は $-x^2 + 2$。L1 は 20 次まで与えられた自由度のなかから、
正解と同じ 2 次の項だけを選び出しています。値も $-0.83$ と、正解の $-1$ に向かっています。

L2 は係数をゼロにはしませんが、小さく保ちます。

```python
def test_L2正則化は係数をゼロにはしないが小さく保つ(dataset) -> None:
    model = train_polynomial_regression(
        dataset.x_train, dataset.y_train, DEGREE, Regularization.L2, alpha=0.01
    )

    # L1 と違いスパースにはならない
    assert np.count_nonzero(model.coef_) == DEGREE
    # それでも正則化なしの数千倍という係数にはならない。実測で最大 0.82
    assert np.abs(model.coef_).max() < 1.0
```

## 正則化なしだけ一致しない

原著は正則化なしのテスト誤差を `1862.044186833804` と出しています。
**この数値は再現しませんでした。** 実測は `12.924`。

原因は [#02](nb02.md) と同じ系統です。次数 20 の多項式特徴量は、
互いに強く相関した列を 20 本並べることになり、**条件数が 9 億** に達します。

```python
def test_正則化なしの多項式特徴量は条件数が悪い(dataset) -> None:
    # 原著の「正則化なし 1862.044」が再現しない理由。行列はフルランクだが
    # 条件数が 9 億に達し、ソルバの実装差がそのまま結果に出る
    features = polynomial_features(dataset.x_train, DEGREE)
    design = np.c_[np.ones(len(features)), features]
    singular_values = np.linalg.svd(design, compute_uv=False)

    assert np.linalg.matrix_rank(design) == design.shape[1]
    assert singular_values[0] / singular_values[-1] > 1e8
```

ノートブック #02 と違い **ランク落ちはしていません**（フルランク 21）。それでも条件数が悪いので、
ソルバの実装差が結果に大きく出ます。原著の当時の scikit-learn では係数が $10^7$ まで、
いまの版では $8633$ までしか膨らみません。

```python
def test_正則化なしは係数が爆発する(dataset) -> None:
    model = train_polynomial_regression(dataset.x_train, dataset.y_train, DEGREE)

    # 元の多項式の係数は -1 と 2 だけなのに、実測で最大 8633 まで膨らむ。
    # 原著の当時の scikit-learn では 1e7 に達していた（ソルバの実装差）
    assert np.abs(model.coef_).max() > 1_000
```

### ここに気づきがある

**L1・L2 は 15 桁一致し、正則化なしだけ一致しません。**

正則化は「過学習を防ぐ道具」として説明されるのが普通ですが、
数値計算の観点では **不良設定な問題を良設定にする道具** でもあります。
$\alpha$ を足すことで実質的に条件数が改善され、解が一意に定まり、
どのソルバで解いても同じ答えになる。だから再現するのです。

原著はこの点に触れていませんが、**3 実装で数値を突き合わせたことで浮かび上がりました**。

## まとめ

| 設定 | テスト誤差 | 最大係数 | 原著と一致するか |
| :--- | ---: | ---: | :--- |
| 正則化なし | 12.924 | 8,633 | しない（原著は 1862.044） |
| L1（Lasso, α=0.01） | 0.152773 | 0.83 | **15 桁一致** |
| L2（Ridge, α=0.01） | 0.103708 | 0.82 | **15 桁一致** |

Kotlin 版・F# 版では、L1 の実装そのものが違うため面白い差が出ます。
特に [Kotlin 版](../kotlin/nb03.md) の Smile は **係数を厳密なゼロにしません**。
