# #17 SVM 用のデータセットを作る（Python）

原著ノートブック: `Chapter_11_Support_Vector_Machines/Building_the_datasets.ipynb`

第 11 章（SVM）で使う 3 つのデータセットを **乱数で作る** 回です。

そして **このシリーズで唯一、原著の出力を原理的に再現できない回** でもあります。
原著は乱数の種を固定していません。実行するたびに違うデータが出ます。

「忠実に再現する」を諦めるのではなく、**何なら検証できるのか** を考え直しました。

## 再現できないものを、どう検証するか

原著のコードはこうです。

```python
for i in range(50):
    x = 6*random.random()-3
    y = 6*random.random()-3
    z = int(x+y > 0.5)
    rows.append([x,y,z])

#Adding noise
for i in range(10):
    x = 6*random.random()-3
    y = 6*random.random()-3
    z = random.randint(0,1)
    rows.append([x,y,z])
```

`random.seed(...)` がどこにもありません。生成結果は再現できません。

しかし **原著が実際に生成した CSV はリポジトリに入っています**（`linear.csv` など）。
そして生成の **規則** はコードに書いてあります。

だから検証できることが 1 つあります。

> 配布されている CSV は、本当にこの規則で作られたのか。

これは再現ではなく **検算** です。そして実際にやってみると、
データの構造がはっきり見えてきました。

## 規則を実装する

```python
def linear_rule(x: float, y: float) -> int:
    """直線 `x + y = 0.5` の上側なら 1。"""
    return int(x + y > 0.5)


def one_circle_rule(x: float, y: float) -> int:
    """原点を中心とする半径 √2.8 の円の内側なら 1。"""
    return int(x**2 + y**2 < 2.8)


def two_circles_rule(x: float, y: float) -> int:
    """(1, 0) と (-1, 0) を中心とする 2 つの円の **どちらか** の内側なら 1。"""
    return int(((x - 1) ** 2 + y**2 < 2) or ((x + 1) ** 2 + y**2 < 2))
```

3 つとも **境界のちょうど上は 0** です（`>` と `<` で等号を含まない）。
これも書いてあるとおりに写します。

```python
def test_直線の規則は境界のちょうど上を0にする() -> None:
    # 原著は x + y > 0.5（等号を含まない）
    assert linear_rule(0.25, 0.25) == 0
    assert linear_rule(0.3, 0.3) == 1
```

## 検算 1 — 行数

```python
@pytest.mark.parametrize(("spec", "total"), [(LINEAR, 60), (ONE_CIRCLE, 110), (TWO_CIRCLES, 220)])
def test_配布CSVの行数は規則の点とノイズの合計(spec, total) -> None:
    # 原著は「規則どおりの点」と「ノイズ」を続けて追加している
    assert spec.total == total
    assert len(load(spec)) == total
```

| データセット | 規則どおりの点 | ノイズ | 合計 | 配布 CSV の行数 |
| :--- | ---: | ---: | ---: | ---: |
| `linear` | 50 | 10 | 60 | **60** |
| `one_circle` | 100 | 10 | 110 | **110** |
| `two_circles` | 200 | 20 | 220 | **220** |

すべて一致します。

## 検算 2 — 先頭は規則に 1 つも違反しない

ここが本題です。

```python
@pytest.mark.parametrize("spec", SPECS)
def test_先頭の点は規則に1つも違反しない(spec) -> None:
    # 配布 CSV の先頭 spec.points 件は規則どおりに作られた点。
    # ここに違反が 1 つも無いことが、規則を正しく読めた証拠になる
    violations = rule_violations(spec, load(spec))

    assert [index for index in violations if index < spec.points] == []
```

**3 つとも、先頭部分に違反が 1 件もありません。**

これは強い証拠です。`x + y > 0.5` を `>=` と読み違えていたら、
境界近くの点で違反が出るはずです。`2.8` を `2.0` と読み違えていたら、
何十件も違反が出ます。

**再現できないデータでも、規則が正しいことは確かめられます。**

## 検算 3 — 違反はノイズ部分に、しかも約半分

```python
@pytest.mark.parametrize(
    ("spec", "count"), [(LINEAR, 5), (ONE_CIRCLE, 7), (TWO_CIRCLES, 12)]
)
def test_違反はすべてノイズ部分にあり約半数(spec, count) -> None:
    # ノイズはラベルを 0 か 1 で振り直すので、規則と食い違うのは約半分。
    # 実測: 10 個中 5 個 / 10 個中 7 個 / 20 個中 12 個
    violations = rule_violations(spec, load(spec))

    assert len(violations) == count
    assert all(index >= spec.points for index in violations)
    assert 0.2 <= len(violations) / spec.noise <= 0.8
```

| データセット | ノイズの数 | 規則に違反した数 | 割合 |
| :--- | ---: | ---: | ---: |
| `linear` | 10 | 5 | 0.50 |
| `one_circle` | 10 | 7 | 0.70 |
| `two_circles` | 20 | 12 | 0.60 |

ノイズ点は `random.randint(0, 1)` でラベルを振り直すので、
**元の規則と一致する確率は半分** です。実測 5/10、7/10、12/20 は
その分布（二項分布）として自然な値です。

**違反が「必ずノイズ部分にだけ」現れる** ことも確認できました。
CSV の並び順が「規則どおりの点 → ノイズ」であるという構造が、
数値だけから見えます。

## 生成器も書く

検算だけでなく、生成そのものも実装しました。読者が同じデータを作れるようにです。

```python
def generate(spec: Spec, seed: int | None = None) -> pd.DataFrame:
    """原著と同じ手順でデータセットを作る。

    原著は種を固定していないので実行のたびに違うものが出る。
    ここでは `seed` を渡せるようにして、テストで扱えるようにした。
    **原著が配布している CSV とは一致しない**（一致しようがない）。
    """
```

**原著に無い `seed` 引数を足しました。** 原著から離れる変更ですが、
これが無いとテストが書けません。理由を docstring に明記しています。

そして「一致しない」ことも、明示的にテストにしました。

```python
def test_生成したものは配布CSVとは一致しない() -> None:
    # 原著が種を固定していない以上、これは一致しようがない。
    # 「再現できない」ことを明示的に記録しておく
    generated = generate(LINEAR, seed=0)
    published = load(LINEAR)

    assert len(generated) == len(published)
    assert generated["x_1"].iloc[0] != published["x_1"].iloc[0]
```

奇妙なテストに見えますが、意図があります。
**将来これが「一致する」ようになったら、それは何かがおかしい** ということです。
「再現できない」という事実そのものを、テストで固定しました。

## 生成器も規則を守る

```python
@pytest.mark.parametrize("spec", SPECS)
def test_生成した点は規則どおりでノイズだけが外れる(spec) -> None:
    # 生成器は原著と同じ手順。種を固定しているので毎回同じものが出る
    generated = generate(spec, seed=0)

    assert len(generated) == spec.total
    assert [index for index in rule_violations(spec, generated) if index < spec.points] == []
```

配布 CSV に対して行ったのと **まったく同じ検算** を、自分の生成器にも掛けます。
同じ性質が成り立てば、生成器は原著と同じものを作っています
（同じ乱数列ではないが、同じ規則の）。

## まとめ

| 項目 | 原著と一致するか |
| :--- | :--- |
| 3 つのデータセットの規則 | 完全一致 |
| 配布 CSV の行数（60 / 110 / 220） | 完全一致 |
| 先頭部分に規則違反が無いこと | 検証済み |
| ノイズ部分の違反数（5 / 7 / 12） | 実測して固定 |
| 生成される座標そのもの | **再現できない**（原著が種を固定していない） |
