# #15 手書き数字を認識する（Python）

原著ノートブック: `Chapter_10_Neural_Networks/Image_recognition.ipynb`

MNIST の手書き数字 7 万枚を、[#13](nb13.md) と同じ形のネットワークで分類します。
違いは入力が 784 次元（28 × 28 画素）になり、出力が 2 クラスから 10 クラスに増えることだけです。

この回は **このシリーズで初めて訓練とテストを分けて評価** します。
原著はテストセットで **正解率 0.942** を出しています。

## データは Keras の配布ファイルをそのまま共有する

原著は `keras.datasets.mnist.load_data()` を呼びます。
これは Google のサーバから `mnist.npz` を取ってきて展開するだけの関数です。

```python
def load_mnist() -> Mnist:
    """MNIST を読み込む。

    原著は `keras.datasets.mnist.load_data()` を呼ぶ。それは
    `mnist.npz` を Google のサーバから取ってくるだけなので、
    ここでは共有データセット経由で同じファイルを読む。
    Kotlin 版・F# 版も同じファイルを使う。
    """
    with np.load(dataset_path("mnist.npz")) as archive:
        return Mnist(
            archive["x_train"],
            archive["y_train"],
            archive["x_test"],
            archive["y_test"],
        )
```

**Keras 経由をやめて生ファイルを読む** ようにしたのは、Kotlin 版・F# 版と
同じ画像を使うためです。3 言語が同じ 11 MB のファイルを読むので、
「言語によって画像が違うから数字が合わない」という疑いを消せます。

このファイルはリポジトリに入れていないので、テストは未取得ならスキップします。

```python
mnist_required = pytest.mark.skipif(
    not _mnist_available(),
    reason="mnist.npz（約 11 MB）が未取得です。datasets の README を参照してください",
)
```

## `reshape(-1, 784)` の `-1`

```python
    def reshaped_train(self) -> NDArray[np.uint8]:
        """28 × 28 の画像を 784 次元のベクトルに直す。

        原著は `-1` を「件数はそのまま」の意味で使っている。
        """
        return self.x_train.reshape(-1, INPUT_DIM)
```

```python
@mnist_required
def test_784次元に直すと件数は変わらない(mnist) -> None:
    # 原著は reshape(-1, 28*28) と書く。-1 は「件数はそのまま」の意味
    assert mnist.reshaped_train().shape == (60000, 784)
    assert mnist.reshaped_test().shape == (10000, 784)
```

`-1` は「残りから逆算せよ」という指示です。60000 × 28 × 28 = 47,040,000 個の値を
784 で割れば 60000 が出る、という計算を NumPy がやってくれます。

**画像を 1 列に伸ばしてしまうので、縦横の隣接関係は失われます。**
それでも 0.94 まで届くのがこの章の見どころです（畳み込みは本書では扱いません）。

## ネットワークは #13 とまったく同じ形

```python
def build_model():
    """原著と同じ形のネットワークを組む。

    [#13](nb13.md) と層の数も Dropout の割合も同じで、
    入力が 2 から 784 に、出力が 2 から 10 に変わっただけである。
    """
    from tensorflow import keras

    return keras.Sequential(
        [
            keras.layers.Input((INPUT_DIM,)),
            keras.layers.Dense(HIDDEN_UNITS[0], activation="relu"),
            keras.layers.Dropout(DROPOUT_RATE),
            keras.layers.Dense(HIDDEN_UNITS[1], activation="relu"),
            keras.layers.Dropout(DROPOUT_RATE),
            keras.layers.Dense(CLASSES, activation="softmax"),
        ]
    )
```

[#13](nb13.md)（2 次元の点を 2 クラスに分ける）と比べると、変わったのは
`Input` の次元と最後の `Dense` のユニット数だけです。

**同じ道具で、2 次元の玩具データと 784 次元の実データの両方を扱える。**
これが原著がこの並びで章を置いた理由でしょう。

## パラメータ数は完全に一致する

```python
def test_パラメータ数は原著と同じ109386() -> None:
    # 原著の model.summary() が出す Total params: 109,386
    assert build_model().count_params() == 109386
    assert (784 * 128 + 128) + (128 * 64 + 64) + (64 * 10 + 10) == 109386
```

| 層 | 重み | バイアス | 小計 |
| :--- | ---: | ---: | ---: |
| Dense(128) | 784 × 128 = 100352 | 128 | 100480 |
| Dense(64) | 128 × 64 = 8192 | 64 | 8256 |
| Dense(10) | 64 × 10 = 640 | 10 | 650 |
| **合計** | | | **109386** |

**全体の 92% が最初の層** です。784 次元をいきなり 128 に落とすところで
重みの大半を使っています。Dropout は学習しないのでパラメータを持ちません。

## 原著が挙げる具体例を固定する

原著はいくつかの画像を名指しで表示します。それをそのままテストにしました。

```python
@mnist_required
def test_6番目の訓練画像のラベルは2(mnist) -> None:
    # 原著の出力: The label is 2
    assert mnist.y_train[5] == 2


@mnist_required
def test_5番目のテスト画像のラベルは4(mnist) -> None:
    # 原著の出力: The label is 4 / The prediction is 4
    assert mnist.y_test[4] == 4


@mnist_required
def test_19番目のテスト画像のラベルは3(mnist) -> None:
    # 原著はここで予測を外して 8 と答える例に使っている
    assert mnist.y_test[18] == 3
```

**ラベルは固定できますが、予測は固定できません。**
原著は 19 番目を「3 なのに 8 と答えてしまう例」として出しますが、
学習のたびに間違える画像は変わります。
ここでテストできるのは「原著が見ていたのと同じ画像を読んでいる」ことだけです。

## 学習は小さく回す

6 万枚を 10 エポック（バッチ 10）回すと、手元では数分かかります。
テストでは訓練データを削ります。

```python
@pytest.fixture(scope="module")
def trained(mnist):
    # 6 万枚 × 10 エポックは数分かかる。1 万枚 × 5 エポックで済ませる
    return fit(mnist, epochs=5, sample_size=10000)
```

```python
@mnist_required
def test_学習後のテスト正解率は7割を超える(mnist, trained) -> None:
    # 原著は 6 万枚 × 10 エポックで 0.942。
    # ここは 1 万枚 × 5 エポックなので、それより低い 0.77〜0.86 になる。
    # 幅があるのは、TensorFlow の乱数が **プロセス全体で共有** されるため。
    # このファイル単体で走らせると 0.86、#13・#14 のあとだと 0.77 になった。
    # 種を固定しても、先に別のモデルを作ると状態が進む
    accuracy = evaluate_test_accuracy(trained, mnist)

    assert accuracy > 0.7
```

**訓練データを 6 分の 1 に減らしても 0.86 に届きます。**
原著の 0.942 との差 0.08 が、残り 5 万枚と 5 エポックぶんの価値です。

ただしこの 0.86 は安定しません。最初は `> 0.8` と書いていたのですが、
**テスト全体を通しで走らせると 0.769 になって落ちました。**
このファイル単体なら 0.86 です。

`fit` の中で `np.random.seed(0)` と `tf.random.set_seed(1)` を呼んでいるのに、なぜか。
**TensorFlow の乱数状態はプロセス全体で 1 つ** だからです。
`set_seed` は状態を初期値に戻しますが、その後に生成される乱数は
**それまでに何個の演算が乱数を消費したか** に影響されます。
[#13](nb13.md)・[#14](nb14.md) が先にモデルを作っていると、初期重みが変わります。

**「種を固定したから再現する」は、プロセスに 1 つしかモデルが無いときの話** でした。
閾値を 0.7 に下げ、なぜ幅があるかをコメントに残しています。

## 基準を持って評価する

```python
@mnist_required
def test_でたらめに答えるより大幅に良い(mnist, trained) -> None:
    # 10 クラスなので、でたらめなら 0.1。常に同じ数字を答えても 0.12 程度
    accuracy = evaluate_test_accuracy(trained, mnist)
    most_common_rate = float(np.max(np.bincount(mnist.y_test)) / len(mnist.y_test))

    assert accuracy > most_common_rate * 5
```

[#14](nb14.md) の「常に平均を答える」に対応する基準です。
MNIST は 10 クラスがほぼ均等なので、**もっとも多い数字を常に答えても 0.12 程度**。
0.86 はその 7 倍です。

このテストがあると、`assert accuracy > 0.8` のような固定値と違って
**「データが偏っていたから当たっただけ」を排除できます**。

## `argmax` は `axis` を指定すれば一度で済む

```python
def predict(model, images: NDArray[np.uint8]) -> NDArray[np.int_]:
    """softmax の 10 次元出力から、もっとも高いクラスを選ぶ。

    原著は `[np.argmax(pred) for pred in predictions_vector]` と
    リスト内包表記で書いている。`axis=1` を指定すれば一度で済む。
    """
    return np.argmax(model.predict(images, verbose=0), axis=1)
```

結果は同じですが、1 万枚ぶんの Python のループが消えます。
NumPy を使うときの定石です。
