# 第 9 章 決定木（Python 版）

原著第 9 章「Splitting data by asking questions」を Python で実装します。これまでの分類器はすべて **直線** でデータを分けてきました。決定木は「質問を積み重ねる」ことで、直線では表せない領域を切り出します。

サンプル実装は `apps/grokking-ml-python/src/grokking_ml/ch09_decision_trees.py` です。

> **Jupyter Notebook で試す**: この章の実験は [ch09.ipynb](notebooks/ch09.ipynb) にまとめてあります。実装本体を読み込んで動かすので、値を変えてその場で試せます。

## この章で作るもの

- ジニ不純度とエントロピー（分割の良さを測る 2 つの指標）
- 情報利得
- 分割候補の列挙と最良分割の選択
- 再帰的な木の構築

## これまでとの違い

| | 第 5〜6 章 | 第 8 章 | 第 9 章 |
| :--- | :--- | :--- | :--- |
| モデル | 重みベクトル | 単語ごとの確率表 | **木構造** |
| 学習 | 勾配降下法 | 数え上げ | **貪欲な再帰探索** |
| 決定境界 | 直線 | （確率の等高線） | **軸に平行な階段状** |
| 人間が読めるか | 重みの大小だけ | 単語ごとの確率 | **「もし〜なら」で説明できる** |

決定木の最大の利点は **説明可能性** です。「20 歳未満だから推薦した」と言えます。ロジスティック回帰の「重み 2.25 と 1.53 の和が閾値を超えたから」よりも、人間に伝わります。

## データセット

原著と同じアプリ推薦データを使います。特徴量は性別（0=女性、1=男性）と年齢、ラベルは 1 が「推薦する」です。

| 性別 | 年齢 | 推薦 |
| ---: | ---: | ---: |
| 1 | 15 | 1 |
| 0 | 25 | 0 |
| 0 | 32 | 0 |
| 1 | 35 | 0 |
| 0 | 12 | 1 |
| 1 | 14 | 1 |
| 1 | 55 | 0 |
| 0 | 40 | 0 |

眺めると「若い人には推薦する」という規則が見えます。**性別は関係ありません。** 決定木がそれを自力で見つけられるかが本章の焦点です。

## 不純度

「分割が良い」とはどういうことか。**分けたあとの各グループが、なるべく単一のラベルで占められていること** です。この「混ざり具合」を測るのが不純度です。

```python
def gini_impurity(labels: Sequence[int]) -> float:
    """ジニ不純度。ランダムに 2 つ選んだとき、ラベルが食い違う確率。"""
    if not labels:
        return 0.0
    total = len(labels)
    return 1.0 - sum((count / total) ** 2 for count in Counter(labels).values())


def entropy(labels: Sequence[int]) -> float:
    """エントロピー。ラベルの散らばりを情報量で測る。"""
    if not labels:
        return 0.0
    total = len(labels)
    return -sum(
        (count / total) * math.log2(count / total) for count in Counter(labels).values()
    )
```

| 集合 | ジニ不純度 | エントロピー |
| :--- | ---: | ---: |
| `[1, 1, 1]`（純粋） | 0.0 | 0.0 |
| `[1, 1, 1, 0]`（偏り） | 0.375 | 0.811 |
| `[1, 1, 0, 0]`（均等） | 0.5 | 1.0 |
| `[0, 1, 2, 3]`（4 クラス均等） | 0.75 | 2.0 |

**ジニ不純度は「ランダムに 2 つ選んだとき、ラベルが食い違う確率」** と読めます。全部同じなら 0、半々なら 0.5 です。

**エントロピーは「ラベルを 1 つ伝えるのに必要なビット数」** です。2 クラス均等なら 1 ビット、4 クラス均等なら 2 ビット。この解釈がテストにそのまま書けます。

```python
def test_entropy_of_four_equal_classes_is_two_bits():
    assert entropy([0, 1, 2, 3]) == pytest.approx(2.0)
```

2 つの指標は値の範囲が違いますが、**順序は一致します**。

```python
def test_gini_and_entropy_agree_on_ordering():
    # どちらの指標でも「純粋 < 偏り < 均等」の順になる
    pure, skewed, balanced = [1, 1, 1, 1], [1, 1, 1, 0], [1, 1, 0, 0]
    assert gini_impurity(pure) < gini_impurity(skewed) < gini_impurity(balanced)
    assert entropy(pure) < entropy(skewed) < entropy(balanced)
```

Python の連鎖比較（`a < b < c`）がそのまま「順序が保たれる」という主張になります。

不純度を **引数として渡せる形** にしているのが設計上の要点です。

```python
Impurity = Callable[[Sequence[int]], float]
```

型エイリアスで「不純度の測り方」という概念に名前が付きます。これにより、木の構築側は「どちらの指標を使うか」を知らずに済みます。

## 分割

質問は「`feature` 番目の特徴量が `threshold` 未満か」という形に限定します。

```python
@dataclass(frozen=True)
class Split:
    """1 つの質問による分割。「feature 番目の特徴量が threshold 未満か」を問う。"""

    feature: int
    threshold: float

    def matches(self, point: Point) -> bool:
        """左（True）へ進むか。"""
        return point[self.feature] < self.threshold
```

この形に限定するため、決定境界は **軸に平行な階段状** になります。斜めの直線は表せません。代わりに、階段を細かくすればどんな形でも近似できます。

### 候補の列挙

閾値は無限にありますが、試す価値があるのは **データの値と値の間** だけです。

```python
def candidate_splits(points: Sequence[Point]) -> list[Split]:
    """試す価値のある分割の候補。隣り合う値の中点を閾値にする。"""
    splits: list[Split] = []
    for feature in range(len(points[0])):
        values = sorted({point[feature] for point in points})
        for low, high in pairwise(values):
            splits.append(Split(feature=feature, threshold=(low + high) / 2))
    return splits
```

年齢が 12, 14, 15, 25... と並ぶなら、13, 14.5, 20... を試します。**中点を使うのは、どちらの点にも寄らない位置を選ぶため** です。閾値 14 だと「14 歳ちょうど」の扱いが `<` の定義に依存してしまいます。

集合内包表記で重複を除いてからソートしているので、同じ値が複数あっても候補は 1 つです。

## 情報利得

分割の良さは「不純度がどれだけ下がったか」で測ります。

```python
def weighted_impurity(
    left_labels: Sequence[int],
    right_labels: Sequence[int],
    impurity: Impurity = gini_impurity,
) -> float:
    """分割後の不純度。左右の大きさで重み付けして平均する。"""
    total = len(left_labels) + len(right_labels)
    if total == 0:
        return 0.0
    left_weight = len(left_labels) / total
    right_weight = len(right_labels) / total
    return left_weight * impurity(left_labels) + right_weight * impurity(right_labels)


def information_gain(
    labels: Sequence[int],
    left_labels: Sequence[int],
    right_labels: Sequence[int],
    impurity: Impurity = gini_impurity,
) -> float:
    """情報利得。分割によって不純度がどれだけ下がったか。"""
    return impurity(labels) - weighted_impurity(left_labels, right_labels, impurity)
```

**左右の大きさで重み付けする** のが重要です。1 個と 999 個に分かれた場合、1 個側が純粋でも全体としてはほとんど改善していません。単純平均では、この違いを見落とします。

```python
def test_information_gain_is_zero_for_a_useless_split():
    labels = [1, 1, 0, 0]
    assert information_gain(labels, [1, 0], [1, 0]) == pytest.approx(0.0)


def test_information_gain_is_maximal_for_a_perfect_split():
    labels = [1, 1, 0, 0]
    assert information_gain(labels, [1, 1], [0, 0]) == pytest.approx(0.5)
```

## 最良分割の探索

すべての候補を試し、利得が最大のものを選びます。**貪欲法** です。

```python
def best_split(
    points: Sequence[Point],
    labels: Sequence[int],
    impurity: Impurity = gini_impurity,
) -> tuple[Split, float] | None:
    """情報利得がもっとも大きい分割。改善しないなら None。"""
    best: tuple[Split, float] | None = None
    for split in candidate_splits(points):
        _, left_labels, _, right_labels = apply_split(points, labels, split)
        if not left_labels or not right_labels:
            continue
        gain = information_gain(labels, left_labels, right_labels, impurity)
        if best is None or gain > best[1]:
            best = (split, gain)
    if best is None or best[1] <= 0.0:
        return None
    return best
```

戻り値を `tuple[Split, float] | None` にしているのが要点です。**「良い分割が存在しない」という状態を型で表現します。** 例外や番兵値（`gain = -1` など）を使うと、呼び出し側がその約束を知らないまま使ってしまいます。

実際のデータで各候補の利得を計算すると、次のようになります（根の不純度は 0.4688）。

| 特徴量 | 閾値 | 情報利得 |
| :--- | ---: | ---: |
| 性別 | 0.5 | 0.0312 |
| 年齢 | 13.0 | 0.1116 |
| 年齢 | 14.5 | 0.2604 |
| **年齢** | **20.0** | **0.4688** |
| 年齢 | 28.5 | 0.2812 |
| 年齢 | 33.5 | 0.1688 |
| 年齢 | 37.5 | 0.0938 |
| 年齢 | 47.5 | 0.0402 |

「年齢 < 20」の利得が 0.4688 で、根の不純度と等しくなっています。**この 1 回の質問で不純度が完全に 0 になる** ということです。性別の利得は 0.0312 しかありません。

**決定木は自力で「年齢が効く、性別は関係ない」を見つけました。** 特徴量の選択を人間がやらずに済むのが、木の実用的な強みです。

## 木の構築

```python
@dataclass(frozen=True)
class Leaf:
    """葉。多数決で決めたラベルを返す。"""

    label: int

    def predict(self, point: Point) -> int:
        return self.label


@dataclass(frozen=True)
class Node:
    """内部ノード。質問に応じて左右の枝へ進む。"""

    split: Split
    left: Tree
    right: Tree

    def predict(self, point: Point) -> int:
        branch = self.left if self.split.matches(point) else self.right
        return branch.predict(point)


Tree = Leaf | Node
```

`Tree = Leaf | Node` という **和型** で木を表します。「木は葉か内部ノードのどちらか」という定義がそのまま型になります。

`predict` を両方のクラスに持たせることで、`Node.predict` は再帰的に子の `predict` を呼ぶだけで済みます。分岐が `isinstance` でなくメソッド呼び出しになるのがオブジェクト指向的な解き方です。

```python
def build_tree(
    points: Sequence[Point],
    labels: Sequence[int],
    max_depth: int = 5,
    min_samples: int = 1,
    impurity: Impurity = gini_impurity,
) -> Tree:
    """決定木を再帰的に構築する。"""
    if max_depth <= 0 or len(labels) <= min_samples or len(set(labels)) == 1:
        return Leaf(majority_label(labels))
    found = best_split(points, labels, impurity)
    if found is None:
        return Leaf(majority_label(labels))
    split, _ = found
    left_points, left_labels, right_points, right_labels = apply_split(points, labels, split)
    return Node(
        split=split,
        left=build_tree(left_points, left_labels, max_depth - 1, min_samples, impurity),
        right=build_tree(right_points, right_labels, max_depth - 1, min_samples, impurity),
    )
```

停止条件が 4 つあります。

| 条件 | 理由 |
| :--- | :--- |
| `max_depth <= 0` | 深すぎる木は過学習する（第 4 章の次数と同じ） |
| `len(labels) <= min_samples` | 少なすぎるデータからの分割は信用できない |
| `len(set(labels)) == 1` | すでに純粋なので分ける必要がない |
| `best_split` が `None` | どう分けても改善しない |

**上 2 つは第 4 章の正則化と同じ役割です。** 木は放っておくと訓練データを丸暗記するまで育つので、成長を止めるつまみが要ります。

## ジニとエントロピーの比較

```python
def test_entropy_and_gini_produce_the_same_tree_here():
    by_gini = build_tree(POINTS, LABELS, impurity=gini_impurity)
    by_entropy = build_tree(POINTS, LABELS, impurity=entropy)
    assert by_gini == by_entropy
```

このデータでは **どちらの指標を使っても同じ木になりました**。値の絶対値は違う（0.4688 と 0.9544）のに、順序が同じだからです。

実務でもこの 2 つが違う木を作ることは稀です。エントロピーは対数計算のぶん遅いため、既定値にはジニ不純度を選びました。

`frozen=True` の dataclass が `__eq__` を生成しているので、**木全体の等価性が 1 行で比較できます**。木の比較を手で書くと再帰関数が必要になります。

## まとめ

- 不純度は「混ざり具合」の指標です。ジニは食い違う確率、エントロピーは必要なビット数と読めます。
- 情報利得は左右の大きさで重み付けします。単純平均では偏った分割を見落とします。
- 閾値の候補はデータの値の中点だけで十分です。無限に試す必要はありません。
- 「良い分割がない」ことは `None` で表します。番兵値を使うと呼び出し側が約束を知らずに使います。
- 木は放っておくと丸暗記します。深さと最小サンプル数が第 4 章の正則化に当たります。
