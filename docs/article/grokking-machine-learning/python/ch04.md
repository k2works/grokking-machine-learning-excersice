# 第 4 章 過学習・未学習と正則化（Python 版）

原著第 4 章「Optimizing the training process」を Python で実装します。モデルが **単純すぎる（未学習）** ときと **複雑すぎる（過学習）** ときの見分け方を学び、複雑さを抑える手段として L1 / L2 正則化を実装します。

サンプル実装は `apps/grokking-ml-python/src/grokking_ml/ch04_regularization.py` です。

> **Jupyter Notebook で試す**: この章の実験は [ch04.ipynb](notebooks/ch04.ipynb) にまとめてあります。実装本体を読み込んで動かすので、値を変えてその場で試せます。

## この章で作るもの

- 多項式モデル `y = bias + w1*x + w2*x² + ... + wn*xⁿ`
- データを訓練用とテスト用に分ける `train_test_split`
- 正則化項を加えた二乗トリック
- 次数を変えたときの訓練誤差とテスト誤差の比較

第 3 章の線形回帰は直線でした。本章では **次数** というつまみを回して、モデルの複雑さを自由に変えられるようにします。

## 未学習と過学習

| 状態 | 訓練誤差 | テスト誤差 | 原因 |
| :--- | :--- | :--- | :--- |
| 未学習（underfitting） | 大きい | 大きい | モデルが単純すぎてデータの傾向を表せない |
| ちょうどよい | 小さい | 小さい | — |
| 過学習（overfitting） | とても小さい | 大きい | モデルが複雑すぎて訓練データを丸暗記した |

重要なのは、**訓練誤差だけを見ていては過学習を検出できない** ことです。過学習したモデルの訓練誤差は限りなく小さくなります。そのため、学習に使わないデータ（テストデータ）を取り分けておく必要があります。

## モデル

第 3 章の `Model`（傾きと切片）を、任意次数へ拡張します。

```python
@dataclass(frozen=True)
class PolynomialModel:
    """多項式モデル y = bias + w1*x + w2*x^2 + ... + wn*x^n。"""

    weights: tuple[float, ...]
    bias: float

    @property
    def degree(self) -> int:
        return len(self.weights)

    def predict(self, x: float) -> float:
        return self.bias + sum(w * x**power for power, w in enumerate(self.weights, start=1))


def polynomial_features(x: float, degree: int) -> list[float]:
    """x から [x, x^2, ..., x^degree] を作る。"""
    return [x**power for power in range(1, degree + 1)]
```

重みを `tuple` にしているのは、`frozen=True` の dataclass を本当に不変にするためです。`list` を持たせると `frozen=True` でも中身を書き換えられてしまいます。

`enumerate(self.weights, start=1)` によって、重み `w[i]` が `x^(i+1)` に対応することがコード上で明示されます。

## 訓練データとテストデータの分割

```python
def train_test_split(
    features: Sequence[float],
    labels: Sequence[float],
    test_ratio: float = 0.3,
    seed: int = 0,
) -> tuple[list[float], list[float], list[float], list[float]]:
    """データを訓練用とテスト用に分割する。"""
    rng = random.Random(seed)
    indices = list(range(len(features)))
    rng.shuffle(indices)
    test_size = int(len(features) * test_ratio)
    test_indices = indices[:test_size]
    train_indices = indices[test_size:]
    return (
        [features[i] for i in train_indices],
        [labels[i] for i in train_indices],
        [features[i] for i in test_indices],
        [labels[i] for i in test_indices],
    )
```

**特徴量とラベルを別々にシャッフルしてはいけません。** インデックスの列をシャッフルし、そのインデックスで両方を並べ替えることで対応関係を保ちます。これはテストでも明示的に検証しています。

```python
def test_train_test_split_keeps_pairs_together():
    train_x, train_y, test_x, test_y = train_test_split(FEATURES, LABELS, test_ratio=0.3, seed=0)
    for x, y in zip(train_x + test_x, train_y + test_y):
        assert LABELS[FEATURES.index(x)] == pytest.approx(y)
```

## 正則化

過学習したモデルの重みは、極端に大きな正と負の値が打ち消し合う形になりがちです。そこで **「誤差を減らす」ことに加えて「重みを小さく保つ」ことも目的に加える** のが正則化です。

損失関数に重みのペナルティを足します。

| 種類 | ペナルティ | 勾配 | 効果 |
| :--- | :--- | :--- | :--- |
| L1（Lasso） | λ Σ\|wᵢ\| | λ · sign(wᵢ) | 重みを **ほぼ 0** まで押し下げる（スパースになる） |
| L2（Ridge） | λ Σwᵢ² | 2λ · wᵢ | 重み全体をなだらかに縮める |

```python
class Regularization(Enum):
    """正則化の種類。"""

    NONE = "none"
    L1 = "l1"
    L2 = "l2"


def regularization_gradient(weight: float, kind: Regularization, strength: float) -> float:
    """正則化項の勾配。重みを 0 に引き戻す向きの力を返す。"""
    if kind is Regularization.L1:
        return strength * (1.0 if weight > 0 else -1.0 if weight < 0 else 0.0)
    if kind is Regularization.L2:
        return strength * 2.0 * weight
    return 0.0
```

`Enum` で種類を表すことで、呼び出し側が文字列を打ち間違えても実行時に気づけます。`is` で比較しているのは、`Enum` メンバーがシングルトンだからです。

L1 の勾配は **重みの大きさによらず一定** です。だから小さな重みも同じ力で 0 へ押され、最終的にほぼ 0 に張り付きます。一方 L2 の勾配は重みに比例するため、0 に近づくほど力が弱まり、完全な 0 にはなりません。この違いがスパース性の有無を生みます。

## 正則化つきの二乗トリック

第 3 章の二乗トリックに、正則化の勾配を引く項を足すだけです。

```python
def square_trick(
    model: PolynomialModel,
    x: float,
    y: float,
    learning_rate: float,
    kind: Regularization = Regularization.NONE,
    strength: float = 0.0,
) -> PolynomialModel:
    """二乗トリックに正則化項を加えた 1 点分の更新。"""
    error = y - model.predict(x)
    features = polynomial_features(x, model.degree)
    weights = tuple(
        w + learning_rate * (error * feature - regularization_gradient(w, kind, strength))
        for w, feature in zip(model.weights, features)
    )
    return PolynomialModel(weights, model.bias + learning_rate * error)
```

**バイアス（切片）には正則化を掛けません。** バイアスはモデルの複雑さではなく、データ全体の位置を表すためです。ここを正則化すると、単に予測が原点方向へ引っ張られるだけで精度が落ちます。この設計判断はテストで固定しています。

```python
def test_square_trick_does_not_regularize_the_bias():
    model = PolynomialModel(weights=(2.0,), bias=1.0)
    plain = square_trick(model, x=3.0, y=10.0, learning_rate=0.01)
    regularized = square_trick(
        model, x=3.0, y=10.0, learning_rate=0.01, kind=Regularization.L2, strength=0.1
    )
    assert regularized.bias == pytest.approx(plain.bias)
```

デフォルト引数を `Regularization.NONE` と `0.0` にしてあるので、正則化を使わない呼び出しは第 3 章と同じ書き味になります。

## 学習

```python
def polynomial_regression(
    features: Sequence[float],
    labels: Sequence[float],
    degree: int,
    learning_rate: float = 0.001,
    epochs: int = 5000,
    kind: Regularization = Regularization.NONE,
    strength: float = 0.0,
    seed: int = 0,
) -> PolynomialModel:
    """確率的勾配降下法で多項式回帰を学習する。"""
    rng = random.Random(seed)
    model = PolynomialModel(tuple(0.0 for _ in range(degree)), 0.0)
    for _ in range(epochs):
        i = rng.randrange(len(features))
        model = square_trick(model, features[i], labels[i], learning_rate, kind, strength)
    return model
```

第 3 章と違い、初期値をランダムではなく **すべて 0** にしています。多項式回帰では次数が上がるほど `x^n` の値が大きくなり、初期値によっては発散するためです。

### 次数を上げるとどうなるか

| 次数 | 訓練 RMSE | テスト RMSE | 汎化ギャップ |
| ---: | ---: | ---: | ---: |
| 1 | 0.1736 | 0.2200 | 0.046 |
| 3 | 0.0550 | 0.2988 | 0.244 |
| 5 | 0.0601 | 0.2947 | 0.235 |

真のデータは 1 次関数なので、1 次モデルで十分です。次数を上げると訓練誤差は 0.17 → 0.06 と下がりますが、テスト誤差は逆に 0.22 → 0.29 へ悪化しました。**訓練データのノイズまで再現してしまった** のです。これが過学習です。

注目すべきは右端の **汎化ギャップ**（テスト誤差 − 訓練誤差）です。0.046 から 0.24 へ 5 倍に広がっています。テストではこのギャップの拡大を検証しています。

```python
def test_high_degree_model_overfits():
    train_x, train_y, test_x, test_y = train_test_split(FEATURES, LABELS, test_ratio=0.3, seed=0)
    simple = polynomial_regression(train_x, train_y, degree=1, learning_rate=0.01, epochs=20000)
    complex_ = polynomial_regression(train_x, train_y, degree=5, learning_rate=0.01, epochs=20000)

    # 次数を上げると訓練誤差は下がる
    assert model_rmse(complex_, train_x, train_y) < model_rmse(simple, train_x, train_y)
    # しかし汎化ギャップ（テスト誤差 - 訓練誤差）は広がる
    simple_gap = model_rmse(simple, test_x, test_y) - model_rmse(simple, train_x, train_y)
    complex_gap = model_rmse(complex_, test_x, test_y) - model_rmse(complex_, train_x, train_y)
    assert complex_gap > simple_gap
```

テスト誤差そのものの大小ではなくギャップを見ているのは、**そのほうが過学習の定義に忠実** だからです。テスト誤差の絶対値は分割の運に左右されますが、ギャップの拡大は複雑さを上げれば必ず起きます。

### 正則化を掛けるとどうなるか

5 次モデルに λ = 0.01 の正則化を掛けます。

| 正則化 | 訓練 RMSE | テスト RMSE | 重みの絶対値合計 | 学習された重み |
| :--- | ---: | ---: | ---: | :--- |
| なし | 0.0601 | 0.2947 | 2.747 | 2.227, -0.157, 0.093, -0.088, -0.182 |
| L1 | 0.0743 | 0.2231 | 2.422 | 2.123, -0.214, **-0.0003**, **-0.0005**, -0.084 |
| L2 | 0.1315 | **0.1239** | 2.820 | 1.709, -0.404, 0.420, 0.118, -0.169 |

読み取れることが 3 つあります。

1. **訓練誤差は悪化し、テスト誤差は改善した。** 正則化は訓練データへの当てはまりをわざと諦める代わりに、未知のデータへの当てはまりを買っています。これがまさに狙いです。
2. **L1 は 3 次と 4 次の重みをほぼ 0 にした。** 「この次数は要らない」とモデル自身が判断したことになります。L1 が特徴量選択に使われるのはこの性質のためです。
3. **L2 は重みを 0 にはしないが、1 次の重みを 2.23 → 1.71 へ縮めた。** 全体をなだらかに抑え込んでいます。

```python
def test_l1_regularization_drives_weights_to_zero():
    ...
    assert weight_magnitude(regularized) < weight_magnitude(plain)
    # L1 は不要な次数の重みをほぼ 0 まで押し下げる
    assert sum(1 for w in regularized.weights if abs(w) < 5e-3) >= 2
    assert sum(1 for w in plain.weights if abs(w) < 5e-3) == 0
```

「ちょうど 0」ではなく「5e-3 未満」で検証しているのは、劣勾配による確率的更新では厳密な 0 に張り付かないためです。数学的な理想ではなく **実装が実際に返す値** を基準にしています。

## まとめ

- 過学習は訓練誤差だけでは検出できません。学習に使わないデータを必ず取り分けます。
- 過学習の指標は汎化ギャップ（テスト誤差 − 訓練誤差）です。次数を上げると必ず広がります。
- 正則化は損失に重みのペナルティを足すだけで実装でき、二乗トリックへの追加は 1 項で済みます。
- L1 は重みをほぼ 0 にして次数を選び、L2 は全体をなだらかに縮めます。
- バイアスは正則化しません。複雑さではなく位置を表すパラメータだからです。
