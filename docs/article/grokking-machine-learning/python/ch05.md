# 第 5 章 パーセプトロン（Python 版）

原著第 5 章「Using lines to split our points」を Python で実装します。第 3・4 章の回帰は **数値を予測** するものでしたが、本章からは **分類** に入ります。点を直線で 2 つのクラスに分けるパーセプトロンを実装します。

サンプル実装は `apps/grokking-ml-python/src/grokking_ml/ch05_perceptron.py` です。

## この章で作るもの

- 線形分類器 `score = w・x + bias`、`score >= 0` なら 1
- 誤分類した点だけを使ってモデルを動かすパーセプトロントリック
- パーセプトロン誤差関数と正解率
- トリックを繰り返すパーセプトロンアルゴリズム

## 回帰と分類の違い

| | 回帰（第 3・4 章） | 分類（本章） |
| :--- | :--- | :--- |
| 出力 | 連続値（価格など） | ラベル（0 か 1） |
| モデルが表すもの | データに沿う直線 | データを **分ける** 直線 |
| 誤差 | 予測値と正解値の差 | 誤分類した点の境界からの距離 |
| 更新するタイミング | すべての点で | **誤分類した点だけ** |

もっとも大きな違いは最後の行です。回帰では正しく予測できている点でもわずかに誤差があるため常に更新しますが、分類では **正しく分類できている点は 1 ミリも動かしません**。

## データセット

原著と同じ「悲しい／楽しい」文の分類データを使います。特徴量は 2 つの単語 `aack` と `beep` の出現回数、ラベルは 1 が「楽しい」です。

| aack | beep | ラベル |
| ---: | ---: | ---: |
| 1 | 0 | 0 |
| 0 | 2 | 0 |
| 1 | 1 | 0 |
| 1 | 2 | 0 |
| 1 | 3 | 1 |
| 2 | 2 | 1 |
| 2 | 3 | 1 |
| 3 | 2 | 1 |

`aack` と `beep` の合計が多いほど「楽しい」文になる、という分けられ方をしています。この 2 群は直線で完全に分離できます（線形分離可能）。

## モデル

```python
Point = Sequence[float]


@dataclass(frozen=True)
class Perceptron:
    """線形分類器 score = w・x + bias。score >= 0 なら 1、そうでなければ 0。"""

    weights: tuple[float, ...]
    bias: float

    def score(self, point: Point) -> float:
        return self.bias + sum(w * x for w, x in zip(self.weights, point))

    def predict(self, point: Point) -> int:
        return 1 if self.score(point) >= 0 else 0
```

`score` と `predict` を分けているのが要点です。`score` は **境界線からどれだけ離れているか** を表す連続値、`predict` はそれを 0 か 1 に潰した結果です。後述する誤差関数はスコアのほうを使います。

`Point = Sequence[float]` という型エイリアスによって、「特徴量ベクトル」という概念に名前が付きます。第 4 章までは 1 次元でしたが、本章から入力が多次元になります。

`score >= 0` と `>` ではなく `>=` にしているのは、境界線上の点を正のクラスへ倒す約束です。この決めごとは明示的にテストしています。

```python
def test_predict_treats_zero_as_positive():
    model = Perceptron(weights=(1.0, 1.0), bias=-2.0)
    assert model.score((1.0, 1.0)) == pytest.approx(0.0)
    assert model.predict((1.0, 1.0)) == 1
```

境界のような **どちらとも決められる箇所こそ、決めた内容をテストで固定します。** 実装を読み替えるときの拠りどころになります。

## パーセプトロントリック

分類の学習則は、回帰の二乗トリックより単純です。

```python
def perceptron_trick(
    model: Perceptron,
    point: Point,
    label: int,
    learning_rate: float = 0.01,
) -> Perceptron:
    """パーセプトロントリック。誤分類した点だけモデルを動かす。"""
    error = label - model.predict(point)
    if error == 0:
        return model
    weights = tuple(w + learning_rate * error * x for w, x in zip(model.weights, point))
    return Perceptron(weights, model.bias + learning_rate * error)
```

`error = label - predict` は 3 通りの値しか取りません。

| ラベル | 予測 | error | 動き |
| ---: | ---: | ---: | :--- |
| 1 | 1 | 0 | 動かない |
| 0 | 0 | 0 | 動かない |
| 1 | 0 | +1 | 境界線を点のほうへ寄せる |
| 0 | 1 | -1 | 境界線を点から遠ざける |

`error == 0` のとき **元のモデルをそのまま返す** ことで、「正しい点は動かさない」という規則がコード上で明示されます。新しいオブジェクトを作らないので、テストでは同一性ではなく等価性で確認できます。

```python
def test_perceptron_trick_leaves_correct_points_untouched():
    model = Perceptron(weights=(1.0, 2.0), bias=-4.0)
    # 予測 1、ラベル 1 なので動かない
    assert perceptron_trick(model, (1.0, 2.0), label=1) == model
```

`@dataclass` が `__eq__` を生成しているので、この比較がそのまま書けます。

第 4 章の二乗トリックと式を並べると、違いは掛ける値だけだと分かります。

| 章 | 更新式（重み） |
| :--- | :--- |
| 第 3・4 章（二乗トリック） | `w + 学習率 × 特徴量 × 誤差の大きさ` |
| 第 5 章（パーセプトロン） | `w + 学習率 × 特徴量 × 誤差の符号（+1 / -1 / 0）` |

回帰は「どれだけ外したか」を使い、分類は「外したかどうか」だけを使います。

## 誤差関数

分類の誤差は「何個間違えたか」で測れそうですが、それでは学習に使えません。**間違えた個数は境界線を少し動かしても変わらない** ため、改善の方向が分からないからです。

そこでパーセプトロン誤差は、誤分類した点について **境界線からの距離（スコアの絶対値）** を使います。

```python
def perceptron_error(model: Perceptron, point: Point, label: int) -> float:
    """1 点分の誤差。正しく分類していれば 0、誤っていればスコアの絶対値。"""
    if model.predict(point) == label:
        return 0.0
    return abs(model.score(point))
```

こうすると「大きく間違えている点」ほど誤差が大きくなり、連続的に改善できます。誤分類した点が境界線に近づけば誤差が下がる、という手がかりが生まれます。

正解率は別に用意します。誤差関数は学習の手がかり、正解率は人間が結果を評価する指標であり、目的が違うためです。

```python
def accuracy(model: Perceptron, points: Sequence[Point], labels: Sequence[int]) -> float:
    """正解率。"""
    correct = sum(1 for point, label in zip(points, labels) if model.predict(point) == label)
    return correct / len(points)
```

## パーセプトロンアルゴリズム

```python
def perceptron_algorithm(
    points: Sequence[Point],
    labels: Sequence[int],
    learning_rate: float = 0.01,
    epochs: int = 1000,
    seed: int = 0,
) -> tuple[Perceptron, list[float]]:
    """パーセプトロンアルゴリズム。モデルとエポックごとの平均誤差を返す。"""
    rng = random.Random(seed)
    dimensions = len(points[0])
    model = Perceptron(tuple(0.0 for _ in range(dimensions)), 0.0)
    errors: list[float] = []
    for _ in range(epochs):
        errors.append(mean_perceptron_error(model, points, labels))
        i = rng.randrange(len(points))
        model = perceptron_trick(model, points[i], labels[i], learning_rate)
    return model, errors
```

構造は第 3 章の線形回帰とまったく同じです。違うのは適用するトリックだけです。**同じ骨格に別の学習則を差し込むと別のアルゴリズムになる** ことが、章をまたいで見えてきます。

次元数を `len(points[0])` から取っているので、2 次元に限定されません。

## 実行結果

```bash
cd apps/grokking-ml-python
uv run python -c "
from grokking_ml.ch05_perceptron import *
P = [(1,0),(0,2),(1,1),(1,2),(1,3),(2,2),(2,3),(3,2)]
L = [0,0,0,0,1,1,1,1]
model, errors = perceptron_algorithm(P, L)
print(model.weights, model.bias, accuracy(model, P, L))
"
```

学習率 0.01、1000 エポックで次の結果になりました。

| 項目 | 値 |
| :--- | ---: |
| aack の重み | 0.02 |
| beep の重み | 0.01 |
| バイアス | -0.04 |
| 正解率 | 1.0 |
| 学習中の最大平均誤差 | 0.0325 |
| 最終の平均誤差 | 0.0 |

境界線は `0.02 × aack + 0.01 × beep - 0.04 = 0`、つまり `2 × aack + beep = 4` です。8 点すべてを正しく分類できています。

重みが 0.02 や 0.01 と小さいことに驚くかもしれません。分類では **重みの絶対値ではなく比率と符号だけが意味を持つ** ためです。すべての重みとバイアスを 100 倍しても、境界線はまったく同じ位置にあり、予測も変わりません。回帰では重みの大きさそのものが予測値を決めていたのと対照的です。

## 誤差の推移が示すもの

テストでは誤差の推移について、一見奇妙な事実を固定しています。

```python
def test_perceptron_algorithm_separates_the_dataset():
    model, errors = perceptron_algorithm(POINTS, LABELS, learning_rate=0.01, epochs=1000, seed=0)
    assert accuracy(model, POINTS, LABELS) == pytest.approx(1.0)
    assert len(errors) == 1000
    # 初期モデル（重みもバイアスもすべて 0）はすべての点が境界線上にあるため誤差 0
    assert errors[0] == pytest.approx(0.0)
    # 学習の途中では誤差が生じ、最終的に 0 へ戻る
    assert max(errors) > 0.0
    assert errors[-1] == pytest.approx(0.0)
```

**初期状態の誤差が 0 になります。** 重みもバイアスもすべて 0 なので、どの点のスコアも 0 です。誤分類した点の誤差は `|スコア| = 0` になり、合計しても 0 なのです。

これはパーセプトロン誤差の性質を突いた例です。この誤差関数は「境界線からどれだけ食い込んでいるか」しか見ていないので、**全点が境界線上にある退化した状態を最良と誤認します**。正解率は 0.5 しかないのに、です。

第 3 章では `errors[-1] < errors[0]`（誤差が減った）を検証しましたが、本章で同じ検証を書くと `0.0 < 0.0` で失敗します。**誤差が単調に減るという思い込みをテストが壊してくれました。** 代わりに「途中で誤差が生じ、最終的に 0 へ戻る」という実際の挙動を検証しています。

学習が進むかどうかを見るなら、誤差ではなく正解率を見るべきです。これが `accuracy` を別に用意した理由でもあります。

## まとめ

- 分類は誤分類した点だけを使って学習します。正しい点は動かしません。
- `score`（連続値）と `predict`（0/1）を分けると、誤差関数がスコアを使えます。
- 境界線上をどちらのクラスに倒すかは決めごとです。テストで固定します。
- パーセプトロン誤差は全点が境界線上にある退化状態を 0 と評価します。学習の進み具合は正解率で見ます。
- 学習ループの骨格は第 3 章の線形回帰とまったく同じで、差し替わるのはトリックだけです。
