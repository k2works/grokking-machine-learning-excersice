# 第 12 章 アンサンブル学習（Python 版）

原著第 12 章「Combining models to maximize results」を Python で実装します。**弱い学習器をたくさん集めて、強い学習器を作ります。** 集め方には多数決（バギング）と逐次的な重み付け（AdaBoost）の 2 つの流儀があります。

サンプル実装は `apps/grokking-ml-python/src/grokking_ml/ch12_ensembles.py` です。

## この章で作るもの

- AdaBoost

## 弱学習器としての切り株

第 9 章の決定木で、深さを 1 に制限したものを **決定株（stump）** と呼びます。「1 つの質問だけ」しかできない、非常に弱い学習器です。

本章では次のデータを使います。1 次元上に 3 つの領域が並んでいます。

| x | 1 | 2 | 3 | 4 | 5 | 6 | 7 | 8 |
| :--- | ---: | ---: | ---: | ---: | ---: | ---: | ---: | ---: |
| ラベル | +1 | +1 | -1 | -1 | -1 | -1 | +1 | +1 |

**1 本の切り株では絶対に解けません。** 質問は 1 つだけなので、線を 1 本しか引けないからです。3 つの領域を分けるには最低 2 本要ります。

```python
def test_a_single_stump_cannot_solve_three_regions():
    stump = build_tree(POINTS, LABELS, max_depth=1)
    assert tree_accuracy(stump, POINTS, LABELS) < 1.0
```

実際の正解率は 0.75 です。この弱い学習器をどう束ねるかが本章の主題になります。

## バギング（多数決）

まず素直な方法から。**データを少しずつ変えて木を何本も育て、多数決を取ります。**

```python
def bootstrap_sample(
    points: Sequence[Point],
    labels: Sequence[int],
    rng: random.Random,
) -> tuple[list[Point], list[int]]:
    """復元抽出で元と同じ大きさの標本を作る。"""
    indices = [rng.randrange(len(points)) for _ in range(len(points))]
    return [points[i] for i in indices], [labels[i] for i in indices]
```

**復元抽出**（同じ点を何度でも選べる）が要点です。元と同じ大きさの標本を作りますが、中身は違います。ある点は 3 回選ばれ、別の点は 1 度も選ばれません。

```python
def test_bootstrap_sample_draws_with_replacement():
    sample_points, _ = bootstrap_sample(POINTS, LABELS, random.Random(0))
    # 復元抽出なので、同じ点が複数回選ばれ、選ばれない点も出る
    assert len(set(sample_points)) < len(POINTS)
```

第 4 章の `train_test_split` と対比すると違いがはっきりします。あちらは **重複なく分割** し、こちらは **重複ありで同じ大きさ** を作ります。目的が「評価」と「多様性の確保」で違うためです。

```python
@dataclass(frozen=True)
class Forest:
    """多数決で予測する木の集まり。"""

    trees: tuple[Tree, ...]

    def votes(self, point: Point) -> list[int]:
        return [tree.predict(point) for tree in self.trees]

    def predict(self, point: Point) -> int:
        return majority_label(self.votes(point))
```

第 9 章で書いた `majority_label` をそのまま再利用しています。**葉のラベルを決める多数決と、森の予測を決める多数決は同じ操作** です。

### バギングは効かなかった

```python
def test_forest_of_stumps_does_not_beat_a_single_stump_here():
    stump = build_tree(POINTS, LABELS, max_depth=1)
    forest = train_forest(POINTS, LABELS, tree_count=10, max_depth=1)
    # バギングは似た木ばかり作るので、この問題では改善しない
    assert accuracy(forest, POINTS, LABELS) <= tree_accuracy(stump, POINTS, LABELS) + 1e-9
```

| モデル | 正解率 |
| :--- | ---: |
| 切り株 1 本 | 0.75 |
| 切り株 10 本のバギング | **0.75** |

**改善しませんでした。** 理由は明快です。復元抽出でデータを揺らしても、**どの標本でも「x = 2.5 で切る」のが最良** なので、10 本ともほぼ同じ木になります。同じ意見を 10 回聞いても結論は変わりません。

バギングが効くのは、**個々の学習器が「違う間違い方」をするとき** です。深い木のように分散が大きい学習器なら、平均化でばらつきが減ります。切り株のように偏りが大きい（表現力が足りない）学習器では、何本集めても偏りは消えません。

## AdaBoost（逐次的な重み付け）

そこで発想を変えます。**前の学習器が間違えた点を重点的に見る** ように、次の学習器を育てます。

```python
def train_adaboost(
    points: Sequence[Point],
    labels: Sequence[int],
    rounds: int = 5,
    max_depth: int = 1,
    impurity: Impurity = gini_impurity,
) -> AdaBoost:
    """AdaBoost。間違えた点の重みを上げながら弱学習器を足していく。"""
    weights = [1.0 / len(points)] * len(points)
    learners: list[WeightedTree] = []
    for _ in range(rounds):
        tree = build_tree_with_weights(points, labels, weights, max_depth, impurity)
        error = weighted_error(tree, points, labels, weights)
        if error >= 0.5:
            # 当てずっぽう以下の学習器は採用しない
            break
        alpha = learner_weight(error)
        learners.append(WeightedTree(tree=tree, weight=alpha))
        weights = [
            weight * math.exp(-alpha * label * tree.predict(point))
            for point, label, weight in zip(points, labels, weights)
        ]
        total = sum(weights)
        weights = [weight / total for weight in weights]
    return AdaBoost(learners=tuple(learners))
```

3 つの要素があります。

### 1. 重み付き誤り率

```python
def weighted_error(
    tree: Tree,
    points: Sequence[Point],
    labels: Sequence[int],
    weights: Sequence[float],
) -> float:
    """重み付き誤り率。重みの大きい点を間違えるほど大きくなる。"""
    total = sum(weights)
    if total == 0.0:
        return 0.0
    wrong = sum(
        weight
        for point, label, weight in zip(points, labels, weights)
        if tree.predict(point) != label
    )
    return wrong / total
```

**「何個間違えたか」ではなく「どれだけ重い点を間違えたか」** を測ります。

```python
def test_weighted_error_counts_the_weight_not_the_number():
    tree = Leaf(1)
    # 3 点中 1 点だけ間違えるが、その点の重みが大きい
    points = [(0.0,), (1.0,), (2.0,)]
    labels = [1, 1, -1]
    assert weighted_error(tree, points, labels, [0.1, 0.1, 0.8]) == pytest.approx(0.8)
    assert weighted_error(tree, points, labels, [0.45, 0.45, 0.1]) == pytest.approx(0.1)
```

同じ木・同じデータでも、重み次第で誤り率が 0.8 にも 0.1 にもなります。**「今は何が重要か」を重みが表します。**

### 2. 発言権

```python
def learner_weight(error: float) -> float:
    """弱学習器の発言権。誤り率が小さいほど大きい。"""
    epsilon = 1e-10
    clamped = min(max(error, epsilon), 1.0 - epsilon)
    return 0.5 * math.log((1.0 - clamped) / clamped)
```

この式には 3 つの性質があり、それぞれテストで固定しました。

```python
def test_learner_weight_is_zero_for_a_coin_flip():
    # 誤り率 0.5 の学習器には発言権がない
    assert learner_weight(0.5) == pytest.approx(0.0)


def test_learner_weight_is_negative_for_a_bad_learner():
    # 当てずっぽうより悪い学習器は「逆を言えば当たる」ので負の発言権になる
    assert learner_weight(0.7) < 0.0
```

| 誤り率 | 発言権 | 意味 |
| ---: | ---: | :--- |
| 0.05 | 1.47 | よく当たるので強く聞く |
| 0.5 | **0.0** | 当てずっぽうなので無視 |
| 0.7 | **-0.42** | 逆張りすれば役立つ |

**誤り率 0.5 で発言権がちょうど 0 になる** のが、この式の美しさです。第 7 章で AUC が 0.5 でランダムを意味したのと同じ構図です。

負の発言権も理屈が通っています。「7 割外す予測器」は、逆を取れば 7 割当たります。ただし本実装では `error >= 0.5` で打ち切るため、実際には使いません。

クランプ（`epsilon`）が必要なのは、誤り率 0 のとき `log(1/0)` が無限大になるためです。第 6 章の対数損失、第 8 章のナイーブベイズに続く 3 度目の同じ対処です。

### 3. 重みの更新

```python
        weights = [
            weight * math.exp(-alpha * label * tree.predict(point))
            for point, label, weight in zip(points, labels, weights)
        ]
```

`label * tree.predict(point)` は、当たれば +1、外れれば -1 です（**ラベルが +1 / -1 だから成立します**。第 11 章と同じ理由でこの表現を選びました）。

- 当たった点: `exp(-alpha)` 倍 → 重みが **減る**
- 外れた点: `exp(+alpha)` 倍 → 重みが **増える**

その後 `total` で割って正規化します。**次のラウンドは「今まで外した点」に集中します。**

**同じ弱学習器を同じ本数使って、結果が分かれました。** 束ね方の違いだけです。

```python
def test_adaboost_beats_bagging_here():
    forest = train_forest(POINTS, LABELS, tree_count=10, max_depth=1)
    boosted = train_adaboost(POINTS, LABELS, rounds=10, max_depth=1)
    assert accuracy(boosted, POINTS, LABELS) > accuracy(forest, POINTS, LABELS)
```

学習された切り株を見ると、動きが分かります。

| ラウンド | 発言権 | 分割 |
| ---: | ---: | :--- |
| 1 | 0.549 | x < 2.5 なら +1 |
| 2 | 0.805 | x < 6.5 なら -1 |
| 3 | 0.693 | （全部 +1 の葉） |
| 4 | 0.733 | x < 2.5 なら +1 |

**1 本目は左端、2 本目は右端に注目しました。** 1 本目が右端の `x = 7, 8` を外したので、その重みが上がり、2 本目が拾いに行ったのです。

重み付き投票の結果、`x = 7, 8` では「1 本目は -1、2 本目は +1」となり、発言権の大きい 2 本目が勝ちます。**役割分担が自然に生まれました。**

## バギングと AdaBoost の使い分け

| | バギング | AdaBoost |
| :--- | :--- | :--- |
| 学習器の作り方 | **並列**（互いに独立） | **逐次**（前の結果に依存） |
| データの扱い | 復元抽出でばらつかせる | 重みで注目点を変える |
| 減らせるもの | 分散（過学習） | 偏り（表現力不足） |
| 向く弱学習器 | 深い木（分散が大きい） | 浅い木（偏りが大きい） |
| 並列化 | できる | **できない** |

本章のデータは「切り株では表現力が足りない」問題だったので、AdaBoost が勝ちました。逆に「深い木が過学習する」問題ならバギング（ランダムフォレスト）が効きます。**どちらが優れているかではなく、何を減らしたいかで選びます。**

## まとめ

- 決定株（深さ 1 の木）は、質問が 1 つしかできない弱い学習器です。
- バギングは「違う間違い方をする学習器」を集めるときに効きます。同じ木ばかりできる問題では改善しません。
- AdaBoost は重み付き誤り率で「今なにが重要か」を表し、外した点の重みを上げます。
- 発言権は誤り率 0.5 でちょうど 0 になります。当てずっぽうの意見は無視されます。
- 同じ弱学習器を同じ本数使っても、束ね方で結果が変わります（0.75 対 1.00）。
