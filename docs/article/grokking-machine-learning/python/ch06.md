# 第 6 章 ロジスティック回帰（Python 版）

原著第 6 章「A continuous approach to splitting points」を Python で実装します。第 5 章のパーセプトロンは「0 か 1 か」という硬い予測でした。本章ではシグモイド関数を挟み、**「0 から 1 の確率」** という連続的な予測に置き換えます。

サンプル実装は `apps/grokking-ml-python/src/grokking_ml/ch06_logistic_regression.py` です。

> **Jupyter Notebook で試す**: この章の実験は [ch06.ipynb](notebooks/ch06.ipynb) にまとめてあります。実装本体を読み込んで動かすので、値を変えてその場で試せます。

## この章で作るもの

- シグモイド関数
- 確率を返すロジスティック分類器
- 対数損失（ログロス）
- すべての点を動かすロジスティックトリック

## なぜ確率が要るのか

パーセプトロンには 2 つの弱点がありました。

1. **どれくらい確信しているか分からない。** 境界線ぎりぎりの点も、遠く離れた点も、同じ「1」です。
2. **正しく分類できた点からは何も学べない。** 境界線の 1 ミリ内側にいる危うい点も、更新の対象外です。

ロジスティック回帰は、予測を確率にすることで両方を解きます。0.51 と 0.99 を区別でき、正解している点からも「まだ 0.51 しかない」という改善の余地を汲み取れます。

## シグモイド関数

スコア（実数、範囲は -∞ から +∞）を確率（0 から 1）へ写す関数です。

```python
def sigmoid(x: float) -> float:
    """シグモイド関数。実数を 0 から 1 の範囲へ押し込む。"""
    if x >= 0:
        return 1.0 / (1.0 + math.exp(-x))
    # x が大きな負の数のとき exp(-x) が溢れるため、数学的に等価な式へ切り替える
    exponential = math.exp(x)
    return exponential / (1.0 + exponential)
```

教科書の定義は `1 / (1 + exp(-x))` の 1 行です。しかしそのまま書くと、`x = -1000` のときに `exp(1000)` を計算しようとして `OverflowError` で落ちます。

そこで負の入力では、分子分母に `exp(x)` を掛けた等価な式 `exp(x) / (1 + exp(x))` へ切り替えます。この式なら `exp(-1000)` は 0 に潰れるだけで、例外は起きません。**数学的に同じ式でも、浮動小数点の上では安全な形と危険な形があります。**

この分岐は仕様なのでテストで固定します。

```python
def test_sigmoid_does_not_overflow_for_large_negative_input():
    # 素朴な 1/(1+exp(-x)) 実装は exp のオーバーフローで落ちる
    assert sigmoid(-1000.0) == pytest.approx(0.0)
    assert sigmoid(1000.0) == pytest.approx(1.0)
```

シグモイドの性質もテストで押さえておきます。値域が `[0, 1]` に収まること、単調増加であること、`sigmoid(x) + sigmoid(-x) == 1` という対称性。**確率として使う以上、値域を外れないことは仕様です。**

```python
def test_sigmoid_is_symmetric_around_zero():
    assert sigmoid(2.0) + sigmoid(-2.0) == pytest.approx(1.0)
```

## モデル

```python
@dataclass(frozen=True)
class LogisticClassifier:
    """ロジスティック分類器。予測は 0 から 1 の確率。"""

    weights: tuple[float, ...]
    bias: float

    def score(self, point: Point) -> float:
        return self.bias + sum(w * x for w, x in zip(self.weights, point))

    def predict_probability(self, point: Point) -> float:
        return sigmoid(self.score(point))

    def predict(self, point: Point, threshold: float = 0.5) -> int:
        return 1 if self.predict_probability(point) >= threshold else 0
```

第 5 章のパーセプトロンとの違いは `predict_probability` が挟まったことだけです。`score` の計算はまったく同じです。

`predict` に `threshold` 引数を持たせているのが本章の追加です。パーセプトロンは 0.5 相当の閾値が固定でしたが、確率が手に入ると **後から基準を変えられます**。

```python
def test_predict_uses_the_threshold():
    model = LogisticClassifier(weights=(1.0, 2.0), bias=-4.0)
    assert model.predict((1.0, 2.0)) == 1
    assert model.predict((1.0, 2.0), threshold=0.8) == 0
```

この点の確率は 0.73 です。既定の 0.5 では「楽しい」と判定されますが、0.8 を要求すると「悲しい」になります。**モデルを再学習せずに、判定の厳しさだけを変えられます。** 医療診断のように見逃しを避けたい場面と、誤検知を避けたい場面で閾値を変える、という実務的な調整がここに繋がります（第 7 章の主題です）。

## 対数損失

第 5 章のパーセプトロン誤差には、全点が境界線上にある退化状態を 0 と評価する欠陥がありました。対数損失にはその問題がありません。

```python
def log_loss(model: LogisticClassifier, point: Point, label: int) -> float:
    """1 点分の対数損失。予測確率が正解から離れるほど大きくなる。"""
    probability = model.predict_probability(point)
    # log(0) を避けるためにごくわずかに内側へ丸める
    epsilon = 1e-15
    probability = min(max(probability, epsilon), 1.0 - epsilon)
    if label == 1:
        return -math.log(probability)
    return -math.log(1.0 - probability)
```

正解ラベルに対応する確率の対数を取り、符号を反転します。

| 正解 | 予測確率 | 損失 | 意味 |
| ---: | ---: | ---: | :--- |
| 1 | 0.99 | 0.01 | 自信を持って正解 |
| 1 | 0.51 | 0.67 | 当たってはいるが自信がない |
| 1 | 0.50 | 0.69 | 完全に五分五分 |
| 1 | 0.01 | 4.61 | 自信を持って間違い |

**当たったかどうかではなく、どれくらいの確信で当たったかを測ります。** 0.51 で正解しても損失は 0.67 残るので、学習はまだ進みます。

`epsilon` で確率を内側へ丸めているのは、`log(0)` が `-inf`（実装によっては例外）になるのを避けるためです。シグモイドは数学的には 0 にも 1 にもなりませんが、浮動小数点では `sigmoid(-1000) == 0.0` になります。**数学的に起きないことが実装では起きます。**

```python
def test_log_loss_is_large_when_confident_and_wrong():
    confident = LogisticClassifier(weights=(10.0, 20.0), bias=-40.0)
    assert log_loss(confident, (1.0, 2.0), label=0) > 5.0
```

「自信を持って間違えると重く罰せられる」という性質が、対数損失を分類の損失関数として優れたものにしています。

## ロジスティックトリック

```python
def logistic_trick(
    model: LogisticClassifier,
    point: Point,
    label: int,
    learning_rate: float = 0.01,
) -> LogisticClassifier:
    """ロジスティックトリック。すべての点を、確率の外れ具合に比例して動かす。"""
    error = label - model.predict_probability(point)
    weights = tuple(w + learning_rate * error * x for w, x in zip(model.weights, point))
    return LogisticClassifier(weights, model.bias + learning_rate * error)
```

第 5 章と見比べてください。式は同じ形で、`predict`（0 か 1）が `predict_probability`（0 から 1）に変わっただけです。**それだけで挙動が大きく変わります。**

| | パーセプトロン | ロジスティック |
| :--- | :--- | :--- |
| error の値 | -1, 0, +1 の 3 通り | -1 から +1 の連続値 |
| 正しい点 | 動かない（error = 0） | **わずかに動く**（error ≠ 0） |
| 更新量 | 一定 | 確信のなさに比例 |

早期リターンが消えたことに注目してください。第 5 章では `if error == 0: return model` がありましたが、本章では **すべての点が学習に寄与します**。確率が 0.999 の点はほとんど動かず、0.51 の点は大きく動く。「動く／動かない」という離散的な判断が、「どれだけ動くか」という連続量に置き換わりました。

```python
def test_logistic_trick_moves_even_correctly_classified_points():
    model = LogisticClassifier(weights=(1.0, 2.0), bias=-4.0)
    # 予測は 1（正解）だが、確率は 0.73 なのでまだ動く
    moved = logistic_trick(model, (1.0, 2.0), label=1, learning_rate=0.1)
    assert moved != model
    assert moved.weights[0] > model.weights[0]
```

第 5 章では「動かないこと」を、本章では「動くこと」をテストしています。**同じ形のテストで、逆の性質を固定しているのが 2 つの章の対比そのものです。**

なお、この更新式は対数損失をスコアで微分した結果と一致します。二乗トリックが二乗誤差の勾配降下法だったのと同じ関係です。

## 実行結果

第 5 章と同じ「悲しい／楽しい」データを使います。

```bash
cd apps/grokking-ml-python
uv run python -c "
from grokking_ml.ch06_logistic_regression import *
P = [(1,0),(0,2),(1,1),(1,2),(1,3),(2,2),(2,3),(3,2)]
L = [0,0,0,0,1,1,1,1]
model, losses = logistic_regression(P, L)
print(model.weights, model.bias, accuracy(model, P, L))
"
```

学習率 0.1、1000 エポックで次の結果になりました。

| 項目 | 値 |
| :--- | ---: |
| aack の重み | 2.2506 |
| beep の重み | 1.5327 |
| バイアス | -5.6115 |
| 正解率 | 1.0 |
| 初期の平均対数損失 | 0.6931 |
| 最終の平均対数損失 | 0.1638 |

第 5 章のパーセプトロンでは重みが 0.02 程度でしたが、本章では 2.25 まで大きくなりました。**確率を使うと重みの絶対値に意味が生まれる** ためです。重みを 2 倍にすると境界線の位置は変わりませんが、確率がより 0 と 1 に寄ります。つまり **重みの大きさが「確信の強さ」を表します**。

初期の損失 0.6931 は `-log(0.5)` です。全パラメータが 0 のとき、すべての予測は確率 0.5 になります。第 5 章のパーセプトロン誤差が初期状態で 0 だったのと対照的に、**対数損失は「五分五分」を正しく「何も分かっていない状態」と評価します**。

```python
def test_logistic_regression_separates_the_dataset():
    model, losses = logistic_regression(POINTS, LABELS, learning_rate=0.1, epochs=1000, seed=0)
    assert accuracy(model, POINTS, LABELS) == pytest.approx(1.0)
    assert len(losses) == 1000
    # パーセプトロン誤差と違い、対数損失は初期状態でも 0 にならない
    assert losses[0] == pytest.approx(-math.log(0.5))
    assert losses[-1] < losses[0]
```

第 5 章では書けなかった `losses[-1] < losses[0]`（損失が減った）が、本章では素直に書けます。**損失関数を替えたことで、第 3 章と同じ形のテストが戻ってきました。**

## 確率として使えるか

```python
def test_logistic_regression_produces_calibrated_probabilities():
    model, _ = logistic_regression(POINTS, LABELS, learning_rate=0.1, epochs=1000, seed=0)
    # 明確に楽しい文は高い確率、明確に悲しい文は低い確率になる
    assert model.predict_probability((3.0, 2.0)) > 0.5
    assert model.predict_probability((1.0, 0.0)) < 0.5
```

学習後のモデルは `(3, 2)` に 0.9853、`(1, 0)` に 0.0335 という確率を与えます。単に分類できているだけでなく、**どちらがより確からしいかまで答えられる** ようになりました。

## まとめ

- シグモイドは教科書の 1 行をそのまま書くと大きな負の入力で落ちます。等価な式へ切り替えます。
- 予測を確率にすると、閾値を後から変えられます。再学習は不要です。
- 対数損失は「当たったか」ではなく「どれくらいの確信で当たったか」を測ります。
- ロジスティックトリックは第 5 章と同じ式で、`predict` を `predict_probability` に替えただけです。全点が学習に寄与します。
- 分類でも確率を扱うと重みの絶対値に意味が生まれます（確信の強さ）。
