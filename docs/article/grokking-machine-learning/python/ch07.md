# 第 7 章 分類モデルの評価指標（Python 版）

原著第 7 章「How do you measure classification models?」を Python で実装します。第 5・6 章では正解率だけでモデルを評価してきました。本章では **正解率がまったく役に立たない場面** を出発点に、混同行列・適合率・再現率・F1 スコア・AUC を実装します。

サンプル実装は `apps/grokking-ml-python/src/grokking_ml/ch07_metrics.py` です。

## この章で作るもの

- 混同行列（すべての指標の土台）
- 正解率・適合率・再現率
- F1 スコアと F ベータスコア
- ROC 曲線と AUC

## 正解率 99% の役立たずモデル

1000 人に 10 人が罹る病気を診断するモデルを考えます。**全員を「陰性」と判定する** モデルの正解率は 99% です。

```python
SICK_LABELS = [1] * 10 + [0] * 990
ALWAYS_HEALTHY = [0] * 1000


def test_accuracy_can_be_high_while_the_model_is_useless():
    matrix = confusion_matrix(SICK_LABELS, ALWAYS_HEALTHY)
    # 990/1000 を当てているので正解率は 99%
    assert accuracy(matrix) == pytest.approx(0.99)
    # しかし病人を 1 人も見つけられていない
    assert recall(matrix) == pytest.approx(0.0)
```

このモデルは病人を 1 人も見つけられません。それでも正解率は 99% です。**正解率は、陽性と陰性の数が偏っているときに壊れます。**

本章の指標はすべて、この問題への対処として存在します。

## 混同行列

すべての指標は、4 つの数から導けます。

```python
@dataclass(frozen=True)
class ConfusionMatrix:
    """混同行列。すべての指標の土台になる 4 つの数。"""

    true_positives: int
    false_positives: int
    false_negatives: int
    true_negatives: int

    @property
    def total(self) -> int:
        return (
            self.true_positives
            + self.false_positives
            + self.false_negatives
            + self.true_negatives
        )
```

| | 予測 = 1 | 予測 = 0 |
| :--- | :--- | :--- |
| **正解 = 1** | 真陽性（TP） | 偽陰性（FN）= 見逃し |
| **正解 = 0** | 偽陽性（FP）= 誤検知 | 真陰性（TN） |

4 つの数を **フィールド名で区別している** のが要点です。タプルや辞書で持つと `matrix[1]` が何なのか分からなくなり、偽陽性と偽陰性の取り違えという典型的なバグを招きます。

集計は辞書で行います。

```python
def confusion_matrix(labels: Sequence[int], predictions: Sequence[int]) -> ConfusionMatrix:
    """正解ラベルと予測から混同行列を作る。"""
    counts = {(1, 1): 0, (0, 1): 0, (1, 0): 0, (0, 0): 0}
    for label, prediction in zip(labels, predictions):
        counts[(label, prediction)] += 1
    return ConfusionMatrix(
        true_positives=counts[(1, 1)],
        false_positives=counts[(0, 1)],
        false_negatives=counts[(1, 0)],
        true_negatives=counts[(0, 0)],
    )
```

4 つのキーを **あらかじめ 0 で初期化** しています。`defaultdict` を使えば初期化は省けますが、そうすると「起こりうる組は 4 つだけ」という事実がコードから消えます。ここでは明示を選びました。

キーワード引数で `ConfusionMatrix` を構築しているのも意図的です。位置引数だと `(1, 0)` を `false_positives` に渡すような取り違えが静かに通ってしまいます。

## 適合率と再現率

```python
def precision(matrix: ConfusionMatrix) -> float:
    """適合率。陽性と予測したもののうち、本当に陽性だった割合。"""
    predicted_positive = matrix.true_positives + matrix.false_positives
    if predicted_positive == 0:
        return 0.0
    return matrix.true_positives / predicted_positive


def recall(matrix: ConfusionMatrix) -> float:
    """再現率。本当に陽性のもののうち、拾えた割合。"""
    actual_positive = matrix.true_positives + matrix.false_negatives
    if actual_positive == 0:
        return 0.0
    return matrix.true_positives / actual_positive
```

| 指標 | 問い | 分母 |
| :--- | :--- | :--- |
| 適合率（precision） | 「陽性」と言ったとき、どれくらい信じてよいか | 陽性と **予測した** 数 |
| 再現率（recall） | 本当の陽性を、どれくらい拾えたか | 実際に **陽性である** 数 |

**分母が違うだけです。** 分子はどちらも真陽性です。

2 つはトレードオフの関係にあります。

```python
def test_precision_and_recall_trade_off():
    # 全員を陽性と予測すると再現率は 1.0 だが適合率は下がる
    aggressive = confusion_matrix(SICK_LABELS, [1] * 1000)
    assert recall(aggressive) == pytest.approx(1.0)
    assert precision(aggressive) == pytest.approx(0.01)
```

全員を「陽性」と判定すれば見逃しはゼロ（再現率 1.0）ですが、陽性と言った 1000 件のうち当たりは 10 件だけ（適合率 0.01）です。**冒頭の「全員陰性」モデルとちょうど裏返しの失敗** です。片方の指標だけを追うと、必ずもう一方が壊れます。

0 除算の扱いも仕様として決め、テストで固定します。

```python
def test_metrics_are_zero_when_undefined():
    empty = ConfusionMatrix(0, 0, 0, 0)
    assert accuracy(empty) == pytest.approx(0.0)
    assert precision(empty) == pytest.approx(0.0)
    assert recall(empty) == pytest.approx(0.0)
    assert f1_score(empty) == pytest.approx(0.0)
```

数学的には未定義ですが、例外を投げるか 0 を返すかは実装の決めごとです。ここでは 0 を選び、その判断をテストに残しました。

## F1 スコア

適合率と再現率を 1 つの数にまとめる指標です。ただし **算術平均ではなく調和平均** を使います。

```python
def f_beta_score(matrix: ConfusionMatrix, beta: float = 1.0) -> float:
    """F ベータスコア。beta が大きいほど再現率を重視する。"""
    p = precision(matrix)
    r = recall(matrix)
    if p == 0.0 and r == 0.0:
        return 0.0
    beta_squared = beta * beta
    return (1 + beta_squared) * p * r / (beta_squared * p + r)


def f1_score(matrix: ConfusionMatrix) -> float:
    """F1 スコア。適合率と再現率の調和平均。"""
    return f_beta_score(matrix, beta=1.0)
```

なぜ調和平均かというと、**偏りを強く罰するため** です。

```python
def test_f1_punishes_an_unbalanced_pair_more_than_the_arithmetic_mean():
    # 適合率 1.0、再現率 0.1 のモデル
    matrix = ConfusionMatrix(true_positives=1, false_positives=0, false_negatives=9, true_negatives=90)
    arithmetic_mean = (precision(matrix) + recall(matrix)) / 2
    assert f1_score(matrix) < arithmetic_mean
```

適合率 1.0・再現率 0.1 のモデルは、算術平均なら 0.55 と「まあまあ」に見えます。しかし F1 スコアは 0.18 です。**片方が壊れているモデルを、平均で誤魔化させません。**

F1 を特殊形として持つ一般形が F ベータスコアです。`beta` で重視する側を選べます。

```python
def test_f_beta_with_large_beta_favors_recall():
    # 適合率 0.75、再現率 0.6
    matrix = ConfusionMatrix(true_positives=3, false_positives=1, false_negatives=2, true_negatives=4)
    # beta=2 は再現率重視なので、再現率(0.6)寄りの値になる
    assert f_beta_score(matrix, beta=2.0) < f1_score(matrix)
    # beta=0.5 は適合率重視なので、適合率(0.75)寄りの値になる
    assert f_beta_score(matrix, beta=0.5) > f1_score(matrix)
```

病気の見逃しを避けたいなら `beta > 1`（再現率重視）、迷惑メール判定で誤検知を避けたいなら `beta < 1`（適合率重視）を選びます。**指標そのものを、目的に合わせて調整できます。**

## 閾値と ROC

第 6 章で `predict` に `threshold` を持たせたことが、ここで効いてきます。確率を返すモデルなら、**再学習せずに適合率と再現率のバランスを変えられます。**

```python
def predictions_at_threshold(probabilities: Sequence[float], threshold: float) -> list[int]:
    """確率と閾値から 0 / 1 の予測を作る。"""
    return [1 if probability >= threshold else 0 for probability in probabilities]


def test_lowering_the_threshold_increases_recall():
    labels = [1, 1, 0, 0]
    probabilities = [0.9, 0.4, 0.6, 0.1]
    strict = confusion_matrix(labels, predictions_at_threshold(probabilities, 0.8))
    loose = confusion_matrix(labels, predictions_at_threshold(probabilities, 0.3))
    assert recall(loose) > recall(strict)
    assert precision(loose) < precision(strict)
```

閾値を下げれば拾える陽性が増え（再現率↑）、誤検知も増えます（適合率↓）。**閾値はモデルの性能ではなく、運用上の選択です。**

では、モデル自体の良し悪しは何で測るのか。**すべての閾値を試して、その全体を見ます。** それが ROC 曲線です。

```python
def roc_points(
    labels: Sequence[int],
    probabilities: Sequence[float],
) -> list[tuple[float, float]]:
    """ROC 曲線の点列。閾値を動かしたときの (偽陽性率, 真陽性率) を返す。"""
    thresholds = sorted({*probabilities, 0.0, 1.0 + 1e-9}, reverse=True)
    points: list[tuple[float, float]] = []
    for threshold in thresholds:
        matrix = confusion_matrix(labels, predictions_at_threshold(probabilities, threshold))
        actual_negative = matrix.false_positives + matrix.true_negatives
        false_positive_rate = (
            matrix.false_positives / actual_negative if actual_negative > 0 else 0.0
        )
        points.append((false_positive_rate, recall(matrix)))
    return sorted(points)
```

試す閾値は、**データに現れた確率そのもの** です。それ以外の値を試しても予測は変わりません。加えて両端（全部を陽性にする 0.0 と、全部を陰性にする `1.0 + 1e-9`）を足しています。

`1.0 + 1e-9` という値が要るのは、`predictions_at_threshold` が `>=` で比較するためです。確率がちょうど 1.0 の点があると、閾値 1.0 では陽性のままになってしまいます。**境界の扱いを決めたら、その帰結を最後まで面倒みる必要があります。**

```python
def test_roc_points_start_and_end_at_the_corners():
    labels = [1, 1, 0, 0]
    probabilities = [0.9, 0.6, 0.4, 0.1]
    points = roc_points(labels, probabilities)
    assert points[0] == (0.0, 0.0)
    assert points[-1] == (1.0, 1.0)
```

## AUC

ROC 曲線の下の面積です。台形則で積分します。

```python
def auc(labels: Sequence[int], probabilities: Sequence[float]) -> float:
    """ROC 曲線下の面積。台形則で積分する。"""
    points = roc_points(labels, probabilities)
    area = 0.0
    for (x1, y1), (x2, y2) in pairwise(points):
        area += (x2 - x1) * (y1 + y2) / 2
    return area
```

`itertools.pairwise` は隣り合う 2 要素の組を作ります。`zip(points, points[1:])` でも同じですが、`pairwise` はリストの複製を作らず、意図も明確です。

AUC の意味は「面積」よりも **「陽性を陰性より高くランク付けできた組の割合」** と理解するほうが実用的です。

```python
def test_auc_counts_correctly_ordered_pairs():
    # 陽性 2 件と陰性 2 件の組 4 通りのうち、3 通りで陽性が上位
    labels = [1, 0, 1, 0]
    probabilities = [0.8, 0.6, 0.4, 0.2]
    assert auc(labels, probabilities) == pytest.approx(0.75)
```

このテストは、当初 0.5 を期待して書いて **失敗しました**。「陽性と陰性が交互なら情報がない」と考えたのですが、実際には 4 組中 3 組で陽性が上位にあり、0.75 が正解でした。**思い込みをテストが正してくれた例です。** 0.5 になるのは陽性が最上位と最下位に 1 つずつある場合です。

| 並び | AUC | 意味 |
| :--- | ---: | :--- |
| 陽性がすべて上位 | 1.0 | 完全な順位付け |
| 陽性が最上位と最下位 | 0.5 | ランダムと同じ |
| 陰性がすべて上位 | 0.0 | 完全に逆 |

AUC の最大の利点は **閾値に依存しないこと** です。

```python
def test_auc_ignores_the_threshold():
    # AUC は閾値に依存しない。確率の順位だけで決まる
    labels = [1, 1, 0, 0]
    scaled = [0.99, 0.98, 0.02, 0.01]
    compressed = [0.55, 0.54, 0.46, 0.45]
    assert auc(labels, scaled) == pytest.approx(auc(labels, compressed))
```

確率が 0.99 と 0.01 に分かれていても、0.55 と 0.45 に固まっていても、**順位が同じなら AUC は同じ** です。第 6 章で見た「重みの大きさ＝確信の強さ」は AUC には影響しません。モデルの識別能力だけを取り出せます。

## 指標の使い分け

| 指標 | 見るべき場面 | 弱点 |
| :--- | :--- | :--- |
| 正解率 | クラスの数が釣り合っているとき | 偏りがあると壊れる |
| 適合率 | 誤検知のコストが高いとき | 見逃しを無視する |
| 再現率 | 見逃しのコストが高いとき | 誤検知を無視する |
| F1 | 両方を 1 つの数で見たいとき | 閾値に依存する |
| AUC | モデル自体の識別能力を見たいとき | 実運用の閾値を教えてくれない |

## まとめ

- 正解率はクラスが偏ると壊れます。全員陰性で 99% になります。
- 混同行列の 4 つの数は、必ずフィールド名で区別します。偽陽性と偽陰性の取り違えを防ぐためです。
- 適合率と再現率は分母が違うだけで、必ずトレードオフします。
- F1 は調和平均なので、偏ったモデルを平均で誤魔化させません。F ベータで重視する側を選べます。
- AUC は閾値に依存しない、順位付けの良し悪しの指標です。
