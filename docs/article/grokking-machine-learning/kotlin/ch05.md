# 第 5 章 パーセプトロン（Kotlin 版）

原著第 5 章「Using lines to split our points」を Kotlin で実装します。第 3・4 章の回帰は **数値を予測** するものでしたが、本章からは **分類** に入ります。点を直線で 2 つのクラスに分けるパーセプトロンを実装します。

サンプル実装は `apps/grokking-ml-kotlin/src/main/kotlin/ch05/Perceptron.kt` です。

> **Kotlin Notebook で試す**: この章の実験は [ch05.ipynb](notebooks/ch05.ipynb) にまとめてあります。実装本体を読み込んで動かすので、値を変えてその場で試せます。

## この章で作るもの

- 線形分類器 `score = w・x + bias`、`score >= 0` なら 1
- 誤分類した点だけを使ってモデルを動かすパーセプトロントリック
- パーセプトロン誤差関数と正解率
- トリックを繰り返すパーセプトロンアルゴリズム

## 回帰と分類の違い

| | 回帰（第 3・4 章） | 分類（本章） |
| :--- | :--- | :--- |
| 出力 | 連続値（価格など） | ラベル（0 か 1） |
| モデルが表すもの | データに沿う直線 | データを **分ける** 直線 |
| 誤差 | 予測値と正解値の差 | 誤分類した点の境界からの距離 |
| 更新するタイミング | すべての点で | **誤分類した点だけ** |

もっとも大きな違いは最後の行です。分類では **正しく分類できている点は 1 ミリも動かしません**。

## データセット

原著と同じ「悲しい／楽しい」文の分類データを使います。特徴量は 2 つの単語 `aack` と `beep` の出現回数、ラベルは 1 が「楽しい」です。

| aack | beep | ラベル |
| ---: | ---: | ---: |
| 1 | 0 | 0 |
| 0 | 2 | 0 |
| 1 | 1 | 0 |
| 1 | 2 | 0 |
| 1 | 3 | 1 |
| 2 | 2 | 1 |
| 2 | 3 | 1 |
| 3 | 2 | 1 |

この 2 群は直線で完全に分離できます（線形分離可能）。

## モデル

```kotlin
/** 特徴量ベクトル。 */
typealias Point = List<Double>

/** 線形分類器 score = w・x + bias。score >= 0 なら 1、そうでなければ 0。 */
data class Perceptron(val weights: List<Double>, val bias: Double) {
    fun score(point: Point): Double =
        bias + weights.zip(point) { w, x -> w * x }.sum()

    fun predict(point: Point): Int = if (score(point) >= 0) 1 else 0
}
```

`typealias Point = List<Double>` によって、「特徴量ベクトル」という概念に名前が付きます。第 4 章までは入力が 1 個の `Double` でしたが、本章から多次元になります。

`typealias` は新しい型を作るわけではなく、あくまで別名です。`List<Double>` を渡せてしまうので型安全性は増えませんが、シグネチャの読みやすさは大きく変わります。**別名で足りるか、`value class` で本物の型を作るべきかは、誤用が起きうるかで決めます。** ここでは特徴量ベクトルを取り違える相手（別種のリスト）がいないため、別名で十分です。

`score` と `predict` を分けているのが要点です。`score` は **境界線からどれだけ離れているか** を表す連続値、`predict` はそれを 0 か 1 に潰した結果です。誤差関数はスコアのほうを使います。

`score >= 0` と `>` ではなく `>=` にしているのは、境界線上の点を正のクラスへ倒す約束です。この決めごとは明示的にテストしています。

```kotlin
@Test
fun `predict は境界線上を正のクラスとして扱う`() {
    val model = Perceptron(listOf(1.0, 1.0), -2.0)
    assertEquals(0.0, model.score(listOf(1.0, 1.0)), 1e-9)
    assertEquals(1, model.predict(listOf(1.0, 1.0)))
}
```

## パーセプトロントリック

```kotlin
/** パーセプトロントリック。誤分類した点だけモデルを動かす。 */
fun perceptronTrick(
    model: Perceptron,
    point: Point,
    label: Int,
    learningRate: Double = 0.01,
): Perceptron {
    val error = label - model.predict(point)
    if (error == 0) return model
    val weights = model.weights.zip(point) { w, x -> w + learningRate * error * x }
    return Perceptron(weights, model.bias + learningRate * error)
}
```

`error = label - predict` は 3 通りの値しか取りません。

| ラベル | 予測 | error | 動き |
| ---: | ---: | ---: | :--- |
| 1 | 1 | 0 | 動かない |
| 0 | 0 | 0 | 動かない |
| 1 | 0 | +1 | 境界線を点のほうへ寄せる |
| 0 | 1 | -1 | 境界線を点から遠ざける |

`if (error == 0) return model` という早期リターンで、「正しい点は動かさない」という規則がコードの先頭に現れます。同じモデルをそのまま返すため、テストでは等価比較で確認できます。

```kotlin
@Test
fun `perceptronTrick は正しく分類できた点では動かない`() {
    val model = Perceptron(listOf(1.0, 2.0), -4.0)
    assertEquals(model, perceptronTrick(model, listOf(1.0, 2.0), label = 1))
}
```

`data class` が `equals` を生成しているので、この 1 行で済みます。もし通常の `class` なら参照比較になり、このテストは意図せず通ってしまいます（同じインスタンスを返しているため）。**`data class` にしておくと「値として等しい」ことを検証できます。**

`error` は `Int` ですが、`learningRate * error * x` は `Double` に昇格します。Kotlin は演算子オーバーロードで数値型の混在を吸収するため、明示的な変換は不要です。

第 4 章の二乗トリックと式を並べると、違いは掛ける値だけだと分かります。

| 章 | 更新式（重み） |
| :--- | :--- |
| 第 3・4 章（二乗トリック） | `w + 学習率 × 特徴量 × 誤差の大きさ` |
| 第 5 章（パーセプトロン） | `w + 学習率 × 特徴量 × 誤差の符号（+1 / -1 / 0）` |

## 誤差関数

分類の誤差を「何個間違えたか」で測ると学習に使えません。**間違えた個数は境界線を少し動かしても変わらない** ため、改善の方向が分からないからです。

そこでパーセプトロン誤差は、誤分類した点について **境界線からの距離（スコアの絶対値）** を使います。

```kotlin
/** 1 点分の誤差。正しく分類していれば 0、誤っていればスコアの絶対値。 */
fun perceptronError(model: Perceptron, point: Point, label: Int): Double =
    if (model.predict(point) == label) 0.0 else abs(model.score(point))

/** 全点の平均誤差。 */
fun meanPerceptronError(model: Perceptron, points: List<Point>, labels: List<Int>): Double =
    points.zip(labels).sumOf { (point, label) -> perceptronError(model, point, label) } / points.size

/** 正解率。 */
fun accuracy(model: Perceptron, points: List<Point>, labels: List<Int>): Double =
    points.zip(labels).count { (point, label) -> model.predict(point) == label }.toDouble() / points.size
```

`count { }` は `Int` を返すため、`toDouble()` が必要です。`sumOf { }` はラムダの戻り値型から `Double` を推論するので変換が要りません。**同じ「集計」でも戻り値型が違う** ので、割り算の前に型を確認する習慣が要ります。

誤差関数は学習の手がかり、正解率は人間が結果を評価する指標です。目的が違うので別の関数にしています。

## パーセプトロンアルゴリズム

```kotlin
/** パーセプトロンアルゴリズム。モデルとエポックごとの平均誤差を返す。 */
fun perceptronAlgorithm(
    points: List<Point>,
    labels: List<Int>,
    learningRate: Double = 0.01,
    epochs: Int = 1000,
    seed: Int = 0,
): Pair<Perceptron, List<Double>> {
    val random = Random(seed)
    var model = Perceptron(List(points.first().size) { 0.0 }, 0.0)
    val errors = mutableListOf<Double>()
    repeat(epochs) {
        errors += meanPerceptronError(model, points, labels)
        val i = random.nextInt(points.size)
        model = perceptronTrick(model, points[i], labels[i], learningRate)
    }
    return model to errors
}
```

構造は第 3 章の線形回帰とまったく同じです。違うのは適用するトリックだけです。**同じ骨格に別の学習則を差し込むと別のアルゴリズムになる** ことが、章をまたいで見えてきます。

次元数を `points.first().size` から取っているので、2 次元に限定されません。

## 実行結果

学習率 0.01、1000 エポックで次の結果になりました。

| 項目 | 値 |
| :--- | ---: |
| aack の重み | 0.01 |
| beep の重み | 0.01 |
| バイアス | -0.03 |
| 正解率 | 1.0 |
| 学習中の最大平均誤差 | 0.0275 |
| 最終の平均誤差 | 0.0 |

境界線は `0.01 × aack + 0.01 × beep - 0.03 = 0`、つまり `aack + beep = 3` です。8 点すべてを正しく分類できています。

重みが 0.01 と小さいことに驚くかもしれません。分類では **重みの絶対値ではなく比率と符号だけが意味を持つ** ためです。すべての重みとバイアスを 100 倍しても、境界線はまったく同じ位置にあり、予測も変わりません。回帰では重みの大きさそのものが予測値を決めていたのと対照的です。

Python 版（`2 × aack + beep = 4`）や F# 版とは違う境界線になりました。線形分離可能なデータには **正しい境界線が無数にある** ためです。乱数列の違いで到達する解が変わりますが、どれも正解率 1.0 です。第 3・4 章では「同じくらいの誤差に収束する」ことを確認しましたが、本章では **正解率が 1.0 になること** が言語をまたいだ共通の検証になります。

## 誤差の推移が示すもの

テストでは誤差の推移について、一見奇妙な事実を固定しています。

```kotlin
@Test
fun `perceptronAlgorithm はデータを分離する`() {
    val (model, errors) = perceptronAlgorithm(points, labels, learningRate = 0.01, epochs = 1000, seed = 0)
    assertEquals(1.0, accuracy(model, points, labels), 1e-9)
    assertEquals(1000, errors.size)
    // 初期モデル（重みもバイアスもすべて 0）はすべての点が境界線上にあるため誤差 0
    assertEquals(0.0, errors.first(), 1e-9)
    // 学習の途中では誤差が生じ、最終的に 0 へ戻る
    assertTrue(errors.max() > 0.0)
    assertEquals(0.0, errors.last(), 1e-9)
}
```

**初期状態の誤差が 0 になります。** 重みもバイアスもすべて 0 なので、どの点のスコアも 0 です。誤分類した点の誤差は `|スコア| = 0` になり、合計しても 0 なのです。

これはパーセプトロン誤差の性質を突いた例です。この誤差関数は「境界線からどれだけ食い込んでいるか」しか見ていないので、**全点が境界線上にある退化した状態を最良と誤認します**。正解率は 0.5 しかないのに、です。

第 3 章では「誤差が減った」ことを検証しましたが、本章で同じ検証を書くと `0.0 < 0.0` で失敗します。**誤差が単調に減るという思い込みをテストが壊してくれました。** 学習が進むかどうかを見るなら、誤差ではなく正解率を見るべきです。

## まとめ

- 分類は誤分類した点だけを使って学習します。正しい点は動かしません。
- `typealias` は型安全性を足しませんが、シグネチャの意図を伝えます。
- `data class` の `equals` により、「モデルが動かなかった」ことを値として検証できます。
- `count` は `Int`、`sumOf` はラムダ由来の型を返します。割り算の前に型を確認します。
- パーセプトロン誤差は全点が境界線上にある退化状態を 0 と評価します。学習の進み具合は正解率で見ます。
