# 第 7 章 分類モデルの評価指標（Kotlin 版）

原著第 7 章「How do you measure classification models?」を Kotlin で実装します。第 5・6 章では正解率だけでモデルを評価してきました。本章では **正解率がまったく役に立たない場面** を出発点に、混同行列・適合率・再現率・F1 スコア・AUC を実装します。

サンプル実装は `apps/grokking-ml-kotlin/src/main/kotlin/ch07/Metrics.kt` です。

## この章で作るもの

- 混同行列（すべての指標の土台）
- 正解率・適合率・再現率
- F1 スコアと F ベータスコア
- ROC 曲線と AUC

## 正解率 99% の役立たずモデル

1000 人に 10 人が罹る病気を診断するモデルを考えます。**全員を「陰性」と判定する** モデルの正解率は 99% です。

```kotlin
@Test
fun `正解率が高くてもモデルが役立たずなことがある`() {
    val matrix = confusionMatrix(sickLabels, alwaysHealthy)
    // 990/1000 を当てているので正解率は 99%
    assertEquals(0.99, accuracy(matrix), 1e-9)
    // しかし病人を 1 人も見つけられていない
    assertEquals(0.0, recall(matrix), 1e-9)
}
```

このモデルは病人を 1 人も見つけられません。**正解率は、陽性と陰性の数が偏っているときに壊れます。** 本章の指標はすべて、この問題への対処として存在します。

## 混同行列

すべての指標は、4 つの数から導けます。

```kotlin
/** 混同行列。すべての指標の土台になる 4 つの数。 */
data class ConfusionMatrix(
    val truePositives: Int,
    val falsePositives: Int,
    val falseNegatives: Int,
    val trueNegatives: Int,
) {
    val total: Int get() = truePositives + falsePositives + falseNegatives + trueNegatives
}
```

| | 予測 = 1 | 予測 = 0 |
| :--- | :--- | :--- |
| **正解 = 1** | 真陽性（TP） | 偽陰性（FN）= 見逃し |
| **正解 = 0** | 偽陽性（FP）= 誤検知 | 真陰性（TN） |

4 つとも `Int` なので、**位置引数で構築すると取り違えても型検査を通過します**。そこで生成側では名前付き引数を必ず使います。

```kotlin
/** 正解ラベルと予測から混同行列を作る。 */
fun confusionMatrix(labels: List<Int>, predictions: List<Int>): ConfusionMatrix {
    val counts = labels.zip(predictions).groupingBy { it }.eachCount()
    return ConfusionMatrix(
        truePositives = counts[1 to 1] ?: 0,
        falsePositives = counts[0 to 1] ?: 0,
        falseNegatives = counts[1 to 0] ?: 0,
        trueNegatives = counts[0 to 0] ?: 0,
    )
}
```

集計は `groupingBy { it }.eachCount()` の 1 行です。`zip` が返す `Pair<Int, Int>` をそのままキーにして数え上げます。**`Pair` の `equals` と `hashCode` が自動生成されているから、キーとして直接使えます。**

`counts[1 to 1] ?: 0` の `?: 0` が要るのは、その組み合わせが 1 件も現れないとキー自体が存在しないためです。Kotlin の `Map` の添字アクセスは `V?` を返すので、**null になりうることをコンパイラが強制的に意識させます。** 数え上げの結果に穴があるという事実を、型が教えてくれます。

## 適合率と再現率

0 除算の扱いを 1 か所にまとめます。

```kotlin
/** 0 除算を避ける割り算。分母が 0 なら 0 を返す。 */
private fun safeDivide(numerator: Int, denominator: Int): Double =
    if (denominator == 0) 0.0 else numerator.toDouble() / denominator

/** 正解率。全体のうち正しく当てた割合。 */
fun accuracy(matrix: ConfusionMatrix): Double =
    safeDivide(matrix.truePositives + matrix.trueNegatives, matrix.total)

/** 適合率。陽性と予測したもののうち、本当に陽性だった割合。 */
fun precision(matrix: ConfusionMatrix): Double =
    safeDivide(matrix.truePositives, matrix.truePositives + matrix.falsePositives)

/** 再現率。本当に陽性のもののうち、拾えた割合。 */
fun recall(matrix: ConfusionMatrix): Double =
    safeDivide(matrix.truePositives, matrix.truePositives + matrix.falseNegatives)
```

`safeDivide` を `private` にして切り出したことで、3 つの指標が **それぞれ 1 行の式** になりました。分子と分母の定義だけがコードに残り、「どの数をどの数で割るか」という指標の本質が見えます。

`numerator.toDouble() / denominator` の変換位置に注意が要ります。`numerator / denominator` と書くと **整数除算になり、0.75 が 0 になります**。Kotlin は `Int / Int` を `Int` として計算するため、この間違いは型エラーになりません。第 4 章で見た「暗黙の昇格が便利な場面」の裏面です。

| 指標 | 問い | 分母 |
| :--- | :--- | :--- |
| 適合率（precision） | 「陽性」と言ったとき、どれくらい信じてよいか | 陽性と **予測した** 数 |
| 再現率（recall） | 本当の陽性を、どれくらい拾えたか | 実際に **陽性である** 数 |

2 つはトレードオフの関係にあります。

```kotlin
@Test
fun `precision と recall はトレードオフ`() {
    // 全員を陽性と予測すると再現率は 1.0 だが適合率は下がる
    val aggressive = confusionMatrix(sickLabels, List(1000) { 1 })
    assertEquals(1.0, recall(aggressive), 1e-9)
    assertEquals(0.01, precision(aggressive), 1e-9)
}
```

全員を「陽性」と判定すれば見逃しはゼロ（再現率 1.0）ですが、当たりは 10 件だけ（適合率 0.01）です。**冒頭の「全員陰性」モデルとちょうど裏返しの失敗** です。

## F1 スコア

適合率と再現率を 1 つの数にまとめますが、**算術平均ではなく調和平均** を使います。

```kotlin
/** F ベータスコア。beta が大きいほど再現率を重視する。 */
fun fBetaScore(matrix: ConfusionMatrix, beta: Double = 1.0): Double {
    val p = precision(matrix)
    val r = recall(matrix)
    if (p == 0.0 && r == 0.0) return 0.0
    val betaSquared = beta * beta
    return (1 + betaSquared) * p * r / (betaSquared * p + r)
}

/** F1 スコア。適合率と再現率の調和平均。 */
fun f1Score(matrix: ConfusionMatrix): Double = fBetaScore(matrix, beta = 1.0)
```

なぜ調和平均かというと、**偏りを強く罰するため** です。

```kotlin
@Test
fun `f1Score は偏りを算術平均より強く罰する`() {
    // 適合率 1.0、再現率 0.1 のモデル
    val unbalanced = ConfusionMatrix(1, 0, 9, 90)
    val arithmeticMean = (precision(unbalanced) + recall(unbalanced)) / 2
    assertTrue(f1Score(unbalanced) < arithmeticMean)
}
```

適合率 1.0・再現率 0.1 のモデルは、算術平均なら 0.55 と「まあまあ」に見えますが、F1 スコアは 0.18 です。**片方が壊れているモデルを、平均で誤魔化させません。**

`f1Score` を `fBetaScore` のデフォルト引数付き呼び出しとして定義しているのは、第 6 章の `predict` / `threshold` と同じ形です。**一般形を 1 つ書き、よく使う特殊形に名前を付ける。** `beta` で重視する側を選べます。

```kotlin
@Test
fun `fBetaScore は beta が大きいほど再現率を重視する`() {
    // 適合率 0.75、再現率 0.6
    assertTrue(fBetaScore(sample, beta = 2.0) < f1Score(sample))
    assertTrue(fBetaScore(sample, beta = 0.5) > f1Score(sample))
}
```

病気の見逃しを避けたいなら `beta > 1`（再現率重視）、迷惑メール判定で誤検知を避けたいなら `beta < 1`（適合率重視）です。

## 閾値と ROC

第 6 章で `predict` に `threshold` を持たせたことが、ここで効いてきます。確率を返すモデルなら、**再学習せずに適合率と再現率のバランスを変えられます。**

```kotlin
@Test
fun `閾値を下げると再現率が上がり適合率が下がる`() {
    val labels = listOf(1, 1, 0, 0)
    val probabilities = listOf(0.9, 0.4, 0.6, 0.1)
    val strict = confusionMatrix(labels, predictionsAtThreshold(probabilities, 0.8))
    val loose = confusionMatrix(labels, predictionsAtThreshold(probabilities, 0.3))
    assertTrue(recall(loose) > recall(strict))
    assertTrue(precision(loose) < precision(strict))
}
```

**閾値はモデルの性能ではなく、運用上の選択です。** ではモデル自体の良し悪しは何で測るのか。すべての閾値を試して、その全体を見ます。それが ROC 曲線です。

```kotlin
/** ROC 曲線の点列。閾値を動かしたときの (偽陽性率, 真陽性率) を返す。 */
fun rocPoints(labels: List<Int>, probabilities: List<Double>): List<Pair<Double, Double>> {
    val thresholds = (probabilities + listOf(0.0, 1.0 + 1e-9)).distinct().sortedDescending()
    return thresholds.map { threshold ->
        val matrix = confusionMatrix(labels, predictionsAtThreshold(probabilities, threshold))
        val falsePositiveRate =
            safeDivide(matrix.falsePositives, matrix.falsePositives + matrix.trueNegatives)
        falsePositiveRate to recall(matrix)
    }.sortedWith(compareBy({ it.first }, { it.second }))
}
```

試す閾値は **データに現れた確率そのもの** です。それ以外の値を試しても予測は変わりません。

`1.0 + 1e-9` という値が要るのは、`predictionsAtThreshold` が `>=` で比較するためです。確率がちょうど 1.0 の点があると、閾値 1.0 では陽性のままになります。**境界の扱いを決めたら、その帰結を最後まで面倒みる必要があります。**

`sortedWith(compareBy({ it.first }, { it.second }))` で 2 段のキー指定をしています。`Pair` は `Comparable` ではないため `sorted()` は使えず、比較の順序を明示する必要があります。

## AUC

ROC 曲線の下の面積です。台形則で積分します。

```kotlin
/** ROC 曲線下の面積。台形則で積分する。 */
fun auc(labels: List<Int>, probabilities: List<Double>): Double =
    rocPoints(labels, probabilities)
        .zipWithNext { (x1, y1), (x2, y2) -> (x2 - x1) * (y1 + y2) / 2 }
        .sum()
```

`zipWithNext` は隣り合う 2 要素に関数を適用します。**インデックス操作もループも書かずに、「隣同士の台形を足す」という定義がそのまま並びます。** ラムダの引数で `Pair` を分解宣言できるため、座標名も付けられます。

AUC の意味は「面積」よりも **「陽性を陰性より高くランク付けできた組の割合」** と理解するほうが実用的です。

| 並び | AUC | 意味 |
| :--- | ---: | :--- |
| 陽性がすべて上位 | 1.0 | 完全な順位付け |
| 陽性が最上位と最下位 | 0.5 | ランダムと同じ |
| 陰性がすべて上位 | 0.0 | 完全に逆 |

```kotlin
@Test
fun `auc は正しく並んだ組の割合`() {
    // 陽性 2 件と陰性 2 件の組 4 通りのうち、3 通りで陽性が上位
    assertEquals(0.75, auc(listOf(1, 0, 1, 0), listOf(0.8, 0.6, 0.4, 0.2)), 1e-9)
}
```

AUC の最大の利点は **閾値に依存しないこと** です。

```kotlin
@Test
fun `auc は閾値に依存しない`() {
    val labels = listOf(1, 1, 0, 0)
    val scaled = listOf(0.99, 0.98, 0.02, 0.01)
    val compressed = listOf(0.55, 0.54, 0.46, 0.45)
    assertEquals(auc(labels, scaled), auc(labels, compressed), 1e-9)
}
```

確率が 0.99 と 0.01 に分かれていても、0.55 と 0.45 に固まっていても、**順位が同じなら AUC は同じ** です。第 6 章で見た「重みの大きさ＝確信の強さ」は AUC には影響しません。

## 指標の使い分け

| 指標 | 見るべき場面 | 弱点 |
| :--- | :--- | :--- |
| 正解率 | クラスの数が釣り合っているとき | 偏りがあると壊れる |
| 適合率 | 誤検知のコストが高いとき | 見逃しを無視する |
| 再現率 | 見逃しのコストが高いとき | 誤検知を無視する |
| F1 | 両方を 1 つの数で見たいとき | 閾値に依存する |
| AUC | モデル自体の識別能力を見たいとき | 実運用の閾値を教えてくれない |

## まとめ

- 正解率はクラスが偏ると壊れます。全員陰性で 99% になります。
- 同じ型のフィールドが 4 つ並ぶ `data class` は、名前付き引数で構築します。型検査は取り違えを防いでくれません。
- `groupingBy { it }.eachCount()` で数え上げが 1 行になります。`Pair` はそのままキーに使えます。
- `Int / Int` は整数除算です。指標の計算では必ず `toDouble()` の位置を確認します。
- `zipWithNext` により、台形則の定義がそのまま式になります。
