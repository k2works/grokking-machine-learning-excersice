# 第 6 章 ロジスティック回帰（Kotlin 版）

原著第 6 章「A continuous approach to splitting points」を Kotlin で実装します。第 5 章のパーセプトロンは「0 か 1 か」という硬い予測でした。本章ではシグモイド関数を挟み、**「0 から 1 の確率」** という連続的な予測に置き換えます。

サンプル実装は `apps/grokking-ml-kotlin/src/main/kotlin/ch06/LogisticRegression.kt` です。

> **Kotlin Notebook で試す**: この章の実験は [ch06.ipynb](notebooks/ch06.ipynb) にまとめてあります。実装本体を読み込んで動かすので、値を変えてその場で試せます。

## この章で作るもの

- シグモイド関数
- 確率を返すロジスティック分類器
- 対数損失（ログロス）
- すべての点を動かすロジスティックトリック

## なぜ確率が要るのか

パーセプトロンには 2 つの弱点がありました。

1. **どれくらい確信しているか分からない。** 境界線ぎりぎりの点も、遠く離れた点も、同じ「1」です。
2. **正しく分類できた点からは何も学べない。** 境界線の 1 ミリ内側にいる危うい点も、更新の対象外です。

ロジスティック回帰は、予測を確率にすることで両方を解きます。

## シグモイド関数

```kotlin
/** シグモイド関数。実数を 0 から 1 の範囲へ押し込む。 */
fun sigmoid(x: Double): Double =
    if (x >= 0) {
        1.0 / (1.0 + exp(-x))
    } else {
        // x が大きな負の数のとき exp(-x) が溢れるため、数学的に等価な式へ切り替える
        val exponential = exp(x)
        exponential / (1.0 + exponential)
    }
```

教科書の定義は `1 / (1 + exp(-x))` の 1 行です。JVM の `exp` は例外を投げずに `Infinity` を返すため、素朴な実装でも落ちはしません。しかし `1.0 / Infinity` が 0.0 になるだけで、途中に `Infinity` を経由する計算はいつ精度を失ってもおかしくありません。

そこで負の入力では、分子分母に `exp(x)` を掛けた等価な式 `exp(x) / (1 + exp(x))` へ切り替えます。**数学的に同じ式でも、浮動小数点の上では安全な形と危険な形があります。**

`if` が式なので、この分岐はそのまま関数本体の式になります。中間変数への代入は不要です。

シグモイドの性質はテストで押さえます。

```kotlin
@Test
fun `sigmoid の値域は 0 から 1`() {
    listOf(-1000.0, -10.0, 0.0, 10.0, 1000.0).forEach {
        assertTrue(sigmoid(it) in 0.0..1.0, "sigmoid($it)=${sigmoid(it)}")
    }
}
```

`in 0.0..1.0` という範囲リテラルが「値域」という概念をそのまま表します。失敗時にはメッセージで実際の値が出ます。**確率として使う以上、値域を外れないことは仕様です。**

## モデル

```kotlin
/** ロジスティック分類器。予測は 0 から 1 の確率。 */
data class LogisticClassifier(val weights: List<Double>, val bias: Double) {
    fun score(point: Point): Double = bias + weights.zip(point) { w, x -> w * x }.sum()

    fun predictProbability(point: Point): Double = sigmoid(score(point))

    fun predict(point: Point, threshold: Double = 0.5): Int =
        if (predictProbability(point) >= threshold) 1 else 0
}
```

第 5 章のパーセプトロンとの違いは `predictProbability` が挟まったことだけです。`score` の計算はまったく同じです。

`predict` に `threshold` のデフォルト引数を持たせているのが本章の追加です。パーセプトロンは 0.5 相当の閾値が固定でしたが、確率が手に入ると **後から基準を変えられます**。

```kotlin
@Test
fun `predict は閾値を使う`() {
    assertEquals(1, model.predict(listOf(1.0, 2.0)))
    assertEquals(0, model.predict(listOf(1.0, 2.0), threshold = 0.8))
}
```

デフォルト引数のおかげで、既定の使い方（`predict(point)`）は第 5 章と同じ書き味のまま、必要なときだけ `threshold = 0.8` と足せます。**既存の呼び出しを一切壊さずに調整点を増やせました。**

この点の確率は 0.73 です。既定の 0.5 では「楽しい」と判定されますが、0.8 を要求すると「悲しい」になります。モデルを再学習せずに判定の厳しさだけを変えられる、という性質は第 7 章の主題につながります。

## 対数損失

第 5 章のパーセプトロン誤差には、全点が境界線上にある退化状態を 0 と評価する欠陥がありました。対数損失にはその問題がありません。

```kotlin
/** 1 点分の対数損失。予測確率が正解から離れるほど大きくなる。 */
fun logLoss(model: LogisticClassifier, point: Point, label: Int): Double {
    // log(0) を避けるためにごくわずかに内側へ丸める
    val epsilon = 1e-15
    val probability = min(max(model.predictProbability(point), epsilon), 1.0 - epsilon)
    return if (label == 1) -ln(probability) else -ln(1.0 - probability)
}
```

正解ラベルに対応する確率の対数を取り、符号を反転します。

| 正解 | 予測確率 | 損失 | 意味 |
| ---: | ---: | ---: | :--- |
| 1 | 0.99 | 0.01 | 自信を持って正解 |
| 1 | 0.51 | 0.67 | 当たってはいるが自信がない |
| 1 | 0.50 | 0.69 | 完全に五分五分 |
| 1 | 0.01 | 4.61 | 自信を持って間違い |

**当たったかどうかではなく、どれくらいの確信で当たったかを測ります。**

`min(max(x, epsilon), 1.0 - epsilon)` は範囲へのクランプです。Kotlin には `coerceIn` があるので `x.coerceIn(epsilon, 1.0 - epsilon)` とも書けますが、ここでは 3 言語で式を揃えるため `min`/`max` にしています。実務のコードなら `coerceIn` のほうが意図が明確です。

クランプが必要なのは、`ln(0.0)` が `-Infinity` になるためです。シグモイドは数学的には 0 にも 1 にもなりませんが、浮動小数点では `sigmoid(-1000.0) == 0.0` になります。**数学的に起きないことが実装では起きます。**

## ロジスティックトリック

```kotlin
/** ロジスティックトリック。すべての点を、確率の外れ具合に比例して動かす。 */
fun logisticTrick(
    model: LogisticClassifier,
    point: Point,
    label: Int,
    learningRate: Double = 0.01,
): LogisticClassifier {
    val error = label - model.predictProbability(point)
    val weights = model.weights.zip(point) { w, x -> w + learningRate * error * x }
    return LogisticClassifier(weights, model.bias + learningRate * error)
}
```

第 5 章と見比べてください。式は同じ形で、`predict`（0 か 1）が `predictProbability`（0 から 1）に変わっただけです。

| | パーセプトロン | ロジスティック |
| :--- | :--- | :--- |
| error の値 | -1, 0, +1 の 3 通り | -1 から +1 の連続値 |
| error の型 | `Int` | `Double` |
| 正しい点 | 動かない（早期リターン） | **わずかに動く** |
| 更新量 | 一定 | 確信のなさに比例 |

`error` の型が変わった点に注目してください。第 5 章では `Int - Int = Int` でしたが、本章は `Int - Double = Double` です。Kotlin の演算子オーバーロードが自動で昇格させるため、コードの見た目は変わりません。**型が変わったのに書き換えが要らないのは、`==` による比較（`error == 0`）を消したからでもあります。** 浮動小数点を 0 と厳密比較する分岐は書くべきではなく、実際そうする必要もありませんでした。

早期リターンが消えたことで、**すべての点が学習に寄与します**。確率が 0.999 の点はほとんど動かず、0.51 の点は大きく動く。

```kotlin
@Test
fun `logisticTrick は正しく分類できた点でも動く`() {
    // 予測は 1（正解）だが、確率は 0.73 なのでまだ動く
    val moved = logisticTrick(model, listOf(1.0, 2.0), label = 1, learningRate = 0.1)
    assertNotEquals(model, moved)
    assertTrue(moved.weights[0] > model.weights[0])
}
```

第 5 章では `assertEquals(model, ...)` で「動かないこと」を、本章では `assertNotEquals` で「動くこと」を検証しています。**同じ形のテストで逆の性質を固定しているのが 2 つの章の対比そのものです。** どちらも `data class` の `equals` があるから 1 行で書けます。

なお、この更新式は対数損失をスコアで微分した結果と一致します。二乗トリックが二乗誤差の勾配降下法だったのと同じ関係です。

## 実行結果

第 5 章と同じ「悲しい／楽しい」データを使います。学習率 0.1、1000 エポックで次の結果になりました。

| 項目 | 値 |
| :--- | ---: |
| aack の重み | 2.0201 |
| beep の重み | 1.5903 |
| バイアス | -5.5970 |
| 正解率 | 1.0 |
| 初期の平均対数損失 | 0.6931 |
| 最終の平均対数損失 | 0.1582 |

第 5 章のパーセプトロンでは重みが 0.01 程度でしたが、本章では 2.02 まで大きくなりました。**確率を使うと重みの絶対値に意味が生まれる** ためです。重みを 2 倍にしても境界線の位置は変わりませんが、確率がより 0 と 1 に寄ります。つまり **重みの大きさが「確信の強さ」を表します**。

第 5 章では 3 言語が別々の境界線に到達しましたが、本章では 3 言語ともほぼ同じ重み（2.0〜2.3、1.5〜1.6）に収束しました。**損失関数に最小点がひとつしかないため、どの経路を通っても同じ場所へ向かいます。** 第 5 章の「正しい境界線が無数にある」状態との違いです。

初期の損失 0.6931 は `-ln(0.5)` です。全パラメータが 0 のとき、すべての予測は確率 0.5 になります。第 5 章のパーセプトロン誤差が初期状態で 0 だったのと対照的に、**対数損失は「五分五分」を正しく「何も分かっていない状態」と評価します**。

```kotlin
@Test
fun `logisticRegression はデータを分離する`() {
    val (trained, losses) = logisticRegression(points, labels, learningRate = 0.1, epochs = 1000, seed = 0)
    assertEquals(1.0, accuracy(trained, points, labels), 1e-9)
    assertEquals(1000, losses.size)
    // パーセプトロン誤差と違い、対数損失は初期状態でも 0 にならない
    assertEquals(-ln(0.5), losses.first(), 1e-9)
    assertTrue(losses.last() < losses.first())
}
```

第 5 章では書けなかった `losses.last() < losses.first()`（損失が減った）が、本章では素直に書けます。**損失関数を替えたことで、第 3 章と同じ形のテストが戻ってきました。**

学習後のモデルは `(3, 2)` に 0.9745、`(1, 0)` に 0.0272 という確率を与えます。単に分類できているだけでなく、**どちらがより確からしいかまで答えられる** ようになりました。

## まとめ

- シグモイドは教科書の 1 行をそのまま書くと `Infinity` を経由します。等価な式へ切り替えます。
- `threshold` のデフォルト引数により、既存の呼び出しを壊さずに調整点を増やせます。
- 対数損失は「当たったか」ではなく「どれくらいの確信で当たったか」を測ります。
- `error` の型が `Int` から `Double` に変わっても、演算子オーバーロードが吸収します。浮動小数点を 0 と厳密比較する分岐は不要です。
- `assertEquals` / `assertNotEquals` の対比が、第 5 章と本章の性質の違いをそのまま表します。
