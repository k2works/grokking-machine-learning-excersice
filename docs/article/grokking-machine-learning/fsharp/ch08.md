# 第 8 章 ナイーブベイズ（F# 版）

原著第 8 章「Using probability to its maximum」を F# で実装します。第 5〜7 章の分類器は境界線を **学習** しました。本章の分類器は **数え上げるだけ** です。それでいて実用的な精度が出ます。

サンプル実装は `apps/grokking-ml-fsharp/src/GrokkingMl/Ch08NaiveBayes.fs` です。

## この章で作るもの

- 文書を単語集合に分解するトークナイザ
- 単語ごとのクラス別出現回数を数える学習
- ラプラス平滑化つきの単語スパム確率
- 対数空間での文書スパム確率の合成

## 学習しない学習器

| | 第 5〜6 章 | 第 8 章 |
| :--- | :--- | :--- |
| 学習 | エポックを回して重みを更新 | **数えるだけ**（1 回のパス） |
| ハイパーパラメータ | 学習率、エポック数、シード | 平滑化の強さのみ |
| 乱数 | 使う | **使わない** |
| 結果の再現性 | シード依存 | **常に同一** |

そのため本章の実装は、**3 言語すべてで数値が完全に一致します**。

## ベイズの定理と「ナイーブ」な仮定

知りたいのは「この文書がスパムである確率」です。しかし単語列全体の出現確率を数えることはできません。そこで **「単語は互いに独立に出現する」** と仮定します。これがナイーブ（素朴）と呼ばれる所以です。**明らかに間違った仮定ですが、それでも実用的に機能します。**

## トークナイズと学習

```fsharp
/// 文章を小文字の単語列に分解する。
let tokenize (text: string) =
    text.ToLowerInvariant().Split(' ')
    |> Array.filter (fun word -> word <> "")
    |> Array.toList

/// 文書とラベル（1 がスパム）から分類器を学習する。
let train (documents: string list) (labels: int list) =
    // 同じ単語が何度出ても 1 文書につき 1 回だけ数える（ベルヌーイ型）
    let wordSetsFor label =
        List.zip documents labels
        |> List.filter (fun (_, l) -> l = label)
        |> List.map (fst >> tokenize >> Set.ofList)

    let countWords label =
        wordSetsFor label
        |> List.collect Set.toList
        |> List.countBy id
        |> Map.ofList

    { SpamWordCounts = countWords 1
      HamWordCounts = countWords 0
      SpamDocuments = List.length (wordSetsFor 1)
      HamDocuments = List.length (wordSetsFor 0) }
```

`List.map (fst >> tokenize >> Set.ofList)` の `>>` は **関数合成** です。「タプルの第 1 要素を取り、トークナイズし、集合にする」という 3 段の処理が、ラムダを書かずに 1 つの関数として組み上がります。`fun (doc, _) -> Set.ofList (tokenize doc)` と書くより、処理の流れが左から右に読めます。

`wordSetsFor` と `countWords` を **ローカル関数** にしているのが要点です。`documents` と `labels` をクロージャで捕捉するので引数はラベルだけで済み、スパム用とハム用で同じ処理を 2 度書かずにすみます。

`List.countBy id` は第 7 章と同じ数え上げです。`id`（恒等関数）を渡すことで「要素そのものをキーとして数える」という意味になります。

### なぜ集合にするのか

「spam spam spam」で `spam` を 3 回数えるか 1 回数えるかは、モデルの種類の違いです。回数を数えるのが多項分布型、出現の有無だけを見るのがベルヌーイ型です。ここではベルヌーイ型を選びました。

```fsharp
[<Fact>]
let ``train は同じ単語を 1 文書につき 1 回だけ数える`` () =
    let repeated = train [ "spam spam spam" ] [ 1 ]
    Assert.Equal(1, Map.find "spam" repeated.SpamWordCounts)
```

## モデル

```fsharp
/// ナイーブベイズ分類器。単語ごとの出現回数からスパム確率を求める。
type NaiveBayesClassifier =
    { SpamWordCounts: Map<string, int>
      HamWordCounts: Map<string, int>
      SpamDocuments: int
      HamDocuments: int }

    member this.TotalDocuments = this.SpamDocuments + this.HamDocuments

    member this.Vocabulary =
        Set.union (Set.ofSeq (Map.keys this.SpamWordCounts)) (Set.ofSeq (Map.keys this.HamWordCounts))
```

**F# の `Map` は不変です。** Python の `Counter`（可変な `dict` のサブクラス）や Kotlin の `Map`（読み取り専用インターフェースだが実体は可変かもしれない）と違い、値として振る舞います。モデル全体が本当に不変であることが型で保証されます。

## ラプラス平滑化

ある単語がスパム文書に 3 回、通常文書に 0 回現れたとします。素朴に計算すると確率は `3 / 3 = 1.0` です。

これは危険です。**確率 1.0 は「絶対にスパム」を意味し、他のどんな単語が来ても覆せません**。そこで、すべてのカウントに 1 を足します。

```fsharp
/// その単語を含む文書がスパムである確率。ラプラス平滑化つき。
let wordSpamProbabilityWith (smoothing: float) (model: NaiveBayesClassifier) (word: string) =
    let countIn counts =
        Map.tryFind word counts |> Option.defaultValue 0 |> float

    let spam = countIn model.SpamWordCounts + smoothing
    let ham = countIn model.HamWordCounts + smoothing
    spam / (spam + ham)

/// 平滑化 1.0 での単語のスパム確率。
let wordSpamProbability (model: NaiveBayesClassifier) (word: string) =
    wordSpamProbabilityWith 1.0 model word
```

`Map.tryFind word counts |> Option.defaultValue 0 |> float` というパイプラインが、**「探す → 無ければ 0 → 浮動小数点にする」** という 3 つの手順をそのまま並べます。Kotlin の `(map[word] ?: 0).toDouble()` と同じ意図ですが、`Option` という明示的な型を経由します。

`countIn` をローカル関数にしたことで、スパム側とハム側が対称な 1 行になりました。

引数順は第 4 章から一貫して「ハイパーパラメータ → データ」です。だから `wordSpamProbabilityWith 1.0` の部分適用で既定値版を作れます。**F# にデフォルト引数がない代わりの、いつもの解き方です。**

```fsharp
[<Fact>]
let ``wordSpamProbability はラプラス平滑化を使う`` () =
    // lottery はスパム 3 件、ハム 0 件。平滑化なしなら 1.0 になってしまう
    Assert.Equal(3, Map.find "lottery" model.SpamWordCounts)
    Assert.Equal(None, Map.tryFind "lottery" model.HamWordCounts)
    // (3+1) / ((3+1) + (0+1)) = 0.8
    Assert.Equal(0.8, wordSpamProbability model "lottery", 6)
```

`Assert.Equal(None, Map.tryFind ...)` という行が F# らしい点です。**「そのキーは存在しない」ことを `None` という値として検証できます。** Kotlin では `null` との比較、Python の `Counter` では 0 との比較になり、「無い」と「0 件」の区別が曖昧になります。

未知語はスパム 0 件・通常 0 件なので、平滑化後はちょうど 0.5 になります。**「何も知らない単語は判定に寄与しない」** という望ましい性質が自然に出ます。

## 対数空間で合成する

各単語の確率を掛け合わせるのが素直な実装ですが、**そのまま書くと壊れます**。0.1 を 100 語分掛けるとアンダーフローします。そこで対数を取り、掛け算を足し算に変えます。

```fsharp
/// 文書がスパムである確率。対数空間で計算する。
let predictProbabilityWith (smoothing: float) (model: NaiveBayesClassifier) (document: string) =
    if model.TotalDocuments = 0 then
        0.0
    else
        let prior = priorSpamProbability model

        // 学習時に見ていない単語は何も語らないので無視する
        let words =
            tokenize document
            |> Set.ofList
            |> Set.filter (fun word -> Set.contains word model.Vocabulary)

        let accumulate (logSpam, logHam) word =
            let spamGivenWord = wordSpamProbabilityWith smoothing model word
            (logSpam + log (safe spamGivenWord), logHam + log (safe (1.0 - spamGivenWord)))

        let logSpam, logHam =
            Set.fold accumulate (log (safe prior), log (safe (1.0 - prior))) words

        // log の差から確率へ戻す（シグモイドと同じ形）
        1.0 / (1.0 + exp (logHam - logSpam |> max -700.0 |> min 700.0))
```

2 つの累積値を **タプルで畳み込んでいます**。`Set.fold` の状態が `(logSpam, logHam)` というタプルなので、可変変数が 1 つも要りません。Python と Kotlin では `logSpam += ...` という再代入で書いた箇所です。

第 3 章の学習ループでも `(model, errors)` をタプルで畳み込みました。**「複数の値を同時に更新したい」という場面で、F# は一貫してタプルの畳み込みを使えます。**

最後の行の `1 / (1 + exp(差))` は **第 6 章のシグモイドとまったく同じ形** です。ロジスティック回帰では重み付き和をシグモイドに通しました。ここでは対数確率の差を通しています。**まったく違う道筋で同じ関数に辿り着きます。**

`logHam - logSpam |> max -700.0 |> min 700.0` のクランプは、第 6 章の `logLoss` と同じパイプライン形式です。.NET では `exp 710.0` は `infinity` になり落ちませんが、3 言語で同じ式にするため入れています（Python では例外になります）。

空の文書は、単語による更新が 1 つも起きないので **事前確率そのもの** を返します。

```fsharp
[<Fact>]
let ``空の文書は事前確率を返す`` () =
    Assert.Equal(priorSpamProbability model, predictProbability model "", 6)
```

## 実行結果

スパム 3 通、通常 5 通の小さなデータセットで学習します。

### 単語ごとのスパム確率

| 単語 | スパム文書 | 通常文書 | 平滑化後の確率 |
| :--- | ---: | ---: | ---: |
| lottery | 3 | 0 | 0.8000 |
| winning | 2 | 0 | 0.7500 |
| sale | 2 | 1 | 0.6000 |
| today | 0 | 2 | 0.2500 |
| meeting | 0 | 3 | 0.2000 |
| unseen（未知語） | 0 | 0 | 0.5000 |

### 文書ごとのスパム確率

| 文書 | 確率 |
| :--- | ---: |
| （空） | 0.3750 |
| project deadline | 0.0909 |
| sale today | 0.2308 |
| lottery | 0.7059 |
| lottery winning | 0.8780 |
| lottery winning sale | 0.9153 |

**これらの値は Python 版・Kotlin 版と完全に一致します。** 乱数も学習ループもないためです。第 3〜6 章では言語ごとに数値が違いましたが、本章では 3 言語のどれで計算しても同じ答えになります。

スパム語が重なるほど確率が上がるのは掛け算の効果です。「lottery」単独では 0.71、「winning」が加わると 0.88 になります。

## まとめ

- ナイーブベイズに学習ループはありません。数え上げの 1 パスで終わります。
- 関数合成（`fst >> tokenize >> Set.ofList`）により、変換の流れが左から右に読めます。
- `Map` が不変なので、モデル全体の不変性が型で保証されます。
- `Map.tryFind |> Option.defaultValue` で、「キーが無い」ことが `None` という値として扱えます。
- 2 つの累積値は `Set.fold` にタプルを畳み込めば、可変変数なしで更新できます。
