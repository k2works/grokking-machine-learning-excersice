# 第 9 章 決定木（F# 版）

原著第 9 章「Splitting data by asking questions」を F# で実装します。これまでの分類器はすべて **直線** でデータを分けてきました。決定木は「質問を積み重ねる」ことで、直線では表せない領域を切り出します。

**本章は 3 言語のうち F# がもっとも自然に書けた章です。** 決定木は再帰的な代数的データ型そのものであり、F# の判別共用体とパターンマッチが直接その形をしているためです。

サンプル実装は `apps/grokking-ml-fsharp/src/GrokkingMl/Ch09DecisionTrees.fs` です。

## この章で作るもの

- ジニ不純度とエントロピー（分割の良さを測る 2 つの指標）
- 情報利得
- 分割候補の列挙と最良分割の選択
- 再帰的な木の構築

## データセット

原著と同じアプリ推薦データを使います。特徴量は性別（0=女性、1=男性）と年齢、ラベルは 1 が「推薦する」です。

| 性別 | 年齢 | 推薦 |
| ---: | ---: | ---: |
| 1 | 15 | 1 |
| 0 | 25 | 0 |
| 0 | 32 | 0 |
| 1 | 35 | 0 |
| 0 | 12 | 1 |
| 1 | 14 | 1 |
| 1 | 55 | 0 |
| 0 | 40 | 0 |

「若い人には推薦する」という規則が見えます。**性別は関係ありません。** 決定木がそれを自力で見つけられるかが本章の焦点です。

## 不純度を関数型として扱う

```fsharp
/// 不純度の測り方。
type Impurity = int list -> float

/// ラベルごとの割合。
let private shares (labels: int list) =
    let total = float (List.length labels)

    labels
    |> List.countBy id
    |> List.map (fun (_, count) -> float count / total)

/// ジニ不純度。ランダムに 2 つ選んだとき、ラベルが食い違う確率。
let giniImpurity: Impurity =
    fun labels ->
        if List.isEmpty labels then
            0.0
        else
            1.0 - (shares labels |> List.sumBy (fun share -> share * share))

/// エントロピー。ラベルの散らばりを情報量で測る。
let entropy: Impurity =
    fun labels ->
        if List.isEmpty labels then
            0.0
        else
            -(shares labels |> List.sumBy (fun share -> share * log share / log 2.0))
```

**F# では関数型に名前を付けられます。** `type Impurity = int list -> float` は型略称であり、シグネチャに `Impurity` と書けば「不純度の測り方を受け取る」と伝わります。

`shares`（ラベルごとの割合）を private のヘルパーに切り出したことで、2 つの指標がそれぞれ 1 つの式になりました。**共通部分を括り出すと、2 指標の違い（`share²` の和か、`share·log₂(share)` の和か）だけが残ります。**

F# の標準ライブラリに `log2` はないため、`log share / log 2.0` と底の変換を書いています。

| 集合 | ジニ不純度 | エントロピー |
| :--- | ---: | ---: |
| `[1; 1; 1]`（純粋） | 0.0 | 0.0 |
| `[1; 1; 1; 0]`（偏り） | 0.375 | 0.811 |
| `[1; 1; 0; 0]`（均等） | 0.5 | 1.0 |
| `[0; 1; 2; 3]`（4 クラス均等） | 0.75 | 2.0 |

## 分割とその適用

```fsharp
/// 1 つの質問による分割。「Feature 番目の特徴量が Threshold 未満か」を問う。
type Split =
    { Feature: int
      Threshold: float }

/// 左（true）へ進むか。
let matches (split: Split) (point: Point) = point[split.Feature] < split.Threshold

/// 分割を適用して左右に振り分ける。
let applySplit (points: Point list) (labels: int list) (split: Split) =
    let left, right =
        List.zip points labels
        |> List.partition (fun (point, _) -> matches split point)

    { LeftPoints = List.map fst left
      LeftLabels = List.map snd left
      RightPoints = List.map fst right
      RightLabels = List.map snd right }
```

`List.partition` が「条件を満たすものとそうでないもの」のタプルを返すので、振り分けが素直に書けます。

戻り値は 4 本のリストなので、第 4 章と同じくレコード型（`Partition`）で名前を付けました。

### 候補の列挙

```fsharp
/// 試す価値のある分割の候補。隣り合う値の中点を閾値にする。
let candidateSplits (points: Point list) =
    [ for feature in 0 .. List.length (List.head points) - 1 do
          let values = points |> List.map (fun point -> point[feature]) |> List.distinct |> List.sort

          for low, high in List.pairwise values do
              { Feature = feature; Threshold = (low + high) / 2.0 } ]
```

リスト内包表記の中で `let` と二重の `for` が書けます。**「各特徴量について、隣り合う値の中点を集める」という手順がそのまま入れ子になります。** `flatMap` を明示的に呼ぶ必要がありません。

閾値に中点を使うのは、**どちらの点にも寄らない位置を選ぶため** です。

## 最良分割の探索

```fsharp
/// 情報利得がもっとも大きい分割。改善しないなら None。
let bestSplit (impurity: Impurity) (points: Point list) (labels: int list) =
    candidateSplits points
    |> List.choose (fun split ->
        let partition = applySplit points labels split

        if List.isEmpty partition.LeftLabels || List.isEmpty partition.RightLabels then
            None
        else
            Some(split, informationGain impurity labels partition.LeftLabels partition.RightLabels))
    |> function
        | [] -> None
        | candidates ->
            let best = candidates |> List.maxBy snd
            if snd best > 0.0 then Some best else None
```

`List.choose` は「変換しつつ `None` を捨てる」操作です（Kotlin の `mapNotNull` に相当）。

`|> function | [] -> ... | candidates -> ...` という書き方に注目してください。**`function` キーワードは「引数を受け取って即座にパターンマッチする無名関数」** です。パイプラインの途中で場合分けを差し込めるので、`match` のために変数を導入せずに済みます。

`List.maxBy` は空リストで例外を投げるため、`[] -> None` の枝で先に処理しています。**空の可能性を型で扱わない標準関数があることは、F# でも意識が必要です。**

戻り値の `(Split * float) option` が **「良い分割が存在しないかもしれない」ことを型で表現します。**

実際のデータで各候補の利得を計算すると、次のようになります（根の不純度は 0.4688）。

| 特徴量 | 閾値 | 情報利得 |
| :--- | ---: | ---: |
| 性別 | 0.5 | 0.0312 |
| 年齢 | 14.5 | 0.2604 |
| **年齢** | **20.0** | **0.4688** |
| 年齢 | 28.5 | 0.2812 |
| 年齢 | 47.5 | 0.0402 |

「年齢 < 20」の利得が根の不純度と等しく、**この 1 回の質問で不純度が 0 になります**。**決定木は自力で「年齢が効く、性別は関係ない」を見つけました。**

## 木の表現

ここが F# のもっとも自然な部分です。

```fsharp
/// 決定木。葉か内部ノードのいずれか。
type Tree =
    | Leaf of label: int
    | Node of split: Split * left: Tree * right: Tree

/// 木による予測。
let rec predict (tree: Tree) (point: Point) =
    match tree with
    | Leaf label -> label
    | Node(split, left, right) -> predict (if matches split point then left else right) point
```

**「木は葉か内部ノードのどちらか」という定義が、そのまま 3 行の型宣言になります。** クラス階層もインターフェースも要りません。判別共用体は再帰的に定義でき、`Node` が `Tree` を 2 つ持つと書くだけです。

`predict` は `match` の 2 つの枝がそのまま定義です。`Node(split, left, right)` というパターンで、3 つのフィールドが同時に名前付きで取り出されます。

木を走査する関数はすべてこの形になります。

```fsharp
/// 木の深さ。葉だけなら 0。
let rec depth (tree: Tree) =
    match tree with
    | Leaf _ -> 0
    | Node(_, left, right) -> 1 + max (depth left) (depth right)

/// 葉の数。
let rec leafCount (tree: Tree) =
    match tree with
    | Leaf _ -> 1
    | Node(_, left, right) -> leafCount left + leafCount right
```

使わないフィールドは `_` で明示的に無視します。**「葉のラベルは深さの計算に関係ない」ことがコード上に現れます。**

パターンは入れ子にできるので、テストでは木の形を直接検査できます。

```fsharp
[<Fact>]
let ``木の構造をパターンマッチで検査できる`` () =
    match buildTreeWith giniImpurity 1 1 points labels with
    | Node(_, Leaf _, Leaf _) -> ()
    | _ -> failwith "深さ 1 の木は葉 2 枚を持つはずだった"
```

`Node(_, Leaf _, Leaf _)` という 1 つのパターンが **「根が内部ノードで、子が両方とも葉」** という構造の主張そのものです。Python や Kotlin では `isinstance` / `is` を 3 回書く必要があります。

## 木の構築

```fsharp
let rec buildTreeWith
    (impurity: Impurity)
    (maxDepth: int)
    (minSamples: int)
    (points: Point list)
    (labels: int list)
    =
    if maxDepth <= 0
       || List.length labels <= minSamples
       || (labels |> List.distinct |> List.length) = 1 then
        Leaf(majorityLabel labels)
    else
        match bestSplit impurity points labels with
        | None -> Leaf(majorityLabel labels)
        | Some(split, _) ->
            let partition = applySplit points labels split

            Node(
                split,
                buildTreeWith impurity (maxDepth - 1) minSamples partition.LeftPoints partition.LeftLabels,
                buildTreeWith impurity (maxDepth - 1) minSamples partition.RightPoints partition.RightLabels
            )

/// 既定の設定（ジニ不純度、深さ 5、最小サンプル 1）で木を構築する。
let buildTree (points: Point list) (labels: int list) =
    buildTreeWith giniImpurity 5 1 points labels
```

`bestSplit` の `option` を `match` で受けるので、**「分割がない場合」を書き忘れることがありません。** Kotlin の `?: return` は簡潔ですが、F# は両方の枝を必ず書かせます。

引数順は第 4 章から一貫して「ハイパーパラメータ → データ」です。だから `buildTreeWith giniImpurity 5 1` の部分適用で既定版を作れます。**デフォルト引数のない F# での、いつもの解き方です。**

停止条件は 4 つです。

| 条件 | 理由 |
| :--- | :--- |
| `maxDepth <= 0` | 深すぎる木は過学習する（第 4 章の次数と同じ） |
| `List.length labels <= minSamples` | 少なすぎるデータからの分割は信用できない |
| ラベルが 1 種類 | すでに純粋なので分ける必要がない |
| `bestSplit` が `None` | どう分けても改善しない |

**上 2 つは第 4 章の正則化と同じ役割です。**

## 実行結果

深さ 1、葉 2 枚の木で **正解率 1.0** に達しました。

```text
Node({ Feature = 1; Threshold = 20.0 }, Leaf 1, Leaf 0)
```

「20 歳未満なら推薦、そうでなければ推薦しない」という 1 つの質問だけです。最大深さを 5 に設定していますが、根で完全に分かれたのでそれ以上は伸びませんでした。

判別共用体は既定で構造的等価性と `ToString` を持つため、**木の構造をそのまま出力・比較できます**。

この結果は Python 版・Kotlin 版と完全に一致します。第 7・8 章と同じく **乱数を使わないアルゴリズム** だからです。

## ジニとエントロピーの比較

```fsharp
[<Fact>]
let ``ジニとエントロピーはこのデータで同じ木を作る`` () =
    Assert.Equal(
        buildTreeWith giniImpurity 5 1 points labels,
        buildTreeWith entropy 5 1 points labels
    )
```

このデータでは **どちらの指標を使っても同じ木になりました**。値の絶対値は違う（0.4688 と 0.9544）のに、順序が同じだからです。

判別共用体の構造的等価性により、**木全体の比較が 1 行で書けます**。

## まとめ

- 判別共用体は再帰的な木構造をそのまま表現できます。`Tree = Leaf | Node of ... * Tree * Tree` の 3 行で定義が終わります。
- 木を走査する関数はすべて `match` の 2 枝になります。使わないフィールドは `_` で意図を示せます。
- 入れ子パターン（`Node(_, Leaf _, Leaf _)`）により、木の形そのものをテストで主張できます。
- 関数型に名前を付けられる（`type Impurity = int list -> float`）ので、戦略の差し替えがシグネチャに現れます。
- `List.choose` と `function` キーワードにより、パイプラインの中で場合分けを完結できます。
