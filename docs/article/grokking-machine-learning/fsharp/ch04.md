# 第 4 章 過学習・未学習と正則化（F# 版）

原著第 4 章「Optimizing the training process」を F# で実装します。モデルが **単純すぎる（未学習）** ときと **複雑すぎる（過学習）** ときの見分け方を学び、複雑さを抑える手段として L1 / L2 正則化を実装します。

サンプル実装は `apps/grokking-ml-fsharp/src/GrokkingMl/Ch04Regularization.fs` です。

## この章で作るもの

- 多項式モデル `y = bias + w1*x + w2*x² + ... + wn*xⁿ`
- データを訓練用とテスト用に分ける `trainTestSplit`
- 正則化項を加えた二乗トリック
- 次数を変えたときの訓練誤差とテスト誤差の比較

## 未学習と過学習

| 状態 | 訓練誤差 | テスト誤差 | 原因 |
| :--- | :--- | :--- | :--- |
| 未学習（underfitting） | 大きい | 大きい | モデルが単純すぎてデータの傾向を表せない |
| ちょうどよい | 小さい | 小さい | — |
| 過学習（overfitting） | とても小さい | 大きい | モデルが複雑すぎて訓練データを丸暗記した |

**訓練誤差だけを見ていては過学習を検出できません。** 学習に使わないデータを取り分けておく必要があります。

## モデル

第 3 章の `Model`（傾きと切片）を任意次数へ拡張します。

```fsharp
/// 多項式モデル y = bias + w1*x + w2*x^2 + ... + wn*x^n。
type PolynomialModel =
    { Weights: float list
      Bias: float }

    member this.Degree = List.length this.Weights

/// x から [x; x^2; ...; x^degree] を作る。
let polynomialFeatures (x: float) (degree: int) =
    [ for power in 1..degree -> x ** float power ]

/// モデルによる予測。
let predict (model: PolynomialModel) (x: float) =
    model.Weights
    |> List.mapi (fun index w -> w * x ** float (index + 1))
    |> List.sum
    |> (+) model.Bias
```

`Degree` をフィールドではなく **メンバー** にすることで、重みの個数と次数が食い違う状態を作れなくしています。レコードは既定で不変なので、この派生値が古くなる心配もありません。

`polynomialFeatures` はリスト内包表記で書いています。`[ for power in 1..degree -> ... ]` は `List.map` を使うより意図が直接的です。

## 訓練データとテストデータの分割

戻り値が 4 つのリストになるため、レコード型で名前を付けます。

```fsharp
/// 訓練用とテスト用に分割したデータセット。
type Split =
    { TrainFeatures: float list
      TrainLabels: float list
      TestFeatures: float list
      TestLabels: float list }

/// データを訓練用とテスト用に分割する。
let trainTestSplit (testRatio: float) (seed: int) (features: float list) (labels: float list) =
    let rng = Random(seed)

    let indices =
        List.init (List.length features) id
        |> List.sortBy (fun _ -> rng.Next())

    let testSize = int (float (List.length features) * testRatio)
    let testIndices = List.truncate testSize indices
    let trainIndices = List.skip testSize indices

    { TrainFeatures = trainIndices |> List.map (fun i -> features[i])
      TrainLabels = trainIndices |> List.map (fun i -> labels[i])
      TestFeatures = testIndices |> List.map (fun i -> features[i])
      TestLabels = testIndices |> List.map (fun i -> labels[i]) }
```

4 要素のタプルを返すこともできますが、`fst` / `snd` すら使えず「3 番目は何だったか」を毎回思い出すことになります。**要素が 3 つ以上になったらレコード型で名前を付ける** のが読みやすさの分かれ目です。

F# の標準ライブラリにはリストのシャッフルがないため、`List.sortBy (fun _ -> rng.Next())` でランダムなキーによる並べ替えとして表現しています。

引数の順序は第 3 章と同じ方針です。ハイパーパラメータ（`testRatio`、`seed`）を先、データを後に置くことで、`trainTestSplit 0.3 0` と部分適用して「分割方法を固定した関数」を作れます。

## 正則化

過学習したモデルの重みは、極端に大きな正と負の値が打ち消し合う形になりがちです。そこで **「誤差を減らす」ことに加えて「重みを小さく保つ」ことも目的に加える** のが正則化です。

| 種類 | ペナルティ | 勾配 | 効果 |
| :--- | :--- | :--- | :--- |
| L1（Lasso） | λ Σ\|wᵢ\| | λ · sign(wᵢ) | 重みを **ほぼ 0** まで押し下げる（スパースになる） |
| L2（Ridge） | λ Σwᵢ² | 2λ · wᵢ | 重み全体をなだらかに縮める |

```fsharp
/// 正則化の種類。
type Regularization =
    | NoRegularization
    | L1
    | L2

/// 正則化項の勾配。重みを 0 に引き戻す向きの力を返す。
let regularizationGradient (weight: float) (kind: Regularization) (strength: float) =
    match kind with
    | NoRegularization -> 0.0
    | L1 -> strength * (if weight > 0.0 then 1.0 elif weight < 0.0 then -1.0 else 0.0)
    | L2 -> strength * 2.0 * weight
```

判別共用体に対する `match` は、F# コンパイラが網羅性を検査します。将来 `ElasticNet` を追加すれば、この `match` は「不完全なパターン マッチ」の警告を出し、実装漏れが分かります。ワイルドカード `_` を書いてしまうとこの利点が失われるため、意図的に書いていません。

ケース名を `None` ではなく `NoRegularization` にしているのは、F# の標準 `Option` 型の `None` と衝突するためです。判別共用体のケース名は名前空間を共有するので、汎用的な単語は避けます。

L1 の勾配は **重みの大きさによらず一定** です。だから小さな重みも同じ力で 0 へ押され、最終的にほぼ 0 に張り付きます。L2 の勾配は重みに比例するため、0 に近づくほど力が弱まり、完全な 0 にはなりません。

## 正則化つきの二乗トリック

```fsharp
/// 二乗トリックに正則化項を加えた 1 点分の更新。
let squareTrick
    (learningRate: float)
    (kind: Regularization)
    (strength: float)
    (model: PolynomialModel)
    (x: float)
    (y: float)
    =
    let error = y - predict model x
    let features = polynomialFeatures x model.Degree

    let weights =
        List.map2
            (fun w feature ->
                w + learningRate * (error * feature - regularizationGradient w kind strength))
            model.Weights
            features

    { Weights = weights
      Bias = model.Bias + learningRate * error }
```

`List.map2` は 2 本のリストを同時に走査します。`List.zip` してから `List.map` するより 1 段階少なく書けます。

F# にはデフォルト引数がないため、ハイパーパラメータ 3 つを常に渡すことになります。冗長に見えますが、これも部分適用で解決できます。

```fsharp
/// 既定のハイパーパラメータ（学習率 0.01、20000 エポック、シード 0）で学習する。
let train (degree: int) (kind: Regularization) (strength: float) =
    polynomialRegression degree 0.01 20000 kind strength 0
```

**デフォルト引数の代わりに、設定済みの関数を作る。** これが F# での定番の解き方です。呼び出し側は `train 5 L2 0.01 trainX trainY` と書けます。

**バイアス（切片）には正則化を掛けません。** バイアスはモデルの複雑さではなく、データ全体の位置を表すためです。この設計判断はテストで固定しています。

```fsharp
[<Fact>]
let ``squareTrick はバイアスを正則化しない`` () =
    let model = { Weights = [ 2.0 ]; Bias = 1.0 }
    let plain = squareTrick 0.01 NoRegularization 0.0 model 3.0 10.0
    let regularized = squareTrick 0.01 L2 0.1 model 3.0 10.0
    Assert.Equal(plain.Bias, regularized.Bias, 6)
```

## 学習

```fsharp
/// 確率的勾配降下法で多項式回帰を学習する。
let polynomialRegression
    (degree: int)
    (learningRate: float)
    (epochs: int)
    (kind: Regularization)
    (strength: float)
    (seed: int)
    (features: float list)
    (labels: float list)
    =
    let rng = Random(seed)
    let initial = { Weights = List.replicate degree 0.0; Bias = 0.0 }

    let step model _ =
        let i = rng.Next(List.length features)
        squareTrick learningRate kind strength model features[i] labels[i]

    List.fold step initial [ 1..epochs ]
```

第 3 章と同じく `List.fold` で学習ループを表現しています。第 3 章では誤差の履歴も畳み込んでいましたが、本章では最終モデルだけが必要なので、状態はモデル 1 つで済みます。畳み込む状態が減った分、`step` が 1 行になりました。

初期値をランダムではなく **すべて 0** にしているのは、次数が上がるほど `x^n` の値が大きくなり、初期値によっては発散するためです。

## 実験

`y = 2x + 3` に小さなノイズを乗せた 10 点を、7 点の訓練データと 3 点のテストデータに分けます。

### 次数を上げるとどうなるか

| 次数 | 訓練 RMSE | テスト RMSE | 汎化ギャップ |
| ---: | ---: | ---: | ---: |
| 1 | 0.1538 | 0.2958 | 0.142 |
| 3 | 0.0562 | 0.2970 | 0.241 |
| 5 | 0.0537 | 0.3370 | 0.283 |

真のデータは 1 次関数なので、1 次モデルで十分です。次数を上げると訓練誤差は 0.154 → 0.054 と下がる一方、テスト誤差は 0.296 → 0.337 へ悪化し、**汎化ギャップ**（テスト誤差 − 訓練誤差）は 0.142 → 0.283 へ倍増しました。訓練データのノイズまで再現してしまったのです。

```fsharp
[<Fact>]
let ``高次モデルは過学習する`` () =
    let s = split ()
    let simple = train 1 NoRegularization 0.0 s.TrainFeatures s.TrainLabels
    let complex = train 5 NoRegularization 0.0 s.TrainFeatures s.TrainLabels

    let gap (model: PolynomialModel) =
        modelRmse model s.TestFeatures s.TestLabels
        - modelRmse model s.TrainFeatures s.TrainLabels

    // 次数を上げると訓練誤差は下がる
    let simpleTrainError = modelRmse simple s.TrainFeatures s.TrainLabels
    let complexTrainError = modelRmse complex s.TrainFeatures s.TrainLabels
    Assert.True(complexTrainError < simpleTrainError)
    // しかし汎化ギャップ（テスト誤差 - 訓練誤差）は広がる
    Assert.True(gap complex > gap simple, $"simple={gap simple} complex={gap complex}")
```

`gap` をテスト内のローカル関数として定義できるのが F# の書き味です。比較したい概念そのものに名前を付けられるので、アサーションが仕様の文になります。

なお、`Assert.True( 長い式 )` を複数行に分けて書くとオフサイドルールに引っかかるため、途中結果を `let` で束縛しています。F# ではインデントが構文なので、**長い式は分割せず名前を付ける** のが素直です。

### 正則化を掛けるとどうなるか

5 次モデルに λ = 0.01 の正則化を掛けます。

| 正則化 | 訓練 RMSE | テスト RMSE | 重みの絶対値合計 | 学習された重み |
| :--- | ---: | ---: | ---: | :--- |
| なし | 0.0537 | 0.3370 | 2.793 | 2.236, -0.206, -0.017, -0.145, -0.190 |
| L1 | 0.0751 | 0.2088 | 2.467 | 2.152, -0.220, **-0.0011**, **-0.0001**, -0.094 |
| L2 | 0.1233 | **0.1498** | 2.920 | 1.741, -0.350, 0.512, 0.116, -0.201 |

読み取れることが 3 つあります。

1. **訓練誤差は悪化し、テスト誤差は改善した。** 正則化は訓練データへの当てはまりをわざと諦める代わりに、未知のデータへの当てはまりを買っています。
2. **L1 は 3 次と 4 次の重みをほぼ 0 にした。** 「この次数は要らない」とモデル自身が判断したことになります。
3. **L2 は重みを 0 にはしないが、1 次の重みを 2.24 → 1.74 へ縮めた。** 全体をなだらかに抑え込んでいます。

```fsharp
[<Fact>]
let ``L1 正則化は不要な重みをほぼ 0 にする`` () =
    let s = split ()
    let plain = train 5 NoRegularization 0.0 s.TrainFeatures s.TrainLabels
    let regularized = train 5 L1 0.01 s.TrainFeatures s.TrainLabels

    Assert.True(weightMagnitude regularized < weightMagnitude plain)
    Assert.True(regularized.Weights |> List.filter (fun w -> abs w < 5e-3) |> List.length >= 2)
    Assert.Empty(plain.Weights |> List.filter (fun w -> abs w < 5e-3))
```

「ちょうど 0」ではなく「5e-3 未満」で検証しているのは、劣勾配による確率的更新では厳密な 0 に張り付かないためです。実際 F# 版の 3 次の重みは -0.0011 で、Python 版（-0.0003）や Kotlin 版（0.0001）より 0 から離れています。**数学的な理想ではなく実装が実際に返す値** を基準にしたので、3 言語で同じ閾値を使えました。

この表の値が Python 版・Kotlin 版と異なるのは、シャッフルと乱数列が言語ごとに違い、訓練データとテストデータの分かれ方も変わるためです。傾向（次数を上げるとギャップが広がる、L1 が重みを 0 にする、L2 がテスト誤差を改善する）は 3 言語で共通しています。

## まとめ

- 過学習は訓練誤差だけでは検出できません。学習に使わないデータを必ず取り分けます。
- 戻り値が 3 要素以上になったらタプルではなくレコード型で名前を付けます。
- 判別共用体 × `match` は網羅性を検査してくれます。`_` を書くとその利点が失われます。
- デフォルト引数がない代わりに、部分適用で「設定済みの関数」を作ります。
- L1 は重みをほぼ 0 にして次数を選び、L2 は全体をなだらかに縮めます。
