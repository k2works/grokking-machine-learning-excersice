# 第 12 章 アンサンブル学習（F# 版）

原著第 12 章「Combining models to maximize results」を F# で実装します。**弱い学習器をたくさん集めて、強い学習器を作ります。** 集め方には多数決（バギング）と逐次的な重み付け（AdaBoost）の 2 つの流儀があります。

サンプル実装は `apps/grokking-ml-fsharp/src/GrokkingMl/Ch12Ensembles.fs` です。

## この章で作るもの

- ブートストラップ標本（復元抽出）
- 多数決で予測する森（バギング）
- 重み付き誤り率と学習器の発言権
- AdaBoost

## 前章の実装を部品として使う

本章は **第 9 章の決定木をそのまま部品として使います。**

```fsharp
open GrokkingMl.Ch09DecisionTrees
```

`open` 1 行で `Tree`・`buildTreeWith`・`majorityLabel`・`giniImpurity` がすべて使えます。第 10・11 章では前章の実装を「比較対象」として呼びましたが、本章では **構成部品** です。

**第 9 章で `Impurity` を関数型として定義しておいたことが、ここで効きます。** アンサンブルの関数もすべて `impurity` を引数で受け取り、そのまま `buildTreeWith` へ渡すだけで済みます。

## 弱学習器としての切り株

第 9 章の決定木で、深さを 1 に制限したものを **決定株（stump）** と呼びます。「1 つの質問だけ」しかできない、非常に弱い学習器です。

本章では次のデータを使います。1 次元上に 3 つの領域が並んでいます。

| x | 1 | 2 | 3 | 4 | 5 | 6 | 7 | 8 |
| :--- | ---: | ---: | ---: | ---: | ---: | ---: | ---: | ---: |
| ラベル | +1 | +1 | -1 | -1 | -1 | -1 | +1 | +1 |

**1 本の切り株では絶対に解けません。** 質問は 1 つだけなので、線を 1 本しか引けないからです。実際の正解率は 0.75 です。

## バギング（多数決）

```fsharp
/// 復元抽出で元と同じ大きさの標本を作る。
let bootstrapSample (rng: Random) (points: Point list) (labels: int list) =
    let indices = List.init (List.length points) (fun _ -> rng.Next(List.length points))
    (indices |> List.map (fun i -> points[i]), indices |> List.map (fun i -> labels[i]))
```

**復元抽出**（同じ点を何度でも選べる）が要点です。第 4 章の `trainTestSplit` と対比すると違いがはっきりします。あちらは `List.sortBy` で **重複なく並べ替え**、こちらは `List.init` で **重複ありのインデックス列** を作ります。目的が「評価」と「多様性の確保」で違うためです。

引数順は第 4 章から一貫して「変わりにくいもの → データ」です。`rng` を先頭に置いたので、`bootstrapSample rng` という部分適用ができます。

```fsharp
/// 多数決で予測する木の集まり。
type Forest = { Trees: Tree list }

/// 各木の投票。
let votes (forest: Forest) (point: Point) =
    forest.Trees |> List.map (fun tree -> predict tree point)

/// 多数決による予測。
let forestPredict (forest: Forest) (point: Point) = majorityLabel (votes forest point)
```

第 9 章で書いた `majorityLabel` をそのまま再利用しています。**葉のラベルを決める多数決と、森の予測を決める多数決は同じ操作** です。

関数名を `forestPredict` としたのは、第 9 章の `predict`（木の予測）と名前が衝突するためです。**F# のモジュールは `open` で名前が平坦に入る** ため、章をまたいで使う関数には接頭辞が要ります。Kotlin ではパッケージ名で修飾できますが、F# では名前そのものを分ける判断になりました。

### バギングは効かなかった

| モデル | 正解率 |
| :--- | ---: |
| 切り株 1 本 | 0.75 |
| 切り株 10 本のバギング | **0.75** |

**改善しませんでした。** 復元抽出でデータを揺らしても、**どの標本でも「x = 2.5 で切る」のが最良** なので、10 本ともほぼ同じ木になります。同じ意見を 10 回聞いても結論は変わりません。

バギングが効くのは、**個々の学習器が「違う間違い方」をするとき** です。切り株のように偏りが大きい（表現力が足りない）学習器では、何本集めても偏りは消えません。

## AdaBoost（逐次的な重み付け）

### 重み付き誤り率

```fsharp
let weightedError (tree: Tree) (points: Point list) (labels: int list) (weights: float list) =
    let total = List.sum weights

    if total = 0.0 then
        0.0
    else
        List.zip3 points labels weights
        |> List.sumBy (fun (point, label, weight) -> if predict tree point <> label then weight else 0.0)
        |> fun wrong -> wrong / total
```

**`List.zip3` で 3 本のリストを同時に走査できます。** Kotlin では `zip` が 2 本までなのでインデックス経由にしましたが、F# では第 11 章のカーネル分類器と同じくタプルの分解で書けます。

**「何個間違えたか」ではなく「どれだけ重い点を間違えたか」** を測ります。同じ木・同じデータでも、重み次第で誤り率が 0.8 にも 0.1 にもなります。

### 発言権

```fsharp
let learnerWeight (error: float) =
    let epsilon = 1e-10
    let clamped = error |> max epsilon |> min (1.0 - epsilon)
    0.5 * log ((1.0 - clamped) / clamped)
```

| 誤り率 | 発言権 | 意味 |
| ---: | ---: | :--- |
| 0.05 | 1.47 | よく当たるので強く聞く |
| 0.5 | **0.0** | 当てずっぽうなので無視 |
| 0.7 | **-0.42** | 逆張りすれば役立つ |

**誤り率 0.5 で発言権がちょうど 0 になる** のが、この式の美しさです。第 7 章で AUC が 0.5 でランダムを意味したのと同じ構図です。

`error |> max epsilon |> min (1.0 - epsilon)` というクランプは、第 6 章の対数損失、第 8 章のナイーブベイズに続く 3 度目です。**パイプラインで「下限で切って上限で切る」が手順どおり並ぶ** 書き方も同じです。

### 学習ループ

```fsharp
let trainAdaBoostWith
    (rounds: int)
    (maxDepth: int)
    (impurity: Impurity)
    (points: Point list)
    (labels: int list)
    =
    let initialWeights = List.replicate (List.length points) (1.0 / float (List.length points))

    let step (learners, weights) _ =
        let tree = buildTreeWithWeights impurity maxDepth points labels weights
        let error = weightedError tree points labels weights

        // 当てずっぽう以下の学習器は採用しない
        if error >= 0.5 then
            (learners, weights)
        else
            let alpha = learnerWeight error

            let updated =
                List.zip3 points labels weights
                |> List.map (fun (point, label, weight) ->
                    weight * exp (-alpha * float label * float (predict tree point)))

            let total = List.sum updated
            (learners @ [ { Tree = tree; Weight = alpha } ], updated |> List.map (fun w -> w / total))

    let learners, _ = List.fold step ([], initialWeights) [ 1..rounds ]
    { Learners = learners }
```

**`(learners, weights)` というタプルを畳み込みます。** 第 3 章の学習ループ、第 8 章の対数確率、第 10 章の順伝播に続く `fold` の 4 度目です。「複数の状態を同時に更新する」という要求に、F# は一貫して同じ道具で応えます。

`float label * float (predict tree point)` は、当たれば +1、外れれば -1 です（**ラベルが +1 / -1 だから成立します**。第 11 章と同じ理由でこの表現を選びました）。

- 当たった点: `exp(-alpha)` 倍 → 重みが **減る**
- 外れた点: `exp(+alpha)` 倍 → 重みが **増える**

学習器の蓄積だけは `learners @ [ ... ]`（末尾追加）にしました。第 10 章の逆伝播では `::`（先頭追加）が正しい順序を作りましたが、**ここでは学習の順序がそのまま発言の順序** なので、末尾に足すほうが素直です。要素数が数十なので O(n) のコストも問題になりません。

## 実行結果

| モデル | 正解率 |
| :--- | ---: |
| 切り株 1 本 | 0.75 |
| バギング（切り株 10 本） | 0.75 |
| **AdaBoost（切り株 10 本）** | **1.00** |

**同じ弱学習器を同じ本数使って、結果が分かれました。** 束ね方の違いだけです。

学習された切り株を見ると、動きが分かります。

| ラウンド | 発言権 | 分割 |
| ---: | ---: | :--- |
| 1 | 0.5493 | x < 2.5 なら +1 |
| 2 | 0.8047 | x < 6.5 なら -1 |
| 3 | 0.6931 | （全部 +1 の葉） |
| 4 | 0.7332 | x < 2.5 なら +1 |

**1 本目は左端、2 本目は右端に注目しました。** 1 本目が右端の `x = 7, 8` を外したので、その重みが上がり、2 本目が拾いに行ったのです。

重み付き投票の結果、`x = 7, 8` では「1 本目は -1、2 本目は +1」となり、発言権の大きい 2 本目が勝ちます。**役割分担が自然に生まれました。**

これらの値は Python 版・Kotlin 版と完全に一致します。**AdaBoost には乱数がない** ためです。

## バギングと AdaBoost の使い分け

| | バギング | AdaBoost |
| :--- | :--- | :--- |
| 学習器の作り方 | **並列**（互いに独立） | **逐次**（前の結果に依存） |
| データの扱い | 復元抽出でばらつかせる | 重みで注目点を変える |
| 減らせるもの | 分散（過学習） | 偏り（表現力不足） |
| 向く弱学習器 | 深い木（分散が大きい） | 浅い木（偏りが大きい） |
| 並列化 | できる | **できない** |

本章のデータは「切り株では表現力が足りない」問題だったので、AdaBoost が勝ちました。**どちらが優れているかではなく、何を減らしたいかで選びます。**

## まとめ

- 第 9 章の決定木を、書き換えずに部品として再利用できました。`Impurity` を関数型にしておいた設計が効いています。
- `open` で名前が平坦に入るため、章をまたいで使う関数には `forestPredict` のような接頭辞が要ります。
- `List.zip3` により、3 本のリストの同時走査がタプルの分解で書けます。
- `fold` にタプルを畳み込む形が、本シリーズで 4 度目の登場です。
- 蓄積の向きは要求で決めます。第 10 章は `::`（逆順に積む）、本章は `@`（順序どおり足す）が素直でした。
